# 参考 · Terrasavr（外部玩家存档编辑器调研）

> 状态：2026-11 调研一次。**用途是兼容性对照，不是集成**：我们不会调用它，也不复制它的代码。
> 目的只有两个：① 它的版本/文件形态覆盖比我们宽多少；② 差的那部分值不值得补。
> 复现方法见 §8；本页结论都出自站点自身产物（脚本 + 语言包），不是印象。

## 1. 它是什么

- 地址 `https://yal.cc/r/terrasavr/`（作者 YellowAfterlife；HTTP/HTTPS 都 200）。
- 形态：Haxe/OpenFL 编译成 JS（`script.js` 约 690 KB）+ 一份语言包 zip，纯浏览器端操作。
- 站点自述（`<noscript>` 原文要点）：可对角色存档做「外观、增删物品与 BUFF 等」操作并**保存回磁盘**；
  「works with latest version of Terraria, but can also load and save player files made by earlier versions,
  meaning that it can be used to **migrate savegames back and forth between game versions**」。
- 结论：它的核心差异化就是**双向跨版本**，其余是编辑器功能。

## 2. 它能写的版本（原文表）

出处：`script.js` 的 `ya.initPC`（`app.TabVersion` 的版本表）：

| 分组 | 版本 = `release` |
| --- | --- |
| 1.1.x | `1.1.2=39` |
| 1.2.x | `1.2.0=69`、`1.2.1=73`、`1.2.2=77`、`1.2.3=93`、`1.2.4=98` |
| 1.3.x | `1.3.0=145`、`1.3.1=168`、`1.3.3=175`、`1.3.4=184`、`1.3.5=190` |
| 1.4.x | `1.4.0=225`、`1.4.0.5=230`、`1.4.1.2=237`、`1.4.3.0=248`、`1.4.4.0=269`、`1.4.5.0=315`、`1.4.5.7=325` |

两点值得注意：

- **没有 326（1.4.5.8）**：最高只到 325。325 与 326 同布局段（`[324,∞)`），所以他们写 325 对 1.4.5.8 也成立
  —— 这也解释了为什么「版本表只给代表版本」是可行的产品选择。
- 每个分组只给**代表版本**（例如 1.4.1 只给 1.4.1.2），不是全版本；同布局段内写哪个数字无差别。

## 3. 能力清单（语言包实际文案 + 代码视图类）

顶栏（`Terrasavr.zh-CN.json` 的 `tab.top.*`）：人物 / 装备 / 工具 / 背包 / 储蓄罐 / 保险箱 / 熔炉 / 虚空袋 /
药水（BUFF） / 研究 / 出生点 / 帮助，加上「加载存档」「保存存档」。

细化能力：

| 能力 | 文案出处 | 说明 |
| --- | --- | --- |
| 物品编辑 | `tab.edit.*` | 名称 / ID / 数量 / 词缀，带词缀分类（增益、减益、最优…） |
| 物品库与分类 | `tab.library.*`、`lib.item.*` | 按材料、矿石、家具、宠物、按 ID 分段等上百个分类浏览 |
| 预设片段 | `tab.items.save*` / `tab.buffs.menu.save*` | `.tsr`（装备/时装/物品）、`.tsb`（BUFF），**Terrasavr 专用**，游戏不认 |
| 研究进度 | `tab.research.*` | 编辑 + 「全部解锁」「移除全部」 |
| 出生点 | `tab.spawnpoints.*` | 按「世界名 + worldID」增删；文案自己提示「除非复制别人的数据，否则毫无意义」 |
| 外观 | `tab.char.*` | 发型、性别与服装、7 种颜色（我们只展示颜色，不可改） |
| 存取指令 | `tab.buffs.*`、`lib.prefix.*` | 固定前缀组（传说/神话/虚幻/无情…） |
| 语言与字体 | `tab.lang.*` | 自定义字体、强制系统字体；整套 UI 可翻译 |

代码里另有 `app.TabFlags` / `TabShelf` / `TabServers` / `TabVersion` / `TabLang` 等视图类；其中 `TabVersion`
就是 §2 的版本表视图。类名只说明「存在这个视图」，当前语言包不一定都有对应文案，别拿类名当功能清单。

## 4. 兼容面（我们真正要对表的那一层）

- **只吃 `.plr`**：`tplr` / `tmodloader` 在 690 KB 脚本里 0 次命中；`.bak` 唯一命中是压缩代码的误匹配。
- 脚本里出现 zip / 「Unsupported compression」是它**自带的 zip 读取器**（只用于语言包与内置资源），
  与存档无关 —— 不要据此以为它支持压缩存档。
- **物品与目标版本的合法性**（`tab.char.version.ttip` 原文）：
  > 存档的版本。**无法向存档中加入选定版本中没有的物品**。并且低于选定版本的游戏客户端将无法加载此存档。

  → 它的做法是「先把存档重写成目标版本的字段布局，再按该版本的物品表拦截」。我们只做了前半段。

## 5. 与我们的实现对照

| 维度 | Terrasavr | 本仓库（`web/src/lib/save/`） |
| --- | --- | --- |
| 读的范围 | 1.1.2（39）起 | 1.3.0.1（135）起 —— `release < 135` 没有 20 字节 `FileMetadata` 文件头，还没处理 |
| 写的范围 | 39–325 双向 | **220–326 双向**（1.4.0.1 起） |
| 跨版本实现 | 自己的完整序列化器（能把任意版本读成内存模型再写成另一版本） | 按门槛**插入/删除字节**（`plrConvert.ts`），其余字节原样保留 |
| 降级丢数据处理 | 静默丢（只提示「低版本客户端加载不了」） | 显式提示「会删掉哪些段」，且退款队列非空 / 尾部读不出来时**拒绝转换** |
| 按目标版本拦截物品 | 有（依赖它自己的逐版本物品表） | 无（`data/items.json` 只有 1.4.5.8 一份，没有逐物品引入版本） |
| 研究进度 | 可编辑 + 全解锁 | 只展示 |
| 出生点 | 可增删 | 只展示 |
| 外观（发型 / 颜色） | 可改 | 只展示 |
| 预设片段 / 翻译 / 字体 | 有（`.tsr`/`.tsb`、UI 翻译） | 无（不在本项目范围） |

## 6. 已经按这份对照补齐的部分

- 双向版本转换：`plrConvert.ts` 的 `upgradePlr`（按门槛插入）/ `downgradePlr`（按门槛删除）/ `convertPlr`（统一入口）。
- 降级所需的尾段偏移：`plr.ts` 的 `PlrTrack.anchors` 记录声音变体、音调、退款队列、一次性对话的起止。
- 界面：版本下拉 = 同布局段 + 按目标段分组的跨段目标，升/降各一条说明文案。
- 验证（可复跑，见 `localSaves.test.ts`）：485 份真实存档（226/230/269/279/315/318/325/326 八个版本）
  × 所有跨段目标 = **10,743 次转换，0 失败**；同段 47 / 升级 67 / 降级 142 组逐字段比对通过。

## 8. 复现（本页所有结论的取数方式）

# 语言包（1.5 MB，内含 zh-CN，是功能文案的权威出处）

unzip -q /tmp/tl.zip -d /tmp/tlang

# §2 的版本表

s = open('/tmp/terrasavr.js', encoding='utf-8', errors='replace').read()
i = s.find('ya.initPC=function()')
print(s[i:s.find('};', i)][:1200])
PY

grep -oiE "tplr|tmodloader" /tmp/terrasavr.js | wc -l
