# 技术事实（别猜，已核实 / 实测）

> 源码与实测细节见 [`TECHNICAL_RESEARCH.md`](TECHNICAL_RESEARCH.md) 与 [`REST_API限制.md`](REST_API限制.md)；
> 产品与硬约束（C1–C15）见 [`设计原则与约束.md`](设计原则与约束.md) §3。
>
> **存档格式（`.plr` / `.wld`）以本文件为唯一事实源**：页面 / 计划 / 功能文档只链接到这里，不再复述字节布局。

- Terraria **1.4.5.8**，TShock 目标 **v6.2.1**，REST 端口 **7878**。
  存档（`.plr` / `.wld`）的解析与编辑已支持到 **1.4.6.1（release 329）**；世界版本转换从 1.4.0.1 升级、降级到 1.4.4；`data/` 仍是 1.4.5.8
  （TShock / OTAPI 尚未支持 1.4.6.1，服务端能力以 TShock 为准）。
- `/v3/server/rawcmd` 以 token 用户的用户组身份执行，**严格继承权限，不提权**。
- **`AllowServer=false` 的指令无法通过 rawcmd 执行**（`/i`、`/tp`、`/home`、`/buff` 等 24 条）：
  前端与后端都必须直接拒绝并提示「只能在游戏内执行」。
- **参数补全的数据来自 TShock 自己的用法串**（`GetString("Invalid syntax. Proper syntax: {0}<cmd> <args>")`,
  `Commands.cs` 中 73 处）+ 源码枚举常量 + `switch (args.Parameters[N])` 的 case 标签 + 「方法体不引用
  `args.Parameters` → 无参数」的机械判定；`data/commands.json` 的 `paramSets`（95 条中 70 条）由
  `tools/gen-data.mjs` 提取。**提取不到就不给候选，绝不猜参数**；改动后须跑
  `web/src/lib/completion.realdata.test.ts` 与 `server/scripts/sync-commands.sh`。
- **参数取值（`kind: 'enum'`）在补全下拉框里带可读备注名**（如 `brain` → 克苏鲁之脑）：
  `spawnboss` 取值是 NPC 别名 → 由 `data/npcs.json` 的 `sb` / `sbAliases` + `loc.NPCName` 解析；
  `worldevent` / `worldmode` / `time` / `clear` / `firework` / `region` / `warp` / `group` 等的固定术语，
  以及多级子命令（`/region define`、`/worldevent invasion <类型>`、`/pm` / `/wm` / `/fish` 等）
  统一在 `web/src/lib/commandMeta.ts` 维护（国际事件名取自游戏本地化 `Bestiary_Events` / `Bestiary_Invasions`）。
  补全支持字面量子命令与按备注名搜索（如输入「血月」命中 `bloodmoon`）；覆盖度由
  `commandMeta.test.ts` 对着真实 `commands.json` 兜底（所有 enum 取值都必须有备注）。
  维护方式与全部子命令清单见 `docs/功能-指令多级补全与备注.md`。
- **未知/插件指令不前置拒绝**：`commands.json` 只含核心 95 条，插件指令（如 FishShop 的 `/fish`）
  无法静态枚举，故未知指令照常发往 TShock，由 TShock 判定（不存在 → `command_not_found`，
  与「参数错误 → `command_error`」分开：前者说明提供该指令的插件没装）。
  判定只认 TShock 的**完整句式**并先做归一化（转小写 + 空白合并）：
  en `Invalid command entered. …` / zh `输入的命令无效。…`；插件自己打印的「无效指令：xxx」不算，
  否则首页依赖插件的卡片会被误隐藏（`server/internal/tshock/client.go` 的 `markersCommandNotFound`）。
- **用户组是写进账号库的，但 web token 里的组是登录时的快照**：`/user group <账号> <组>`（GM 执行）
  走 `UserAccountManager.SetUserGroup` → `UPDATE Users SET UserGroup = ...`，离线账号也能改；
  而 REST 的 `SecureRest.TokenData` 是 **struct**，`Tokens` 是 `Dictionary<string, TokenData>`，
  校验时每个请求 `TryGetValue` 再 `TShock.Groups.GetGroupByName(tokenData.UserGroupName)`
  （`TShockAPI/Rest/SecureRest.cs`，6.2.1）。所以换组后旧 token 仍按旧组判权限（含 rawcmd / `/webui/batch`），
  必须把 `Tokens[token]` 整条替换成新的 `UserGroupName` 才生效——这就是 `/webui/me/refresh` 做的事。
  `/tempgroup` 只改在线玩家的 `tempGroup`、**不写库**，网页刷新看不到（与 TShock 语义一致）。
- **会话按上游隔离**：`session.Session.Upstream` + 按上游派生的 Cookie 名，切服不串用 token、
  也不清掉别服的登录态；`/api/capabilities` 是统一能力矩阵（一次请求拿到各插件可用性）。
- **剪贴板 API 只在安全上下文存在**：`navigator.clipboard` 在 `https:` / `localhost` 下才有；
  本项目常规部署是 `http://IP:18080`（C12），那种页面里它是 `undefined`，`navigator.clipboard.writeText(...)`
  会**同步抛 TypeError**（`.catch` 接不住）。所以复制统一走 `web/src/lib/clipboard.ts` 的 `copyText()`：
  优先 Clipboard API，否则退回隐藏 `textarea` + `document.execCommand('copy')`（已废弃但非安全上下文仍可用），
  两条都失败才不显示「已复制」（不假装成功）。
- **普通玩家默认无法登录**：建 token 需用户组有 `tshock.rest.useapi`，执行指令需 `tshock.rest.command`；
  `default` 组没有，密码正确也被拒（TShock 对「密码错」与「无权限」返回同一 403，后端无法区分）。
  需服主执行：`/group addperm default tshock.rest.useapi tshock.rest.command`（GM 等带 `*` 的组免配）。
  前端登录失败时会展示该命令并提供复制。
- TShock token 只存内存，**重启即失效**；建 token **按来源 IP 限流**（默认 5 次/分钟）。
  经反代时所有玩家共用一个来源 IP（实测网关 `<gateway-ip>`），故这是**全站**限额。
- **`POST /v2/token/create` 不解析表单体**（实测 500），登录凭证**只能走 query string**；
  因此必须由后端发起，浏览器不直连。
- **后端→TShock 的出站 HTTP 方法默认 `POST`**（`TSHOCK_METHOD=POST|GET`，默认 POST）：
  TShock **不校验方法**（只按 URI 路由），参数始终只在 query string；
  默认 POST 是为了规避部分机房把**明文 GET** 劫持成 302 —— 实测腾讯云对 Host 为未备案域名的 GET
  返回 `302 → dnspod.qcloud.com/static/webblock.html`（POST/PUT/OPTIONS 均正常）。域名被拦时根治靠备案或用 IP，
  详见 `docs/REST_API限制.md` §1 / §8.1。
- `/v2/server/status` 的 `serverversion` 形如 **`v1.4.5.8`（带前导 `v`）**，与 `data/meta.json` 比较前必须去掉。
- `EnableTokenEndpointAuthentication=true` 时 `server/status` 需要 token（无 token 返回 401）。
- **`GET /api/session` 会校验上游 token**（`/tokentest`）：TShock 重启后刷新页面会回到未登录态（页面显示「请先登录！」占位，**不自动弹框**）；执行指令遇 `token_invalid` 才弹登录框，并在重登后自动重试一次。
- 图标：一张图集 `data/items-atlas.webp`（1024×4906，每格之间 1px 透明缝），前端按 `items-atlas.json` 的 `regions[item.icon]` 裁切第一帧。
- **容器访问公网 TShock 可能被本机代理挡住**（实测 OrbStack/macOS）：容器出站走 Clash（`127.0.0.1:7890`），出口 IP `<container-exit-ip>`，而宿主机直连出口 `<host-exit-ip>`；
  远端 TShock 对容器连接返回空回复（`curl` 52 / 后端 `tshock_unavailable`），宿主机 `/api/login` 正常。
  解决：给 Clash 加该 IP 的 `DIRECT` 规则，或用 `scripts/dev-native.sh` 在宿主机直跑后端。
- **角色存档（`.plr`）**：AES-128-CBC（`PaddingMode.None`，key 与 IV 都是 `"h3y_gUyZ"` 的 UTF-16LE 字节）
  加密后按 `Player.Deserialize` 的字段顺序平铺；文件头是 20 字节 `FileMetadata`（release ≥ 135）。
  **解密与解析都在浏览器里**（`web/src/lib/save/aes.ts` + `plr.ts`；WebCrypto 的 AES-CBC 会强做 PKCS#7
  去填充，与本格式不符，所以自带一份无填充实现），文件不上传。
- **角色存档（`.plr`）里除了外观 / 属性 / 各容器，还有这些字段**（顺序照抄 `Player.Deserialize`，1.4.5.8；
  1.4.6.1 的门槛与读取顺序逐项比对**无变化**）：
  `voidVaultInfo`（byte，≥199）→ **当前 BUFF**（`buffType`/`buffTime` 成对，数量 10/22/44 按版本，读到 0 就丢弃并减少目标数）
  → **重生点列表**（`spX`/`spY`/`spI`/`spN` 各 200 项，`spX == -1` 结束；按「世界名 + worldID」分开存，游戏用 `FindSpawn()` 匹配当前世界）
  → `hbLocked` → `hideInfo[13]` → `anglerQuestsFinished` → Dpad 绑定 ×4 → `builderAccStatus`（8/10/11/12 按版本）
  → `bartenderQuestLog` → `dead`（+ 仅在死亡时写 `respawnTimer`）→ `lastTimePlayerWasSaved`（**`DateTime.UtcNow.ToBinary()`，真 UTC**，界面按本地时区显示）
  → `golferScoreAccumulated` → **研究进度**（`ItemsSacrificedUnlocksTracker`：≥282 先一个 bool，再 `int32` 条数 + 每条 `string` 物品持久 ID + `int32` 数量）
  → 4 个临时槽 → **旅途创意能力**（`bool` 循环 + `ushort` 能力 id + 各自 payload；只有 3 个能力持久化：
  `5` / `11` 各 1 字节 bool、`14` 是 4 字节 float，其余没有 payload，未知 id 时游戏自己也会 `break`）
  → 超级矿车位 → `CurrentLoadoutIndex` +
  三套 `Loadouts`（各 20 装备 + 10 染料 + 隐藏位）→ `voiceVariant` / `voicePitchOffset` → 退款队列（≥300）→ 一次性对话（≥310）。
  **垃圾桶 `trashItem` 不在存档里**（只存在于运行时），所以本地 `.plr` 的垃圾桶槽永远是空的。
  **研究进度里存的是「物品持久 ID」**（`ItemsSacrificedUnlocksTracker` 的字典键），
  它就是物品的内部键名（`ItemID.Search.GetName(netId)`，例如 29 → `LifeCrystal`），
  **与 `data/items.json` 的 `key` 完全一致**（用 GameDump 导出 6161 条逐一比对，0 不一致）——
  所以前端不需要额外数据表就能把研究进度对回物品名。少数对不回是**正常**的：老存档会留下已改名/移除的物品
  （实测 `Joy.plr` 里的 `EldMelter`，1.4.5 已改名为 `ElfMelter`），界面按原始键名显示。
  两个实测坑：① `statLifeMax` / `statManaMax` 读的时候游戏会夹到 **500 / 200**，所以「展示值」不等于文件里的
  原始字节值（回写要用原始值）；② 真实服务器目录里见过**研究进度段没有前导 bool** 的 release 318 存档
  （第三方改过的存档，原版写端必写这个 `bool`）——解析尾部必须「读不动就停、不记偏移」，不能把整份存档判死。
  解析一直读到**尾段结束**（`web/src/lib/save/plr.ts` 的 `readPlrTail`）：配装之后的声音变体 / 音调 /
  退款队列 / 一次性对话**不展示也不编辑**，但要记下各自的起止偏移（`PlrTrack.anchors` 的
  `voiceAt` / `pitchAt` / `refundsAt` / `dialoguesAt` / `tailEnd`）—— 版本转换要靠它们知道该删到哪儿。

- **1.4.4.9 的 `Player.Deserialize` 到 262 就结束**（本机反编译源码核对）：所以 262–279 这一段
  （1.4.4 ~ 1.4.4.9）与 1.4.5.x 的差别全部是 280 之后新增的字段，和真实存档的逐字节对账一致。
- **`.plr` 版本号（`Main.curRelease`）**：1.4.5.8 = **326**、1.4.6.0 / 1.4.6.1 = **329**
  （`Player.SavePlayer` 写死 `329`）。327–329 与 326 **字段布局完全相同**（没有任何新门槛），
  所以改版本只是改文件头那 4 字节；1.4.5.8 客户端读 329 会被「更高版本」拒绝，反过来会自动升级。
- **世界文件（`.wld`）是 `.NET BinaryReader` 写出的平铺结构**，`.wld.bak` / `.wld.bak2` 只是同格式备份副本
  （同一解析器，无需区分）。事实与出处（反编译源码 `TR_SRC`，Terraria 1.4.5.8；1.4.6.1 逐项对照，差异见下）：
  - 第 0 段（文件头）：`int32 release` → `Terraria.IO/FileMetadata.cs` 的 `FileMetadata.Read`
    （8 字节 = 7 字节魔数 `relogic` + 1 字节 `FileType`，`World=2`、`Player=3`；`uint32 Revision`；
    `uint64` 位标志，仅 bit0 = 收藏）→ `int16` 段数 → 段数 × `int32` 段指针 → 图格 frame 位压缩数组。
    来源：`Terraria.IO/WorldFile.cs` 的 `LoadFileFormatHeader`。
  - **段指针是「各段结束位置」**：`pointers[0]` = 文件头结束，`pointers[1]` = 头部字段结束
    （**也就是图格段起点**），`pointers[2]` = 图格段结束（箱子段起点）…（`LoadWorld_Version2` 的
    `Position == positions[i]` 断言）。所以缩略图从 `pointers[1]` 开始读，而不是 `pointers[2]`。
  - **指针表末尾可能是 `0` 占位（老存档）**：1.4.5.8 的写入端固定写 **11** 个指针；release < 210 的世界
    没有 bestiary / 创造之力段，对应的槽位留 `0`，而加载端按版本号决定检查到哪一段，**这些槽根本不看**。
    实测：1.3.5.3（release 194）的 `Double Cross -zh.wld` 是 10 个指针、最后一个为 `0`。
    所以 **footer 起点 = 最后一个有效（> 0）的段指针**，不能取 `pointers[N-1]`；
    平移重写指针表时那个 `0` 也必须保持 `0`。footer 本身是**顺序读**的
    （`LoadWorld_Version2` 末尾 `LoadFooter(reader)`，不靠指针定位）。
  - **各段的版本门槛**（`LoadChests` / `LoadSigns` / `LoadNPCs` / `LoadTileEntities`）。**箱子段的门槛最隐蔽**：
    `release < 294` 时容量是**整段共享的一个 `int16`**（写在箱子列表之前），≥294 才是每个箱子自带 `int32`；
    另外物品条目里 `stack == 0` 才是空槽，`stack < 0` 是「只堆 1 个但带词缀」（后面仍跟 `int32 id + u8 prefix`）。
    按 ≥294 的格式去读 1.4.4.9 及更早的真实世界 → **一个箱子都读不出来**（实测 30 个真实世界因此丢了 8541 个箱子）。
    箱子=第 3 段、
    招牌=第 4 段、NPC=第 5 段、图格实体=第 6 段（release ≥ 122 起；≥ 170 才有冲压板段、≥ 189 才有
    城镇管理段）。**NPC 段门槛最多，少读一个字节后面全部读偏**：`≥ 268` 才有开头的微光化 NPC
    netID 列表；`≥ 213` 才有 `townNpcVariation` 的 `BitsByte`（bit0 后跟 4 字节索引）；`≥ 315` 才有
    `homelessDespawn` 布尔位；`< 190` 的 netID 存的是**旧版名字字符串**（`NPCID.FromLegacyName`）。
    另外 `GivenName` 可以为空（实测老人 `netId 37` 就是空串），不能当解析失败。
  - **1.4.6 的世界格式只多一个头部位**：`release >= 328` 在 `noLightningSeed` 之后多一个 `noSpidersSeed`（bool）；
    段结构、图格流、箱子 / 招牌 / NPC / 图格实体 / 图鉴 / 创意能力段都与 1.4.5.8 相同。
  - 招牌段（`SaveSigns`：`int16 数量` + 每块 `text,x,y`）没有版本门槛，但存档里常带**残留记录**：
    `LoadSigns` 会用 `tile.active() && Main.tileSign[tile.type]` 过滤，tile 已不在就丢弃这条记录。
    `Main.tileSign` 只包含 **55（告示牌）/ 85（墓碑）/ 425（广播盒）/ 573（墓碑 2）**；
    箱子类图格是 `Main.tileContainer`：**21 / 88（穿衣镜）/ 467 / 470 / 475**。
    实测 `world-S87.wld` 的 9 条招牌记录**全部**落在空气上（墓碑被挖掉），而文本完整可读 —— 解析正确，别当解析错。
  - 第 1 段（头部字段）：顺序照抄 `WorldFile.LoadHeader`。要点：`release >= 209` 起难度是 `int32`
    （0 普通 / 1 专家 / 2 大师 / 3 旅途），特殊种子是紧随其后的一串 `bool`（`zenith` 在 267 前由
    「醉汉 + 颠倒」推导）；`>= 141` 有创建时间（`CreationTime.ToBinary()`）、`>= 284` 有最后游玩时间
    （`DateTime.UtcNow.ToBinary()`）。两者**语义不同**：创建时间是 `DateTime.Now` → Kind = 本地，
    ticks 就是**本地墙上时间**（显示时不能换算）；最后游玩是 UTC → 换算成本地才对（实测与文件 mtime 吻合）。
    Kind 在高 2 位（1 = UTC / 2 = 本地 / 0 = 未指定），解析时必须读，`web/src/lib/save/bytes.ts`
    的 `dotnetBinaryToIso` 就按它决定「带不带 `Z`」；
    `>= 297` 起有团队出生点（`byte` 数量 + 每个 `int16 × 2`）；`>= 299` 起末尾有
    `WorldManifestData`（`ReadString`）。
  - 图格段是 RLE 压缩的属性流：`header1` 的 bit0 表示有 `header2`（`header2` bit0 → `header3`，
    `>= 269` 再 → `header4`）；bit1 图格激活、bit2 有墙、bit3-4 液体类型、bit5 图格 ID 是 2 字节、
    bit6-7 RLE 计数宽度（0 无 / 1 `byte` / 2 `int16`）；`header2` 的 bit1-3 是三种线缆、bit4-6 斜坡；
    `header3` 的 bit3 图格染料、bit4 墙染料、bit2 actuator、bit5 黄线缆、bit6 墙 ID 高字节、
    bit7 = 微光；`header4`（`>= 269`）是隐形 / 满亮度。来源：`MapHelper.DecompressTileData`
    （TEdit `World.FileV2.cs` 的 `DeserializeTileData` 与之逐位一致）。
    RLE 是**同列向下重复**，所以解码必须按 `for x { for y }` 顺序、不能跳读。
  - 小地图颜色表：`tools/gen-world-colors.mjs` 从 TEdit 仓库 `src/TEdit/MapColors.xml`（文件头标注
    "Terraria MapColors.XML … 1.4.5.0"，取 `Paint="0"` 基础色）生成
    `web/src/lib/save/worldColors.generated.ts`；区域背景色与液体色取自 TEdit `docs/settings.xml`

    753（GiantTiki）写的是 `MultiplyMapColor(array[158][0], 0.95f)`，生成器按 158 逐通道 ×0.95 算
    （表长 753 → **754**）。而 **127 / 135 / 210 / 428 / 504 / 541 游戏里没有图格颜色**
    （`MapHelper` 只有墙色 `array4[...]`，或完全没赋值），地图上本来就不可见 ——
    我们**故意**退回中性灰（`0x808080`）而不是照抄「透明」，并写进生成器注释。
