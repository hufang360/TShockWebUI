# 插件接入规范

本仓库把「第三方 / 自研 TShock 插件」的能力做成可选模块。每接入一个插件，写**一篇**
`docs/插件-<插件名>.md`：接入细节（端点 / 字段 / 权限 / 限制）+ 页面信息（用到的
REST API / 指令、依赖插件版本、项目地址）。模板见第 1 节。

## 0. 铁律（所有插件通用）

1. **不虚构 API**：端点、字段、权限必须来自插件源码或实测，写进文档并注明出处。
2. **不提权**：浏览器只持同源 `/api/*`；TShock token 只在后端内存。所有请求用**当前登录玩家
   自己的 token**，权限由插件判定。
3. **插件缺失/无权限要提示**，不能让界面报错或空白：
   - 探测端点 404 → `plugin_not_installed`（前端 `plugin_missing`）
   - 403 → `no_permission`
4. **单容器、单端口**，只暴露固定的 `/api/*`，不做通用 URL 代理。
5. **模块默认不显示**：需在「设置 → 激活模块」探测到插件后手动打开，入口才进侧边栏。
6. **按服务器分开记忆**：模块开关（`tswui:modules`）与界面状态（`tswui:moduleState`）都以
   `X-TSWUI-Target` 对应的 `serverId` 为键——不同服务器装的插件不同。

```markdown

- 插件版本（集成验证版本）、项目地址（GitHub）、权限、配置目录、探测方式

## 1. 插件是什么 / 依赖什么
- 用途、指令、源码出处、REST 端点前缀

## 2. 上游 REST 端点（事实来源）
| 端点 | 参数 | 权限 | 说明 |

## 3. 本仓库后端接口
| /api/... | 对应上游 | 说明 |

## 4. 前端模块
- 激活方式、侧边栏入口、页面结构、默认焦点等交互约定

## 5. 数据字段
- 上游字段 → 本仓库 `FishGood`/`PlayerLook` 等同名字段（含容错）

- 版本差异、字段类型陷阱、实测结论

## 8. 验证命令
- curl / 端到端脚本
```

## 2. 通用实现位置（Cheat sheet）

| 关注点 | 位置 |
| --- | --- |
| 上游客户端（探测 + 调用 + 错误分类） | `server/internal/tshock/<plugin>.go` |
| `/api/*` 路由与 handler | `server/internal/api/handlers.go` |
| 前端传输层契约 | `web/src/lib/transport.ts`（类型 + `BackendTransport`） |
| 真实/Mock 实现 | `web/src/lib/httpTransport.ts` / `mockTransport.ts` |
| 模块开关 | `web/src/lib/modules.ts` + `web/src/pages/SettingsPage.tsx` |
| 按服务器记忆界面状态 | `web/src/hooks/useModuleState.ts` |
| 测试桩 | `web/src/test/playerStubs.ts` |

### 能力探测（capability）约定

- 后端用**缺参数**的只读调用探测：如 `/pm/look`（空 name）、`/v3/fishshop/ask`（空 serial）。
- 404 = 未安装，403 = 无权限，400/2xx = 已安装。
- 返回 `{ "plugin": bool, "permission": bool }`，前端据此禁用模块开关。

### 错误码约定（见 `docs/API_SPEC.md` §0）

`plugin_not_installed`(404) / `no_permission`(403) / `token_invalid`(401) /
`rate_limited`(429) / `tshock_timeout`(504) / `tshock_unavailable`(502) /
`<插件>_error`(400，业务失败，`message` 原样给玩家)。

### 富文本

价格、解锁、备注等字段里可能含 Terraria 标签（`[i:..]` 物品图标、`[c/..:..]` 颜色）。
统一用 `web/src/components/ResultPanel.tsx` 的 `CommandOutput` 渲染（内部走
`lib/richtext.ts` 的 `parseRichText`）。

## 3. 新增一个插件模块的步骤

1. **读源码/实测**：拿到端点、参数、权限、返回字段（尤其注意**字段类型**：数组 vs 字符串、
   int vs bool）。
2. **后端客户端** `server/internal/tshock/<plugin>.go`：探测 + 各端点方法 + 容错类型。
3. **后端路由** `handlers.go`：`/api/<plugin>/capabilities` + 业务端点；业务错误用专属
   `<plugin>_error` 保留上游文案。
4. **传输层** `transport.ts`：加类型 + `BackendTransport` 方法；`httpTransport` / `mockTransport`
   / `web/src/test/playerStubs.ts` 同步。
5. **模块** `modules.ts`：加一个 `ModuleDef`；`SettingsPage` 自动列出（探测逻辑按 id 分派）。
6. **页面** `web/src/pages/<Plugin>Page.tsx`：参照同类页面（列表/网格 + 详情弹框）。
7. **测试**：后端 `*_test.go`（含真实字段形状的回归）、前端页面测试 + `modules.test`。
8. **文档**：新建 `docs/插件-<名>.md`（本模板，含插件版本 / 项目地址 / 用到的 REST API 与指令），
   并在本文件顶部「现有文档」列出。
