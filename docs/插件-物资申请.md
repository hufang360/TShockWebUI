## 1. 插件是什么 / 依赖什么

- 玩家在网页「物资申请」模块里搜索物品、填数量与用途，提交给服主。
- 服主可以在**游戏内**用 `/web req ...` 审核，也可以在网页「待审核」tab 审核（需 `webui.request.review`）。
- 通过后由插件用 TShock 自己的 `TSPlayer.GiveItemCheck` 发放：
  - 玩家在线：立即进背包；背包满时按 TShock 原行为**掉落脚下**。
  - 玩家离线：状态为 `approved`，**下次登录**时由 `PlayerHooks.PlayerPostLogin` 自动发放。
- **不提权、不伪造身份**：申请人身份只来自 token；发放尊重 TShock item ban 与用户组限制。

## 1.1 服主上手（3 步）

```bash
# 1) 更新插件并重启 TShock（DLL 放进 plugins 目录）
# 2) 授予权限（按需改成自己的管理组）
/group addperm default webui.request.use
/group addperm <管理组> webui.request.review
# 3) 玩家登录网页 → 侧边栏「物资申请」；服主在网页「待审核」或游戏内 /web req 审核
```

## 2. 上游 REST 端点（事实来源：`RequestRest.cs` / `Requisitions.cs`）

| 端点 | 参数 | 权限 | 说明 |
| --- | --- | --- | --- |
| `/webui/requests` | `status`（可选） | `webui.request.use` | 我的申请（最多 50 条） |
| `/webui/requests/create` | `items`（JSON 数组）、`reason`、`note` | `webui.request.use` | 提交申请 |
| `/webui/requests/cancel` | `id` | `webui.request.use` | 撤回自己的 `pending` 申请 |
| `/webui/requests/all` | `status`（可选） | `webui.request.review` | 审核列表（最多 100 条） |
| `/webui/requests/review` | `id`、`decision=approve\|deny`、`reason` | `webui.request.review` | 通过 / 拒绝 |
| `/webui/requests/deliver` | `id` | `webui.request.review` | 补发已批准未发放的申请 |

- 全部是 `SecureRestCommand`：`token` 必须是**调用者本人**的有效 token；401/403 沿用 TShock 语义。
- 业务失败返回 HTTP 400 + `{ "error": "..." }`（如数量超限 / 物品被禁用 / 申请已处理）。
- `items` 形如 `[{"id":9,"stack":300}]`；插件会合并重复 id，并按 `item.maxStack` 拆组发放。

## 3. 本仓库后端接口

| `/api/...` | 对应上游 | 说明 |
| --- | --- | --- |
| `GET /api/requests/capabilities` | `/webui/meta` + `/webui/requests` | `{plugin, submit, review}` |
| `GET /api/requests?status=` | `/webui/requests` | 我的申请 |
| `POST /api/requests` | `/webui/requests/create` | 提交（基础参数校验 + 会话限流） |
| `POST /api/requests/cancel` | `/webui/requests/cancel` | 撤回 |
| `GET /api/requests/all?status=` | `/webui/requests/all` | 审核列表 |
| `POST /api/requests/review` | `/webui/requests/review` | 审核 |
| `POST /api/requests/deliver` | `/webui/requests/deliver` | 补发 |

错误映射见 [`API_SPEC.md`](API_SPEC.md) §6.4（唯一契约）；本表只记「哪个上游对应哪个 `/api`」。

## 4. 前端模块

- 模块 id：`requisition`；侧边栏名称「物资申请」。
- 探测到插件能力且当前用户可提交或可审核时，登录后**自动激活**；也可在「设置 → 激活模块」手动开关。
- 页面结构：
  - 左栏：物品搜索（`SearchInput`，复用 `searchItems` / `ItemIcon`）→ 申请清单（数量 1–9999）→ 用途 / 备注 → 提交。
    - 搜索框用 `shortcut`：页面里按 `/` 直接把焦点送进输入框（与物品图鉴 / 鱼店同规）。
    - 「物品收藏」图标按钮（⭐ + `Popover`）是**输入框的 addon**（`SearchInput` 的 `trailingAddon`，
      与输入框同一个 `InputGroup`，视觉上连成一体）：列出 `tswui:itemFavorites` 的收藏物品（图标 / 名称 / ID，
      最新收藏在前），点一件**直接加入申请清单**、收藏本身保留，并**自动收起浮层**；常申请的东西不用每次重新搜。
    - 申请清单空态外面套一层**虚线框**（`border-dashed`）：空清单也占一个「位置」，不会凭空消失。
  - 右栏：我的申请（状态、物品、审核人、拒绝原因、撤回）。
  - 有 `webui.request.review` 时多一个「待审核」外层 tab：通过 / 拒绝（拒绝必须填原因）/ 补发。
    - 里面左上角是「**待审核 / 全部**」两个**二级 tab**（`Tabs variant="line"`，原来是原生下拉框，
      得点开才知道还有另一边），切换即按 `pending` / `all` 重新拉取。
    - 记录按**两列**排（`grid md:grid-cols-2` + `content-start` + 每项 `self-start`）：卡片各按内容定高，
      不会像等高网格那样在正文下面留一块空白。
    - 两个 `TabsList` 都带 `aria-label`（「申请分类」/「筛选范围」）：外层也有一个叫「待审核」的 tab，
      不加标签时同名的两个 tab 在无障碍树里无法区分（单测也靠它定位）。
- 状态色：`pending` 警告、`approved` 信息、`delivered` 成功、`denied` 危险、`cancelled` 中性。

## 5. 数据字段

`Requisition`（插件 `ToDict` → 后端 `tshock.Requisition` → 前端 `Requisition`）：

| 字段 | 说明 |
| --- | --- |
| `id` | 自增编号（持久化 `NextId`） |
| `account` / `player` | 申请人账号 / 提交时的角色名（角色名只用于展示） |
| `items[]` | `{ id, stack }`；`stack` 是总数量，不是组数 |
| `reason` / `note` | 用途（必填）/ 备注或坐标（选填），均 ≤200 字符 |
| `status` | `pending` / `approved` / `delivered` / `denied` / `cancelled` |
| `createdAt` / `updatedAt` | UTC ISO-8601 |
| `reviewedBy` / `reviewedAt` | 审核人账号 / 时间 |
| `denyReason` | 拒绝原因 |
| `deliveredAt` / `deliveryError` | 发放时间 / 失败原因（失败时保持 `approved` 以便补发） |
| `world` | 提交时的世界名（多世界排查用） |

## 6. 权限、限额与配置

权限（TShock 动态权限字符串）：

```bash
/group addperm default webui.request.use
/group addperm <管理组> webui.request.review
```

插件启动时若没有组拥有对应权限会在控制台警告。

`tshock/WebUI/config.json` 新增字段（均可省略，使用默认值）：

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `RequestsEnabled` | `true` | 关闭后不再接受新申请 |
| `RequestMaxItems` | `10` | 一次最多几种物品（WebUI 前端 / 后端目前固定按 10 校验） |
| `RequestMaxStacksPerLine` | `10` | 每种最多几组（按物品 `maxStack` 计算） |
| `RequestMaxTotalStacks` | `30` | 单条申请总组数上限 |
| `RequestMaxPendingPerPlayer` | `3` | 每人待审上限（0 = 不限） |
| `RequestMaxPerDayPerPlayer` | `10` | 每人每天提交上限（0 = 不限） |
| `RequestMinIntervalSeconds` | `10` | 两次提交的最小间隔（0 = 不限） |
| `RequestMaxPendingTotal` | `200` | 全服待审上限（0 = 不限） |
| `RequestHistoryDays` | `30` | 已结束申请保留天数（0 = 不清理） |
| `RequestAutoDeliver` | `true` | 通过后自动发放；关掉则只标记 `approved`，用 `/web req give` 或网页「补发」 |
| `RequestNotifyReviewers` | `true` | 新申请时给在线审核人发游戏内提示 |

## 7. 游戏内指令

| 指令 | 权限 | 说明 |
| --- | --- | --- |
| `/web req list [pending\|approved\|all]` | `webui.request.review` | 列表（默认 pending） |
| `/web req show <id>` | `webui.request.review` | 详情（物品用 `[i:ID]` 显示） |
| `/web req ok <id>` | `webui.request.review` | 通过；在线立即发放，离线下次登录 |
| `/web req no <id> [原因]` | `webui.request.review` | 拒绝并记录原因 |
| `/web req give <id>` | `webui.request.review` | 补发已批准未发放的申请 |

## 8. 已知限制 / 坑

- **物品禁用**：提交 / 发放都按 TShock 自己的规则判定（`PreventBannedItemSpawn` + item ban 的用户组白名单；
  发放再用 `GiveItemCheck` 复检）；失败时不会静默发出，申请保持 `approved` 并记录 `deliveryError`。
- **背包满**：TShock 的 `GiveItem` 在非 SSC / 背包满时把物品掉在脚下；玩家需要自己捡。
- **离线发放依赖登录**：长期不登录的玩家，申请会一直保持 `approved`；`RequestHistoryDays` 只清理已结束记录，不清理 `pending` / `approved`。
- **不处理词缀**：申请只记录物品 id + 数量，不含 prefix；需要特定词缀的装备请在用途里说明，由服主手动处理。
- **网页审核是管理视图**：仅拥有 `webui.request.review` 的账号能看到「待审核」tab；不改变「WebUI 是玩家工具」的定位。
- **隐私**：申请内容只对本人和审核人可见，不写入公开的「服务器动态」事件流；审核人只收到物品摘要提示。
- **按服务器独立**：`requests.json` 属于该 TShock 实例；多服务器切换时各自独立。
- **协议**：新增端点只扩充能力 `requests` / `requests_review`，协议号仍为 1；旧插件没有这些能力时模块提示升级。

## 9. 验证命令

```bash
# 构建 + 部署插件
bash scripts/build-plugin.sh PLUGINS_DIR="$HOME/tr/s/ts/plugins"
docker restart tshock

# 协议握手（应包含 requests、requests_review）
curl -s --get 'http://127.0.0.1:7878/webui/meta'

# 玩家：提交 / 查看 / 撤回（TOKEN = 玩家自己的 token）
curl -s -X POST --get 'http://127.0.0.1:7878/webui/requests/create' \
  --data-urlencode 'token=<TOKEN>' \
  --data-urlencode 'items=[{"id":9,"stack":300}]' \
  --data-urlencode 'reason=建城堡外墙'
curl -s -X POST --get 'http://127.0.0.1:7878/webui/requests' --data-urlencode 'token=<TOKEN>'

# 服主：审核（需 webui.request.review）
curl -s -X POST --get 'http://127.0.0.1:7878/webui/requests/all' \
  --data-urlencode 'token=<ADMIN_TOKEN>' --data-urlencode 'status=pending'
curl -s -X POST --get 'http://127.0.0.1:7878/webui/requests/review' \
  --data-urlencode 'token=<ADMIN_TOKEN>' --data-urlencode 'id=1' \
  --data-urlencode 'decision=approve'

# 网页后端
curl -s -b <cookie> 'http://127.0.0.1:8080/api/requests/capabilities'
```

验收点：

1. 玩家 A 提交后，审核人在线收到提示；`/web req show 1` 能看到物品与用途。
2. 在线玩家通过后立即收到物品；离线玩家重新登录后自动收到，并收到结果提示。
3. 拒绝后玩家在「我的申请」看到原因。
4. 玩家看不到、也不能撤回别人的申请。
5. 被禁用物品 / 超量 / 超待审上限 / 频繁提交都返回明确文案。
6. 未装插件 / 旧插件：模块显示「未安装」/「版本过旧」，不是空白。
