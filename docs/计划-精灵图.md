# 计划：精灵图（`#/slice`）

状态：**已实现（2026-10-29）**。当前行为以 [`页面-精灵图.md`](页面-精灵图.md) 为准；
本文件只保留设计与取舍（ASCII 布局、计算规则、导出策略），不再重复页面细节。
定位：侧边栏「**工具**」分组的**公开本地工具**（与「玩家存档」「世界存档」同级）。

## 1. 为什么放在「工具」

- 处理对象是**本地 PNG 精灵表（spritesheet）**：一张图按行 × 列切成若干帧，用于整理插件素材 / 贴图。
- **不读 TShock、不需要登录、不需要权限、文件不上传**：解码、切片、导出全部在浏览器里做（`Canvas` + `toBlob`），
  因此入口恒在，**不跟随任何模块开关**（与 `.plr` / `.wld` 查看器同一原则）。
- 与现有能力的关系：只做「切图 + 导出」，**不做**九宫格编辑、动画预览、图集打包（超出本次范围）。

## 2. 范围

**做**

- 导入单张 PNG（点选 / 拖放），显示原图尺寸。
- 输入**行数 / 列数**，叠加网格与序号，实时看到分割区域。
- 可选**边距（margin）/ 间距（gap）**，适配带留白或间隔的精灵表。
- **每个切片可微调**：X / Y / 宽 / 高；方向键微移（1px，Shift = 8px）；「对齐到网格」「恢复默认」。
- 导出：**单个切片**（PNG）/ **全部切片**（ZIP，免依赖生成）。
- 可选「跳过全透明切片」。

**不做**

- 不解析 `.xnb`、不读游戏安装目录、不猜贴图语义（不自称 Terraria 专用）。
- 不上传、不请求任何 `/api/*`；不做多图批处理队列。
- 不做动画帧率预览、不做精灵表再打包 / 合成。

## 4. 计算与交互

### 4.1 默认切片矩形（纯函数，可单测）

对第 `c` 列（`0 ≤ c < cols`）：

```
left(c)   = round(margin + c * (W - 2*margin + gap) / cols)
right(c)  = round(margin + (c+1) * (W - 2*margin + gap) / cols) - gap
width(c)  = right(c) - left(c)
```

行同理（`H` / `rows`）。用 `round` 均分而不是 `floor`，避免整图少 1–2px；边界返回**含入不含出**的矩形，
奇数尺寸也不会重叠或漏像素。`margin` / `gap` 仅影响首尾与间隔，不参与覆盖表。

### 4.2 微调（覆盖表）

```ts
interface SliceRect { x: number; y: number; w: number; h: number }
// key = row * cols + col；不在表里 = 用默认矩形
type Overrides = Map<number, SliceRect>
```

- 微调只改**当前切片**；`W/H/rows/cols/margin/gap` 任一变化都让默认矩形失效 →
  清空覆盖表并提示「切分参数变了，已清掉 N 处微调」。
  （原设计是弹确认框；实现时发现输入框逐字输入会反复弹窗，改为**自动清空 + 提示**。）
- 「恢复此切片」= 删除该 key（回到默认网格）。原设计里另设的「对齐到网格」语义重复，实现时去掉。
- 方向键微移只在焦点在预览区 / 微调输入框时生效；`Shift` = 8px。
- 边界钳制：`x ≥ 0`、`y ≥ 0`、`x + w ≤ W`、`y + h ≤ H`；`w` / `h` 至少 1px。

### 4.3 导入与渲染

- `File` → `createImageBitmap`（失败回退 `img.onload`）→ 画到**离屏 canvas**（原图只解码一次）。
- 预览用**一个 canvas**：先按缩放画原图（`imageSmoothingEnabled = false`，保持像素锐利），再叠加网格 / 序号 / 选中框；
  棋盘格底用 CSS 渐变铺在 canvas 容器上（不额外画）。
- 缩放：`适应宽度 / 50% / 100% / 200% / 400%`，默认「适应宽度」；容器宽度变化只影响适应宽度档。
- 无 `canvas`（jsdom）时，预览显示占位与尺寸文字，逻辑（矩形 / 导出参数）仍可单测。

### 4.4 切片列表

- 复用 `lib/virtualGrid.ts` 的 `computeVirtualGrid`，只渲染可视行；
  缩略图按需绘制（`IntersectionObserver` 进入视口时才 `drawImage`），避免几百张 canvas 同时挂载。
- 列表底部一行统计：`共 N 张 · 已微调 M 张 · 全透明 K 张`（`K` 仅勾选「跳过全透明」时计算，点击可跳转到第一张非空）。

## 5. 导出

| 动作 | 产物 | 说明 |
| --- | --- | --- |
| 导出此切片 | `r{行}c{列}.png`（从 1 起） | 该切片当前矩形（含微调）原样裁切，不缩放 |
| 导出全部 | `{原文件名}-slices.zip` | 每张一个 PNG 条目，命名同上；跳过全透明（勾选时） |

- ZIP 用 `lib/spriteSheet/zip.ts` 手写 **store-only**（不压缩）格式：PNG 本身已压缩，无需引入依赖；
  需要 CRC32 表（约 20 行）与本地文件头 / 中央目录 / EOCD。
- 导出走 `canvas.toBlob('image/png')` + 现有 `downloadBlob`（`lib/playerPage.ts`）；
  全部导出时先计算要导出的数量，`0` 张（全被跳过）时按钮禁用并提示。
- 命名可选（默认 `r1c1`）：实现时先只保留默认，若用户要「纯序号 001.png」再加一个下拉，避免多一个标签。

```

```

- 路由：`TabId` 增加 `'spritesheet'`；`lib/routes.ts` 映射 `spritesheet → 'slice'`（`#/slice`），
  并让旧值 / 未知值行为不变。
- 导航：`App.tsx` 的 `nav` 在「工具」组末尾追加
  `{ id: 'spritesheet', label: t('nav.slice'), icon: ScissorsLineDashed, group: 'tools' }`，带 `onPrefetch`。
- 懒加载：`AppRoutes.tsx` 的 `loadSpriteSheetPage` + `routeLoaders`，与其它重页面一致。
- 不新增后端：`/api/*` 不变。

### 存储

- 不持久化图片本身（HTMLImageElement 无法序列化）；仅按需持久化**最后一次行列 / 边距 / 间距 / 跳过透明**
  到 `tswui:spriteSheet`（本机、跨刷新），并在 `docs/设计原则与约束.md` §4.6 登记该键。
- 页面在本次会话内切走再回来保留图片（模块级内存缓存，与 `lib/worldPage.ts` 的缓存同思路），刷新即清空。

单测（纯函数）

  边界钳制 / 自动猜测（正方形格、非整除时取最大公约数）。

页面测试

- 导入 PNG（mock `createImageBitmap`）→ 填 `2×3` → 预览出现 6 个序号、统计「共 6 张」。
- 改一个切片的 X → 统计出现「已微调 1 张」；改行列 → 弹确认，确认后覆盖清空。
- 「导出此切片」「导出全部」→ mock `canvas.toBlob` 与 `downloadBlob`，断言文件名与数量（跳过透明时数量减少）。

验收（需真实浏览器）

- 导入一张带间隔的精灵表 → 行列 + 间距对齐 → 逐片微调 → 单张与 ZIP 导出后在图片查看器里核对像素尺寸与内容。

## 8. 实现时的取舍（原「待确认」项）

用户「开始实施」= 接受默认方案，因此：

1. 导出命名用 `r1c1.png`（ZIP 内同名）；纯序号命名不做。
2. 「把当前偏移应用到全部切片」未做（避免覆盖已有微调；需要时再补）。
3. 预览区**鼠标拖拽矩形**后来按用户要求补上（新增「框选」模式）；网格模式仍是点击选中。
   同时补了**逐片命名**（导出文件名优先用名字）与**右侧栏压缩**（300px + 小号控件）。
4. 只支持**统一网格**（每行等列数）；瀑布式精灵表靠逐片微调位置。
