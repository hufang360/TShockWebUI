# 计划：在「玩家管理」里绘制玩家全身图

> 状态：**已实现**（前端 `PlayerAvatar` + 生成脚本 `tools/gen-player-atlas.py`）。
> 最终实现见文末 §6「实现记录」。

> 目标：在「玩家管理」结果区**用户名下方**显示一张玩家角色全身图，
> 相当于**创建角色界面**里的角色预览——只画皮肤 / 衣服 / 头发（**不含盔甲与饰品穿戴后的外观**）。
> 约束：**不改动 PlayerManager 插件**。

## 1. 数据来源（已就绪）

`GET /api/player/look` 已返回画角色所需的外观字段（见 `docs/API_SPEC.md` §5.2、
`server/internal/tshock/player.go` 的 `PlayerLook`）：

| 字段 | 含义 |
| --- | --- |
| `skinVariant` | 皮肤样式（决定 `Player_<skinVariant>_*.png` 用哪一套） |
| `hair` | 发型编号（0 基，对应 `Player_Hair_<hair+1>.png` / `Player_HairAlt_<hair+1>.png`） |
| `hairDye` | 染发剂编号（0 = 无；着色近似处理，见 §6） |
| `hairColor` / `skinColor` / `eyeColor` | 头发 / 皮肤 / 眼睛颜色 |
| `shirtColor` / `underShirtColor` / `pantsColor` / `shoeColor` | 上衣 / 内衣 / 裤子 / 鞋子颜色 |

颜色是 `TShock.Utils.EncodeColor` 的 **int32 小端 RGBA**（`R=b[0] G=b[1] B=b[2] A=b[3]`，见
`TShockAPI/Utils.cs:839`），可能为 `null`（此时用游戏默认色）。在线 / 离线玩家都返回这些字段。

## 2. 贴图（已解包）

- 皮肤/身体部件：`Content/Images/Player_<skinVariant>_<part>.png`。
  part 编号见 `Terraria.ID/PlayerTextureID.cs`：
  `0 Head / 1 EyeWhites / 2 Eyes / 3 TorsoSkin / 4 Undershirt / 5 Hands / 6 Shirt /
  7 ArmSkin / 8 ArmUndershirt / 9 ArmHand / 10 LegSkin / 11 Pants / 12 Shoes /
  13 ArmShirt / 14 Extra / 15 EyeBlink`。
- 头发：`Player_Hair_<n>.png`、`Player_HairAlt_<n>.png`，`n = hair+1`（各 228 个）。
- **实测这些贴图都是灰度遮罩**（`skinVariant=0` 抽样：只有 R=G=B），
  绘制时用玩家颜色做**相乘着色**即可（等价游戏里的 `spriteBatch` 颜色调制）。
- 帧布局：每帧 **40×56**；站姿帧 = `bodyFrame/legFrame/headFrame = (0, 0, 40, 56)`
  （见 `Terraria.GameContent.UI.Elements/UICharacter.cs:UpdateAnim`：非动画预览把三个 `*.Frame.Y` 置 0）。

## 3. 关键事实：不能简单叠图

已做实验：把 `Player_0_*` 的各部件按帧 (0,0,40,56) 直接 `alpha_composite`，结果
**人形可辨但部件错位**（眼睛偏右、手臂与身体重叠、头发位置异常）。
原因：游戏是按 `PlayerDrawLayers` 的层级 + 每层的偏移/旋转/帧来画的，不是同原点叠加。

参考实现（游戏自己）：
- `Terraria.GameContent.UI.Elements/UICharacter.cs`：角色选择界面的预览——`PlayerFrame()` +
  `Main.PlayerRenderer.DrawPlayer(...)`，非动画时帧 (0,0)。
- `Terraria.Graphics.Renderers/LegacyPlayerRenderer.cs` → `PlayerDrawLayers.DrawPlayer_RenderAllLayers`。
- `Terraria.DataStructures/PlayerDrawSet.cs` 的 `BoringSetup()`：算 `Position / bodyPosition / headPosition /
  bodyVect / headVect / torsoOffset / legFrame / bodyFrame / hairFrame …`。
- 相关层：`DrawPlayer_12_Skin`（躯干/腿）、`DrawPlayer_13_Leggings`、`DrawPlayer_14_Shoes`、
  `DrawPlayer_17_Torso`、`DrawPlayer_21_Head`（头/眼/头发）、`DrawPlayer_28_ArmOverItem`（前臂）、
  后臂在 `DrawPlayer_12_Skin_Composite_BackArmShirt`（`GetCompositeOffset_BackArm/FrontArm`）。
- 头/眼/头发的静态预览另有简单写法：`Terraria/Main.cs:44912` 附近（发型选择器），
  固定 56px 帧 + `Player.GetHairDrawOffset()`（`Player.cs:4535`，仅发型 163/164 有 1–2px 微调）。

## 4. 实施步骤（建议）

1. **生成图集** `tools/gen-player-atlas.py`：
   - 只打包需要的：12 套 `skinVariant` × 用到的 part（0,1,2,3,4,6,7,8,9,10,11,12,13）+ 228 个发型
     （`Player_Hair_*`；`HairAlt` 视需要）。
   - 输出 `data/player-atlas.png` + `data/player-atlas.json`（`regions` 形如
     `"player:<variant>:<part>:<frameIndex>"`、`"hair:<hair>:<frameIndex>"`），只取站姿所需帧。
   - 风格照 `tools/gen-atlas.py`（高降序、限宽 1024）。
2. **前端组件** `web/src/components/PlayerAvatar.tsx`：
   - 输入：`PlayerLook` 的外观字段；输出：一个 canvas（建议 2× 或 3× 缩放 + 最近邻）。
   - 按移植后的**层级/偏移**合成：后臂 → 腿（皮肤/裤/鞋）→ 躯干（皮肤/内衣/衬衫）→ 头（头/眼白/眼睛）→
     头发 → 前臂；每层用对应颜色相乘着色。
   - 先只实现**站姿、无持物**；盔甲/饰品/坐骑一律不画（符合需求）。
3. **接入页面** `web/src/pages/PlayerManagerPage.tsx`：在用户名下方放 `PlayerAvatar`。
4. **校准**：用 headless Chrome 截图 + 识图比对游戏角色选择界面，迭代偏移直到人形正确。
5. **文档**：把最终采用的层级/偏移与帧选择写进本节或 `docs/功能-富文本解析.md` 类似的事实文档。

## 5. 验收

- 有 `playermanager` 权限、已登录时，进「玩家管理」能在用户名下看到自己的角色全身图。
- 换 `skinVariant` / `hair` / 各颜色能体现在图上；未设置颜色时用游戏默认色。
- 不依赖 `.plr` 导出（`/pm/look` 足够），不改插件，不发额外请求。
- 图集体积与首屏影响可接受（懒加载，仅在打开该模块时加载）。

## 6. 实现记录（最终采用的层级 / 帧）

实现文件：

- `tools/gen-player-atlas.py` → `data/player-atlas.{json,png}`（懒加载，约 1000×952 / 50 KB）。
  只打包需要的**合成帧**（每格 40×56）：键 `b:<variant>:<part>:<role>`（`variant` 0–11，
  `part` 见 `PlayerTextureID`，`role` 见下）与 `h:<hair>`（hair 0 基 → `Player_Hair_<hair+1>.png` 第 0 帧）。
  变体缺部件时按 `PlayerDataInitializer` 的 `CopyVariant` 链回退（5/6/7/9 → 4；11 → 10；其余 → 0），
  回退在生成期烘进 key，前端无需知道。
- `web/src/lib/playerRender.ts`：纯函数生成绘制序列（可单测）。
- `web/src/lib/playerAtlas.ts`：图集 + JSON 懒加载（只在渲染预览时拉取）。
- `web/src/components/PlayerAvatar.tsx`：canvas 合成，灰阶遮罩 × 颜色相乘着色。
- `web/src/pages/PlayerManagerPage.tsx`：用户名下方渲染。

### 关键结论：站立帧下所有部件同原点

`PlayerDrawSet.CreateCompositeData` 的合成帧把「手臂偏移」同时加在绘制位置与旋转原点上（`bodyVect`），
站立（旋转 0）时两者抵消，**整个角色 = 一组 40×56 帧贴在同一个左上角**（= `Position + (-10,-10)`，
`Player.width=20 / height=42`，`base = panelCenter - (10,21)`）。因此不需要逐层像素偏移，只需按层级顺序贴图。

`Body=0`（无护甲）时 `usesCompositeTorso=true`，走合成分支。每层用的合成帧（男 / 女）：

| 层（`DrawPlayer_*`） | part | role | 男 (列,行) | 女 (列,行) |
| --- | --- | --- | --- | --- |
| 01_BackHair | — | `h:<hair>` 后发 | — | — |
| 12_Skin | 3 | `torso` | (0,0) | (0,2) |
| 12_Skin | 10 | `leg` | (0,0) | (0,0) |
| 12_Skin | 7 / 5 | `backArm` | (2,2) | (2,2) |
| 12_Skin | 8 / 13 | `backArm` | (2,2) | (2,2) |
| 13_Leggings | 11 / 12 | `leg` | (0,0) | (0,0) |
| 15_SkinLongCoat | 14 | `longCoat`（仅 3/7/8） | (0,0) | (0,0) |
| 17_Torso | 4 / 6 | `backShoulder` | (1,1) | (1,3) |
| 17_Torso | 4 / 6 | `torso` | (0,0) | (0,2) |
| 21_Head | 0 / 1 / 2 | `head` / `eyeWhites` / `eyes` | (0,0) | (0,0) |
| 28_ArmOverItem | 7/8/13/6 | `frontArm` | (2,0) | (2,0) |
| 28_ArmOverItem | 7/8/13/6 | `frontShoulder` | (0,1) | (0,3) |

女性只在 `pt/pt2/pt3`（躯干与两肩）的 Y 上 +2；手臂帧不区分性别。
绘制顺序：后发 → 躯干皮肤 → 腿皮肤 → 后臂 → 裤子 → 鞋 → 长袍 → 背肩上衣 + 躯干上衣 →
头/眼白/眼睛 → 前发 → 前臂组 → 前肩组。

### 颜色与头发

- 颜色为 `TShock.Utils.EncodeColor` 的 int32 小端 RGBA（`R=b0 G=b1 B=b2 A=b3`）；**可能为负数**，
  前端用 `>>> 0` 还原。`null` 用游戏默认色（`Player.cs` 字段初值）。
- 贴图是灰阶遮罩：canvas 用 `multiply`（灰阶 × 颜色）再 `destination-in` 恢复原 alpha，
  等价游戏的 `spriteBatch` 颜色调制，且透明区不会变成实心块。
- 后发判定照抄 `Player.GetHairSettings`：带后发时最底层先画后发，且**前发源帧高度裁到 26**（否则 54）。
- `hairDye` 暂不处理（游戏走专用 shader），第一版直接用 `hairColor`。

### 未做 / 取舍

- 不含盔甲、饰品、坐骑、手持物（符合需求）。
- 眼睛眨眼帧（part 15）、染发剂渐变、`hideVisuals` 均未处理。

## 7. 已知取舍 / 风险

- `hairDye`（染发剂）在游戏里走专用 shader，第一版按纯色近似（不做渐变）。
- `hideVisuals`（隐藏饰品的位掩码）当前后端未透出，且本需求不画饰品，可忽略。
- 站姿帧的**手臂偏移**最容易出错（后臂/前臂两处）；如果精力有限，可先只做
  「头 + 头发」头像版（`Main.cs:44912` 直接照抄，几乎零风险），再做全身。
- 皮肤部件若某些 `skinVariant` 缺 part，需要回退到该 variant 的 `_0`（或跳过该层）。
