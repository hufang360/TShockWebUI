## 1. 定位

**公开的本地图片工具**，不做任何服务器交互：

- 不读 TShock、不需要登录与任何权限、**文件不上传**（解码、裁切、PNG 编码、ZIP 打包、GIF 编解码全在浏览器里做）。
- 只产出**下载文件**；不写任何图片数据进 localStorage。
- 入口恒在侧边栏「工具」分组，不跟随任何模块开关（与「玩家存档」「世界存档」同一原则）。

## 2. 范围

### 2.1 做

- **分割**：导入一张 PNG 精灵表 → 行 × 列（可选边距 / 间距）切分，或鼠标框选任意区域 → 每张切片可命名 / 微调 → 导出单张、打包 ZIP、或串成帧导出 GIF 动画。
- **合并**：多张 PNG 拼成一张精灵图（横向 / 纵向 / 网格 + 间距），导出 PNG。
- **GIF 分拆**：一张 GIF 按帧拆成 PNG（单帧 / 全部打包 ZIP）。
- 可选「跳过全透明切片」。
- 自带 Demo（`data/buff-atlas.png` 图集，403 格）。

### 2.2 不做

- 不解析 `.xnb`、不读游戏安装目录、不推断贴图语义（不自称 Terraria 专用）。
- 不请求任何 `/api/*`；不做多图批处理队列。
- 不做九宫格编辑、锚点 / 图层、瀑布式精灵表专用排版、动画拖动排序。

页首左上角是下划线 `Tabs`（分割 / 合并 / GIF），三个 tab **常驻挂载**（`hidden` 切换），切回来图片与帧序列还在；上次的 tab 存在 `tswui:spriteSheetTab`。

- 没有独立的「导入」卡：工具条与画布同卡，页面纵向只有「预览卡 / 列表卡」两层。
- 容器 ≥820px 时提示小字与工具条同行，窄屏隐藏（顶栏 ⓘ 里另有一份说明）。
- 「适应」同时受宽度与可用高度约束：高度取视口 **62%**，夹在 **280–760px**，竖长精灵表不会撑出好几屏。
- 预览缩放：适应 / 50% / 100% / 200% / 400% / 800%；`imageSmoothingEnabled = false`，像素保持锐利；canvas 按 `devicePixelRatio`（上限 2）放大后备缓冲。
- 预览分层（`SliceCanvas.tsx`）：网格按**去重后的边界**画 1px 中灰细线（逐格 `strokeRect` 会把相邻边叠成 2px）；微调过的切片画琥珀色虚线；选中切片「聚光灯」——其余区域压暗、选中区域原样重画、白色光晕外圈 + 主色 2px 边框；序号徽标在左上角（格子小于 **26×18** 不画）。
- 切片列表只渲染可视区附近的格子（`scrollLeft` + 容器宽度手算窗口），几百上千张不会同时挂载等量 canvas。
- 空态用 `Empty`（`ImageUp` + 拖放提示），整页可拖放；错误用 `Alert variant="destructive"`，成功提示用 `Alert variant="info"`。

### 3.4 交互与反馈要点

- **切分方式**（`ToggleGroup`，`h-7`）：`网格` 点击选中 + 微调；`框选` 按住拖出矩形 → 松开即新增一张**手动切片**并自动选中，点一下（没拖开）仍是选中。手动切片与网格参数无关，**改行列不会被清掉**。
- 改行 / 列 / 边距 / 间距**立即生效**，无「应用」按钮；同时**清空网格切片的微调与名称**并提示「切分参数变了，已清掉 N 处微调 / 名称（手动框选的切片保留）」。用自动清空而不是确认框，是因为输入框逐字输入会反复弹窗。
- 微调：改 X / Y / 宽 / 高、点微移四键、在预览上按方向键（`Shift` = 8px）都写入覆盖表；「恢复此切片」= 删除覆盖项。
- 「自动猜测行列」= 假设正方形单元格且整除整图（`side = gcd(W, H)`），推断 `cols = W / side`、`rows = H / side`；猜不出（边长 < 4px、格数 > 4096）回退 1×1 并提示手填。
- 「来个 Demo」载入自带 `data/buff-atlas.png` 并套用它的切分参数；**已有图片时先弹确认**（覆盖会清空微调、命名、手动框选与帧序列）。
- 整页没有「未登录」状态，也没有任何权限判定分支。

## 4. 数据模型与计算

### 4.1 默认矩形（`lib/spriteSheet/slice.ts`）

可用区域均分后 `round` 到边界，行优先编号 `index = row * cols + col`：

```text
usable = max(1, total - 2*margin - gap*(count-1))
cell   = usable / count
edge(i) = round(margin + i*(cell + gap))        i = 0..count
edge(count) = max(edge(count-1) + 1, total - margin)   // 强制贴边，round 误差不吃掉最后 1px
第 i 格：start = edge(i)
         end   = i === count-1 ? edge(count) : edge(i+1) - gap
```

- 奇数尺寸也不重叠、不漏像素（101 切成 3 格 → 34 / 34 / 33）。
- 单格最小 1×1；行列上限 **256**（`MAX_GRID`）；`toInt` 对空字符串保持原值（否则 `Number('') === 0` 会把输入框清空瞬间变成 1）。
- 所有矩形最后过 `clampRect`：`x,y ≥ 0`、`x+w ≤ W`、`y+h ≤ H`、宽高 ≥ 1。

### 4.2 切片身份与模型（`model.ts`）

```text
// 网格切片：默认矩形 + 覆盖表
type Overrides = Map<number, SliceRect>          // key = index
// 手动切片：独立数组，矩形已在图片范围内
interface ManualSlice { id: number; rect: SliceRect }   // id 页面内自增，删除后不复用
// 统一身份
key = `g:<index>` | `m:<id>`
```

- **不用数组下标当身份**：改行列、删手动切片时下标会挪，`key` 不会，选中项与命名都跟着 key 走。
- `buildEntries()` 决定展示与导出顺序：网格在前（行列顺序），手动按创建顺序追加；`index + 1` 就是序号徽标。
- `hitTest()` 从后往前找命中的切片（微调后重叠时以更靠后的为准）。
- 命名存 `key → 名字`；名字为空回退默认名（网格 `r1c1`、手动 `slice-<id>`）。改行列时只清网格切片的名称。

### 4.3 文件名（`model.ts`）

- 命名优先，否则默认名；`sanitizeFilePart`：去掉 `\ / : * ? " < > |` 与控制字符（换成 `-`）、压空白、去开头 `.`、限长 64、空则回退。
- **重名自动加 `-2` / `-3`**（忽略大小写），保证 ZIP 内不互相覆盖；单张导出与 ZIP 用同一套名字。
- 合并导出 `<第一张文件名>-merged.png`；全部切片 `<原文件名>-slices.zip`；GIF 动画 `<原文件名>-animation.gif`；分拆帧 `<原文件名>-frame-001.png`、全部 `<原文件名>-frames.zip`。

### 4.4 合并排版（`merge.ts`，纯函数）

不缩放，尺寸不同时在自己格子里居中：

- `row`：依次横排，行高 = 最大高，每张垂直居中；总宽 = 宽度和 + `gap*(n-1)`。
- `column`：依次竖排，列宽 = 最大宽，水平居中。
- `grid`：固定列数，单元格 = 最大宽 × 最大高，图在格内居中；总宽/高按列行数与 `gap` 展开。

## 5. 导出

### 5.1 PNG 裁切（`export.ts`）

- `cropCanvas`：新建 canvas → `imageSmoothingEnabled = false` → `drawImage(src, rect.x, rect.y, w, h, 0, 0, w, h)`，**不缩放**。
- `canvasToBlob`：优先 `toBlob('image/png')`，不支持时回退 `toDataURL` + `atob`。
- 无 canvas（jsdom / 被禁用）时返回 `null`，由调用方提示，不静默成功。
- 全透明判定 `isBlank`：把切片画到离屏 canvas 后读 `getImageData` 的 alpha，全 0 才算空；拿不到像素（跨域污染 / 无 canvas）按**不透明**处理（宁可多导一张也不误删）。统计在勾选「跳过全透明」后才算，且用 `setTimeout(0)` 推迟一帧，避免拖慢输入。

### 5.2 ZIP（`zip.ts`，store-only）

手写最小 ZIP 写入器，不引第三方依赖（PNG 已压缩，再 deflate 只是浪费 CPU）：

- CRC-32（IEEE，`0xedb88320` 反射表）+ DOS 日期时间（1980 起，秒精度 2s）+ 文件名 UTF-8 标记 `flag = 0x0800`。
- 结构：每条目「本地文件头（30B）+ 文件名 + 数据」→ 中央目录（46B + 文件名）→ EOCD（22B）。
- `method = 0`（store）、`version = 20`；空条目列表也合法（只有 EOCD）。
- 测试用固定小载荷断言 CRC 向量与「能被 `unzip` 解开」。

### 5.3 GIF89a 编码（`gif.ts`）

把切片按加入顺序合成为同尺寸帧（尺寸取最大宽 / 高，较小帧**居中**、四周透明）后编码。零依赖纯函数。

```text
GIF89a + 逻辑屏幕描述符（不用全局色表）
  [NETSCAPE2.0 循环块]                         // loop = 1（只播一次）时不写
  每帧：图形控制扩展(延迟/透明/disposal=2) + 图像描述符(局部色表) + LZW 数据块
0x3b                                           // trailer
```

- 每帧独立量化、写**局部色表**：≤255 色原样保色；超出走中位切分（按最宽通道对半分桶，取加权均值）降到上限。
- 透明：`alpha < 128` 视为透明，色表末尾预留一个透明索引；有透明的帧一律 `disposal = 2`（还原背景），否则上一帧会透出来。
- 延迟按 1/100 秒四舍五入（`round(ms/10)`，夹在 1–100），GIF 精度只有 10ms。
- 色表大小必须是 2 的幂（`tableBits = ceil(log2(max(2, palette.length)))`，`minCodeSize = max(2, tableBits)`），不足补黑。
- LZW：变长码，字典满 4096 发 clear 并重置。**码宽增长的判定必须 +1**（`nextCode === (1 << codeSize) + 1`）：编码器的字典总比解码器先一条，宽早了会让两边位宽错开一格、整段数据解不出来——这是实现时踩过的坑，测试用「编码→解码往返」盯住。
- 至少 2 帧才能导出，不足时按钮禁用并提示。

### 5.4 GIF 解码（`gifDecode.ts`）

自写解析器，输出**合成后的整幅画面**（逻辑屏幕尺寸，不裁透明边），帧延迟一并返回：

- 支持全局 / 局部色表、透明索引、interlace（4 遍行序 `[0,8] [4,8] [2,4] [1,2]`）、disposal 0–3（2 = 还原背景、3 = 还原上一帧，靠画前快照实现）、NETSCAPE 循环次数。
- LZW 解码：`code < dict.length` 直接取；否则按 `prev + prev[0]` 的经典特例；字典满 4096 等 clear。
- 非法 / 罕见损坏文件直接抛错，由页面提示「这个 GIF 读不出来：{reason}」。

### 5.5 导出一览

| 动作 | 产物 | 说明 |
| --- | --- | --- |
| 导出此切片（按钮 / 双击缩略图） | `{名字}.png` | 当前矩形（含微调）原样裁切，不缩放 |
| 导出全部 | `{原文件名}-slices.zip` | 每张一个 PNG 条目，勾选「跳过全透明」时先按 alpha 过滤；0 张可导时按钮禁用 |
| 导出精灵图（合并 tab） | `{第一张}-merged.png` | 按排版结果合成 |
| 导出此帧 / 全部帧 | `{原文件名}-frame-001.png` / `{原文件名}-frames.zip` | 逻辑屏幕尺寸，不裁透明边 |
| 导出 GIF | `{原文件名}-animation.gif` | 帧间隔与循环来自设置，≥2 帧 |

下载统一走 `downloadBlob`（object URL + `<a download>` + `revokeObjectURL`）。任一张编码失败直接抛错提示，不做「静默少几张」。

## 8. 依赖与可移植性

- **运行时零第三方依赖**：只用到 `canvas 2D`、`createImageBitmap`、`Blob` / `URL.createObjectURL`、`TextEncoder`、`ImageData`。GIF / ZIP 都是自己写的，不引 `jszip` / `gif.js` / `gifuct`。
- **与后端无关**：没有 `/api/*`，没有 token，没有会话。
- 换项目时只需要替换这几类 import：`@/components/ui`（Button / Card / Input / Select / ToggleGroup / Alert / Empty / Tabs / Badge / Separator）、`@/components/TopBar` 与 `InfoPopover` / `IconAction`、`t()` 文案、`useLocalState` 与存储键、`downloadBlob`、`cn`。
- Demo 素材 `data/buff-atlas.png`（1022×428、140 KB）与 `data/buff-atlas.json` 由 `tools/gen-buff-atlas.py` 生成（400 张 32×32 Buff 图标，高降序 / 宽升序、每格 1px 透明缝 → 31 列 × 13 行、边距 0、间距 1）。**该图集在本仓库还被 Buff 图标使用**，迁出时要么自带一份图集，要么让 Demo 指向新项目的素材（版权归 Re-Logic，注意随包分发）。

## 9. 已知限制与后续方向

现状限制：

- 网格切分是**统一网格**（每行等列数）；不规则精灵表只能逐个框选或对网格切片微调。
- 框选切片只记矩形与名字（无图层 / 锚点 / 九宫格）；框在已有切片上会**多**出一张，导出会同时包含两者。
- 改行列会清掉网格切片的微调与命名（不弹确认）。
- GIF 只支持 1-bit 透明与每帧 ≤256 色（超出会被量化，颜色可能略偏）；预览只自动循环，没有暂停 / 逐帧。
- 帧顺序 = 加入顺序，不支持拖动排序。
- 合并不缩放，也不支持九宫格 / 更多排版参数。
- 分拆导出的是整幅逻辑屏幕（不裁透明边）。

独立项目顺理成章可以做的：读 ZIP（导入已有图集与 `.json` 元数据）、图集再打包 / 回写、动画拖动排序与逐帧播放控、九宫格与锚点编辑、非均匀网格（按行分割线）、`.xnb` 解析、与 TShock 插件素材目录联动的批量处理。
