# 服务器动态（Server Feed）

> 首页「服务器动态」卡片：把服务器的**进服 / 退服 / Boss 击杀**做成一条实时时间线，
> 并叠加上世界状态徽标（困难模式 / 血月 / 日食 / 下雨 / 入侵），让首页「活」起来。
>
> 本文是这个功能的**唯一专门文档**：现状、行为、限制都在这里（字段级契约见 §4 指向的两处文档）；
> 后续关于「服务器动态」的一整套想法统一追加到 **§7 想法 / Roadmap**，不要再散落到别处。

## 1. 边界

- **默认落盘**：事件在插件内存保留最近 2000 条；同时后台线程按天追加到
  `tshock/WebUI/events/events-YYYY-MM-DD.jsonl`（默认保留 7 天 / 50MB）。
  **TShock 重启后历史仍在**。可用 `PersistEvents=false` 退回「纯内存」旧行为；
  聊天是否落盘另由 `PersistChat`（默认**关**，保护隐私）控制。
- **不写数据库**：JSONL 按天文件，启动时读尾部恢复，不需要 SQLite / 外部存储。
- **不新增权限**：`/webui/events` 是 `SecureRestCommand`，只要一个**有效 token** 即可（同其它只读端点），
  不额外要求 `tshock.rest.*` 权限，也不提权。
- **属于自研信使插件的能力**：未安装 `WebUI` 时该端点 404，后端返回 `plugin_not_installed`，
  前端**直接隐藏**该卡片（`pluginMissing('events')`，见 `HomePage.tsx`）。
  历史 / 实时推送对**旧插件（含 RC2）向后兼容**：降级规则见 [`API_SPEC.md`](API_SPEC.md) §6.3。
- 纯展示，不参与指令执行。
- **以插件记录为准，后端只做短缓存**：事件 / 世界状态在后端内存里只作「减少 TShock 请求」的优化
  （ring 500 条、世界状态 ≤30s）；同一个服务器地址 / 端口下可能先后开**不同的服**，
  插件事件库的 `instance` 一变，后端立即作废旧缓存并让网页重同步（`instance` / `event: reset` 的字段见
  [`插件-信使.md`](插件-信使.md) §2.2 与 [`API_SPEC.md`](API_SPEC.md) §6.3）。

## 2. 数据流（一眼版）

```
TShock 事件钩子（插件主线程，只入队 / 不改游戏状态）
  ServerJoin / ServerLeave / NpcKilled / PlayerChat
        │  EventLog.Add(type, text)
        ├─► 内存缓冲 EventLog（最近 2000 条，seq 单调递增）
        └─► 后台写线程：按天追加 JSONL（tshock/WebUI/events/，启动读尾部恢复）
        │
        │  插件 REST：GET /webui/events?since=&limit=   → 增量（旧插件也支持）
        │             GET /webui/events?tail=N          → 最新 N 条（新插件，磁盘历史）
        ▼
后端 GET /api/events?since=|tail=   （同源会话 Cookie；内部转发 + 注入 token）
      GET /api/events/stream?since=  →  SSE；**每个上游共享一个轮询 goroutine**（feedhub），
          把事件 / 世界状态 fan-out 给所有订阅者 —— TShock 侧请求数与在线人数无关
        │
        ▼
首页卡片 / 「聊天」页：打开先取 tail（最近 N 条）→ 变 SSE 实时推送；
SSE 不可用时退回按设置的刷新间隔轮询。
```

世界状态徽标走的是**另一条**只读端点 `/api/serverinfo`（→ 插件 `/webui/serverinfo`），
按刷新间隔拉一次，见 §5。

## 3. 事件来源（插件）

`plugin/WebUI/Plugin.cs`：

| 钩子 | `type` | 文本模板 | 条件 |
| --- | --- | --- | --- |
| `ServerApi.Hooks.ServerJoin` | `join` | `{玩家名} 加入了服务器` | 能拿到非空玩家名时（无名字的爬虫 / 扫描连接不记） |
| `ServerApi.Hooks.ServerLeave` | `leave` | `{玩家名} 离开了服务器` | 同上 |
| `ServerApi.Hooks.NpcKilled` | `boss` | `Boss「{NPC 名}」被击败` | **仅 `e.npc.boss == true`**（普通小怪不记） |
| `ServerApi.Hooks.ServerBroadcast` | `announce` | 游戏内世界公告原文（如「光之女皇已苏醒！」「血月正在升起……」「哥布林军队正在逼近！」） | 本地化键文案 + 颜色 `ChatColors.BossOrEvent` / `ChatColors.World`；跳过「已被击败」类（已由 `boss` 记录） |
| `ServerApi.Hooks.NpcSpawn` | `npc` | `旅商已到达` | NPC 类型 = 旅商（NPC 368），**始终记录**；`Main.gameMenu`（世界加载回放存档 NPC）时不记；其它城镇 NPC 与 NPC 死亡不记 |
| `PlayerHooks.PlayerChat` | `chat` | `{玩家名}: {聊天内容}` | `Config.RecordChat`（默认开）；**仅普通聊天** |
| `POST /webui/chat`（网页发言） | `chat` + `source=webui` | `{前缀} {玩家名}: {聊天内容}` | 网页端主动发送；**不伪造身份**、带前缀（默认 `[WebUI]`，可配） |
| `ServerApi.Hooks.WorldMeteorDrop` | `announce` | `一颗陨石坠落了` | 陨石落地 |
| `ServerApi.Hooks.WorldStartHardMode` | `announce` | `世界进入困难模式：圣光与暗影的远古之灵被释放` | 困难模式开始 |
| `GameUpdate` 状态对比 | `announce` | 血月 / 日食 / 入侵 / 南瓜月 / 霜月 **结束**；下雨 / 沙尘暴 **开始与结束** | 仅在运行中发生状态变化时记（开局不广播已有状态） |

- NPC 名取自 `Lang.GetNPCNameValue(netID)`（服务端语言），取不到时回退 `NPC#{netID}`
  （`EventLog.NpcName`）。
- 文本是**插件端硬编码的中文**，不随网页端语言切换（见 §6）。
- 事件文本里包含玩家名 / Boss 名，均为 TShock 服务端已公开的信息，不含 IP、token 等敏感数据。

关于聊天（`chat`）：

- 聊天里可能带 Terraria 物品标签 `[i:..]`，前端按富文本渲染成图标（`RichText`），不会显示原始标签。
- 用 TShock 的 `PlayerHooks.PlayerChat`（**不是** OTAPI 的 `ServerChat`）：该钩子在
  **权限 / 禁言 / 长度**校验之后触发，且**只对真正的聊天**触发，以 `/` 开头的指令不会进事件流。
- 在线授权的 `y` / `n` 确认走 OTAPI `ServerChat` 并被拦截（`e.Handled`），**不会被记录为聊天**。
- 采集开关：插件配置 `RecordChat`（默认 `true`）。关掉即完全不采集聊天内容，重启 TShock 生效。
- 文本截断：`EventLog.MaxTextLength = 200`，超出加省略号。

`plugin/WebUI/EventLog.cs`：

- `Capacity = 2000`，`LinkedList` 内存环形缓冲 + `lock` 串行化；超出逐个 `RemoveFirst()`。
- **持久化**：`PersistEvents`（默认 `true`）时后台线程按天写 `events-YYYY-MM-DD.jsonl`；
  启动 `Init()` 读尾部恢复并继续 `seq`；写盘在后台线程，**不在游戏主线程同步 I/O**。
  保留策略 `HistoryDays`（默认 7）/ `HistoryMaxMB`（默认 50），启动与写入时裁剪。
- 每条字段：`seq`（`long`，启动时接磁盘最大值继续递增）、`type`、`text`、`time`（UTC，ISO-8601 `"o"`）、
  可选 `source`。
- **实例标识**：`tshock/WebUI/instance.id`（首次生成后持久化，读不到时退回进程级随机值）。
  同一份事件历史 = 同一个 `instance`；同一个地址 / 端口换成另一份存档目录里的服时它会变。
- `Since(since, limit)`：返回 `seq > since` 的最多 `limit` 条，并附当前最大 `lastSeq` 与 `instance`。
- `Tail(limit)`：返回**最新** `limit` 条（升序）+ `firstSeq` / `lastSeq` / `instance`。
- 配置：`PersistEvents` / `PersistChat` / `HistoryDays` / `HistoryMaxMB`（见 `docs/插件-信使.md`）。
- `Clear()`：测试 / 需要时清空内存（不删磁盘文件）。

## 4. 契约

| 方向 | 唯一契约 |
| --- | --- |
| 插件 → 后端（`/webui/events`、`/webui/chat`） | [`插件-信使.md`](插件-信使.md) §2.2（参数 / 返回 / 事件类型） |
| 后端 → 浏览器（`/api/events`、`/api/events/stream`、`/api/chat`、`/api/serverinfo`） | [`API_SPEC.md`](API_SPEC.md) §6.3（SSE 事件、`feedhub` 共享轮询、`instance` / `event: reset`、降级） |

本页**不再复述字段**，只留两条跨层语义：

- 旧插件没有 `instance`（能力 `events_instance`）时，后端退回「`lastSeq` 回退」判断
  「同一地址后面还是不是同一个服」——新服 `seq` 恰好更大时会漏判（已知取舍，见 §6）。
- 旧插件仍可能发 `type=webui`：前端按 `chat` + `source=webui` 渲染，不丢事件。

## 5. 前端展示（`web/src/pages/HomePage.tsx`）

> 事件文本用共享的 `components/RichText.tsx`（从 `ResultPanel` 抽出）渲染：
> 聊天里若带 `[i:123]` / `[i/s5:75]` / `[c/RRGGBB:文字]` 会渲染成**物品图标 / 彩色文字**（与指令结果面板一致）。

- **卡片位置**：「服务器动态」固定排在第 **2** 位（第 1 是「服务器状态」）。
  「快捷入口」默认隐藏（与侧栏导航重复），仍可在「管理卡片」中重新打开。
  默认顺序定义在 `web/src/lib/homeCards.ts` 的 `BUILTIN_CARD_IDS` / `DEFAULT_HOME_CARDS`。
  - 用户仍可在「管理卡片」里自行拖拽 / 隐藏；改动只存本机 `tswui:homeCards`。
  - 移动端先渲染高频指令卡片，再渲染概览（状态 / 动态 / 最近执行）；桌面端仍为左右两栏。
  - 变更默认布局时递增 `HOME_CARDS_LAYOUT_VERSION` 并配 `upgradeHomeCardsLayout()`：
    老布局一次性升级——把 `events` / `quick` 落到第 2 / 第 3 位，并在 v3 默认隐藏 `quick`；
    其余卡片相对顺序、隐藏态、自定义卡片全部保留（`web/src/lib/homeCards.test.ts` 有覆盖）。
- **拉取时机（v1.4 起）**：`useServerFeed` 挂载即刷新一次（**进入首页 / 指令模块即触发**）：
  先拉 `eventsTail`（最近 N 条） + 一次 `/api/serverinfo`（含游戏内时间）。
  - **实时**：传输层实现 `eventsStream`（SSE）时，建长连接推送事件，不再轮询事件；
    连接失败 / 未实现则回退到按 `settings.eventsRefreshInterval` 轮询 `/api/events?since=`。
  - `/api/serverinfo`（世界状态徽标）仍按 `settings.eventsRefreshInterval`（1 / 3 / 5 / 15 分钟）拉。
  - 页面隐藏时断开 SSE，回到前台重连并先拉一次增量。
  - 「页面数据刷新间隔」触发时，`HomePage` 把 `refreshToken` +1，**连带刷新**服务器动态。
- **展示**：徽标 + 最近 **6** 条事件（前端内存最多 **20** 条，每条按 `type` 配色圆点：join 绿 / leave 灰 / boss 橙 / chat 蓝）；
  事件按时间**升序**（最旧在上、最新在下），列表默认**贴底**停在最新一条；每条右侧显示时间
  （刚刚 / N 分钟前 / `HH:MM` / 昨天 `HH:MM` / `M-D HH:MM`，鼠标悬停可看完整本地时间）；跨天时自动插入「今天 / 昨天 / M月D日」分隔线。
  卡片右上角是两个**图标按钮**（`IconAction`，同尺寸同灰度）：**刷新**（立即拉一次，不必等间隔）与**向右箭头**（跳到「聊天」页 `#/chat`，
  文字「查看全部」已去掉，只留箭头；含义靠 Tooltip / `aria-label`）。
  **卡片底部**一行 `<世界名> · 刷新于 HH:MM:SS · 游戏内 HH:MM`（`formatGameTime`：白天 4:30 起算 / 夜晚 19:30 起算；
  世界名用来区分同一地址下先后开的不同服，过长时截断、悬停看全文）。
  上游换服触发自动重同步时，底部**短暂显示「已切换服务器」**（10s，悬停有解释），随后自行消失。
- **登录态失效（403）走统一重新登录流程**：换服后旧会话 token 通常在新服无效，
  动态卡片的请求拿到 `token_invalid` 就拉起登录框（只弹一次），登录成功后重新拉取并自动同步到新服；
  用户取消登录则保持未登录态（不再空转撞 403）。
- **服务器状态卡片**底部也显示 `刷新于 HH:MM:SS`（`loadStatus` 成功时记录 `lastStatusAt`）。
- **1 分钟选项限权**：仅 `GM` / `superadmin` / `vip` 组可选（设置页拉 `/api/me` 得到用户组后启用该选项）。

### 聊天页（`web/src/pages/ChatPage.tsx`，`#/chat`）

独立页面，侧栏**紧跟「指令」下一行**（原来是「指令」页顶部的「聊天」tab）。
它渲染 `components/ServerFeed.tsx` 的 `ServerFeedTab`，底部是 `components/WebChatInput.tsx`：

- 只在**页面挂载时**轮询 / 建 SSE（切走即卸载、停止推送）；
- **内存保留 500 条**（插件现在内存最多 2000 条）；打开先拉「最近 N 条」，列表默认渲染最近 **30** 条，
  顶部「加载更早的 N 条」按批展开更旧的记录（纯前端渲染窗口，不新增协议）；
- 实时优先走 SSE（`transport.eventsStream`），不可用时回退轮询；
- 列表按时间升序、默认**贴底**（最新一条在最下面）；每条右侧显示时间，跨天自动插入日期分隔线；
  用户向上翻看时出现「↓ 最新」浮按钮，一点回到底部；
- **滚动条在浏览器右侧**：聊天页不固定高度（`usePageHeight` 只输出 `min-height`），列表本身**不溢出滚动**，
  整页由 AppShell 的 `<main>` 滚——所以滚动条是全局那条，而不是嵌在列表里（`ServerFeedList` 的 `pageScroll`）。
  输入框（连同筛选 chips / 世界徽标）`sticky bottom-0` 钉在视口底部；`<main>` 在聊天页带
  `scrollbar-gutter: stable`（常驻预留滚动条槽），否则切筛选后事件变少、滚动条消失会让整列左右跳 8px；贴底跟随、
  「↓ 最新」（投到吸底区域上方）、「加载更早」都改作用在 `<main>` 上（`useBottomList` 的 `scroller` 选项）。
- **有新事件到达就滚到最底部**（聊天窗口手感，`ServerFeedList` 的 `followNewest`，只有聊天页传）：
  自动轮询 / SSE 推送到新消息、手动刷新、自己发完言刷新回来，都会停在最新一条。
  首页「服务器动态」卡片不传这个 prop，仍是「用户往回翻看时新事件不把视图拉走」；
- 外面**不包 `Card`**：和指令页一样，列表直接铺在工作区上，省下卡片边框与内边距的高度；
- **类型筛选**（全部 / 进服 / Boss / 事件 / 旅商 / 聊天）在**输入框正上方那一行**（chips 靠左）；
  世界状态徽标在**它的上一行、单行靠左**；**刷新**一簇（上次刷新文案 + 刷新按钮）在**输入框发送按钮左边**
  （回复玩家后想立刻看回应时点一下）。
  「进服」只是文案（`feed.filterPresence`）：`presence` 筛选仍**同时显示进服与退服**（`join` + `leave`）。
- 复用首页同一套 `useServerFeed` hook 与 `ServerFeedList`；插件缺失时显示提示而非隐藏。
- 需要在版本 / 服务器切换时重新拉取，所以 `ChatPage` 接收 `serverId` prop（由 `App.tsx` 传入 `activeServerId`）。
- **插件缺失**：捕获 `kind === 'plugin_missing'` → `eventsPlugin = false` → 隐藏卡片并停止轮询。
- **底部常驻输入框**（共享组件 `components/WebChatInput.tsx`）固定在页面底部（`sticky bottom-0`）。
  发言成功的 `已发送（显示为 [WebUI] hf）` 用 sonner 提示条弹出（全局 `<Toaster>` 挂在 `App`，堆叠 / 可关闭 / 4 秒自动消失）；
  失败在输入框左下角显示红字 + 「重试」。
  提交后调用 `transport.sendChat(text)`（→ `POST /api/chat`），带前缀发到游戏内聊天，成功后刷新事件流。
  草稿存本机 `tswui:chat:draft`，切页再回来还在。失败保留输入、可就地「重试」；插件缺失 / 未登录时禁用。
- **首页卡片不再放发言框**：卡片太小，回复玩家统一在「聊天」页做。
- **容错**：插件是「检测之后才装」时不能永久停摆。`useServerFeed` 遇 `plugin_missing` 后不再 `clearInterval`，
  而是改为 **30 秒慢速重试**（`MISSING_RETRY_MS`），装好插件后自动恢复；瞬时错误（超时 / 不可用）按正常间隔重试。
  设置页「在线授权 / 账户」同理：缺失态带「重新检测」按钮，并在窗口重新获得焦点时自动重试。
- **Mock**：`web/src/lib/mockTransport.ts` 提供 3 条假事件 + 假 `serverInfoExtra`，Mock 模式在界面上有 `Mock` 标记。

## 6. 已知限制 / 待解问题

| 限制 | 现状 | 影响 |
| --- | --- | --- |
| NPC 只记旅商 | 城镇 NPC 到达 / 离开、NPC 死亡均不记 | Boss 战时城镇 NPC 会批量死亡，记死亡会刷屏；只保留旅商到达 |
| 6 类事件 | join / leave / boss / announce / npc / chat | 玩家死亡、商店购买等仍没有 |
| 聊天默认采集 / 落盘 | `RecordChat` 默认开；`PersistChat` 默认**关** | 聊天默认不进磁盘；部署方可关 `RecordChat` 完全不采集 |
| 文本服务端硬编码中文 | `Plugin.cs` 直接拼中文字符串 | 网页切英文时事件文本仍是中文 |
| 磁盘历史有保留窗口 | `HistoryDays=7` / `HistoryMaxMB=50` | 超出自动删最旧；`PersistEvents=false` 时为纯内存（重启清空） |
| 世界状态与事件流分离 | 徽标来自 `/api/serverinfo`，非事件 | 状态变化不在时间线里体现 |
| 无去重 / 无合并 | 每条事件独立 | 高峰进出服会刷屏（首页只显示最近 6 条，动态 tab 窗口 30 条 + 「加载更早」） |
| SSE 来源是后端共享轮询 | 每个上游一个 goroutine 轮询插件，fan-out 给所有人；空闲自适应退避 | 延迟约一个轮询间隔（有事件 2.5s / 静默最多 10s）；TShock 请求数与在线人数无关 |
| 换服后旧登录态通常失效 | TShock token 存在各服的数据库里，换服后旧 token 无效；动态请求 403 → 前端统一弹重新登录（只弹一次），登录成功后自动重同步 | 换服后需要重新登录一次（这是 TShock 的权限模型，不是缓存问题） |
| 同地址可能先后开多个服 | 插件用 `instance`（`tshock/WebUI/instance.id`）标识事件库；后端一发现变化就清空 ring / 世界状态并下发 `event: reset`，前端清空列表重拉 | 旧插件没有 `instance`，只能靠「`seq` 回退」兜底：新服 `seq` 恰好更大时会漏判（暂不解决） |
| 网页发言不绕过禁言 | 在线 `mute` 直接拒绝 403；离线无法判定 | 不走 `PlayerHooks.PlayerChat` → 依赖该钩子的插件收不到 |

### 已完成

- 记录玩家聊天（事件 `type=chat, source=game`，插件配置 `RecordChat` 可关）——首页卡片与「聊天」页同步可见。
- 服务器动态升级为**独立的「聊天」页**（`pages/ChatPage.tsx`，侧栏紧跟「指令」，`#/chat`；
  `ServerFeedTab` 复用 `useServerFeed`；原先是指令页顶部的 tab）。
- 「聊天」页底部常驻输入框用于网页发言（共享 `WebChatInput`；首页卡片太小，不放入口）：
  `POST /api/chat` → 以前缀广播到游戏内聊天，并记入事件流 `type=chat, source=webui`（与真实玩家区分；
  不伪造身份、不绕过禁言、有每账号限流；失败可重试）。
- 插件检测容错：事件流遇 `plugin_missing` 改 30s 慢速重试（装好插件自动恢复）；账户区块带「重新检测」+ 焦点重试。
- **列表体验重做（贴底 + 懒加载 + 时间）**：首页卡片与「聊天」页都改成「最旧在上、最新在下」并按时间升序，
  默认滚到最底部（最新一条）；用户向上回看时新事件不会把视图拉走；每条右侧显示时间（刚刚 / N 分钟前 / …）；
  首次直接拉满插件的 500 条事件，「聊天」页默认只渲染最近 30 条，可「加载更早」按批展开；
  首页卡片右上角新增「刷新 + 查看全部」直达「指令 → 动态」。
- **无名字的进 / 退服不记**：公网爬虫 / 扫描器连接拿不到玩家名，这类不属玩家行为，插件不再记 join/leave。
- **Boss / 事件召唤公告（本版）**：新增 `type=announce` 与 `type=npc`，记录游戏内世界公告原文
  （通过 `ServerApi.Hooks.ServerBroadcast` 拦截 `ChatHelper.BroadcastChatMessage`）：
  - `announce`（BossOrEvent / World 色）：Boss 苏醒（如「光之女皇已苏醒！」）、血月 / 日食 / 入侵 / 南瓜月 / 霜月等。
  - `npc`：**仅旅商到达**，通过 `NpcSpawn` + NPC 368 **始终记录**（`Main.gameMenu` 时不记）；城镇 NPC 的到达/离开与 NPC 死亡都不记，避免 Boss 战时伤亡刷屏。
  仅保留本地化键文案（排除玩家聊天与插件消息）；重复的「已被击败」不重复记入。
  前端新增「事件」「NPC」筛选与紫 / 蓝色圆点。
- **更多事件信息（本版）**：陨石落地、进入困难模式，以及
  血月 / 日食 / 入侵 / 南瓜月 / 霜月**结束**、下雨 / 沙尘暴的开始与结束（状态对比补记）。
  不记玩家死亡，也不记专家/大师模式的 Boss 宝藏袋掉落。
- **跨天日期分隔**：列表按天插入「今天 / 昨天 / M 月 D 日」小标题。
- **类型筛选 + 手动刷新**：「全部 / 进服 / Boss / 事件 / 旅商 / 聊天」筛选 chips 在**输入框正上方**（贴近列表底部，不占列表高度），
  世界状态徽标（困难模式 / 血月 / 日食 / 下雨 / 入侵，单行不换行，太窄时横向滚动）在**它上面那一行、靠左**。
  刷新一簇在「聊天」页被挪到**输入框发送按钮左边**（`ServerFeedTab` 的 `actionsSlot`；其它场景仍可退回顶栏）：
  左边显示「上次刷新 HH:MM」（手机端隐藏），
  hover / 长按出 Tooltip，点它才是刷新。
  列表最底部那行仍是「世界名 · 刷新于 HH:MM:SS · 游戏内 HH:MM」。
  按钮是**强制重新同步**：断开 SSE、忘掉 `lastSeq` / 已加载历史、清掉流冷却，再按「首次打开」重拉尾部事件并重连
  （事件按 `seq` 去重合并，不清空已有）；跑的时候图标转圈 + 按钮禁用。
  适用于：怀疑漏了事件、插件刚装好、换服后想立刻对齐、以及旧插件纯轮询（默认 180s）时不想等。
  > 历史坑：早前 SSE 已连接时 `tick()` 会整体跳过拉取（只把「刷新于」改成当前时间），按钮等于安慰剂，已修。
  > 现在「刷新于 …」只在**真的拉取过**时更新；SSE 期间由流帧（事件 / 世界状态）各自更新时间。
  > 自动刷新（页面刷新间隔 / 发言成功）走的是轻量 `tick`，**不断开 SSE**；只有手动刷新才断流重连。
- **回到底部**：用户向上翻看时右下角出现「↓ 最新」浮按钮。
- **事件保留更久**：插件 `EventLog.Capacity` 200 → 500（内存代价极小），前端保留 500 条。
- **历史持久化 + 实时推送（本版）**：
  - 插件按天落盘 `tshock/WebUI/events/*.jsonl`（后台写线程，`PersistEvents` 默认开，
    `PersistChat` 默认关），重启不清空；内存保留 2000 条（启动接磁盘 `seq` 继续递增）。
  - `/webui/events` 新增 `tail=N`（取最新 N 条，能力 `events_history`）；
    后端 `/api/events?tail=` 对旧插件（含 RC2）自动降级为「拉一页取尾部」。
  - 后端新增 `/api/events/stream`（SSE）；`useServerFeed` 打开先取最近 N 条 → SSE 实时；
    失败 / 未实现退回轮询；页面隐藏断开、回前台重连。
- **多玩家下的 TShock 减压（本版）**：
  - SSE 改成**每上游共享一个轮询 goroutine**（`feedhub.go`）：TShock 的 REST 请求数与在线人数无关，
    不再「每个浏览器连接各轮询一次」。
  - 轮询间隔**空闲自适应退避**：有事件 / 刚活动 2.5s，静默 >30s→5s、>120s→10s。
  - 世界状态（徽标 / 游戏内时间）随 SSE 推 `event: world`（~20s），前端不再单独轮询 `/api/serverinfo`。
  - 后端加插件 `meta` 短缓存（60s）与世界状态缓存（30s），全玩家共享。
  - 部署建议：把 TShock `RESTMaximumRequestsPerInterval` 提到 60（游戏内 `/web limit 60`）。
- **同地址多服不再串数据（本版）**：同一个服务器地址 / 端口可能先后开不同的服，
  插件事件库新增持久化实例标识（`tshock/WebUI/instance.id`，能力 `events_instance`），
  `/webui/events` 的响应带上 `instance`；后端 hub 发现它变化就清空 ring / `lastSeq` / 世界状态、
  作废插件 meta 缓存，并给 SSE 订阅者发 `event: reset`；前端收到后**静默清空旧列表并重拉**，
  换服后首页卡片 / 聊天页在一个轮询周期内换成新服内容。旧插件（无 `instance`）用「`seq` 回退」兜底。
  界面侧：底部新增世界名（区分同一地址下的不同服）与 10 秒的「已切换服务器」轻提示，不弹任何错误。
