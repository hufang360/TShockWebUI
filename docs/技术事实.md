# 技术事实（别猜，已核实 / 实测）

> 源码与实测细节见 [`TECHNICAL_RESEARCH.md`](TECHNICAL_RESEARCH.md) 与 [`REST_API限制.md`](REST_API限制.md)；
> 产品与硬约束（C1–C15）见 [`设计原则与约束.md`](设计原则与约束.md) §3。

- Terraria **1.4.5.8**，TShock 目标 **v6.2.1**，REST 端口 **7878**。
- `/v3/server/rawcmd` 以 token 用户的用户组身份执行，**严格继承权限，不提权**。
- **`AllowServer=false` 的指令无法通过 rawcmd 执行**（`/i`、`/tp`、`/home`、`/buff` 等 24 条）：
  前端与后端都必须直接拒绝并提示「只能在游戏内执行」。
- **参数补全的数据来自 TShock 自己的用法串**（`GetString("Invalid syntax. Proper syntax: {0}<cmd> <args>")`,
  `Commands.cs` 中 73 处）+ 源码枚举常量 + `switch (args.Parameters[N])` 的 case 标签 + 「方法体不引用
  `args.Parameters` → 无参数」的机械判定；`data/commands.json` 的 `paramSets`（95 条中 70 条）由
  `tools/gen-data.mjs` 提取。**提取不到就不给候选，绝不猜参数**；改动后须跑
  `web/src/lib/completion.realdata.test.ts` 与 `server/scripts/sync-commands.sh`。
- **参数取值（`kind: 'enum'`）在补全下拉框里带可读备注名**（如 `brain` → 克苏鲁之脑）：
  `spawnboss` 取值是 NPC 别名 → 由 `data/npcs.json` 的 `sb` / `sbAliases` + `loc.NPCName` 解析；
  `worldevent` / `worldmode` / `time` / `clear` / `firework` / `region` / `warp` / `group` 等的固定术语，
  以及多级子命令（`/region define`、`/worldevent invasion <类型>`、`/pm` / `/wm` / `/fish` 等）
  统一在 `web/src/lib/commandMeta.ts` 维护（国际事件名取自游戏本地化 `Bestiary_Events` / `Bestiary_Invasions`）。
  补全支持字面量子命令与按备注名搜索（如输入「血月」命中 `bloodmoon`）；覆盖度由
  `commandMeta.test.ts` 对着真实 `commands.json` 兜底（所有 enum 取值都必须有备注）。
  维护方式与全部子命令清单见 `docs/功能-指令多级补全与备注.md`。
- **未知/插件指令不前置拒绝**：`commands.json` 只含核心 95 条，插件指令（如 FishShop 的 `/fish`）
  无法静态枚举，故未知指令照常发往 TShock，由 TShock 判定（不存在 → `command_not_found`，
  与「参数错误 → `command_error`」分开：前者说明提供该指令的插件没装）。
  判定只认 TShock 的**完整句式**并先做归一化（转小写 + 空白合并）：
  en `Invalid command entered. …` / zh `输入的命令无效。…`；插件自己打印的「无效指令：xxx」不算，
  否则首页依赖插件的卡片会被误隐藏（`server/internal/tshock/client.go` 的 `markersCommandNotFound`）。
- **会话按上游隔离**：`session.Session.Upstream` + 按上游派生的 Cookie 名，切服不串用 token、
  也不清掉别服的登录态；`/api/capabilities` 是统一能力矩阵（一次请求拿到各插件可用性）。
- **普通玩家默认无法登录**：建 token 需用户组有 `tshock.rest.useapi`，执行指令需 `tshock.rest.command`；
  `default` 组没有，密码正确也被拒（TShock 对「密码错」与「无权限」返回同一 403，后端无法区分）。
  需服主执行：`/group addperm default tshock.rest.useapi tshock.rest.command`（GM 等带 `*` 的组免配）。
  前端登录失败时会展示该命令并提供复制。
- TShock token 只存内存，**重启即失效**；建 token **按来源 IP 限流**（默认 5 次/分钟）。
  经反代时所有玩家共用一个来源 IP（实测网关 `<gateway-ip>`），故这是**全站**限额。
- **`POST /v2/token/create` 不解析表单体**（实测 500），登录凭证**只能走 query string**；
  因此必须由后端发起，浏览器不直连。
- **后端→TShock 的出站 HTTP 方法默认 `POST`**（`TSHOCK_METHOD=POST|GET`，默认 POST）：
  TShock **不校验方法**（只按 URI 路由），参数始终只在 query string；
  默认 POST 是为了规避部分机房把**明文 GET** 劫持成 302 —— 实测腾讯云对 Host 为未备案域名的 GET
  返回 `302 → dnspod.qcloud.com/static/webblock.html`（POST/PUT/OPTIONS 均正常）。域名被拦时根治靠备案或用 IP，
  详见 `docs/REST_API限制.md` §1 / §8.1。
- `/v2/server/status` 的 `serverversion` 形如 **`v1.4.5.8`（带前导 `v`）**，与 `data/meta.json` 比较前必须去掉。
- `EnableTokenEndpointAuthentication=true` 时 `server/status` 需要 token（无 token 返回 401）。
- **`GET /api/session` 会校验上游 token**（`/tokentest`）：TShock 重启后刷新页面即回登录；执行指令遇 `token_invalid` 会弹登录框并在重登后自动重试一次。
- 图标：一张图集 `data/items-atlas.png`（1024×4906，每格之间 1px 透明缝），前端按 `items-atlas.json` 的 `regions[item.icon]` 裁切第一帧。
- **容器访问公网 TShock 可能被本机代理挡住**（实测 OrbStack/macOS）：容器出站走 Clash（`127.0.0.1:7890`），出口 IP `<container-exit-ip>`，而宿主机直连出口 `<host-exit-ip>`；
  远端 TShock 对容器连接返回空回复（`curl` 52 / 后端 `tshock_unavailable`），宿主机 `/api/login` 正常。
  解决：给 Clash 加该 IP 的 `DIRECT` 规则，或用 `scripts/dev-native.sh` 在宿主机直跑后端。
- **角色存档（`.plr`）**：AES-128-CBC（`PaddingMode.None`，key 与 IV 都是 `"h3y_gUyZ"` 的 UTF-16LE 字节）
  加密后按 `Player.Deserialize` 的字段顺序平铺；文件头是 20 字节 `FileMetadata`（release ≥ 135）。
  **解密与解析都在浏览器里**（`web/src/lib/save/aes.ts` + `plr.ts`；WebCrypto 的 AES-CBC 会强做 PKCS#7
  去填充，与本格式不符，所以自带一份无填充实现），文件不上传。
- **世界文件（`.wld`）是 `.NET BinaryReader` 写出的平铺结构**，`.wld.bak` / `.wld.bak2` 只是同格式备份副本
  （同一解析器，无需区分）。事实与出处（反编译源码 `TR_SRC`，Terraria 1.4.5.8）：
  - 第 0 段（文件头）：`int32 release` → `Terraria.IO/FileMetadata.cs` 的 `FileMetadata.Read`
    （8 字节 = 7 字节魔数 `relogic` + 1 字节 `FileType`，`World=2`、`Player=3`；`uint32 Revision`；
    `uint64` 位标志，仅 bit0 = 收藏）→ `int16` 段数 → 段数 × `int32` 段指针 → 图格 frame 位压缩数组。
    来源：`Terraria.IO/WorldFile.cs` 的 `LoadFileFormatHeader`。
  - **段指针是「各段结束位置」**：`pointers[0]` = 文件头结束，`pointers[1]` = 头部字段结束
    （**也就是图格段起点**），`pointers[2]` = 图格段结束（箱子段起点）…（`LoadWorld_Version2` 的
    `Position == positions[i]` 断言）。所以缩略图从 `pointers[1]` 开始读，而不是 `pointers[2]`。
  - 第 1 段（头部字段）：顺序照抄 `WorldFile.LoadHeader`。要点：`release >= 209` 起难度是 `int32`
    （0 普通 / 1 专家 / 2 大师 / 3 旅途），特殊种子是紧随其后的一串 `bool`（`zenith` 在 267 前由
    「醉汉 + 颠倒」推导）；`>= 141` 有创建时间、`>= 284` 有最后游玩时间，都是
    `DateTime.ToBinary()`（100ns ticks，高 2 位是 Kind，**记录的是保存时的本地时间**）；
    `>= 297` 起有团队出生点（`byte` 数量 + 每个 `int16 × 2`）；`>= 299` 起末尾有
    `WorldManifestData`（`ReadString`）。
  - 图格段是 RLE 压缩的属性流：`header1` 的 bit0 表示有 `header2`（`header2` bit0 → `header3`，
    `>= 269` 再 → `header4`）；bit1 图格激活、bit2 有墙、bit3-4 液体类型、bit5 图格 ID 是 2 字节、
    bit6-7 RLE 计数宽度（0 无 / 1 `byte` / 2 `int16`）；`header2` 的 bit1-3 是三种线缆、bit4-6 斜坡；
    `header3` 的 bit3 图格染料、bit4 墙染料、bit2 actuator、bit5 黄线缆、bit6 墙 ID 高字节、
    bit7 = 微光；`header4`（`>= 269`）是隐形 / 满亮度。来源：`MapHelper.DecompressTileData`
    （TEdit `World.FileV2.cs` 的 `DeserializeTileData` 与之逐位一致）。
    RLE 是**同列向下重复**，所以解码必须按 `for x { for y }` 顺序、不能跳读。
  - 小地图颜色表：`tools/gen-world-colors.mjs` 从 TEdit 仓库 `src/TEdit/MapColors.xml`（文件头标注
    "Terraria MapColors.XML … 1.4.5.0"，取 `Paint="0"` 基础色）生成
    `web/src/lib/save/worldColors.generated.ts`；区域背景色与液体色取自 TEdit `docs/settings.xml`
    的 `<GlobalColors>`。1.4.5 新增的 6 个图格
    （压力板 / 地雷 / 回响块 / 巨型提基等）在颜色表里没有 → 渲染时退回中性灰。
  - **release < 87 是 V1 格式**（`WorldFile.LoadWorld_Version1_Old_BeforeRelease88`）：没有
    `relogic` 文件头、字段顺序完全不同（如 `PacMapv2.wld`，2012 年、release 39）。本仓库只支持
    **140+（1.2.4 起）**，遇到旧格式明确提示「请用游戏打开并重新保存一次」。
  - 体积实测（本机 `~/tr/s` 下 277 个真实 `.wld`，含插件备份）：**最大 15.5 MiB**（1.4.5 大世界 8400×2400
    带大量建筑）。
  - 实测（本机 `~/tr/s` 下 277 个真实世界，release 194 / 228 / 279 / 315 / 318 / 326）：头部解析后位置
    与 `pointers[1]` **完全相等**。
  - **解析与缩略图都在浏览器里做**（`web/src/lib/save/worldFile.ts` + `worldThumb.ts`，文件不上传）：
    15.4 MiB / 8400×2400 实测 **解析 <1ms、渲染 4200×1200 位图 ≈130ms**（V8，Node 与浏览器同一引擎；
    分辨率由 8M 像素预算决定，小/中世界就是 1 图格 = 1 像素）。渲染按列分块（默认每 128 列让出主线程一次），
    大世界也不会卡住界面。
  - 历史：这两项能力最初由 Go 后端实现（`POST /api/player/import`、`POST /api/world/import`），
    2026-10 按用户要求改为**纯前端**、后端接口与 `server/internal/{plr,world}` 一并删除；
    迁移时用同一批 277 个真实世界 + 390 个真实 `.plr` 做过逐字段 / 逐像素（PNG SHA-256）对比，结果完全一致。
