# 合成表与物品提示（Recipes & Item Tooltip）

文档版本：1.0
对应页面：`web/src/pages/ItemsPage.tsx`（导航「物品图鉴」）
对应组件：`web/src/components/RecipePanel.tsx`、`web/src/components/ItemTooltipContent.tsx`、`web/src/components/ItemIcon.tsx`
相关数据：`data/recipes.json`、`data/item-stats.json`、`data/item-tips.<culture>.json`（见 `data/README.md`）
相关脚本：`tools/gen-game-data.sh`、`tools/gamedump/`、`tools/gen-recipes.mjs`、`tools/gen-item-stats.mjs`

> 本文件记录「物品图鉴 → 本地合成表」与「悬停物品图标 → 游戏同款属性提示」的**数据来源、字段语义、
> 生成方式与验收方法**。所有事实均给出源码出处，禁止臆测。

---

## 1. 定位与范围

- **合成表**：在物品图鉴里直接展示「怎么合成该物品」与「该物品能合成什么」，**不再依赖**服端
  `/r`（查一查插件）指令，也不需要登录。
- **物品提示**：鼠标悬停任意物品图标时，弹出游戏同款的属性提示（伤害、暴击率、击退、防御、镐力……）。
- **不在范围**：嬗变（微光）全量表（`ShimmerTransforms`）、物品商店、管理员后台。

## 2. 事实来源（务必以源码为准）

| 事实 | 出处 |
| --- | --- |
| 全部配方由 `SetupRecipes()` 命令式构建 | `TR_SRC/Terraria/Recipe.cs:604`（604–15161）+ 辅助方法 15260–16794 |
| 配方结构：`createItem` / `requiredItem[15]` / `requiredTile` / `acceptedGroups` / 环境标志 | `Terraria/Recipe.cs` |

| 配方索引：产出与材料倒排 | 由导出数据自行建立（`byResult` / `byIngredient`） |
| 制作站 = `requiredTile`（图格 id），图标由图格反查物品 | `Item.createTile` |
| 工具提示行顺序与文案 | `TR_SRC/Terraria/Main.cs:20852` `MouseText_DrawItemTooltip_GetLinesInfo()` |
| 物品名颜色（稀有度） | `Terraria/Main.cs:20778` `MouseText_DrawItemTooltip_GetItemNameColor()` |
| 暴击显示 = 玩家基础 4% + 物品 `crit` | `Terraria/Player.cs:2413`（`= 4`）、`Player.cs:25710`（`+= inventory[selectedItem].crit`） |
| 稀有度颜色 / 速度 / 击退档位 | `Terraria/Main.cs` 同上 |
| 状态：1.4.5.8，TShock/OTAPI 构建产物与 `TR_SRC` 版本一致 | `tools/gamedump` 运行时读取程序集版本 |

**为什么用运行时导出而不是纯文本解析**：`SetupRecipes()` 含大量 `if(type…)` 区间、`for` 循环与
`AddXxxFurniture()` 辅助方法；`Item.SetDefaults()` 更是 5 个巨型 `switch`。直接调用游戏自身代码
（TShock 的 OTAPI 程序集）可以**零偏差**地拿到最终配方与属性；纯文本复刻在反向（拆解）配方与
`Item.createTile` 上极易出错（详见 §6 备选方案）。

## 3. 数据生成

```bash
# 需要 dotnet 9 SDK（首次自动从 NuGet 还原 TShock 6.2.1 / OTAPI）
bash tools/gen-game-data.sh
#   -> data/recipes.json
#   -> data/item-stats.json（stats）
#   -> data/item-tips.zh-Hans.json / data/item-tips.en-US.json（tip 行）
```

环境变量：

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `TR_SRC` | `<仓库>/../tr-code-1458` | 反编译源码（配方组正则、本地化文案） |

`tools/gamedump` 通过 NuGet `<PackageReference Include="TShock" Version="6.2.1" />`
（→ `TSAPI` → `OTAPI.Upcoming`）引用 `OTAPI.dll`，不写死本机路径；构建与运行均零外部 DLL 依赖。

`tools/gamedump/Program.cs` 做三件事：最小静态环境初始化（`Program.SavePath` / `Main.rand` /
`Main.player[0]` / `Main.recipe` 数组）→ 注册配方组并跑 `Recipe.SetupRecipes()` → 遍历导出配方与
`Item.SetDefaults()` 属性。为什么需要这些初始化：见 `GameDump.cs` 注释。

## 5. 前端行为与验收

- **「合成表」速查页已移除**（2026-10-23）：物品图鉴顶部不再有「查一查 / 合成表」页签，只保留「查一查」；
  原大类（手机 / 天顶剑 / 药水…）的物品 ID 清单存档在
  [`记录-合成表大类物品 ID.md`](记录-合成表大类物品ID.md)。物品详情里的合成表 / 用于合成 / 微光嬗变不受影响。
- **物品提示里的「合成表」入口**：`ItemTooltipContent` 底部「`ID · key`」行后面有个 **⚒ 合成表** 按钮；
  点击由 `ItemDetailProvider`（`web/src/lib/itemDetailContext.tsx`）决定：图鉴页内打开详情抽屉（**已经开着抽屉时再叠一层**，
  见 [`页面-物品图鉴.md`](页面-物品图鉴.md) §4），其它页面跳到「物品图鉴」并打开详情，
  没有 Provider 时不渲染（同收藏 ⭐ 的降级方式）。配方行里的材料 / 产物、掉落条目也一样可点开（同一入口）。
  **详情抽屉自己那份 tips 不显示这个入口**（`hideRecipeLink`，它指的就是当前物品自己）。
  另外**小图标（配方行里的材料 / 产物、掉落条目）本身不可点**（不能点出抽屉），只能走提示里的这个入口；
  物品图鉴的**大格子（64px）点击仍然直接打开抽屉**。
- **悬停提示**：`ItemIcon` 通过 `DatasetContext` 读取 `itemStats`，portal 到 `body`（避免被滚动容器裁切），
  **物品图鉴结果区的 64px 大格子不挂这个提示**（点一下直接开抽屉，DexCell 只用 `ItemIcon tooltip={false}`），
  内容为 `ItemTooltipContent`（名称按稀有度着色 + 当前语言的 `tip` 行）。`tooltip={false}` 的图标不显示，
  避免提示内嵌图标递归。**v1.6 起提示可交互**：延迟 150ms 关闭（鼠标可从图标滑入提示）、文字可选中/复制，
  右上角 ⭐ 可直接收藏（与名称行居中对齐、默认颜色减淡）。**全站所有物品提示都带这个 ⭐**：
  `ItemFavoritesStoreProvider` 挂在 `App` 最外层（`useItemFavoritesState` 落地读写 `tswui:itemFavorites`），
  所以指令执行结果的富文本、浮动终端、首页卡片、聊天、鱼店、数据 ID 速查里的图标提示都能直接收藏；
  图鉴 / 指令页另外各自需要收藏列表（筛选 / tab），也调同一个 hook，实例之间靠 `STORAGE_EVENT` 同步。
  未提供 Provider 时不显示 ⭐（便于单独测试组件）。
  **rc2 起鼠标悬停增加约 350ms 弹出延迟**（未到时间就移走则不弹，避免太容易触发遮 UI）；键盘聚焦不受延迟影响。
- **定位**（`useItemTooltip`）：先按锚点上方/下方弹出，再在 `useLayoutEffect` 实测高度，
  **顶部/底部会被裁时自动翻到另一侧**，仍放不下就把朝向边缘的一侧夹到 `8px` margin；
  全局只允许一个提示存在（新提示打开会立即关掉上一个，避免快速滑动时叠好几个）。
- **详情面板**：选中物品后展示同一份 `ItemTooltipContent`（`variant="panel"`）。
- **基础值说明**：含伤害或蓝耗行的物品，悬停提示 / 详情面板底部会显示一句
  「基础值 · 不含角色属性加成」（`i18n` 键 `tooltip.baseStatsNote`）；其余物品不显示，避免噪音。
- **合成表**：`RecipePanel` 渲染（三个分区均可折叠，默认展开；内部为 `repeat(auto-fill, minmax(15rem, 1fr))` 网格，
  短条目在宽屏自动排成 2 列，长条目在单元格内换行）
  - `byResult[itemId]` → 「合成表（n）」；`byIngredient[itemId]` → 「用于合成（n）」
  - **微光嬗变（n）**：`dataset.shimmerToById`（本物品 → 目标）/ `shimmerFromById`（源 → 本物品）；
    数据见 `data/shimmer.json`（`ItemID.Sets.ShimmerTransformToItem`）。每行为 `[源] → [目标]`。
    （名称含**转换 / 分解**两种情形，统称「嬗变」；不再在合成表里重复显示分解记录。）
  - 物品为**普通 `ItemIcon` + 数量角标**（数量叠在图标右下角，无外框格子、无 `×N` 文字）。
  - **记录格式：`材料1 材料2 @ 制作站(+条件) → 物品`——制作站在箭头前面**（界面制作站直接用文字 `@`；箭头用灰色图标）；
    **徒手制作（`station < 0`）不写制作站**，没有「徒手」字样（有环境条件时只写条件）。
    环境/阵营条件紧跟制作站（徒手时直接跟在材料后）：
    能用物品图标的都用图标——墓地 → **4358**、火把神 → **5043**、水中 → **206**、蜂蜜 → **1128**、岩浆 → **207**、雪 → **593**，
    猩红 → **5533**、腐化 → **5532**；其余回退文字标签。（注：`notDecraftable` 不再在配方行里显示，改成了物品级的「可微分」。）
  - 分区标题左侧带**固定物品图标（仅图标）**：合成表 **531** / 用于合成 **36** / 微光嬗变 **5362**。
  - 记录行**无底色**，只有淡灰细描边；hover 时轻微上浮并出现 `bg-primary/10`（与图鉴格子一致）。
  - 合成条目 **hover 时右上角浮动出现「⭐ 收藏 / 复制」两个按钮**（绝对定位、不占位，键盘聚焦时同样显示）：
    复制描述性文本（与界面同格式：`材料 @ 制作站(条件) → 产物`，徒手不带 `@ 制作站`）；
    复制文本一律用名称，**不带 `[i:ID]` 标签**（`copyTags` 恒为 false，勾选框已移除）。
  - **合成记录收藏**（⭐）：正向行与反向（微光分解）行**分别收藏**，键由配方内容算出
    （`web/src/lib/recipeFavorites.ts` 的 `recipeFavoriteKey`：方向 + 产物 × 数量 + 制作站 + 材料 + 环境 + 阵营，
    材料排序后拼接）。**不存配方下标** —— `data/recipes.json` 重新生成后下标会整体错位，内容键才不会指错配方。
    落地 `tswui:recipeFavorites`（`RecipeFavorite { key, ts }`，上限 200，写满丢最旧）；
    点过的 ⭐ 变实心琥珀色（`fill-current text-warning`，与物品提示的 ⭐ 一致）。
    `RecipeFavoritesStoreProvider` 挂在 `App` 最外层，所以详情抽屉 / 叠开的子抽屉里的合成表都能收藏；
    没有 Provider 时不渲染 ⭐（便于单独测试组件）。收藏列表入口：**「物品 ID → ⭐ 收藏」**的结果区左上角（**物品 / 合成表 / 常用**，见
    [`页面-物品图鉴.md`](页面-物品图鉴.md)），以及**聊天页输入框左下角的「合成表」**
    （`RecipeFavoritesPopover`：点一条把记录填进发言框，直接发出去就在游戏里显示成物品图标）。
    填进输入框的文本**只用 `[i:ID]` 标签**、单一格式：`[i:126][i:315][i:314][i:13] @ [i:31] -> [i:296]`
    （`RecipePanel.tsx` 的 `recipeToChatText` / `reverseRecipeToChatText`；材料连写、`@` 制作站、`->` 产物，
    不带名称与数量；徒手没有 `@` 段）。配方行平时不可点，只有在聊天「合成表」弹框里才整行可点
    （`onPick`，Enter / 空格同样触发）。
  - 两个勾选框（**显示物品名称 / 两列视图**）在 **tips 下面、三个配方分区（合成表 / 用于合成 / 微光嬗变）上面**：
    `显示物品名称` 默认**不勾**（仅图标；勾选后才显示名称与配方组的「任何XX」）、
    `两列视图` 默认**不勾**（默认单列；勾选后 `grid-cols-2`）。
  - **小屏（< `sm`）**：合成表 / 掉落即使勾了「两列视图」也只排一列，并在小屏**隐藏该勾选框**
    （与数据ID的「两列表格」同一规则）。
  - 「N 条未显示」每次再加载 60 条；**换物品时展开量重置**（`RecipeRows` 的 `rows` 变时 `useEffect` 重置 `limit`）。
- 无配方、无用途且无微光嬗变时显示「无合成配方，也不是合成材料。」；此时详情里也**不显示这两个勾选框**。
- **可丢微光分解**：数据 `stat.stats.canDecraft`（gamedump，判定见 `data/README.md`）。
  不再在正向行尾挂「可丢微光分解」图标 / 文字，而是**额外显示一条反向记录**：
  `产物 @ 微光（5362 图标）→ 原材料`，例如 `铁镐 @ 微光 → 铁锭 x10 + 任何木材 x3`
  （5362 仅作「微光」标记：文字固定为「微光」，图标不挂物品提示）；
  反向行用虚线描边，与正向行成对排列（换列时不拆开），也可单独复制。
- **词缀变化行（红/绿）**：选中词缀后，除重算基础属性行外，再按游戏 `Main.MouseText_DrawItemTooltip_GetLinesInfo`
  的 `if (item.prefix > 0)` 比较块补变化行：`+15%伤害` / `+10%速度` / `+5%暴击率` / `%大小` / `%射弹速度` / `%击退力` /
  `PrefixArmorPenetration` / `PrefixTagDamage`；颜色用游戏绿 `rgb(120,190,120)` / 红 `rgb(190,120,120)`（蓝耗升高算红）。
  饰品词缀（62–80）不走这些，直接给一行绿色精确效果（如「显著」→ `+4%伤害`，数据 `Player.GrantPrefixBenefits()`）。
  算法见 `web/src/lib/prefixes.ts` 的 `prefixDeltaLines`；已用 OTAPI 对 886 件可重铸物品交叉核对 0 差异。
- **木匣掉落**：`ItemDropsPanel` 在详情里显示「掉落（n）」：物品 + 数量范围 + 概率（**Wiki 风格 `≈1/N`**）；
  数据 `data/item-drops.json`（`Player.OpenFishingCrate` 运行时模拟，底部标注「掉落率仅供参考」）；
  **同样受「显示物品名称 / 两列视图」两个勾选框控制**。
