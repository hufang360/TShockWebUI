## 1. 插件是什么 / 依赖什么

- TShock 第三方插件 **PlayerManager**，提供查看玩家背包与导出角色存档的能力。
- 上游 REST 前缀：`/pm/*`；权限：`playermanager`。
- 本仓库把它做成**「玩家管理」模块**。侧边栏入口跟随「设置 → 激活模块 → 玩家管理」开关；关闭后入口隐藏。
- **「查看存档」（上传本地 `.plr`）已独立成侧边栏菜单**，是公开工具（不读 TShock、不需要登录与权限），
  与本模块开关无关：即使没启用 / 没安装插件，也能从侧边栏直接打开（`pages/PlrPage.tsx`）。

## 2. 上游 REST 端点

| 端点 | 参数 | 权限 | 说明 |
| --- | --- | --- | --- |
| `GET /pm/look` | `name`、`token` | `playermanager` | 玩家血量/蓝量 + 背包（`inventory` 串） |
| `GET /pm/export` | `name`、`base64=true`、`token` | `playermanager` | 整个 `.plr` 存档（base64） |

- 缺 `name` → 400（探测用：说明插件已装且已过权限）。
- 无权限 → 403；插件缺失 → 404。

## 3. 本仓库后端接口

| `/api/...` | 对应上游 | 说明 |
| --- | --- | --- |
| `GET /api/player/capabilities` | `/pm/look`（空 name） | 返回 `{plugin, permission}` |
| `GET /api/player/look?name=` | `/pm/look` | 规范化血量 + 350 槽位背包 |
| `GET /api/player/export?name=` | `/pm/export?base64=true` | 解码后**直接以 `.plr` 附件流**回浏览器 |
| ~~`POST /api/player/import`~~ | —（已删除） | 「导入 .plr」改为**浏览器本地解析**（见下方与 `docs/API_SPEC.md` §5.4），后端不再有该接口 |

- 错误码、业务错误的透出方式、导出体积上限（`maxExportBody = 12 MiB`，解码后约 9 MiB）、
  与指令共用的会话限流：见 [`API_SPEC.md`](API_SPEC.md) §5.2–§5.3（唯一契约）。
- 「导入 .plr」**不经过后端**（浏览器里解密解析，文件不上传，因此不需要登录 / `playermanager`），
  见 API_SPEC §5.4。已用 390 个真实 `.plr` 与旧 Go 实现逐字段比对一致。
- 本表只记「哪个上游对应哪个 `/api`」。

## 4. 前端模块

- id：`players`；侧边栏入口严格跟随模块开关，能力缺失时按 `playerCapabilities` 降级（未装 / 无权限各有提示）。
- **两个独立菜单**（不再共用 tablist）：
  - **查看存档**（`save`，`pages/PlrPage.tsx`）：公开工具，侧边栏入口**恒在**，与模块开关无关。
  - **玩家管理**（`players`，`pages/PlayerManagerPage.tsx`）：依赖 PlayerManager 插件，入口跟随模块开关。
  - 两页共用 `components/player/PlayerLookPanel.tsx`（角色视图）与 `hooks/usePlayerShot.ts`（导出图片）。
- 「玩家管理」页：输入玩家名 → 查看背包 / 下载存档。页面顶部没有标题与 tab（侧边栏已指明位置）。
  页内按钮统一用**常规尺寸**（`size` 不传 = `md`，h-9），与「物资申请」一致。
- 结果分**左右两组**（数据分组见 `web/src/lib/playerSlots.ts`）：
  - **左组** = 背包（含钱币/弹药）+ 下方**银行**（储蓄罐 / 保险箱 / 护卫熔炉 / 虚空袋）；
  - **右组** = 装备区（染料 94–98 / 工具 89–93 / 染料 79–88 / 时装 69–78 / 装备 59–68）与
    **配装 1/2/3** 排在**同一行**，**配装在右侧**。
  - 列数用**容器查询**（AppShell 内容区的 `@container`）：内容 ≥1050px 才左右并列，否则左组在上/右组在下。
    用容器查询而非视口断点，是为了兼顾侧栗展开/收起与 compact 最大宽度。
- 「玩家管理」查询卡片（`canUse` 时显示）：
  - 一行：输入框（最近 / 在线玩家下拉）+ 下载存档 / 刷新 / 查看背包；
  - **默认查看自己**：没记忆过玩家名时默认填当前登录用户，并自动拉一次（只在进入「玩家管理」页时触发）。
  - 输入框一有变动就清掉上一次的错误，避免边打字边弹「无法解析」。
- 模块没启用时，「玩家管理」页给一条提示（去设置打开模块），不再整页消失。
- 未登录时「玩家管理」页显示统一的 `LoginGate`；「查看存档」是独立页面，照常可用。
- **精简视图**（`useLocalState(StorageKeys.playersCompact)`，**默认开**）：开启时隐藏银行与配装。
- **查看存档（公开页 `save`）**：
  - 「导入 .plr」按钮 + **「来个 Demo」**（拉自带存档 `web/public/demo/Joy.plr`，走同一条本地解析路径）+ 整块**拖拽**接收（`onDrop`）；文件 → 浏览器本地解析（`web/src/lib/save/plr.ts`）→
    沿用同一套背包 / 角色渲染（`components/player/PlayerLookPanel.tsx`）；本地存档不显示在线 / 离线徽标。
  - 不需要登录，也不依赖模块开关；文件只用于解析展示，后端不保存。
  - **本地存档独有的属性**（`PlayerLook` 的 `saveVersion` / `gameVersion` / `difficulty` / `playTimeTicks` /
    `golferScore` / `deathsPve` / `deathsPvp` / `lastSaved` / `buffs` / `researchedCount` / `spawns`，
    只在 `.plr` 里填，`/pm/look` 不提供）：
    属性区会多显示**版本**（由存档版本号映到游戏版本，表见 `web/src/lib/save/playerVersions.ts`）、
    **模式**（软核 / 中核 / 硬核 / 旅途）、**游戏时间**（固定 `HH:MM:SS`，小时不封顶）、**Golf 分数**、
    **死亡**（PVE+PVP，为 0 时不显示）、**最后保存**（存档里是 UTC，显示时换成本地时区 `YYYY-MM-DD HH:mm`），
    以及**当前 BUFF**（图标 + 剩余时间 `m:ss`，名字看 tooltip）、**已研究 N 种**（研究进度段的条数；
    尾部结构读不出来时不显示）。属性区下方还会按世界列出**重生点**（`.plr` 按世界分开存；没有设床就不出现，
    实测本机 112 份真实存档都是 0 条）。
    属性行按语义**成对排两列**（生命/魔力、模式/版本、游戏时间/最后保存、Golf/渔夫任务…），
    容器宽度不足 260px 时自动退回一列（用 `@container`，与视口无关）。
    渔夫任务数是存档里的真值（以前本地存档恒显示 0）。导出图片走同一套属性行（`hooks/usePlayerShot.ts`），不含 BUFF 图标。
    **三套配装**（1.4.3 / release ≥262 起）也会读出来并按 TShock 的 260–349 槽渲染（空配装不显示）。
    仍未读的字段（研究进度**明细** / 配装编辑 / 临时槽 / 创意能力 / 声音）见 `docs/TODO.md` P7。
  - 「简约视图」在导入后出现在工具行右侧。
  - **编辑并另存**（工具卡「编辑」按钮，仅本地存档；设计见 [`计划-plr编辑.md`](计划-plr编辑.md)）：
    可改**生命 / 魔力（含上限）/ 渔夫任务 / Golf 分数 / 模式 / 存档版本 / 背包 58 格（物品 + 数量 + 词缀）/
    装备区 40 格（装备 20 / 染料 10 / 杂项装备 5 / 杂项染料 5，只换物品与词缀，装备格不存数量）/ **随身仓储 160 格（猪猪 / 保险箱 / 熔炉 / 虚空袋，各 40，物品 + 数量 + 词缀）** /
    **三套配装 90 格（每套 20 装备 + 10 染料；1.4.3 / release ≥262 起才有）** / 永久增强**；
    编辑面板里「背包 58」「装备区 40」常显，**「随身仓储 160」「配装 90」默认收起**（点标题展开，标题上带件数），
    一次铺 348 个格子会把属性区挤没；保存时在浏览器里**就地打补丁后重新加密**（`lib/save/plrWrite.ts`），产出新文件直接下载，
    **原文件与 `.plr.bak` 都不动，也不上传服务器**。
    - 校验口径与游戏一致：数量 ≤ `Item.maxStack`（新数据 `data/item-limits.json`）、词缀必须 ∈
      `Item.GetRollablePrefixes()`（`data/prefix-sets.json`）、`ItemsThatShouldNotBeInInventory` 的物品拒绝、
      生命上限 500 / 魔力上限 200、版本只能在同一字段布局段内改（`lib/save/plr.ts` 的 `releaseSegment`）。
    - 只校验**改动过**的槽位：玩家存档里原有的历史词缀不会被标红（游戏自己会在加载时按当前规则处理）。
    - **永久增强的可用性由存档版本决定**（字段是随游戏版本逐批加进 `.plr` 的）：恶魔之心 ≥125、
      火把神 ≥229、矿车升级包 ≥253、工匠面包 ≥256、6 个消耗品 ≥260。更老的存档（如 1.4.0.2 = release 226）
      只有恶魔之心，其余项置灰并在标题旁说明「用新版游戏把角色存一次（存档随之升级）后就能改」。
    - 研究进度 / 配装 / 银行 / 退款队列等字段原样保留（不重写整份存档）；`.plr` 的**垃圾桶不存**，编辑器里也没有它。
  - 上次导入的结果存在**内存缓存**里（`lib/playerPage.ts`，按 transport + serverId），切页面回来还在，刷新页面清空。
  - **导出图片**（两页都有）：把**人物全身图 + 属性 + 永久增强 + 背包 / 装备**画成 PNG 下载，见 §4.1。
- 左组·背包簇（仿游戏）：
  - 背包主格 0–49（10×5）；钱币 50–53、弹药 54–57 各一列放在主格**右侧**（列间隔 `gap-x-1`），
    钱币+弹药作为一个整体，窄屏时**一起**换到背包下一行；
  - 垃圾桶用 TShock 槽 179，放在主格**右下角**（第 10 列正下方），空格时显示半透明垃圾桶图标；
  - 槽 58（游戏里 `inventory[58]`，鼠标手持的临时槽）不展示。
- 右组·装备区：两组、整体**居左**；**B 组在左**（染料 94–98 / 工具 89–93），
  **A 组在右**（染料 79–88 / 时装 69–78 / 装备 59–68）；组内列间隔 `gap-x-1`，两组之间 `gap-x-2`。
  （即 `players.group.miscDye` 标题显示为「染料」、`players.group.miscEquip` 为「工具」）
- 右组·配装：每个配装是 **3 列**（染料 / 时装 / 装备，各 10 格，顺序与 tooltip 跟随装备区 A 组），
  3 个配装**并列**在一起（块间隔 `gap-x-2`）。
- 左组·银行（背包下方）：标题前带物品图标（猪猪 87 / 保险箱 346 / 护卫熔炉 3813 / 虚空袋 4131）。

  标题左侧 chevron 展开/收起；折叠状态存 `StorageKeys.playersCollapsed`。

  使它们的**格子行**与配装块的格子行在**同一水平线**上（配装块标题行多一行）。实测四者 slot_y 一致。
- 槽位：**实线、半透明**底框（`border-muted-foreground/40`；空格子与有物品都画，图标压在底框上）；
  悬停时整格微微上移并加深边框/底色。
- 空格子 tooltip：**shadcn/Radix `Tooltip`**（`components/SlotTooltip.tsx`；原生 `title` 在带位移的格子上常常弹不出来）：
  背包 / 仓储显示 `#N`（1 基）；装备 头盔/上衣/裤子/配饰#n；时装 头盔/上衣/裤子/社交 配饰#n；
  两列染料都显示 `染料#n`；工具列 宠物/照明宠物/矿车/坐骑/抓钩；垃圾桶 显示「垃圾桶」；
  **钱币 / 弹药不显示 tooltip**。有物品的格子仍用 `ItemIcon` 的富提示（`ItemTooltip`，自研、游戏同款）。
- 恶魔之心：`extraSlot=false` 时，装备区 / 配装的 染料·时装·装备 三列最下面一格（额外配饰槽）**半透明**
  （即使有物品也半透明）。
- 结果头部：**角色总览** = 左侧全身图（透明背景，无底框）+ 右侧（用户名（`text-lg`）+ 在线/离线徽标（本地导入不显示徽标） + 生命/魔力/渔夫任务/重生点 + 永久增强），
  整组占内容区**一半宽度**（容器 <820px 时改占满整行）；属性区左侧留间隔、名字与属性行拉开，整体高度与人物相近；
  下方用 `Separator` 与背包/装备区隔开。
  全身图 `components/PlayerAvatar.tsx` 只画皮肤/衣服/头发，不含盔甲饰品；数据取 `/pm/look` 的外观字段，
  贴图懒加载 `data/player-atlas.*`。层级/帧与着色见 [`计划-玩家全身图.md`](计划-玩家全身图.md) §6。
  属性行用 `dl`：标签 muted、数值加重 + `tabular-nums`，上限/单位弱化；永久增强图标 `flex-wrap`，过多自动换行。
- 永久增强类（含恶魔之心 / 火把神 / 矿车升级包）**只显示物品图标**（名字看物品 tooltip；已用/未用用 `opacity-40` 区分），
  代码上统一在 `lib/playerBoosts.ts` 的 `PERMANENT_BOOSTS`（解锁项 + 消耗品），页面与导出图片共用同一顺序。
- 探测：登录后、切换服务器后自动重探（`serverId` 变化触发）。
- 首页「我的背包」卡片（`/lookbag <当前登录用户>`）：探测到插件未安装 → 卡片隐藏、「管理卡片」里标「缺少插件」，
  也不再参与自动刷新；若探测不出结果（如网络抖动），执行返回 `command_not_found`（指令不存在）同样会隐藏。
  其它依赖插件的首页卡片（如 `/worldinfo`、`/bossinfo` 依赖 WorldModify）走同一套规则。
- 界面状态（上次输入的玩家名、最近查询列表）按 `serverId` 记忆在 `tswui:moduleState`。
- 探测结果与上次的背包存在**内存缓存**（按 transport + serverId）：侧栏切到别的模块再回来不重新探测/拉取，直接显示上次结果；「刷新」按钮手动重拉。刷新页面缓存清空；登出会清掉该服务器缓存（权限随用户组变化）。

### 4.1 导出图片（截图）

- 按钮：**顶栏右侧的「导出图片」图标按钮**（`ImageDown`，没有导入/查看角色时不显示），两个页面共用 `hooks/usePlayerShot.ts`；「查看存档」页还有顶栏「简约视图」与页面内「导出 .plr」。
- 实现：`web/src/lib/playerShot.ts`（纯布局 + canvas 绘制），角色图复用 `lib/playerAvatarDraw.ts`
  （与 `PlayerAvatar` 同一份绘制代码），物品图标复用 `lib/iconScale.ts` 的尺寸规则。
  **不截 DOM**：页面里的角色图与物品图标都是 `canvas`，`html2canvas` / SVG `foreignObject` 都画不出来；
  直接在 canvas 上重画一遍，不引入新依赖、也不受主题滚动影响（配色读当前主题 CSS 变量）。
- 版面（`buildPlayerShotLayout`，纯函数、有单测）：名称 + 状态（在线 / 离线；本地存档为空）→
  人物全身图（160×224，与页面同一个 4×） + 属性行（生命 / 魔力 / 渔夫任务 / 重生点；本地存档另加
  版本 / 模式 / 游戏时间 / Golf / 死亡 / 最后保存） →
  背包 10×5（垃圾桶在主格第 10 列下方，空格子画垃圾桶图标、**不写标题文字**）+ 钱币 / 弹药列 →
  装备区五列（染料 / 工具 / 染料 / 时装 / 装备）。
  与「简约视图」一致，**不含银行与配装**。
- 输出：`2×` 像素比的 PNG（宽度约 536 CSS px），文件名 `<玩家名>.png`（非法字符换成 `_`）。
- 画布内的格子间距 / 图标缩放与页面一致（格 36px、`game` 模式只缩不放），空格子也画底框。
- 永久增强图标已入图（标题 + 一排 20px 图标，未使用的 40% 透明）；人物图**透明背景、不画底框**；物品名 / tooltip 不导出（图里只有图标 + 数量）。

## 5. 数据字段

`/pm/look` 的 `inventory` 是 `NetItem` 数组用 `~` 连接，每格 `netId,stack,prefixId,favorited`：

| 上游 | 本仓库（`PlayerItem`） |
| --- | --- |
| `netId` | `id`（0 = 空格） |
| `stack` | `stack` |
| `prefixId` | `prefix` |
| `favorited`（`1`/`0`） | `favorited`（bool） |

槽位顺序（共 350）：背包 59 / 装备 20 / 染料 10 / 杂项装备 5 / 杂项染料 5 / 猪猪 40 /
保险箱 40 / 垃圾桶 1 / 熔炉 40 / 虚空袋 40 / 三套配装各 30（20 装备 + 10 染料）。
单格格式异常时按空格处理，绝不因一格丢弃整份数据。

## 6. 权限与限购

- 只有 `playermanager` 权限：**查看与导出同权**（插件当前不拆分）。
- 无 `permission` 时模块开关禁用，并提示让服主给用户组加 `playermanager`。

## 7. 已知限制 / 坑

- 这是**管理员/服主能力**：拿到权限即同时能 look 与 export。
- 导出走附件流，前端用 object URL 触发下载（能带上 `X-TSWUI-Target` 头）。
- 中文玩家名文件名用 RFC 5987 编码（`filename*=UTF-8''...`）。

## 8. 验证命令

```bash
# 探测（需会话 Cookie）
curl -s http://127.0.0.1:18080/api/player/capabilities
# 查看背包
curl -s 'http://127.0.0.1:18080/api/player/look?name=hf'
# 下载存档
curl -s -OJ 'http://127.0.0.1:18080/api/player/export?name=hf'
# 导入 .plr 没有后端接口：在页面里选文件即可（离线 / 未登录都能用）
```
