# 合成表与物品提示（Recipes & Item Tooltip）

文档版本：1.0
对应页面：`web/src/pages/ItemsPage.tsx`（导航「物品图鉴」）
对应组件：`web/src/components/RecipePanel.tsx`、`web/src/components/ItemTooltipContent.tsx`、`web/src/components/ItemIcon.tsx`
相关数据：`data/recipes.json`、`data/item-stats.json`、`data/item-tips.<culture>.json`（见 `data/README.md`）
相关脚本：`tools/gen-game-data.sh`、`tools/gamedump/`、`tools/gen-recipes.mjs`、`tools/gen-item-stats.mjs`

> 本文件记录「物品图鉴 → 本地合成表」与「悬停物品图标 → 游戏同款属性提示」的**数据来源、字段语义、
> 生成方式与验收方法**。所有事实均给出源码出处，禁止臆测。

---

## 1. 定位与范围

- **合成表**：在物品图鉴里直接展示「怎么合成该物品」与「该物品能合成什么」，**不再依赖**服端
  `/r`（查一查插件）指令，也不需要登录。
- **物品提示**：鼠标悬停任意物品图标时，弹出游戏同款的属性提示（伤害、暴击率、击退、防御、镐力……）。
- **不在范围**：嬗变（微光）全量表（`ShimmerTransforms`）、物品商店、管理员后台。

## 2. 事实来源（务必以源码为准）

| 事实 | 出处 |
| --- | --- |
| 全部配方由 `SetupRecipes()` 命令式构建 | `TR_SRC/Terraria/Recipe.cs:604`（604–15161）+ 辅助方法 15260–16794 |
| 配方结构：`createItem` / `requiredItem[15]` / `requiredTile` / `acceptedGroups` / 环境标志 | `Terraria/Recipe.cs` |
| 配方组定义（34 个） | `Terraria/Recipe.cs:497` `SetupRecipeGroups()` |
| 配方索引：产出与材料倒排 | 由导出数据自行建立（`byResult` / `byIngredient`） |
| 制作站 = `requiredTile`（图格 id），图标由图格反查物品 | `Item.createTile` |
| 工具提示行顺序与文案 | `TR_SRC/Terraria/Main.cs:20852` `MouseText_DrawItemTooltip_GetLinesInfo()` |
| 物品名颜色（稀有度） | `Terraria/Main.cs:20778` `MouseText_DrawItemTooltip_GetItemNameColor()` |
| 暴击显示 = 玩家基础 4% + 物品 `crit` | `Terraria/Player.cs:2413`（`= 4`）、`Player.cs:25710`（`+= inventory[selectedItem].crit`） |
| 稀有度颜色 / 速度 / 击退档位 | `Terraria/Main.cs` 同上 |
| 状态：1.4.5.8，TShock/OTAPI 构建产物与 `TR_SRC` 版本一致 | `tools/gamedump` 运行时读取程序集版本 |

**为什么用运行时导出而不是纯文本解析**：`SetupRecipes()` 含大量 `if(type…)` 区间、`for` 循环与
`AddXxxFurniture()` 辅助方法；`Item.SetDefaults()` 更是 5 个巨型 `switch`。直接调用游戏自身代码
（TShock 的 OTAPI 程序集）可以**零偏差**地拿到最终配方与属性；纯文本复刻在反向（拆解）配方与
`Item.createTile` 上极易出错（详见 §6 备选方案）。

## 3. 数据生成

```bash
# 需要 dotnet 9 SDK（首次自动从 NuGet 还原 TShock 6.2.1 / OTAPI）
bash tools/gen-game-data.sh
#   -> data/recipes.json
#   -> data/item-stats.json（stats）
#   -> data/item-tips.zh-Hans.json / data/item-tips.en-US.json（tip 行）
```

环境变量：

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `TR_SRC` | `<仓库>/../tr-code-1458` | 反编译源码（配方组正则、本地化文案） |

`tools/gamedump` 通过 NuGet `<PackageReference Include="TShock" Version="6.2.1" />`
（→ `TSAPI` → `OTAPI.Upcoming`）引用 `OTAPI.dll`，不写死本机路径；构建与运行均零外部 DLL 依赖。

`tools/gamedump/Program.cs` 做三件事：最小静态环境初始化（`Program.SavePath` / `Main.rand` /
`Main.player[0]` / `Main.recipe` 数组）→ 注册配方组并跑 `Recipe.SetupRecipes()` → 遍历导出配方与
`Item.SetDefaults()` 属性。为什么需要这些初始化：见 `GameDump.cs` 注释。

## 4. 数据契约

字段定义见 `data/README.md` 的「文件」章节与 `web/src/types.ts`（`RecipesData` / `ItemStatsData`）。

关键约束：

- `ingredients[].group` 存在时，`id` 只是占位物，实际可用 `groups[group].items` 中任意一种。
- `station = -1` 表示徒手；否则 `stationItems` 是可用于显示图标的代表物品。
- `tip` 行**不含物品名**（名称由前端按稀有度着色渲染）。
- `tip` 不含前缀对比、专家世界提示、召唤栏数量等玩家/世界相关行；伤害与暴击为物品基础值。

## 5. 前端行为与验收

- **悬停提示**：`ItemIcon` 通过 `DatasetContext` 读取 `itemStats`，portal 到 `body`（避免被滚动容器裁切），
  内容为 `ItemTooltipContent`（名称按稀有度着色 + 当前语言的 `tip` 行）。`tooltip={false}` 的图标不显示，
  避免提示内嵌图标递归。
- **详情面板**：选中物品后展示同一份 `ItemTooltipContent`（`variant="panel"`）。
- **合成表**：`RecipePanel` 渲染
  - `byResult[itemId]` → 「合成获得（n）」
  - `byIngredient[itemId]` → 「用于合成（n）」
  - 每行：材料（配方组显示「任何XX」）`→` 结果 `@` 制作站；环境/阵营以小标签展示。
- 无配方也无用途时显示「无合成配方，也不是合成材料。」

验收命令：

```bash
cd web && npm run typecheck && npm run lint && npm run test:run
# 端到端：启动后端后，用 Chrome CDP 探测（见下方「人工验证」）
```

人工验证（本机）：`cd server && WEB_DIST_DIR=../web/dist TSHOCK_URL=http://127.0.0.1:7878 go run .`
后访问 `/`，「物品图鉴」搜索「天顶剑」应显示 `190近战伤害 / 14%暴击率 / 普通速度 / 较强击退力`，
合成表行应显示 10 把剑 + 秘银砧 → 天顶剑。

已核对的样例（与游戏一致）：

| 物品 | 提示行 |
| --- | --- |
| 天顶剑(4956) | 190近战伤害 / 14%暴击率 / 普通速度 / 较强击退力 |
| 铁镐(1) | 5近战伤害 / 4%暴击率 / 很快速度 / 很弱击退力 / 40%镐力 |
| 叶绿面具(1001) | 可装备 / 20防御力 / 近战伤害提高16% / 近战暴击率提高6% |
| 火把(8) | 可放置 / 材料 / 可接线 / 提供照明 |

## 6. 备选方案（未采用）

`tools/` 的纯 Node 文本解释器原型（不在本仓库主流程）：可复刻 3603 条配方中的 3292 条，缺的 311 条
是 `CreateReversePlatformRecipes` / `CreateReverseWallRecipes` 生成的**反向（拆解）配方**，依赖
`Item.createTile` / `createWall`，而 `Item.cs` 的区间分支与 `default:` 分支难以可靠解析。
若将来要摆脱 dotnet/OTAPI 依赖，需要先补全 `Item.cs` 解释器。
