# 功能 · 地图分析（世界存档内容统计）

> 「查看世界」页在缩略图与世界信息下方多一块「地图分析」。纯本地统计，不读 TShock、不上传。
> 参考粒度：TEdit 风格的 `wukong Analysis.txt`（版本 / 段 / 图格占比 / 箱子 / 招牌 / NPC / 实体）。

## 1. 显示什么

| 区块 | 内容 |
| --- | --- |
| 概览 chips | **空气占比**（分母 = 世界总格数 = 宽 × 高）、**水 / 岩浆 / 蜂蜜 / 微光**格数（只显示 > 0 的）、**箱子 / 招牌 / 城镇 NPC / 图格实体**数量 |
| **分层** | 地表 / 地下 / 洞穴 / 地狱四层：每层的 y 范围、**空气占比**、岩浆量（如有）、以及该层占比最高的 3 种方块；比例条画的是「非空气占比」 |
| 图格占比 | 按格数降序，默认 12 行；每行「名字 · 数量 · 占比」+ 比例条；> 12 种时给「展开全部 N 种」 |
| 墙体 | 默认折叠（点标题展开），同样按格数降序取前 12 |
| 箱子里的物品 | 物品 id 合并后的总数量 Top 12 |

**下钻（点开明细）**：概览里的「箱子 / 招牌 / 城镇 NPC」是可点的，点开弹窗看明细：

- 弹窗顶部有**搜索框**（箱子按物品名 / 箱子名，招牌按文本，NPC 按名字），下方显示「匹配 N / 总数」；
- **箱子**：逐箱 `[x, y] · 箱子名` + 非空内容（词缀名 + 物品名 + `×数量`），空格子不列；
- **招牌**：位置 + 全文（保留换行）；
- **城镇 NPC**：类型名 + 名字 + 站位 + 家（无家可归时标注）。

「图格实体」只有数量（段内是各类型自定义结构，暂不解析）。

**导出分析**：卡片右上「导出分析」下载 `<世界名>-analysis.txt`，分节格式对齐参考件
（`===SECTION: World/Tiles/Walls/Zones/Liquids/Chests/Signs/NPCs/Tile Entities===`），
其中 `Zones` 每层一行（y 范围、格数、空气数与占比、水/岩浆、占比最高的 3 种方块），箱子是逐箱逐格列出。

## 2. 数据来源与口径

| 数据 | 来源 | 说明 |
| --- | --- | --- |
| 图格 / 墙 / 液体格数 | `lib/save/worldThumb.ts` 的**解码循环** | 与缩略图**同一次解码**顺手累加，不额外扫 2000 万格；RLE 的每一格都算（`cells = min(rle+1, height-y)`） |
| 空气 | 同上 | 「没有图格」的格数；只有墙 / 只有液体的格也算空气（与 TEdit 报告一致） |
| 分层 | 同上 | 边界：地下起 = `worldSurface`（`groundLevel`）、洞穴起 = `rockLayer`（`rockLevel`）、地狱起 = `height - 200`（游戏常量）；**RLE 跨层会被切开分别计入**；边界重合时该层为 0 格（不硬塞） |
| 箱子数 + 箱子物品 + **逐箱明细** | `SaveChests` 段：`int16 数量` + **`< 294` 时先有一个共享 `int16` 容量** + 每箱 `x,y,name[,≥294: int32 maxItems]` + `maxItems×(int16 stack; =0 空槽；≠0 → int32 type, u8 prefix)` | 数量是**实际箱子数**；物品按 `type` 合并累加 `stack`（`stack < 0` 表示「1 个但带词缀」，按 1 计）；明细只保留非空格子 |
| 招牌数 + **文本明细** | `SaveSigns` 段：`int16 数量` + 每块 `text,x,y` | 文本直接展示 / 导出。存档里可能有**残留记录**（墓碑被挖掉后记录还在），游戏 `LoadSigns` 会丢弃这类记录，我们照原样展示 |
| 城镇 NPC + **明细** | `SaveNPCs` 段：`[≥268: int32 n + n×int32]` + `bool` 循环（类型/名字/坐标/家/flags）+ 第二个 `bool` 循环 | 明细只含「有名字和坐标」的；微光化的只计入数量 |
| 图格实体 | `SaveTileEntities` 段的首个 `int32` | 只读数量，不解析各实体内容 |

段位置全部来自 `parseWorld(bytes, track)` 记录的**段指针表**（`track.pointers[i]` = 第 i 段结束位置）。
某段指针异常 / 读不懂时，**只有那一项显示为缺失**（`null`），不会让整块分析失败。

图格 / 墙的**显示名**取「代表物品」的官方本地化名，拿不到再回退常量名
（`data/tiles.json` / `walls.json` 的 `item` 字段；等价于游戏 `Lang.GetMapObjectName(...)` 的常见情形）。

## 3. 与参考报告的差异（有意为之）

- 参考报告是**一次性全文平铺**（几千行，难读）。我们默认只给**汇总 + Top 列表**，
  明细放在「点数量 → 弹窗」里按需看；需要全文时用「导出分析」得到那份 txt。
- 占比统一以**世界总格数**为分母（与参考一致），不是「非空气格数」。
- 不做贴图渲染列（参考报告是纯文本）。

## 4. 性能

统计与缩略图同一次解码，**额外开销接近 0**（每格 3 次 Map 自增）。
实测大世界（8400×2400 = 2016 万格）解码约 0.15 秒量级，内存只多了几个几百项的 Map。

## 5. 测试

  箱子 2、招牌 1、NPC 2、实体 3、箱子物品 29→5 / 75→99）；RLE 重复计数；真实 demo 世界
  「空气 + 图格 = 总格数」不变量；NPC 段截断 → `null`；段指针越界 → 只降级该项。
- `components/world/WorldAnalysis.test.tsx`：渲染、排序、名字回退、折叠展开、`null` 项隐藏、
  点箱子/招牌开明细、图格实体不可点、导出触发下载。
- `lib/save/worldAnalysisText.test.ts`：导出文本的分节、占比格式、**分层行**、逐箱内容（含词缀）、
  招牌多行压一行、NPC 位置与家、缺段占位 `-`、文件名清洗。
- 分层用例：合成世界（20×240，`groundLevel=20`/`rockLevel=100`）断言每层格数与跨层 RLE 拆分；
  真实 demo 世界断言「各层格数之和 = 总格数」「各层空气之和 = 空气总数」。
- 测试夹具 `test/worldFile.ts` 现在会写**真实的箱子 / 招牌 / NPC / 图格实体段**，不再用桩数据。
