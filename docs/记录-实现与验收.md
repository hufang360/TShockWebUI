## 1. 目标（Definition of Done）

1. 仓库根 `Dockerfile` 能构建出**单容器镜像**，`docker run` 后浏览器可完成：登录 → 看到状态 → 执行一条允许的指令 → 看到真实输出。
2. 镜像 `docker images` 体积 ≤ 30MB（目标 ~12MB）。
3. 浏览器不再持有 TShock token；密码只出现在 `POST /api/login` 的 body。
4. 容器只暴露一个端口；`http://IP:8080` 可直接用。
5. Go 与前端测试全绿；`go vet` 无告警。

## 2. 任务清单

### T1. 前端构建改为根路径，并预留 API 代理
- 文件：`web/vite.config.ts`
- 改动：
  - `base` 固定 `/`（去掉 `/tr/` 与 `VITE_BASE` 分支；如需子路径再议）。
  - 增加 `server.proxy`：`'/api' → http://localhost:8080`。
- 验收：`cd web && npm run build` 产物 `index.html` 引用 `/assets/...`；`grep -c '/tr/' dist/index.html` 为 0。

### T2. 前端传输层重构（BackendTransport）
- 文件：`web/src/lib/tshock.ts`（拆分建议：`transport.ts` + `httpTransport.ts` + `mockTransport.ts`）
- 改动：
  - 按 `API_SPEC.md` 第 8 节定义 `BackendTransport` 接口。
  - 实现 `HttpTransport`（`fetch`，`credentials: 'same-origin'`，`X-Requested-With: tswui`）。
  - `MockTransport` 实现同一接口；`VITE_TRANSPORT=mock|http` 选择，默认 `http`。
  - 删除前端 `classifyTshockError`（错误分类改由后端承担）；保留把 HTTP 错误映射为 `CommandResult`/抛错的薄层。
- 验收（新增 vitest，用 `fetch` mock）：
  - `login` 401 → 抛 `auth`；403 → `permission`；429 → `rate_limited`。
  - `runCommand` 200 body → 原样 `CommandResult`。
  - `serverStatus` 网络失败 → `{reachable:false}`（不抛）。
  - `cd web && npm run test:run` 全绿。

### T3. 前端登录/会话状态改造
- 文件：`web/src/App.tsx`、`LoginDialog.tsx`、`PlayerStatus.tsx`、`hooks/useLocalState.ts`、`lib/storage.ts`、`types.ts`
- 改动：
  - 启动调 `GET /api/session` 决定登录态；`tswui:auth` 废弃（含 token 的旧数据要清理）。
  - 只保留 `tswui:me = { username, savedAt }` 作为渲染缓存。
  - 登录/退出通过 `POST /api/login`、`POST /api/logout`。
  - 移除任何把 token 写入 localStorage 的代码。
- 验收：
  - `grep -rn "tswui:auth\|token" web/src/lib/storage.ts` 说明已无 token 持久化。
  - Mock 模式 App 冒烟测试仍通过（`web/src/App.test.tsx`）。
  - 真实模式（后端在跑）手动：登录→刷新仍登录→退出后刷新为未登录。

### T4. Go 后端骨架：静态资源 + 配置 + 健康检查
- 文件：`server/go.mod`、`server/main.go`、`server/internal/config/config.go`、`server/internal/webdist/.gitkeep`
- 改动：

  - `main`：`http.ServeMux`；`//go:embed all:webdist` 提供 `/`、`/assets/`、`/data/`；未命中回退 `index.html`。

  1. `http://localhost:8080` 打开、数据加载、无 console 错误。
  2. 登录成功，刷新后仍登录（Cookie 会话），重启容器后需重登（符合预期）。
  3. `/api/status` 显示真实世界名与 `1.4.5.8`（**无前导 v**、无版本告警）。

  5. 输入 `/i 29` → 前端直接提示「只能在游戏内执行」，**不发请求**。
  6. 手动删除会话（或重启容器）后执行 → 回登录，token 失效被识别。
  7. 浏览器 devtools 中检查：localStorage 无 token；请求里无密码 URL；Cookie 为 HttpOnly。

## 6. 已知坑（务必看）

1. **TShock 登录必须用 query string**：`POST` 表单体不解析（500）。见 `TECHNICAL_RESEARCH.md` 2.2 / 2.9。
2. **版本号带前导 `v`**：`v1.4.5.8`。后端必须规范化后返回。
3. **限流按来源 IP**：容器/反代后所有玩家共用一个桶；默认 5/分钟。上线前调大阈值。
4. **`EnableTokenEndpointAuthentication=true`** 时 `server/status` 需 token；`/api/status` 要兼容无 token。
5. **容器内 `127.0.0.1` ≠ 宿主机**：本机调试用 `host.docker.internal`（Mac）或 `--network host`（Linux）。
6. **`//go:embed` 目录不能为空**：`server/internal/webdist/` 需有占位文件，否则编译失败。
7. **distroless 无 shell**：调试用 `:debug` 变体或临时换 `alpine`。
