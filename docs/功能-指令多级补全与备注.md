# 功能：指令多级补全与取值备注

文档版本：1.0
相关代码：`web/src/lib/commandMeta.ts`（**手工维护的唯一入口**）、`web/src/lib/completion.ts`（补全逻辑）、
`web/src/lib/dataset.ts`（`withCommandMeta` 合并）、`tools/gen-data.mjs`（核心指令与单层用法串）
相关测试：`web/src/lib/commandMeta.test.ts`、`web/src/lib/completion.realdata.test.ts`

> 目标：让补全下拉框不仅给出参数值，还能说明它是什么；并把 TShock 生成器提取不到的
> **多级子命令**（如 `/worldevent invasion <入侵类型>`、`/pm export <玩家名>`）補全出来。
> 本文同时列出核心指令与 PM / WM / Fish 插件的二、三级子命令含义，方便后续维护。

## 1. 配置在哪、怎么加

所有需要手工维护的内容都在 **`web/src/lib/commandMeta.ts`**，只有两处：

| 配置 | 作用 | 什么时候用 |
| --- | --- | --- |
| `LABELS[指令名][取值] = { zh, en }` | 补全下拉框里显示在取值下面的**备注名** | 给某个枚举取值 / 子命令加中文名 |
| `EXTRA_PARAM_SETS[指令名] = [cmd(...)]` | 追加 / 覆盖**参数形态**（多级子命令） | 生成器没提取到、或要手工纠正时 |

要点：

- **指令名用规范名**（小写、不含 `/`）。TShock 核心指令就是它的名字；插件指令用插件注册名：
  `playermanager`（不是 `pm`）、`worldmodify`（不是 `wm`）、`fishshop`（不是 `fish`）。
- `cmd(显示用指令名, '子命令', [后续参数])` 会生成用法串与首参 `literal`；后续参数按 `CommandParam` 写：
  `kind` 决定候选来源（`player` / `item` / `npc` / `buff` / `enum` / `region` / `warp` / `number` / `text`…）。
- 第 4 个参数是可选说明 `{ zh, en }`，会拼在**参数提示行**后面，用来说明「不加参数」时的含义，
  例如 `cmd('fish', 'jar', [...], { zh: '不加参数 = 查看鱼罐', en: 'no arg = view jar' })`。
- 合并规则：运行期由 `dataset.ts` 的 `withCommandMeta()` **按 `syntax` 覆盖**同名形态（幂等）。
  所以重复写同一个 `syntax` 只保留最后一条，可用来覆盖生成器的结果。
- **字面量子命令会自动进补全**：`completion.ts` 的 `computeLiteralCompletions()` 会把当前层所有匹配形态的
  `literal` 都列出来，并附上 `LABELS` 里的备注名。
- 加完后跑 `cd web && npm run typecheck && npm run test:run`；`commandMeta.test.ts` 的
  「真实数据覆盖度」用例会检查**所有 TShock enum 取值都有备注**。

示例（给 `/worldevent invasion` 的第 3 级加补全）：

```ts
worldevent: [
  cmd('worldevent', 'invasion', [
    { name: 'invasion type', required: true, kind: 'enum',
      values: ['goblins', 'snowmen', 'pirates', 'pumpkinmoon', 'frostmoon', 'martians'] },
    { name: '入侵波数', required: false, kind: 'number' },
  ]),
],
```

## 6. 补全下拉框里的「指令用法」

指令用法**只有一处**：补全下拉框顶部那条「指令帮助」条（`role="note"`，在滚动区之外）。
以前输入框上方还有一行 `/xxx <args>` 小字，两处重复而且常驻占高度，现已并入下拉框（`getParamHint` /
`paramHintFor` 一并删除）。数据全部来自 `data/commands.json` 的 `paramSets[].syntax`（不手写、不猜）。

| 角色 | 显示什么 |
| --- | --- |
| 候选行 | **是什么**：`指令 / 别名 · 说明 / 权限`（不显示语法） |
| **幽灵文字**（输入框内、光标之后，半透明） | **接下来会输入什么**：有候选时补完当前词（`/worldevent invasion gob` → `lins `，正是 Tab / Enter 会接受的那条）；没有候选时补完用法剩下的部分（`/accountinfo ` → `<username>`），当前参数已敲具体值时只提示这一位（`[item amount]`） |
| 帮助条（弹框顶部，`role="note"`） | **完整写法** + 该形态的备注，并把**正在填的那个参数**标成主色 |

> 幽灵文字 = 终端 autosuggestion：只画在输入框里、光标后面，`aria-hidden`、`pointer-events-none`，
> 不占布局、不参与补全。它和帮助条**内容不同**（一个是「这一小段」，一个是「完整写法」），不是重复。
> **说明 / 备注不塞进输入行**（否则一行又长又吵）：它们只在下拉框顶部那条里。
> 横向滚动量在每次 `value` / `caret` 变化后用 `useLayoutEffect` 对一次 —— 只靠 textarea 的 `scroll`
> 事件会漏（删掉长指令时 `scrollLeft` 归零不一定触发），幽灵图层会整体偏左、被已输入文字盖住。
> 实现见 `components/CommandEditor.tsx` 的 `ghostText`（用不可见的已输入前缀对齐光标，再按输入框
> 的 `scrollLeft` 整体平移；光标不在末尾时不出，避免盖住后面已输入的内容）。

> **弹框只在真有候选时出现**：弹出来就得能用 ↑↓ 选。没有候选（自由文本参数、没人在线、
> 多打的第 N 个参数）时不要弹一个「没得选」的空浮层 —— `↑ ↓ 选择 / Tab 接受` 的提示与行为对不上，
> 看着就像坏了（`/worldevent invasion goblins` 就是这么被发现的）。这时用法由幽灵文字补在输入框里。

> **一处只说一件事**：同一句说明如果在帮助条和候选行里各出现一次，就是纯噪声（真踩过：`/help` 那条
> 上下两行字一模一样）。所以行内只留身份信息（指令名 / 别名 / 说明 / 权限），语法与备注只在帮助条。
- 帮助条**纯提示**：不参与 ↑↓ 高亮、点击不插入任何内容（把 `<username>` 这种占位符塞进输入框只会碍事）；
  它放在滚动区之外，翻候选时一直可见。读屏通过输入框的 `aria-describedby` 指到它。
- 「下拉框开着」的判定在**渲染与键盘处理之间必须一致**（同一个 `showDropup`），
  所以 ↑↓ / Tab / Enter 永远对应「有东西可选」；没有候选时 `Enter` 直接执行指令。
  > 回归记录（两次都踩在同一个地方）：帮助行上线初期渲染侧算「开着」、键盘侧按 `items.length > 0` 判，
  > 「只有帮助条」时按 ↓ 掉进历史回翻 → 输入框被清空；再按 ↑ 取到不存在的 `history[-1]`（`undefined`）
  > 写回输入框，页面 `text` 变 `undefined` 后报错。现在两边同一个条件，历史回翻夹在 `[-1, len-1]`。
- 历史回翻**记住草稿**：第一次进入回翻（↑ 或 ↓）时把输入框内容记下来，↓ 回到「未在选择」时原样还原
  （以前会写回空串，等于把正在敲的指令吞了）。
- 价值在于「参数位没有值候选」的场合：`/accountinfo <username>` 没人在线时、`/clear <number>` 这类自由文本参数，
  下拉框以前直接不弹（`computeCompletions` 对严格取值位返回空），现在至少能看到这条指令该怎么写。
- 多个形态的指令（`/group` 10 条、`/itemban` 4 条…共 8 条）**只显示匹配到的那一条**并加 `…`；
  完整清单在「指令小抄」的详情抽屉里（见 [`页面-指令小抄.md`](页面-指令小抄.md)）。
- 没有参数的指令（95 条里 25 条）：帮助条只给 `/指令名`（没有参数可写），行内照常是别名 + 说明，
  幽灵文字也不补（没有下一段可补）。
- 说明文字优先取**该形态自己的备注**（`paramSets[].noteZh/noteEn`，如「分页，默认第 1 页」），
  没有就退回**指令的帮助文本**（`helpZh/helpEn`）——像 `/accountinfo` 这种一句说明的指令不会只剩一串语法。
- 输入变化时高亮会拉回第一条（`highlight` 复位依赖 `value`，不只是候选条数），否则同样长度的一批候选里
  高亮会停在上一条指令上，帮助条就预览到别的指令去了。
- 实现：`lib/completion.ts` 的 `commandSyntaxArgs()`（帮助条的参数部分）、
  `commandHelpLine()`（参数区用法 + `argName` / `argRequired`）、`splitSyntaxArg()`（切出当前参数供高亮）、
  `completionSnippet()`（幽灵文字补的正是它），经 `hooks/useCommandEditing.ts` 的 `getHelp` 传进编辑器；
  指令阶段的用法由编辑器读高亮候选的 `label` + `syntax` 拼成。

## 7. 注意与限制

- 上表来自**本机源码**，不是从测试服务器实时拉取；插件升级后以插件源码 / 游戏内 `/xx help` 为准。
- 插件指令的**名称 / 别名 / 帮助文本**由自研信使插件在运行期提供（`/webui/commands` →
  `transport.runtimeCommands()`），补全里的指令帮助行会显示它们；本文件的 `EXTRA_PARAM_SETS` 只补**参数形态**。
- 目前 `EXTRA_PARAM_SETS` 只按**第一层子命令**补全；更深层（如 `/pm backup help` 的子命令）在对应
  `cmd()` 的后续参数里写 `kind: 'text'` 占位，需要时再按同样方式细化。
- **参数是「指令名」时不补**（`/help <command/page>`、`/aliases <command or alias>`，即 `kind: 'command'`）：
  一级指令玩家前面已经敲过了，空格后不再弹一屏命令名（TShock 的 `/help` 也只收一个参数，
  `Commands.cs:5351`，`/help user add` 直接报语法错，后面没有下一级可补）。
  要看二级子命令就敲 `/help user`（游戏会把 `user` 的子命令逐行列出），或看指令页的「指令库」。
