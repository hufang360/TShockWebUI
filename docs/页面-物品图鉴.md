# 物品图鉴（ItemsPage）

文档版本：1.5
对应页面：`web/src/pages/ItemsPage.tsx`（导航「物品图鉴」）
相关数据：`data/items.json`、`data/items-atlas.json`、`data/item-groups.json`
相关代码：`web/src/lib/collections.ts`、`web/src/lib/pagination.ts`、`web/src/lib/items.ts`、
`web/src/lib/dexState.ts`、`web/src/components/ui/Pagination.tsx`、`web/src/components/ui/NativeSelect.tsx`、

> 本文件描述物品图鉴页的**功能模板**：布局结构、交互规则、集合定义、复制行为、i18n 约定与验收方式。
> 集合来自 `FishShopConfig/js/search.js`，已逐条校验并固化进前端。

## 1. 定位与范围

物品图鉴是玩家侧的**只读浏览工具**：按集合/关键词找到物品，查看图标与 ID，复制 ID / 名称 / `[i:...]` 标签，
再把标签粘贴进指令编辑器。

- **不是**物品生成/商店/管理后台；本页不发起任何指令或 `/api/*` 请求。
- 图标沿用图集方案（`data/items-atlas.json` 的 `regions[item.icon]` 裁切第一帧），见 `docs/设计原则与约束.md` C10 / C11；
  **绘制尺寸与游戏一致（只缩不放，`sizeLimit=32`）+ 像素取整（放大取整数倍）**，见 `docs/功能-富文本解析.md` §6.1。
- 标签只影响聊天显示，不等同于指令参数（`docs/设计原则与约束.md` §6）。

括号内为集合内**去重后**的 ID 数量。

**数据结构**

```ts
type CollectionGroup = 'category' | 'class' | 'friend' | 'range'

interface ItemCollection {
  id: string          // `${group}:${name}`，全局唯一，用作 <select> 的 value
  name: string        // 显示名（保留原始书写，含 emoji / 省略号）
  group: CollectionGroup
  ids: number[]       // 保留原始书写顺序，仅去重
}
```

- `COLLECTION_GROUPS` 决定级联第一级的**分组顺序**：ID 范围 → 集合 → 职业 → 水友专属。
- `COLLECTIONS_BY_ID` 提供 id → 集合 的 O(1) 查找。
- `resolveCollectionItems(collection, itemsById)` 按集合内顺序解析为物品，缺失 ID 自动跳过（不报错）。

## 4. 页面模板（布局）

```
ItemsPage（高度 = 实际可用高度，页面自身不滚动）
├─ 工具条：**一张卡片**（Card > CardBody）
│   ├─ 第 1 行：搜索 Input（`SearchInput`，带清空圆钮；防抖 180ms）
│   ├─ 第 2 行：**一级模式 `ToggleGroup`**（全部物品 / 制作界面 / ⭐ 收藏）+ **「分组 / 集合」合并下拉** + 右侧**上下文控件**：
│   │   - 全部物品（默认）→ **无**（按原始顺序分页）
│   │   - 制作界面 → **创意菜单分类 Tabs**（11 个，小屏自动换行；**无「全部」页签，默认选「工具」**）
│   │   - 分组（ID 范围 / 集合 / 职业 / 水友专属）→ 右侧接一个**第二级「物品集合」下拉**
│   │   - 收藏（⭐） → 不显示上下文控件
│   ├─ 第 3 行（小字）：**快捷搜索**——左侧「最近搜索」+ 竖向分隔线 + 关键词 tag（`匣` / `宝藏袋`）；点任一个都切到「全部物品」并搜该词
├─ 结果区：**不是卡片**（直接铺在页面上，data-testid="dex-list" 的滚动容器占满剩余高度、`overscroll-contain`）
│   └─ 只渲染**当前页**的物品（默认 100 个/页）
│   ├─ 虚拟滚动：外层撑总高度，内层只挂可视行（绝对定位到 startRow）
│   └─ 每个格子：`cursor-pointer`、**无底色**；**整张卡片都会触发 tips**（不只图标画框）
│       = **64×64 图标** + 可选 **ID** 行 + 可选 **名称行（truncate）**
├─ 翻页器（底部固定，与件数小字同一行）：`共 N 件` ｜ `N 件 · 数据版本 X` + 每页个数 Native Select（50/100/200/500）+ `第 x / y 页` + shadcn `Pagination`（上一页 / 页码窗口 + 省略号 / 下一页）
└─ 详情：**右侧抽屉**（shadcn `Sheet`，默认不渲染；data-testid="dex-detail"，`w-full sm:max-w-xl`（576px））
    ├─ 标题栏（固定）：标题「物品详情」
    ├─ 中间滚动区：游戏同款 tips（`bg-black/85` 半透明黑）→ 合成表 / 用于合成 / 微光嬗变（可折叠）→ 下方居左两个勾选框（仅显示图标 / 复制含标签）
    │   └─ **空态插画**：无合成/用途/微光时，右下角放一个大号半透明工作台图标（插画感）
    └─ 底部栏（固定）：左「前往 wiki」、右「复制内容下拉 + 复制」（无图标、带描边）
```

**状态保留**：页码 / 每页数量 / **主筛选方式（`mode`）/ 集合 / 游戏分组页签** / 搜索词 / 滚动位置 / 选中项都放在 `lib/dexState.ts` 的 `DexState` 里，
卸载时写进**模块级内存**（`rememberDexState`），再次挂载即还原 —— 因此「切到其它模块再回来」状态与随机顺序都不变；
**刷新页面会清空模块内存**，于是回到默认状态（默认「全部物品」、第 1 页，默认每页 100）。
测试用 `resetDexState()` 隔离（语义上等价于刷新）。

页面高度由 `useLayoutEffect` 实测得出，两处坑都踩过并修掉：

1. **写死 `calc(100dvh-7rem)`** 比真实可用高度小 64px → 下方留一条空白。
2. **用「视口 − `rect.top`」算高度**：从其它长页面切过来时容器 `main.scrollTop > 0`，
   `rect.top` 会偏小（甚至为负，例如滚了 300px 时 `24 → -276`）→ 高度算成 `1065`（真实 765）→
   **`main` 变成可滚动**，于是在左右空白处滚轮会带着整个页面（连输入框）一起滚。
   现在改成先减掉容器滚动偏移：`可用高度 = 容器 clientHeight − (rect.top − 容器顶 + 容器 scrollTop) − padding`，
   并在挂载时把容器 `scrollTop` 复位为 0；网格滚动容器另加 `overscroll-contain` 阻断滚轮链式传递。
   `MutationObserver` 继续盯容器子元素增删（移动端顶栏 / 侧栏收起按钮 / banner）。

### 4.1 尺寸与格子样式

| 项 | 规则 |
| --- | --- |
| 图标框 | **恒定 64×64**（= `sizeLimit` 32 的 2 倍）→ `mode='game'` 下是整数 2× 最近邻放大（不糊、无 1px 虚边） |
| 格子宽 | `clamp(round((容器宽 − 8) / 10) − 8, 88, 132)` → 一行约 10 个（大屏 10 个、小屏 3~4 个） |
| 格子高 | 由两个 toggle 决定：都开 **110**、只 ID **90**、只名称 **96**、都关 **76**（内边距 12 + 图标 64 + 各自行高） |
| 间距 | 8 |
| 外观 | `rounded-xl`、**无默认底色**（不铺白底）；hover `bg-primary/10` + `-translate-y-0.5`（整体上移 2px）、选中 `bg-primary/20`（都取自主题令牌，只是加深）；整格 `cursor-pointer` + `focus-visible:ring-2` |
| 提示锚点 | 绑在**整个格子**上（`useItemTooltip`），鼠标落在 ID / 名称文字上同样弹提示 |
| 采样 | **缩小用插值**（同游戏 `LinearClamp`）、**放大用最近邻**（`lib/iconScale.ts` 的 `shouldSmooth`）——当前格子恒为 1:1，等于不重采样 |

> 之前自定义格子描边时用过 `outline` + 负 offset（保证"朝内"且不占布局）——随自定义样式一并取消，
> 现在格子外观直接由主题令牌决定，hover / 选中都不会改变尺寸。

> 实测（Chrome headless + 探针，1440×900）：格子底色 `rgba(0,0,0,0)`（**无白底**）、图标 **`64px`**、格子 `130×110`、一行 **10 个**；
> 在格子里的**名称文字**上派发 `mouseover` → 提示照常出现（整卡触发）；关掉「显示名称」→ 格高 `110 → 90`；
> **复现"先停在长页面滚 300px 再切到图鉴"**：修好后 `mainScrollTopAtMount=0`、`mainScrollable=0`、`overscroll-behavior-y: contain`；
> 点格子 → `role="dialog"`、宽 `576`（`max-w-xl`）、打开后 `main` 仍不可滚；弹框内中间区域滚动（标题 / 底部固定）；
> wiki 链接实测 `…/zh/wiki/%E7%81%AB%E6%8A%8A`（返回 200）。

## 5. 交互规则

| 场景 | 行为 |
| --- | --- |
| 默认（全部物品，无搜索） | 按**原始顺序**分页，默认**每页 100**（约 62 页）；右侧无控件 |
| 翻页 | 底部 shadcn `Pagination`：上一页 / 下一页（文字 + 图标）与页码窗口（`paginationRange`，页数多时用省略号收窄，如 `1 … 61 62 63 … 124`）；按钮 36px（`icon`/`md`，与工具栏同高），越界自动禁用；切页同时把网格滚动复位 |
| 每页个数 | 翻页器里的 Native Select：50 / 100（默认）/ 200 / **360** / 500；改动后回到第 1 页，且**跨刷新记忆**（`tswui:dex:pageSize`） |
| 当前页播报 | `第 x / y 页` 作为 `sr-only` + `aria-live` 状态，视觉上不重复（页码按钮已用 `aria-current="page"` 标识当前页） |
| 刷新页面 | 模块内存清空 → 回到默认状态（全部物品、第 1 页；每页数量跨刷新记忆） |
| 切到其它模块再回来 | 状态**原样保留**（主筛选 `mode` / 集合 / 游戏页签 / 页码 / 每页数量 / 搜索 / 滚动位置 / 选中项） |
| 输入关键词 | 在当前池子内搜索（`searchItems`，按匹配分数排序） |
| 一级模式（`ToggleGroup`） | 全部物品 / 制作界面 / ⭐ 收藏（`DexState.mode` + `favoritesOnly`）；一键切换；切换会清空第二级、回到第 1 页并复位滚动 |
| 全部物品（默认） | **右侧无控件**；按原始顺序分页展示 |
| 制作界面 | 右侧显示创意菜单分类 Tabs（**无「全部」页签**，默认选中「工具」）；按页签过滤（一个物品可属于多个页签）并按**游戏 `ByCreativeSortingId` 顺序**展示 |
| 分组（ID 范围 / 集合 / 职业 / 水友专属） | 在「分组」下拉右侧接一个第二级「物品集合」下拉（只列该分组集合）；选具体集合后池子 = 该集合条目（按集合原始顺序）；未选具体集合 = 全部物品；ID 区间在下拉里显示为 `1~1000` 这种短形式 |
| 快捷搜索 | 一级模式下方一行：左侧**最近搜索**（统一规则见 `lib/searchHistory.ts`）+ 分隔线 + 关键词 tag（`匣` / `宝藏袋`）；点任一个都切到全部物品并搜该词 |
| ⭐ 收藏 | 一级模式里的 toggle；开启时只看收藏（按收藏时间倒序），搜索只在收藏内；再点一次回到全部物品 |
| 空态 | 收藏模式且**收藏夹为空** → 「收藏夹是空的」；有记录但搜索无匹配、或其它模式无匹配 → 「没有匹配的物品」 |
| 滚动 | 网格区内部滚动；只渲染可视行（虚拟化） |
| 显示 ID / 显示名称 | **v1.3 起始终显示**（不再有开关）；格高固定 110 |
| 悬停格子 | 底色加深 + 整体上移 2px；**整个格子**（含 ID / 名称文字）悬停都会弹出同一个物品提示；**鼠标悬停有约 350ms 弹出延迟**（未到时间就移走则不弹），提示**可鼠标滑入、可选中/复制文字**（150ms 延迟关闭），顶部/底部溢出自动翻面，且**同时只有一个提示**；右上角 ⭐ 与名称行居中对齐（颜色减淡）可直接收藏 |
| 点击图标 | 打开**右侧详情抽屉**（tips / 复制下拉 + 复制 / 前往 wiki / 合成表 + 用于合成 + 微光嬗变）；Esc、点遮罩、右上角 × 关闭 |
| 复制 | 单个「复制」按钮 + 紧贴的下拉框选内容（**默认 ID**，另有名称 / `[i:ID]` 标签；两者间有一条分隔边线）；反馈 1.2s 内显示「已复制」；剪贴板不可用时静默失败 |
| 前往 wiki | 按当前语言打开 `terraria.wiki.gg`：中文 `/zh/wiki/<中文名>`、英文 `/wiki/<英文名，空格→下划线>`（`lib/items.ts` 的 `wikiUrl`）；按钮与「复制」都**不带图标** |
| 合成表分区折叠 | 详情里「合成表 / 用于合成 / 微光嬗变」三个分区可点击标题折叠（`Collapsible`，默认展开）；内容为 `auto-fill/15rem` 网格，短条目自动 2 列 |
| 合成条目复制 | 每条 hover 时**右上角浮动**出现复制按钮（绝对定位、不占位），复制描述性合成文本（材料 → 产物 @ 制作站 + 条件）；文本是否带 `[i:ID]` 标签由下方「复制含标签」勾选框决定 |
| 仅显示图标 / 单列 / 复制含标签 | 详情合成表**下方居左的三个勾选框**（`tswui:dex:recipeIconOnly` / `tswui:dex:recipeSingleColumn` / `tswui:dex:recipeCopyTag`）：分别控制「只显示图标」（数量改角标；配方组「任何XX」仍显示文字，**默认勾选**）、「合成记录单列」（默认多列自适应）、「复制文本含标签」；**无配方/材料/微光时不显示** |
| 词缀 / 最佳词缀 | 详情 tips 右侧的词缀下拉（`tswui:dex`）按游戏自身评分（`prefix-mods.json` 的 `val`）从高到低排序，并列最佳的标 ⭐ 并显示「最佳词缀：…」（可点击套用）；**饰品不显示这行**（下拉已足够明显）。选中后 tips 按该词缀重算/补效果行 |
| 可丢微光分解 | 融入「合成表」的**每条记录**（`RecipePanel` 行尾，5362 图标无 tips + 文字；多件一组时附「每 N 个分解一次」），数据 `stat.stats.canDecraft` |

## 14. 游戏自身的物品分组（v1.4 / v1.5）：创意菜单页签

游戏创意菜单的 11 个分类页签**作为主筛选「物品分组」模式的右侧上下文控件**显示
（选中主筛选的「物品分组」后出现在其右侧；默认「全部物品」模式下不显示）。

### 数据来源（`data/item-groups.json`）

- **页签**：`Terraria.GameContent.Creative.ItemFilters`——与游戏
  `UICreativeInfiniteItemsDisplay` / `NewCraftingUI` 构造时使用的过滤器列表**完全一致**（顺序也一致）：
  武器 / 盔甲 / 时装 / 物块 / 家具 / 配饰 / 装备 / 消耗品 / 工具 / 材料 / 其他（MiscFallback）。
- **物品分组 / 组内顺序**：`ContentSamples.CreativeHelper.GetItemGroup` 与
  `ContentSamples.ItemCreativeSortingId`（即 `ByCreativeSortingId` 排序用的 `ItemGroup` + `OrderInGroup`）。
- 生成：`tools/gamedump/Program.cs` 的 `DumpItemGroups`（先用反射调
  `Main.Initialize_TileAndNPCData1/2` 填充物块/家具所需的 `tileSolid` / `tileFrameImportant`，否则分组会全错）
  → `tools/gen-item-groups.mjs`。

### 行为

- 点页签 → 只显示该页签内的物品；**一个物品可同时属于多个页签**（如生命水晶同时在消耗品与材料，与游戏一致）。
- 只要处于「物品分组」模式就**按游戏 `ByCreativeSortingId` 顺序**（`ItemGroup` 值 → 组内顺序）展示，**不洗牌、也不显示「换一批」**。
- 页签为 shadcn `Tabs` 但**只用作受控页签栏**（无 `TabsContent`）；`TabsList` 小屏自动换行（`h-auto flex-wrap`）。
- 文案在 `web/src/lib/i18n.tsx` 的 `dex.tab.<id>`，与游戏 `CreativePowers.Tab*` 官方文案对齐（无「全部」页签）。
  （故意**不**改 `loc.<culture>.json`，避免为了几个 UI 标签重生成全部本地化数据。）

### 为何不用 `ItemGroup` 当页签

`ItemGroup` 有 53 个有物品的分组（如 `RemainingUseItems` / `ConsumableThatDoesNotDamage`），是**内部排序**枚举，
不是玩家能认出的分类；游戏里真正的分类**页签**是 `ItemFilters`，且有官方文案。故页签用 `ItemFilters`，
`ItemGroup` 用于组内排序。两者都已落在 `item-groups.json`（`tabs` 与 `items[].g/gv/o/t`）。
