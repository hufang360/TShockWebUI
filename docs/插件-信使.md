## 1. 插件是什么 / 依赖什么

- **自定义插件**（本仓库自研、随 WebUI 分发）：把网页端请求转达给在线玩家 / 服务器，再把游戏内真实结果带回网页。
- 能力：在线授权登录、批量执行、运行时指令目录、只读信息（区域 / 传送点 / NPC / buff、世界状态）、
  服务器动态事件流、web 会话自助管理、Tier B（`allowServer=false` 指令以真实在线玩家身份执行，默认关）。
- REST 前缀：`/webui/*`；主命令：`/webui`（简写 `/web`）。

## 2. 上游 REST 端点

> `/webui/auth/*` 的 HTTP 状态恒为 200，业务状态在 `code` 字段；其余端点是安全端点，沿用 401/403 语义。

| 端点 | 参数 | 说明 |
| --- | --- | --- |
| `/webui/auth/request` | `name`、`secret` | 向在线玩家发确认消息，返回票据；不在线 → `{code:"offline"}` |
| `/webui/auth/poll` | `ticket`、`secret` | 轮询状态；批准时返回铸造的 REST token（仅一次） |
| `/webui/auth/cancel` | `ticket`、`secret` | 放弃等待，回收票据 |
| `/webui/restlimit` | `secret` | TShock 建令牌限流只读快照：`{code, limit, bucket, intervalMinutes}`；`bucket` 是**调用者自己 IP** 的计数。后端在密码登录前调用，桶满就直接判 `rate_limited`（不再被同文案 403 误导） |
| `/webui/batch` | `cmds`（JSON 数组）、`token`、可选 `mode=server\|player` | 批量执行（需 `tshock.rest.command`；`player` 模式需插件开启 Tier B） |
| `/webui/commands` | `token` | 运行时指令目录（含插件指令）；**按调用者用户组过滤**，权限指令不下发 |
| `/webui/me` | `token` | `{username,group,permissions,canUseApi,canRunCommands}` |
| `/webui/data` | `type=regions\|warps\|npcs\|buffs`、`token` | 补全数据源 |
| `/webui/serverinfo` | `token` | 世界状态 / Boss 进度等 |
| `/webui/events` | `since`、`limit`、`token` | 事件流（`join` / `leave` / `boss` / `chat`） |
| `/webui/auth/sessions` | `token` | 本插件铸造的 web 会话列表 |
| `/webui/auth/revoke` | `id` 或 `all=true`、`token` | 吊销会话 |

## 3. 用到的游戏内指令

| 指令 | 权限 | 说明 |
| --- | --- | --- |
| `/webui`（`/web`） | 无 | `auth <验证码>` 同意登录 / `deny <验证码>` 拒绝；仅限游戏内；不带参数显示帮助 |
| `/weblimit`（`webadmin`） | `tshock.rest.cfg` | 高级指令：查看 / 放宽 TShock 建令牌限流 `RESTMaximumRequestsPerInterval`；`<值>`（≥1）、`unlimited`（1000000）、`default`（5）；**会写入 TShock 的 `config.json`**；普通玩家看不到也跑不了 |

## 3.1 在线授权防骚扰（不干扰正常游玩）

在线授权会在游戏内向玩家发确认消息，所以必须防刷。后端（Go）入口已有按客户端 IP 的登录限流，
插件侧再叠四层：

1. **复用不重发**：同一玩家已有未过期票据时，重复请求直接复用旧票据，**不再发游戏内消息**。
2. **新建冷却** `PlayerCooldownSeconds`（默认 60）：冷却期内不允许新建票据（防止反复刷新页面刷屏）。
3. **拒绝/过期冷却** `DeniedCooldownSeconds`（默认 300）：玩家拒绝或票据过期后，再次请求要等更久。
4. **全服 / 来源 IP / 单账号 三个每分钟窗口** + `MaxPendingTickets`：防止有人逐个在线玩家骚扰（前端按量）。

配套：后端调 `/webui/auth/request` 时透传网页访客的 `ip`（`s.clientIP(r)`，受 `TRUST_PROXY` 影响），
插件据此做 `MaxRequestsPerMinutePerIp`；未传 `ip` 时该限制不生效。游戏内提示也压缩为两行。

## 4. 本仓库后端接口

| `/api/...` | 对应上游 | 说明 |
| --- | --- | --- |
| `POST /api/login/online` | `/webui/auth/*` | 在线授权登录（等待玩家游戏内确认，最长 `WEBAUTH_TIMEOUT`） |
| `GET /api/webauth/capabilities` | `/webui/auth/request`（空 `name`） | 探测在线授权 |
| `POST /api/batch` / `GET /api/batch/capabilities` | `/webui/batch` | 批量执行与探测 |
| `GET /api/commands` | `/webui/commands` | 运行时指令目录（补全插件指令） |
| `GET /api/me` | `/webui/me` | 当前用户档案 |
| `GET /api/data` | `/webui/data` | 区域 / 传送点 / NPC / buff 补全 |
| `GET /api/serverinfo` | `/webui/serverinfo` | 服务器状态 |
| `GET /api/events` | `/webui/events` | 服务器动态 |
| `GET /api/sessions` / `POST /api/sessions/revoke` | `/webui/auth/{sessions,revoke}` | web 会话自助管理 |
| `POST /api/command` | `/webui/batch`（`mode=player`） | Tier B：`allowServer=false` 的指令 |

## 5. 前端模块

不是侧边栏模块，而是贯穿全站的能力：

- **在线授权登录**：登录框「在线授权」入口（探测到插件才可用）。
- **批量执行**：首页「统一执行」开关（`tswui:homeBatch`）。
- **运行时补全**：区域 / 传送点 / NPC / buff（登录后注入）。
- **服务器动态**：首页 / 指令页「动态」（见 [`功能-服务器动态.md`](功能-服务器动态.md)）。
- **网页会话**：设置 → 网页账号（自助查看 / 吊销）。

## 6. 配置与权限

插件配置 `<TShock SavePath>/WebUI/config.json`：

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `Secret` | 空 | 与后端 `TSWUI_AUTH_SECRET` 一致；非空时 `/webui/auth/*` 要求 `secret` 匹配 |
| `TimeoutSeconds` | 60 | 单次授权有效期（10–600 秒） |
| `MaxRequestsPerMinute` | 5 | 每账号每分钟请求上限（防游戏内刷屏） |
| `PlayerCooldownSeconds` | 60 | 新建票据后的冷却（秒）：冷却期内重复请求只复用票据、不再发消息 |
| `DeniedCooldownSeconds` | 300 | 拒绝 / 过期后的额外冷却（秒） |
| `MaxRequestsPerMinuteGlobal` | 10 | 全服每分钟请求上限（防逐个骚扰）；0 = 不限 |
| `MaxRequestsPerMinutePerIp` | 3 | 同一来源 IP 每分钟上限（后端传 `ip`）；0 = 不限 |
| `MaxPendingTickets` | 64 | 未完成票据上限；0 = 不限 |
| `TokenTTLMinutes` | 0 | 铸造的 web token 有效期（0 = 不过期） |
| `AllowInGameOnlyCommands` | false | **Tier B**：允许以真实在线玩家身份执行 `allowServer=false` 指令（不提权） |
| `AllowChatConfirm` | true | 允许玩家直接回复 `y`/`n` 确认 |
| `RecordChat` | true | 把普通聊天记入「服务器动态」（不含指令） |

后端环境变量：`TSWUI_AUTH_SECRET`、`WEBAUTH_TIMEOUT`、`TSWUI_ALLOW_INGAME_COMMANDS`（详见 `docs/ARCHITECTURE.md` §5）。

权限：**不提权**——token 就是玩家账号本人所在组（仍需 `tshock.rest.useapi`）；批量执行 / Tier B 每条指令
仍按该组判定，Tier B 不绕过 `AllowServer` 之外的任何限制。**改为默认开需用户确认**。

## 7. 已知限制 / 坑

- 插件不支持热重载：改 DLL 后必须**重启 TShock**。
- `/weblimit` 会修改并保存 TShock 的 `config.json`（属服主明确要求的例外）：只改 `RESTMaximumRequestsPerInterval` 一个字段，需 `tshock.rest.cfg`（控制台也可）；`/webui/restlimit` 只读、不消耗限流桶。
- **权限隔离**：`/web`（授权登录）对所有玩家开放且有 `AllowServer=false`（仅游戏内）；高级指令 `/weblimit` 单独注册并挂 `tshock.rest.cfg`。`/webui/commands` 指令目录按调用者用户组过滤（与 TShock `/help` 一致），普通玩家拿不到带权限的指令。
- `/webui/auth/*` 在登录前调用，本身不需要 token；真正的安全边界是「玩家在游戏内确认」，
  公网部署务必同时设置 `Secret` 且 REST 端口只对后端可达。
- token 只在 TShock 内存与后端内存，重启即失效；后端识别 `token_invalid` 会清会话回登录。
- Tier B 默认关；开启后仍要求目标玩家在线，且权限不多一分。

## 8. 验证命令

```bash
# 构建插件
cd plugin/WebUI && dotnet build -c Debug        # → bin/Debug/net9.0/WebUI.dll
# 或：PLUGINS_DIR="$HOME/tr/s/ts/plugins" bash scripts/build-plugin.sh && docker restart tshock

# 探测（未登录，需 Secret 时带上）
curl -s --get 'http://127.0.0.1:7878/webui/auth/request' --data-urlencode "name="
```

手动验收（在线授权）：玩家 A 游戏内 `/login` → 网页「在线授权」输入 A 的名字 →
A 收到 6 位验证码 → `/web auth <验证码>` → 网页登录成功。
