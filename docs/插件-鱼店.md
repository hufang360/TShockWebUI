## 1. 插件是什么 / 依赖什么

- TShock 第三方插件 **FishShop**（指令 `/fish`），是一个「指令商店」：除物品外还卖
  召唤 Boss / 入侵、生成 NPC、buff、调时间天气月相等服务。
- 上游 REST 端点：`/fishshop/*`（`list` / `ask` / `buy`）。`v1.6.2 ~ v1.6.6` 曾用 `/v3/fishshop/*`，
  但那个版本未对外，WebUI **不做旧前缀回退**（见 §2）。
- 本仓库把它做成**「鱼店」模块**（默认不在侧边栏，需在「设置 → 激活模块」里打开）。
- 运行时配置在 `<TShock SavePath>/FishShop/`：`settings.json`（按 id 的预设，含图标/限购）、
  `config.json`（货架）、`record.json`/`jar.json`（记录/鱼罐）。

## 2. 上游 REST 端点

| 端点 | 参数 | 权限 | 说明 |
| --- | --- | --- | --- |
| `GET /fishshop/list` | — | 无（老版需 `fishshop.rest.use`） | 货架；**能力探测也用这个端点** |
| `GET /fishshop/ask` | `serial` | 无（老版需 `fishshop.rest.use`） | 单件详情（「这个商品怎么卖」） |
| `GET /fishshop/buy` | `serial`、`amount`、`args`（可选） | 无（老版需 `fishshop.rest.buy`） | 购买；只能买 token 同名玩家 |
| ~~`GET /fishshop/refund`~~ | `seq` | — | **新版已删**（连同 `/fish refund` 指令）；从未接线 |

- **权限（新版已取消，已核实 TShock `SecureRest.cs`）**：不传权限参数时 `Permissions.Length == 0` → 只校验 token 有效，
  与游戏内 `/fish list|ask|buy` 一致。状态码：`401` 没带 token；**`403` 只表示 token 无效 / 用户组已变动**；
  业务失败全部 `400` + `error`。老版本缺 `fishshop.rest.*` 也会 403，后端用 `/tokentest` 区分（保留为兼容分支）。
- **游客**：`list` / `ask` 不限；`buy` 在 SSC 开启时被拒（`400`「游客无法访问鱼店」），WebUI 原样展示该文案。
- **只打 `/fishshop/*`，不回退旧前缀**：`/v3/fishshop/*` 只存在于 v1.6.2 ~ v1.6.6（未对外），
  新版插件已去掉 `v3`；为一个没发布的版本保留 404 回退只会让每次调用多打一次空请求，故删除。
- 插件缺失 / 没注册端点 → 404；业务失败（钱不够 / 商品不存在 / 商店打烊 / 游客 / 玩家不在线）→ 400 + `error` 文案。
- **字段以插件 `docs/REST-API.md` §2.1 / §2.2 为准**（上游约定「只增不改名」）：`list` 的每条 = `ask` 的整个
  `response`（`ask` 另多一个 `shop` 店名），`buy` 返回 `amount`（**实际成交件数**）+ `requested`（请求件数）
  + `refunded`（没发出去 + 已自动全额退还）。本仓库已解析全部字段，见 §5。
- **`?self=1`（个人状态）**：让上游按 token 同名玩家身份算限购 / 冷却，多返回 `canBuy` / `blockReason` /
  `myCount` / `myRemain` / `serverCount` / `serverRemain` / `myCdRemain` / `serverCdRemain`。
  代价是**该玩家必须在线**（否则 400「玩家 X 不在线」）；WebUI 先试它、失败静默退回普通货架。
- **`args` 支持引号**：`"我的 小屋"` 是一个参数（`\"` / `\\` 转义），与游戏内 `/fish buy 8 "我的 小屋"` 一致；
  WebUI 用同一套规则数参数个数（`web/src/lib/fishArgs.ts`），判断「参数够不够，能不能点购买」。

> 本仓库的 WebUI **不提供代购**（新版插件也已删除 `player` 参数，只能买自己）。

## 3. 本仓库后端接口

| `/api/...` | 对应上游 | 说明 |
| --- | --- | --- |
| `GET /api/fish/capabilities` | `/fishshop/list` | `{plugin, rest, permission}`；与货架共用同一个端点 |
| `GET /api/fish/list` | `/fishshop/list` | 规范化货架 |
| `GET /api/fish/ask?serial=` | `/fishshop/ask` | 单件（当前前端未用，接口保留） |
| `POST /api/fish/buy` | `/fishshop/buy` | body `{serial, amount, args}`；会扣费，共用会话限流 |

  错误码、`permission` 语义：见 [`API_SPEC.md`](API_SPEC.md) §5.5–§5.8（唯一契约）。
  本表只记「哪个上游对应哪个 `/api`」，字段与错误码不在这里复述。

## 4. 前端模块

- id：`store`；入口：`设置 → 激活模块 → 鱼店`。
- 页面 `web/src/pages/FishShopPage.tsx`：
  - **整页滚动**（与指令 / 物品 ID / 数据 ID 一致）：页面不固定高度，左右两列都跟着页面走，
    滚动条是浏览器右侧那条；货架与卡片都不再套内层滚动区（规则见 `docs/UI组件.md` 的「整页滚动」）。
  - **吸顶工具条**（`sticky top-12`）：布局**照抄「物品 ID」** —— 外层 `flex flex-col gap-2 p-1
    sm:flex-row sm:flex-wrap sm:items-center`；手机上搜索框独占一行，页签换到下一行靠右；
    宽屏搜索 `sm:flex-1`（`max-w-sm`）、页签 `sm:ml-auto`。搜索框是 `SearchInput`（左侧放大镜、
    右侧件数 `{n} 件商品`，失焦且没内容时让位给 `/` 快捷键提示）。往下看商品时它留在顶栏下面。
  - **页签（全部 / 买过 / 收藏，买过带 `Footprints` 图标）**：样式跟「物品 ID」输入框右侧的一致（外层 `rounded-container bg-accent p-0.5`
    + `ToggleGroup variant="outline" size="sm"`，选中项 `bg-card`），带条数。全部 = 当前货架；
    买过 / 收藏 = 本机记录（`tswui:moduleState`，按 `serverId` 分开）。 记的是**内容指纹**，不是 `serial`——见 §4.1。
    已下架的条目仍显示（图标 + 名称取自快照），点开详情会提示「已不在当前货架」并禁用购买。
  - **收藏**：详情**底部操作区最左**的 ⭐（`IconAction` + `aria-pressed`，紧挨着「关闭 / 购买」那一排），
    再点取消；最多存 80 条。详情顶栏保持原样（居中大图标 + 编号名称），不放按钮。
  - **买过**：买成功后自动记一条（**按内容指纹去重**、最新在前，最多 80 条）；
    已全额退款（没拿到货）的不记。搜索框旁边不再挂「最近购买」徽标——记录只在页签里，
    否则同一份数据在界面上出现两次。
  - **页面设置 / 全屏**都在**顶栏右侧**（`TopBarActions`，与「物品 ID」一样）：工具条只留搜索与页签。
    位置**夹在「管理卡片」与浮动终端之间** —— 顶栏挂载顺序就是显示顺序，所以这两颗挂在
    `FishCommandCards` 之后（卡片那组之后）、全局 `headerActions` 之前。
    全屏（`Maximize2` / `Minimize2`）把货架铺满**顶栏以下**的区域（`fixed inset-x-0 top-12 bottom-0`，
    右列收起、工具条贴顶），Esc 退出 —— 顶栏保留是因为退出按钮就在顶栏，盖住它就出不来了。
  - **页面设置**（顶栏的齿轮，`Popover`，与物品 ID 的「页面设置」同规）：
    **图标大小**（`Select` 小尺寸：大 64 / 中 48 / 小 32，默认「大」。原来是小/中/大三连按钮，
    在 320px 的弹框里占一整行太重。**小尺寸不显示编号与名称**，这时也不再显示「隐藏编号和名称」开关）、
    **隐藏编号和名称**（中 / 大下只留图标）、
    **表格视图**（编号 / 图标 / 名称 / 价格 / **备注**，`GoodsTable`；备注单行 `truncate` 截断、`title` 看全文；
    行带斑马纹 `odd:bg-muted/25`，与「物品 ID」的表格同款）、

    **货架层板**（默认显示，关掉就只剩纯网格；表格视图 / 小尺寸下本来就不画，开关也不显示）、
    **遮阳伞**（默认显示，关掉就只剩货架；表格视图下不画，开关也跟着藏起来）。
    标题栏右侧的「恢复默认」按钮把这五项一次改回默认（搜索词 / 页签 / 买过 / 收藏不动），
    打开弹框时焦点落在「图标大小」下拉上，不会先把恢复按钮高亮出来。
    开关按 `serverId` 记在 `tswui:moduleState`。
  - **货架板**（`GoodGrid` + `index.css` 的 `.fish-shelf`）：中 / 大尺寸下每行商品都站在一块板上。
    板上沿在**图标区底部**（图标再往下那圈 4px 内边距处，商品看着像踩在板上），
    板身盖住 `#序号` 那一行（序号像货架边缘的价格标签），名称挂在板下面；
    颜色统一用 `var(--border)`（和卡片描边同款）。
    板的左右两端各留 `p-1`（4px），**宽度就是一整行**（哪怕这一行只摆了一件商品，板也不会缩短）。
    两端各收一段 **45° 斜边**（楔形长度 = 板厚）：上沿一直铺到尖点、下沿斜着升上来与它**交汇**，
    所以板端是收尖的，既没有竖切边、也不会缺一截线条。
    板本身四层：2px 上沿 → 上亮下暗的板身（玻璃台面）→ 1px 下沿 → 板下投影（厚度 + 纵深）。
    两端各一条 60°（从水平算）的细斜线，从板端的**尖点**往里、往上长，靠尖点是实色、往上渐隐，
    到「图标半高再多一点」的地方化掉（和板的斜边在同一个尖点交汇）；斜线在**独立的一层**
    （`.fish-shelf-rails`，自己带渐隐 mask），和板一起画在格子**背后**（图标与文字在它们上面），
    只从图标缝里透出来。
    周期（一格高度 + 行距）、板上沿、板厚、板宽都是**渲染后量出来**的（`getBoundingClientRect` +
    `row-gap` + `grid-template-columns`，`ResizeObserver` 跟随），不写死像素：换字体 / 主题 / 窄屏折行都不会错位。
    小尺寸与表格视图不画（格子排得密、又没有两行字，加板只会更乱）；隐藏编号和名称时退化成板下一薄条。
    「页面设置 → 货架层板」可以手动关掉（有些主题下板线抢眼）。
  - **货架区留 `p-2` 内边距**：最后一行的板线 / 板下投影不会被容器下沿切掉。
  - **遮阳伞**（`ShopAwning` + `lib/fishAwning.ts`，颜色在 `index.css` 的 `.shop-awning`）：
    货架区顶上一圈**蓝白相间**的布条（参考鱼摊遮阳伞的裙边），用 SVG 画。
    几何是**纯函数**按宽度算的（`ResizeObserver` 量，理由同货架板），单测钉住（`fishAwning.test.ts`）：
    - **蓝白相间、紧挨着**：一个布位 = 蓝 33px + 白 24px（比例照参考图，蓝的比白的宽），
      两条共用一条缝 —— 是一整片相间的篷布，不是一根根分开挂的。
    - **放射**：布条从一个**正上方**的消失点放射下来 —— 中间几条竖直、越靠两端越往外斜
      （`AWNING_EDGE_LEAN`，现 16°）。消失点距离由这个角度反推，所以宽窗口也不会斜得离谱；
      布条下端比上端宽一点（透视，近宽远窄）。
    - **两端灰色**：最左 / 最右那一条是篷布绕到背面的一截，画成灰色（`--awning-strip-turn`）。
    - **两端留白**：扇形会把最外侧的布条推出画布，所以**只画完全落在画布内的那些**，两端各留一点空白；
      裁一半 → 尖楔碎渣，夹到边界 → 退化细条，两种都试过，都难看。
    - 每条布下端各自收成**半圆**（半径 = 底宽一半），两侧略暗、下端再压一截（圆柱明暗 + 布边卷下去的影）。
      **不画**下沿底带、横梁、折线、篷影（静止态不投影，边界靠色阶）。
    - 颜色取 `--info` 的混色（蓝：亮色 80% / 暗色 70%；白：亮色 12% / 暗色 24% 的对侧混色；端头灰另设）：
      混色**必须**用 `in srgb`，`in oklch` 跟白色（`--card` 的色相是 0）混会把蓝色拉到 330°、渲染成粉色。
    - 它属于**货架区**（网格 / 空态 / 加载中都顶着同一块篷），所以是独立一层、不参与网格排版，
      `GoodGrid` 量格子几何时不会被它带歪；表格视图下不画（数据表上面顶块篷布没有意义）。
  - **刷新只有顶栏那一处**：输入框里不再放刷新图标；顶栏「刷新全部」在**手动点**时同时刷新货架
    （`FishCommandCards` 的 `onManualRefresh`，自动刷新不触发，避免进页面重复拉一次）。
  - **右列（指令卡片）不跟页面一起滚**：`xl:sticky xl:top-12` 钉在顶栏下面、高度取一屏
    （`calc(100dvh - 4rem)`），内容超出时**整列自己内部滚** —— 往下翻左侧货架时右侧「钓鱼信息」保持在视野里。
  - **卡片高度跟内容走，不被压扁**：列容器上是 `[&>*]:shrink-0`。卡片数量不确定（自定义卡片 + 鱼罐 / 消费榜 / 鱼篓榜），
    默认的 `flex-shrink: 1` 会让卡片一起被压缩：正文被截断、出现框内滚动条、折行的行还会上下叠字；
    现在每张卡保持自身完整高度，多出来的部分交给右侧那条滚动条。
  - **商品网格**（`GoodGrid`），默认**与「物品 ID」同一套格子尺寸**：
    列宽固定 = 格子宽度（`grid-cols-[repeat(auto-fill,…)]`，不拉伸到填满）、列距 8px；
    三档尺寸（页面设置「图标大小」）：
    大 = 图标 **64** × 格子 **72**（= 游戏 `sizeLimit` 32 的 2 倍，整数倍放大不糊）、
    中 = 图标 **48** × 格子 **56**、小 = 图标 **32** × 格子 **40**（只留图标）；详情里的大图标固定 64。
    间距：**大 = 列 16px（`gap-x-4`）/ 行 24px（`gap-y-6`）**，**中 = 列 8px（`gap-x-2`）/ 行 16px（`gap-y-4`）**，
    小 = 行 / 列都 8px（`gap-2`）。中 / 大的行距放宽是为了让货架板压在序号行之后，名称下面仍有呼吸空间。
  - **格子内部从上到下：图标区（比图标大 8px）→ `#编号` → 名称**；名称带词缀时前缀用 `text-warning`，超宽截断
    （大尺寸 72 宽约放得下 4–5 个字，长名字仍会截断，看全名靠悬停图标提示 / 点开详情）。
    编号在名称上方、图标下方，和物品 / NPC 格子的「ID 在上、名称在下」一致。
  - **hover 底色只铺在图标区**（`group-hover/cell:bg-primary/10`），文字行不带底色；整格一起微上浮 `-translate-y-0.5`。
    底色不铺整格是为了让相邻商品看起来不粘成一团（与物品 ID / 数据 ID 同一视觉）。
  - **格子高度跟随内容（`h-auto md:h-auto`）**：格子是 `Button`，尺寸变体自带 `md:h-9`（媒体查询变体在 CSS 里排后面，
    会盖掉无断点的 `h-auto`）。只写 `h-auto` 时 ≥768px 格子被锁成 36px 高，图标和名称溢出压到下一行，
    整片商品互相重叠；`md:h-auto` 是必需的（通用规则见 `docs/UI组件.md` 使用约定）。
  - **背景点缀**：页面底层加一层淡淡的**水波光晕 + 几条淡鱼/水滴**（`pointer-events-none`、`-z-10`、低透明度），突出鱼店氛围。
  - 点击商品 → **右侧详情抽屉**（`components/fishshop/FishDetailSurface.tsx`）：**桌面端不是模态的**——
    遮罩**只盖内容区**（从 `--content-left` 开始，即侧栏右边），**左侧边栏仍可点**，所以抽屉开着也能直接切到指令 / 首页等页面；
    遮罩是共享的 `ContentScrim`（`bg-black/50`、**不模糊**、`z-[45]`，见 `docs/UI组件.md` 的「浮层」一节），
    外观仍是原来的贴右整高抽屉（`sm:max-w-xl`）。
    **点遮罩关闭**；点侧栏导航**不算**关闭（那是要切页，不是要关详情）。
    **窄屏是普通模态抽屉**（`inset-0` 遮罩，点外面关闭）。
    抽屉里：顶栏是可见的标题「商品详情」+ 下面居中的大图标与 `#序号 词缀 名称`（已下架时不显示编号）；底部左侧是 ⭐ 收藏按钮与聊天按钮（`IconAction`，见下「广告到游戏内」），右侧「关闭」是描边按钮（`outline`）→「购买」主色；
    **属性（价格 / 解锁 / 别名 / 限购 / 购买时机 / 购买前检查 / 备注）统一排版：文字标签在值框上面一行的左上角**（`Field`：`dt` 在上、`dd` 在下，不用左侧固定标签列）；值框 = 富文本条（`rounded-xl bg-accent/60`）；
    **限购 / 时机 / 检查只在有值时出现**（`limit`/`serverLimit`/`cd`/`serverCd`、`needAlive`/`needDay`/`needNight`、`check`），
    空商品不额外多出空行；
    **建造类商品（鱼池 / 小房间 / 钓棚 / 刷怪场）在属性下面多一张注解图**（见 §9.1）；
    **右下角半透明渔夫指南图标（3120）点缀**；关闭：右上角 X / `Esc` / 点遮罩（窄屏另可点抽屉外关闭，导航点击不算）。
  - 默认焦点：需参数 → 参数输入框；否则 → 购买按钮。
  - **切页面回来详情还在**：`AppRoutes` 按 `activeTab` 条件渲染，离开鱼店本组件就被卸掉；
    所以「刚在看哪件」按**内容指纹快照**存在 `tswui:moduleState`（`ui.detail`，与「买过 / 收藏」同一套指纹），
    回到鱼店时按快照重新打开（货架拉到后 `findLiveGood` 自动换成实时数据）。
    关闭详情（× / Esc / 「关闭」）会清掉这条。恢复出来的详情**不抢焦点**（回来应该能直接操作页面）。
    数量 / 参数不随详情恢复（那是「这一把」的临时输入，隔了页面/时间再复活容易误买）。
    货架未到时不显示「已下架」，也不允许购买：此时手里的 `serial` 可能已指向别的商品（插件按配置下标发货）。
  - 购买：`buyMax>1` 才显示数量框；`needArgs` 显示参数框（数量固定 1），`argCount>1` 时标签改成
    「参数（N 个，用空格分隔）」；两步确认。
    「参数」「数量」也走同一套排版：标签在输入框上面一行、左上角对齐（不再在输入框左边占一列）。
  - **购买成功不关闭详情**：在界面显示结果（`name`/`cost` 里的 `[i:..]` 渲染成图标）+ 「请打开游戏，进行查收！」提示，
    并刷新货架。`amount < requested`（被 `buyMax` / 堆叠上限夹小）时再补一句「单次上限只给了 N 件（你想买 M 件）」，
    避免玩家以为按自己填的数量成交。失败提示（如「玩家不在线」）显示在数量/输入框下方、购买按钮上面一行。
  - 底部操作栏（固定）：左「关闭」（内附 `Esc` 的 `Kbd`）→ 右「购买」；右上角也有 X。
  - **个人状态（`self=1`）**：`loadShop` 先带 `self=1` 拉货架，能拿到「还能买几次 / 冷却还剩几秒 / 为什么不能买」；
    玩家不在游戏里时上游 400，**静默退回**普通货架（不弹错），此时详情里少一行「我的进度」而已。
    `canBuy=false` 时详情里显示上游 `blockReason` 并禁用购买按钮（省一次必然失败的点击）。
  - **`refunded=true`**（动作执行了但没发货、已自动全额退还）：显示「本次未发货，已全额退款」，
    绝不显示「已购买 ×0」，也**不走**「被夹小」提示（`amount=0 < requested` 会被误判成夹小），
    并跳过购买后的 3 秒冷却（什么都没拿到，不该让人等）。
  - **降级条目**（`comment` 以「该商品配置有误」开头）：显示「暂时买不了」并禁用购买。
  - **广告到游戏内**（详情左下角聊天按钮，tooltip = `广告到游戏内`）：
    走网页发言通道（`POST /api/chat` → 信使插件 `/webui/chat`，带 `[WebUI] 玩家名:` 前缀、受插件限流），
    文本格式 `#序号 [商品标签] = [价格]`，例：`#2 [i:29] = [i/s2:73]`、`#78 [i/p60:1569] = [i/s30:74]`。
    - 商品段：`formatItemTag(good.id, {prefixId, stack})`（词缀先取结构化 `prefix`，没有再取 `icon` / `desc` 标签里的 `pN`）；
      服务类商品（`id < 0`，没有物品）退化为商品名。
    - 价格段：直接用插件给的 `cost` **原文**（它本来就是「标签 + 文字」的富文本），空则写「免费」。
    - 失败（未装信使插件 / 网页发言关闭 / 限流）用 toast 说明原因，不假报成功。
  - **表格视图**（页面设置）：列 = 编号 / 图标 / 名称 / 价格 / 备注；名称列与格子一致，**词缀写在商品名前**（`text-warning`，如「恶魔 吸血鬼刀」）。
  - **参数个数**按插件的引号规则数（`splitFishArgs`）：`"我的 小屋"` 算 1 个参数，与插件解析一致。
  - **货架加载时机**：进入页面（含从其它页面切回来）**总是拉一次**；停留在页面时再按
    「设置 → 页面数据刷新间隔」定时重拉（0 = 只拉进入那一次）。
    货架是组件内状态、离开页面就丢，因此**不能**套用首页卡片那套 `refreshGate`
    （否则 2 分钟内回到鱼店会一片空白）；右侧指令卡片的结果存在全局 store，仍走门控。
  - **不可用时的提示（三种，按探测结果区分）**：
    - `plugin=false`（没装或无法确认）→「服务器未安装 FishShop 插件」；
    - `plugin=true, rest=false`（v1.6.2 之前的老版本）→「鱼店插件版本过旧，没有网页接口」，
      文案提示去升级、并说明进游戏可用 `/fish list` / `/fish buy <编号>`（网页右侧只保留「钓鱼信息」卡片）；
    - `plugin=true, rest=true, permission=false` → 老版本缺 `fishshop.rest.use`（新版不需要该权限，恒为 `true`）。
- 界面状态（搜索词 / 页签 / 页面设置开关）按 `serverId` 记忆在 `tswui:moduleState`。

### 4.1 「买过 / 收藏」怎么认商品（为什么不存 `serial`）

服主上架 / 下架一件商品，后面所有商品的编号都会变，所以不能存编号。

- **`serial` 是配置数组的下标**：插件 `BuyGoods.cs` / `RestApi.cs` 都是 `_config.shop[serial - 1]`，
  插入 / 删除一件商品，后面所有商品整体错位，存下的 `#12` 就指向别的商品。
- **实际存的是一份快照 + 内容指纹**（`web/src/lib/fishGoodKey.ts`）：
  - 严格指纹 = `id:stack:prefix:needArgs:argCount | 名称 | cmds`；
  - 宽松指纹 = 上面去掉名称（服主**改名**后仍能对上）。
  - 刻意**不含价格**：调价不该让收藏失效。
- **认商品时的顺序**：严格指纹 → 宽松指纹**只有唯一命中才算**（服务类商品 `id` 会重复，
  只能靠 `cmds` 区分；唯一命中才认，避免把两件同 id 的商品当成一件）→ 都不中 = 已下架（用快照显示）。
- 同一件货架商品只归一条记录（`resolveStamps` 用 `used` 集占位），所以两件同款不会在「收藏」里重复出现。
- 旧版本存的 `recentBuys`（没有指纹）首次读到时自动换算成「买过」，不会凭空消失。
- 详情里的「在货架上找同款」也走这套指纹（`findLiveGood`），而不是按 `serial` 对比：
  否则刷新货架后，同一个编号已经换成别的商品，详情里就会把 A 的价格 / 限购当成 B 的。

## 5. 数据字段

`FishGood`（上游 → 本仓库同名）：

| 字段 | 上游类型 | 说明 |
| --- | --- | --- |
| `serial` | int | 编号（界面显示 `#serial`） |
| `name` | string | 商品名 |
| `icon` | string | 图标标签 `[i:ID]`（**服务类商品 `desc` 只有文字，靠它显示图标**）；为空回退解析 `desc` |
| `map` | `List<string>` | 别名/分类；前端用 `, ` 连成一行显示 |
| `desc` | string | 说明（物品类通常是 `[i:..]`，服务类等于名称） |
| `cost` | string | 价格（含 `[i:..]`，用 `CommandOutput` 渲染图标） |
| `unlock` | string | 解锁条件 |
| `comment` | string | 备注（也可能含 `[i:..]`） |
| `buyMax` | int | 单次最多购买数（1 = 不显示数量框） |
| `needArgs` | bool | 指令类商品含 `{args}`/`{0}`，购买时需填参数 |
| `allowGroup` | `List<string>` | 限购：仅限用户组 |
| `allowPlayers` | `List<string>` | 限购：仅限玩家（白名单） |
| `denyPlayers` | `List<string>` | 限购：禁止玩家（黑名单） |
| `id` | int | 商品 id（`>0` 原版物品，`<0` 内置商品/服务）；只透传，界面暂不显示 |
| `stack` | int | 单次发放的堆叠数量 |
| `prefix` | int | 词缀数值 id（`0` = 无词缀） |
| `iconId` | int | 图标的物品 id（`0` = 没配）；`icon` 字符串里没 `[i:..]` 时用它兜底显示图标 |
| `argCount` | int | 需要几个透传参数；`needArgs` 的细化版，`>1` 时提示「用空格分隔」 |
| `costMoney` | int | 单件价格的铜币数（不含扣物品） |
| `costItems` | `object[]` | 要扣的物品 `[{id, stack}]`（不含货币） |
| `check` | string | 购买前检查（`check`）的说明文本，空 = 无 |
| `cmds` | `string[]` | 购买后实际执行的指令（原版物品 / 降级条目为 `[]`）；**注解图按它匹配**，见 §9.1 |
| `limit` / `serverLimit` | int | 每人限购次数 / 全服限量（`0` = 不限，**配置值**不是剩余量） |
| `cd` / `serverCd` | int | 玩家冷却 / 全服冷却秒数（`0` = 不限） |
| `needAlive` / `needDay` / `needNight` | bool | 死亡不能买 / 只能白天买 / 只能夜晚买 |
| `shop` | string | 店名，**只有 `ask` 返回**（`list` 的店名在顶层 `name`） |
| `canBuy` | bool | **仅 `self=1`**：粗判能否买（不含 `check`）；缺省 = 不知道，不能当「不能买」 |
| `blockReason` | string | **仅 `self=1`**：不能买的原因（「已达个人限购」「只能在晚上购买！」…） |
| `myCount` / `serverCount` | int | **仅 `self=1`**：该玩家已买几次 / 全服已卖出几个（按商品 `id`） |
| `myRemain` / `serverRemain` | int | **仅 `self=1`**：还能买几次 / 全服还能卖几个（`-1` = 不限） |
| `myCdRemain` / `serverCdRemain` | int | **仅 `self=1`**：个人 / 全服冷却剩余秒数 |

**字段类型陷阱（已实测，必须容错）**：
- `map` 是**数组**（`List<string>`），不是字符串 → Go 侧用 `stringList` 兼容数组/裸串。
- `icon`/`desc`/`cost`/`unlock`/`comment` 里的 `[i:..]` 都要渲染成图标。
- `limit`/`cd` 是**配置值**，不是「你还剩几次 / 还要等几秒」。要知道剩余量就带 `?self=1`（见上），
  但 `canBuy` 仍不含商品的 `check` 项，最终以 `buy` 的报错为准。
- **降级条目**：商品自身配置有误时上游只回基础字段、`comment` 以「该商品配置有误」开头；
  `isDegradedGood()`（`GoodCells.tsx`）据此禁用购买。

`FishBuyResult` 另有 `requested`（请求件数）与 `refunded`（`true` = 动作执行了但没发货、已自动全额退还，
此时 `amount=0`、`cost` 为空）。

## 6. 权限与限购

- **权限**：
  - 新版插件：**不需要任何自定义权限**。任意有效 token 都能看货架 / 询价 / 购买（与游戏内 `/fish` 一致）；
    WebUI 探测得到的 `permission` 恒为 `true`，页面上不会出现「无权限」提示。
    - 游客 `buy` 在 SSC 开启时会被插件拒（400「游客无法访问鱼店」），WebUI 在购买框中原样展示。
  - 老版本 `v1.6.2 ~ v1.6.6`：查看/询价要 `fishshop.rest.use`，购买要 `fishshop.rest.buy`（代购 `buyas`）。
    只有这种服才会看到「老版本鱼店插件需要 fishshop.rest.use 权限」的提示。
- 「我的进度」（`self=1` 时）单独一行：还能买 N 次 / 全服还能买 N 件 / 冷却中还需 N 秒。
- 限购 / 冷却在详情弹框「限制」一行展示（逐行、只显示有的）：
  - 仅限用户组：`GM`；仅限玩家：`hf、star`；禁止玩家：`bad`
  - 每人限购 3 次 / 全服限量 10 件 / 冷却 60 秒 / 全服冷却 30 秒（`limit`/`serverLimit`/`cd`/`serverCd`）
- 「购买时机」（`needAlive`/`needDay`/`needNight`）单独一行：死亡时不能买 / 只能白天买 / 只能夜晚买；
  商品配了 `check` 时再加一行「购买前检查」，把插件给的说明原文展示出来。
- `fishshop.ignore.allowgroup` 权限可豁免用户组/玩家白名单（黑名单不豁免）。

## 7. 已知限制 / 坑

- **玩家不在线时每次刷新多一次请求**：`loadShop` 先试 `self=1`（要个人状态），玩家不在游戏里会 400，
  再退回普通货架。也就是「人不在游戏里」时每次刷新打 2 次上游（多一次必然 400 的请求）；
  换来的是人在游戏里时只打 1 次、且能显示「还能买几次」。服主若把
  `RESTMaximumRequestsPerInterval` 压得很低，可把这个自动刷新间隔调大。
- **防重复购买**：购买成功后弹框不关闭、在按钮上方显示结果，并给按钮加 3 秒冷却
  （显示「请稍候 N 秒」、禁用）+ 结果块闪烁提示。此前后台提示不明显，玩家容易连点重复购买（已踩坑）。
  实现：`FishShopPage.tsx` 的 `buyCooldown` 状态 + `index.css` 的 `.tswui-flash` 动画。
- **购买时可能返钱**：如「野生狗奶」第二次购买会关闭时间静止并返还一半费用到鱼罐。这属于
  插件内部的开关行为（`RefundHalfOnClose`），**REST 不返回返款金额**。
- **退款**：新版插件已删除自助退款（商品 `refund` 字段、`/fishshop/refund`、`/fish refund` 指令都没了），
  WebUI 同步删除 `refund` 字段解析、「可退款」徽章与补全里的 `/fish refund`（点它只会得到「语法错误」）。
  插件内部「买前失败自动全自动退还」仍在，只是 REST 不返回返款金额。
- **插件版本分三代**（实测插件 `changelog.md` + `git log RestApi.cs`）：
  - v1.6.2 之前：**只有游戏内指令**，没有任何 REST 端点 → 网页只能提示「版本过旧」；
  - v1.6.2 ~ v1.6.6：`/v3/fishshop/*`（**未对外发布**，WebUI 不复该前缀）；
  - 新版：`/fishshop/*`；同时**取消 REST 自定义权限**、删除代购 `player` 参数与自助退款。
- 老版本没有 REST 时**网页上看不到货架**：右侧卡片列只保留「钓鱼信息」（`/fish info`），
  要看货架只能进游戏执行 `/fish list`（`/fish list` 卡片已移除）。
- 解锁文案里的 `{0}`：插件 `UnlockID.GetNameByType` 对「渔夫任务」始终用 `stack`（默认 1）填充，
  否则默认次数会显示成 `完成{0}次渔夫任务`（已修）。
- 目标玩家必须在线（购买发到玩家身上，钱从玩家身上扣）；查询货架带 `self=1` 时同样要求在线。
- 插件把购买事务**串行化**（与游戏内 `/fish buy` 共用一把锁）：并发买 `limit`/`serverLimit` 商品不会超卖，
  但会排队、单次 RT 变长；`list` / `ask` 只读不排队。
- **游客 / 无权限**：新版插件不查权限，只有 SSC 开启时游客 `buy` 被拒；WebUI 不做前置拦截
  （前端拿不到 SSC 开关状态，提前拦会误拦 SSC 关闭的服），直接展示插件返回的 400 文案。
- **插件 REST 注册有延迟（5 秒）**：新版插件在 `OnEnabled` 里 `Task.Run` → `await Task.Delay(5000)`
  之后才 `RegisterRestApi()`（源码 `TShockFishShop/TShockFishShop/FishShop.cs`）。
  所以**刚重启 / 刚更新插件就打开鱼店**会探到 404，页面显示「未安装 / 版本过旧」是正常的；
  等几秒点提示里的**「重新检测」**（`fish.recheck`）即可，不用切页面。

### 7.1 排障：更新插件后仍提示「未安装 FishShop 插件」

按顺序排查（2026-10-21 实际踩过）：

1. **WebUI 后端是不是老构建**（最常见）。
   看后端日志里探测打的端点：`endpoint=/v3/fishshop/*` 或 `endpoint=/fishshop/ask` → 老构建
   （前者只认 `v3` 前缀，后者还在用空 `serial` 的 `ask` 探测）；当前代码探测打的是 `/fishshop/list`。
   开发环境重建：`scripts/dev-container.sh backend`；线上需要重新构建镜像 / 二进制。
2. **直连验证插件本身**（不经过 WebUI）：
   `curl 'http://<tshock>:7878/fishshop/list?token=<token>'` →
   `{"response":{"name":"...","total":N,"goods":[...]}}` = 插件在且 REST 正常；
   `404` = 没装 / 还没注册（等 5 秒）；`401` = token 无效；`403` = 老版本缺 `fishshop.rest.use`；
   `400 {"error":"商店打烊"}` = 端点在、业务上拿不到货架。
3. 前端点「重新检测」再确认一次（页面自带的按钮，避免切页面）。

> TShock 侧要求：`RestApiEnabled=true`（插件注册 REST 不依赖它，但调用需要），
> `EnableTokenEndpointAuthentication=true` 时 token 必须是有效令牌。

### 7.x `/fish info` 在网页端没有「渔夫任务完成数」（调查结论）

现象：游戏里 `/fish info` 会打印 `渔夫任务完成数: N`，网页鱼店右侧「钓鱼信息」卡片里没有这一行。

结论：**不是 WebUI 丢字段，是插件按「是否真实在线玩家」把这一行跳过了。**

- 网页的指令走的是 **伪玩家**执行（两种路径结果一样：都没有游戏内索引）：
  - 单条：`/api/command` → 后端 → TShock **`/v3/server/rawcmd`**（`server/internal/tshock/client.go`），
    TShock 用 `new TSRestPlayer(token 用户名, 用户组)` 执行（`TShockAPI/Rest/RestManager.cs` 的 `ServerCommandV3`）；
  - 批量（装了信使插件时，鱼店卡片就是这条）：`runBatch` → `/webui/batch` **`mode=server`**，
    插件 `Batch.cs` 也是 `new TSRestPlayer(token.Username, group)`。
    只有 `mode=player`（Tier B，默认关）才会用真实玩家身份（`PlayerExecutor`）。
- `TSRestPlayer` 没有游戏内索引（`Index = -1`），`TSPlayer.RealPlayer` 因此为 `false`
  （定义：`Index >= 0 && Index < Main.maxNetPlayers && Main.player[Index] != null`）。
- 插件 `TShockFishShop/TShockFishShop/Helper/FishHelper.cs` 的 `FishInfo()` 里正好是：

  ```csharp
  if ( player.RealPlayer )
      player.SendInfoMessage($"渔夫任务完成数: {player.TPlayer.anglerQuestsFinished} ");
  ```

  所以游戏内（真实玩家）有、rawcmd（REST 伪玩家）没有。同一函数里的「月相 / 时间 / 今日完成情况」不依赖
  `RealPlayer`，网页上都能看到 —— 与实测现象一致。

**当前行为（鱼店插件侧已修，v1.6.6 之后）**：`FishHelper.FishInfo()` 读不到执行者的存档时，不再只给一句提示，
而是按 token 的账号名去找**同名且在线的本人**，读他的 `TPlayer.anglerQuestsFinished`：

```csharp
TSPlayer self = ResolveSelf(player);   // RealPlayer ? 自己 : 按名字找同名在线玩家
player.SendInfoMessage(self != null
    ? $"渔夫任务完成数: {self.TPlayer.anglerQuestsFinished}"
    : "渔夫任务完成数: 玩家上线后可见（网页端只读取在线玩家的存档数据，进服后刷新本页即可）");
```

- 人不在线时仍然是那句「玩家上线后可见」；游戏内 `/fish info` 完全不变。
- 只认**精确同名**（角色名或账号名，不区分大小写），且不用 `TSPlayer.FindByNameOrID`：
  它是**前缀**匹配，token 账号 `hf` 会命中在线的 `hf2`，那就变成读别人的存档了。
- 为什么这次不按「跨玩家取数据」拒掉：解析用的就是 `/fishshop/buy` 已用的同一条规则
  （`RestApi.RestSelfPlayer`：token 同名玩家 = 调用者本人），不是拿另一个人的数据；
  顺带修掉「人已进服、网页还让人进服」这个明显误导。
- 早先的结论是「不解析、只给提示」，担心的两点现已不成问题：
  ①「账号名与角色名不保证相同」→ 两个名字都认；②「跨玩家取数据」→ 只认 token 自己的账号名。
- 想要**离线**也能看次数，仍只能走**玩家存档 `.plr`**（WebUI 的存档页已有读取 / 编辑该字段的能力），
  那是另一条链路，不该塞进鱼店。

## 9. 货架物品提示 + 词缀（v1.1，v1.3 调整）

- **悬停提示**：货架格子、最近购买徽标、表格视图、详情页大图标共用 `GoodThumb`，按商品分两种：
  - **原生物品**（`desc` 带 `[i:..]`，即插件按物品类返回）→ `ItemIcon` 开 `tooltip`，显示
    全项目统一的游戏同款物品提示（`ItemTooltipContent`）。
  - **服务 / 指令类**（`desc` 只有文字，`icon` / `iconId` 只是**借来当识别的图**，如鱼池借水桶）→
    `goodIsNativeItem(good) === false` → 关掉物品提示，改用 shadcn `Tooltip`（`SlotTooltip`）只说两句：
    **`#编号` + 商品名**。为什么不直接不弹：图标是借的，玩家看不出这张图代表哪件商品；
    为什么不弹物品属性：那是借来的物品（鱼池的图标其实是个水桶），会让人以为买的是它。
    图标本身**不压透明度**，与真物品一样正常显示。详情页大图标不弹（编号和名称就写在图下面）。
  - 物品来源：`goodIcon(good)` 从 `icon` 字段（其次 `desc`）解析 `[i/...]` 标签；
    `goodIsNativeItem` 只看 `desc` 里有没有物品标签。
- **词缀（prefix）**：`[i/p<id>:itemId]` 里的 `p<id>` 会解析成 `prefix`，前端用
  `dataset.prefixesById` 拿到词缀名（如「传奇」），**在商品名前用语义色 `text-warning` 显示**
  （亮/暗主题都清晰；不再用只在暗底可读的 `text-amber-300`；物品提示内部仍用 `text-amber-300`）：
  - 货架格子：`传奇 天顶剑`；
  - 详情标题：`#2 传奇 天顶剑`；
  - 悬停提示：`ItemTooltipContent` 自带「词缀 + 名称」行。
- 辅助函数 `goodPrefixName(good, dataset)` 统一取词缀名。
- 格子保留 `aria-label={good.name}`（去掉原生 `title`，避免与自定义提示双重弹出）；测试用
  `getByRole('button', { name })` 定位。

### 9.1 建造类商品的注解图（鱼池 / 小房间 / 钓棚 / 刷怪场）

这些商品买的是**建造动作**（WorldModify 的 `/igen ...`、Clipboard 的 `/clip paste ...`），
光看一句「往下挖 16×26」摆不正位置，所以详情里多一张**带格数标注的示意图**：
`web/public/fishshop/diagram-{pond,room,shed,spawnerfarm}.png`。

**匹配规则：看 `cmds`，不看商品名**（`lib/fishDiagram.ts`）。服主可以随便改名（「挖个坑」），
但 `cmds` 是商品真正的行为；`cmds` 由鱼店插件 `/fishshop/list|ask` 返回（字段说明见 `docs/REST-API.md`）。

| 指令里出现 | 注解图 |
| --- | --- |
| `/igen room`、`/wm room` | `diagram-room.png`（小房间） |
| `/igen pond [water/lava/honey/shimmer]`、`/wm pond ...` | `diagram-pond.png`（鱼池；各种液体共用一张） |
| `/igen shed`、`/wm shed` | `diagram-shed.png`（钓棚） |
| 任意指令里带关键字 `spawnerfarm`（如 `/clip paste spawnerfarm foot`） | `diagram-spawnerfarm.png`（刷怪场） |

- 判断顺序：**spawnerfarm（关键字）→ shed → room → pond**。
  `spawnerfarm` 先判：组合指令（先 `/wm backup` 再 `/clip paste spawnerfarm`）里可能还有别的词；
  `/igen` 后面必须是**整词**子指令（`/igen rooms` 不算，`/igen check pond` 也不算 —— 那是检查不是建造）。
- `wm` 与 `igen` 是 WorldModify 的两个入口，都认。
- 没有 `cmds`（原版物品 / 降级条目 / 旧版插件）就不出图，**不猜**。

**组件** `components/fishshop/GoodDiagram.tsx`：

- **标题样式照抄物品详情的「合成」分区**（现为 `components/DetailSection.tsx`，与物品详情的「合成 / 作为材料」同一个）：
  `text-sm font-medium` + 语义色标题 + 20px 图标 + 箭头同在一个 `CollapsibleTrigger` 里，折叠行为与全站一致。
- **居左**：图本身很窄，居中会离左侧属性文字很远；不用 `mx-auto`，按钮 `w-fit` 包住图。
- **可放大**：图本身是个按钮（`cursor-zoom-in`，hover / 聚焦才出放大角标），点了弹一层 `Dialog`，
  顶上一排 **`1/2` · `1:1` · `2×` · `3×`**（`ToggleGroup`，默认 `1:1` = 图片原生像素）。
  缩放一律 `image-rendering: pixelated`（**最近邻**，格线和小字不糊），宽度 = `naturalWidth × 倍率`，
  超出视口就在弹框里滚动。
  - 读缓存时 `load` 可能已经跑完 → 打开时再查一次 `img.complete`，否则倍率不生效。
  - 图片现在是 **2 倍图**（如 `diagram-pond.png` 514×938），所以 `1:1` 已经能读、`1/2` 用来看全景。
- 叠层做法：在详情 `Sheet`（radix dialog）里再开一个 `Dialog`。Radix 允许嵌套（非顶层自动 `aria-hidden`、
  Esc 只关最上层、点放大弹框不会关掉详情），已用测试钉住。**不需要**换 `Drawer`：这里不是「钻取到另一层内容」，
  只是把同一张图放大看。
- 图片本身带标注，界面**不加说明文字**（alt 里有「「鱼池」的建造范围示意图」给读屏）；
  详情头部那个大图标不再弹「编号 + 名称」（名字就在图下面）。

## 10. 右侧指令卡片列

鱼店页右侧有一列指令卡片（`web/src/components/FishCommandCards.tsx`），与首页卡片同一套外观
（共享 `components/CommandCard.tsx`）：

| 卡片 | 指令 | 默认 |
| --- | --- | --- |
| 钓鱼信息 | `/fish info` | 显示 + 自动执行 |
| 鱼罐 | `/fish jar` | **不显示** + 不自动执行 |
| 消费榜 | `/fish rank` | **不显示** + 不自动执行 |
| 鱼篓榜 | `/fish basket` | **不显示** + 不自动执行 |
| 重载配置 | `/fish reload` | **不显示** + 不自动执行（`ListRestart` 图标） |

- 「重载配置」= 插件 `FishShop.cs` 的 `case "reload"`：重载 `settings.json` + `config.json`（服主改完货架不用重启）。
  需要 **`fishshop.reload`** 权限（`Permission.cs`），普通玩家点了只会得到插件回的「你无权执行重载操作！」。
  **执行成功（`status = ok`）后鱼店自动重拉一次货架**（`onConfigReloaded` → `loadShop`），
  否则页面上还是旧价格 / 已下架的商品。批量执行时同样会调。
  同一权限下的 `/fish reset`（重置限购 / 冷却数据）**没接入**：它会清玩家购买记录，不做成一键卡片。

- **五张卡都只走 rawcmd**：它们的输出没有 REST 端点（货架走 REST，其余靠指令）；
  插件没有 REST 接口时右侧卡片照常可用。
- **后四张默认不显示、也不自动执行**：多数人只在想看排行榜 / 改完配置时才瞅一眼，常驻会把右列撑得很长。
  玩家在「管理卡片」里打开「显示」才会出现，需要它跟着自动刷新跑时再勾「自动执行」
  （`FishCardDef.defaultHidden` / `defaultManual`）。显示偏好存本机 `tswui:fishCards:hidden`
  （`{ [卡片 id]: true = 隐藏 }`，没记过的按卡片默认值），因此**升上来看到的就是「只有钓鱼信息」**，
  与老用户之前的观感一致。
- **隐藏的卡片不参与「刷新全部 / 自动刷新」**：`refreshAll` 只跑「显示着 + 自动执行」的卡片，
  免得白打请求还把结果藏起来。
- **记事本**（`components/fishshop/FishNotepad.tsx`）：固定贴在**第一张卡（默认就是「钓鱼信息」）下面一行**，
  随手记鱼价 / 想买的东西。内容按 `serverId` 存本机 `tswui:fishNote`（`{ [serverId]: string }`），
  边打边存、没有保存按钮，不发服务器也不碰 token；一张卡都没显示时记事本仍然在。
- **不依赖鱼店 REST API**：卡片只走 rawcmd（`transport.runCommand`），所以插件没有 REST 接口
  （`plugin=true, rest=false`）或当前用户组无权限时，左侧只显示提示，右侧卡片**照常可用**。
  卡片列在 `authenticated` 时始终渲染，与 `canUse = plugin && rest && permission` 无关，**没有收起开关**。
- **批量执行（统一执行）**：与首页一致；开关已从首页搬到**「设置」**（`Switch`，存 `tswui:homeBatch`），
  未安装批量执行信使插件（WebUI）时开关禁用并提示，自动回退为逐条执行。
- **卡片密度与管理**：鱼店与首页共用压缩版 `CommandCard` / `CardManagerSheet`。卡片底部不再重复显示指令；
  管理器中点击「添加卡片」才展开名称 / 指令表单，自定义卡片按需进入编辑态，「自动执行」统一为 `Checkbox`。
- **页头收进顶栏**：页内不再有标题行；「重新检测」「页面说明」「上次刷新」「管理卡片」「刷新全部」都在内容区顶栏右侧（`TopBarActions` + `IconAction` + `InfoPopover`）。
- **两列 + 右列不吃页面滚动**：外层是 2 列 grid（`xl:grid-cols-[minmax(0,1fr)_360px]`），
  左列 = 吸顶工具条 + 货架（跟着页面滚）；右列包一层 `xl:sticky xl:top-12 xl:h-[calc(100dvh-4rem)]`，
  钉在顶栏下面、自己内部滚 —— 往下翻商品时「钓鱼信息」等卡片不会跟着滚走。
- 卡片内边距与列间距：左卡 `CardBody pt-3` = 右卡 `CardHeader py-3`；列内 `gap-4`。
