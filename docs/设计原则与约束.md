## 1. 产品定位

面向**拥有 TShock 账号的 Terraria 玩家**的 Web 指令伴侣：

- 浏览器里更舒服地编辑指令（中文输入、光标、复制粘贴）。
- 指令 / 参数 / 玩家名 / 物品名自动补全。
- 物品搜索与 `[i:...]` 图标标签插入。
- 通过固定后端接口执行指令并展示**真实**结果。

**不是**服务器管理后台；**不得**用管理员身份代替玩家执行操作。

### 1.1 产品原则

- **玩家优先**，而非服务器管理员优先。
- **真实 API 优先**：不得用硬编码数据或 Mock 冒充真实服务。
- **输入体验优先**：不为花哨功能牺牲原生编辑行为（输入法、光标、选择、撤销）。
- **模块边界清晰**：指令定义 / 补全逻辑 / 物品数据相互独立，方便分模块开发与测试。
- **安全优先**：不绕过 TShock 原有的身份验证和权限控制。
- **范围克制**：不提前实现完整商店系统，不擅自扩大范围。
- **可验证**：只有实际验证通过的功能才能标记为完成；Mock 不得冒充真实能力。

## 2. 范围

### 2.1 已交付能力

阶段 0–4 已交付：登录 / 会话 / 指令编辑器 / 补全 / 物品搜索与图鉴 / 合成表 / `[i:...]` 标签 /
执行结果富文本 / 历史 / 收藏 / 首页卡片与执行队列 / 多服务器切换（可选）/
单容器镜像（distroless）/ 单文件二进制（macOS / Windows / Linux）。

已确认的插件扩展模块（**默认不在侧边栏显示**，探测到插件后在「设置 → 激活模块」手动打开）：

- **玩家管理**（第三方插件 PlayerManager）：看背包 + 下载 `.plr`，权限 `playermanager`。
- **鱼店**（第三方插件 FishShop）：货架 / 询价 / 购买，权限 `fishshop.rest.use` / `buy`。
- **世界管理**（第三方插件 WorldModify）。
- **自研信使插件 WebUI**（`plugin/WebUI/`）：在线授权登录、批量执行、只读信息 / 事件 / 会话自助、
  Tier B（`AllowServer=false` 指令以真实在线玩家身份执行，默认关，需用户确认才可开启）。

### 2.2 明确不在范围

- 多服务器**统一管理**（仅支持受控的前端切换，见 `docs/API_SPEC.md`）。
- 服务器进程启停、系统资源监控、世界文件管理 / 备份恢复。
- 管理员后台、完整经济系统、在线支付、插件市场。
- AI 自动生成游戏指令。
- 用管理员身份代替玩家执行指令。
- 自研插件的越权 / 伪造身份类用途。

**任何扩大范围的改动，先问用户**（见 `AGENTS.md`「遇到这些必须停下来问用户」）。

## 3. 硬约束（已核实，必须遵守）

| # | 约束 | 影响 |
| --- | --- | --- |
| C1 | Terraria 目标 **1.4.5.8** | 物品 ID / 名称 / 图标数据必须用 `tr-code-1458` 生成 |
| C2 | TShock 目标 **v6.2.1**，REST 端口 **7878** | 部署需 `RestApiEnabled=true` |
| C3 | 建 token 需账号组有 `tshock.rest.useapi` | 默认 guest/default 没有，须管理员赋权 |
| C4 | `/v3/server/rawcmd` 需组权限 `tshock.rest.command` | 同上 |
| C5 | rawcmd **严格继承** token 用户的组权限，不按管理员执行 | 安全模型成立的前提 |
| C6 | rawcmd 对 `AllowServer=false` 的指令直接拒绝 | `/i`、`/tp`、`/home`、`/buff` 等 24 条无法经 WebUI 执行（Tier A 前后端双重拒绝） |
| C7 | Token 存内存，TShock 重启即全部失效 | 玩家需重登；后端要能识别 403 并清会话 |
| C8 | 建 token 按**来源 IP**限流（默认 5 次/分钟） | 经反代时所有玩家共用一个桶（实测），上线前须调大阈值 |
| C9 | 无效 token 与无权限都返回 403 | 必须结合响应体区分 `token_invalid` / `no_permission` |
| C10 | 图标为纵向多帧贴图 | 图集取第一帧，单帧 = `宽 × (高 / frames)` |
| C11 | 图标版权属 Re-Logic | 图集 PNG 随仓库提交（生成物），构建时无需游戏资源；改图标需重新生成 |
| C12 | 部署环境**一般不使用 HTTPS** | 安全策略必须按无 HTTPS 设计（Cookie `Secure` 由 env 控制） |
| C13 | TShock `POST /v2/token/create` **不解析表单体**（实测 500） | 登录凭证只能走 query string，必须由**后端**发起，不能由浏览器直连 |
| C14 | 交付形态为**单个 Docker 镜像**（另有单文件二进制） | 前端 + Go 后端合一；访问路径用相对地址 |
| C15 | 浏览器**不得持有 TShock token** | token 存后端内存，浏览器只有 `HttpOnly` Cookie |

> C1–C11 的源码 / 实测出处集中在 `docs/TECHNICAL_RESEARCH.md` 与 `docs/REST_API限制.md`；
> C12–C15 的落地方式见 `docs/ARCHITECTURE.md`。

## 4. 核心设计理念

### 4.1 单容器 / 单端口 / 单文件

- 前端静态资源 + Go 后端（标准库 only）打进一个 distroless 镜像，只暴露 `:8080`。
- 浏览器只走**同源 `/api/*`**；容器**不暴露通用 `/tshock/` 代理**，不做任意 URL 转发。
- 另有 `scripts/build-binary.sh` 产出的单文件二进制（内嵌前端 + `data/`，无需 Docker / Node 即可运行）。

### 4.2 权限继承，绝不提权

- 以 **token 用户的用户组**身份执行；`rawcmd`、插件的批量执行、Tier B 都严格继承权限。
- 前端不做「权限承诺」，真正权限校验始终在 TShock（token 用户组的 `CanRun`）。
- 前端拒绝 `allowServer=false` 只是**纵深防御**的一部分；后端复检，但两者都不是权限边界。
- 未知 / 插件指令不前置拒绝（`commands.json` 只含核心 95 条），照常发往 TShock 由它判定。

### 4.3 凭证只在后端

- 密码只在 `POST /api/login` 的 body；TShock token 只在后端内存与「后端 → TShock」的出站请求里。
- 浏览器只有 `HttpOnly`、`SameSite=Strict` 的会话 Cookie；不得写 token 到 localStorage / URL / 日志。
- 唯一落盘的凭据是登录框的「记住密码」（`tswui:login`，**用户明确要求的取舍**，默认勾选、可一键关闭）。
- 非 GET 请求必须带 `X-Requested-With: tswui`；访问日志与出站日志**不记录 query / body**。
- 任何 403 / `token_invalid` 都要清会话并回登录。

### 4.4 真实 API，Mock 必须显式标注

- 不以硬编码数据冒充真实服务；Mock 模式必须在界面上明确区分。
- 接口先实测再封装；**不虚构 TShock API**、不使用未经验证的指令格式。
- 版本不匹配时必须报警，而不是静默使用不确定的数据。

### 4.5 扩展通过插件，模块可选

- 第三方插件的能力做成**可选模块**：探测到插件后手动激活，缺失 / 无权限时优雅降级并提示。
- 接入约定与铁律见 `docs/插件接入规范.md`（每接入一个插件写一篇 `docs/插件-<名>.md`）。
- 自研**信使插件 WebUI** 提供在线授权、批量执行、只读信息 / 事件 / 会话自助、Tier B（默认关），
  **不提权、不伪造身份**；超出这些的用途必须先问用户。

### 4.6 界面记忆（localStorage）

统一前缀 `tswui:`；写入防抖，写满（`QuotaExceededError`）只丢旧历史、不报错。

| key | 内容 | 说明 |
| --- | --- | --- |
| `tswui:me` | `{ username, savedAt }` | 仅渲染缓存；真实登录态以 `/api/session` 为准 |
| `tswui:login` | `{ username, password, remember }` | 登录框记忆（用户明确要求）；仅勾选时写入 |
| `tswui:draft` | 编辑器草稿 | 防抖写入 |
| `tswui:history` | 最近指令（上限 100） | 不自动执行 |
| `tswui:favorites` | 收藏指令（上限 100） | 不自动执行 |
| `tswui:items:recent` | 最近物品（上限 50） | |
| `tswui:settings` | 主题 / 字号 / 语言 / 执行间隔等 | |
| `tswui:ui` | 当前标签 / 面板状态 | |
| `tswui:homeCards` | 首页卡片布局 `{ order, hidden, custom }` | 自定义卡片不自动执行 |
| `tswui:meta` | `{ schemaVersion, gameVersion }` | 版本不符时清理物品缓存 |

> `tswui:auth`（含 token）**已废弃**：升级时必须清理旧键，且不得再写入 token。

## 5. 执行策略（安全红线）

- 优先使用经过验证的玩家授权 API；只在权限行为经过验证后才使用 `rawcmd`。
- 不允许通过管理员 Token 代替玩家身份执行操作。
- 不允许前端决定或伪造玩家权限。
- 不允许任意 URL 转发（只暴露固定 `/api/*`）。
- 不允许将未经验证的输入拼接进 shell 命令。
- 不允许把 WebUI 当成无限制的服务器管理代理。
- 对高风险操作设置明确的执行策略；对登录 / 指令执行设置频率限制（限流是「可接受滥用」的兜底，不是权限边界）。
- 指令执行结果一律映射为统一模型：`ok` / `command_error` / `no_permission` / `token_invalid` /
  `unavailable` / `timeout` / `bad_response` / `rejected`；**不得把 HTTP 成功当成指令执行成功**。

## 6. 数据原则

- 物品 / 词缀 / 指令 / 合成表 / 图集数据由脚本从**反编译源码与游戏资源**生成到 `data/`（**禁止手改**）。
- 数据必须与目标游戏版本匹配；升级后必须重新生成并抽查已知物品。
- 不人工编造完整清单；补全参数提取不到就不给候选，**绝不猜参数**。
- 生成流程、字段与出处见 `data/README.md` 与 `docs/TECHNICAL_RESEARCH.md`。

---

## 7. 测试与验收原则

- **Mock 不能代替真实服务器测试**：关键权限行为必须在隔离测试服上验证。
- 每条功能必须有可复现的验收命令 / 单测；**只有实际验证通过才能标记为完成**。
- 自动化覆盖：登录成功 / 失败 / 无权限 / 限流、会话过期、token 失效、
  `allowServer=false` 前后端拒绝、未知指令放行、CSRF、日志脱敏、限流、
  图集 region、版本规范化（`v1.4.5.8` → `1.4.5.8`）。
- 真实服务器验收：真实登录、执行指令看真实输出、无权限被拒、token 失效即失效；
  devtools 确认 localStorage 无 token、URL 无密码、Cookie 为 HttpOnly。
- 常用命令与验收脚本见 `AGENTS.md`；已完成任务的实测记录见 `docs/记录-实现与验收.md`。
