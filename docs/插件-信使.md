## 1. 插件是什么 / 依赖什么

- **自定义插件**（本仓库自研、随 WebUI 分发）：把网页端请求转达给在线玩家 / 服务器，再把游戏内真实结果带回网页。
- 能力：在线授权登录、批量执行、运行时指令目录、只读信息（区域 / 传送点 / NPC / buff、世界状态）、
  服务器动态事件流、web 会话自助管理、Tier B（`allowServer=false` 指令以真实在线玩家身份执行，默认关）。
- REST 前缀：`/webui/*`；主命令：`/webui`（简写 `/web`）。

## 2. 上游 REST 端点

> `/webui/auth/*` 的 HTTP 状态恒为 200，业务状态在 `code` 字段；其余端点是安全端点，沿用 401/403 语义。

| 端点 | 参数 | 说明 |
| --- | --- | --- |
| `/webui/meta` | `secret`（可选） | **协议握手**：`{name,version,protocol,minProtocol,capabilities[]}`。后端据此判定兼容性 / 能力（见 §2.1） |
| `/webui/auth/request` | `name`、`secret` | 向在线玩家发确认消息，返回票据；不在线 → `{code:"offline"}` |
| `/webui/auth/poll` | `ticket`、`secret` | 轮询状态；批准时返回铸造的 REST token（仅一次） |
| `/webui/auth/cancel` | `ticket`、`secret` | 放弃等待，回收票据 |
| `/webui/restlimit` | `secret` | TShock 建令牌限流只读快照：`{code, limit, bucket, intervalMinutes}`；`bucket` 是**调用者自己 IP** 的计数。后端在密码登录前调用，桶满就直接判 `rate_limited`（不再被同文案 403 误导） |
| `/webui/batch` | `cmds`（JSON 数组）、`token`、可选 `mode=server\|player` | 批量执行（需 `tshock.rest.command`；`player` 模式需插件开启 Tier B） |
| `/webui/commands` | `token` | 运行时指令目录（含插件指令）；**按调用者用户组过滤**，权限指令不下发 |
| `/webui/me` | `token` | `{username,group,permissions,canUseApi,canRunCommands}` |
| `/webui/data` | `type=regions\|warps\|npcs\|buffs`、`token` | 补全数据源 |
| `/webui/serverinfo` | `token` | 世界状态 / Boss 进度等 |
| `/webui/events` | `since`、`limit`、`tail`、`token` | 事件流：`since=` 增量 / `tail=N` 取最新 N 条（磁盘历史，需能力 `events_history`）。字段见 §2.2 |
| `/webui/chat` | `text`、`token` | 网页发言（前缀广播，不伪造身份）。字段见 §2.2 |
| `/webui/auth/sessions` | `token` | 本插件铸造的 web 会话列表 |
| `/webui/requests*` | `token`、`items`/`reason`/`note`/`id`/`decision` | 物资申请：玩家提交 / 查看 / 撤回；服主审核 / 补发。详见 [`插件-物资申请.md`](插件-物资申请.md) |
| `/webui/auth/revoke` | `id` 或 `all=true`、`token` | 吊销会话 |

### 2.1 协议握手（版本 / 协议 / 能力）

插件与后端同一代码库、会一起迭代，所以除了「装没装」，还要能判定版本与协议。

- 插件：`plugin/WebUI/Meta.cs` 声明 `Protocol`、`MinProtocol`、`Capabilities()`，经 `/webui/meta` 暴露。
- 后端：`server/internal/tshock/meta.go` 声明 `BackendProtocol` 与 `RequiredCapabilities`。
- 兼容：`minProtocol ≤ BackendProtocol ≤ protocol`，且能力清单覆盖后端所需。
- 改协议规则：新增端点 / 字段只扩充 `Capabilities`（不动协议号）；破坏性改动两侧 `Protocol` 一起 +1。
- 已声明但**可选**的能力：`events_history`（磁盘历史 + `tail=N`）、`events_instance`（`instance` 字段）——旧插件没有时后端自动降级，不影响兼容判定。
- 当前能力清单（`Meta.Capabilities()`，按字母序）：
  `auth`、`batch`、`chat`、`commands`、`data`、`events`、`events_history`、`events_instance`、`me`、
  `requests`、`requests_review`、`restlimit`、`serverinfo`、`sessions`。
- 后端错误分类（`refinePluginError`）：端点 404 时用 meta 区分 `plugin_not_installed` / `plugin_outdated` / `plugin_protocol_mismatch`；
  meta 不可得（旧插件 / 真未装）时保持 `plugin_not_installed`。
- 诊断：`GET /api/plugin/status`（免登录） + 设置页「信使插件诊断」卡片。

### 2.2 事件流 / 网页发言（字段）

#### `GET /webui/events`（`SecureRestCommand`，只要有效 token）

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `token` | 是 | 注入的有效 token（不提权） |
| `since` | 否 | 只返回 `seq > since` 的事件，默认 `0` |
| `limit` | 否 | 最多返回条数，默认 / 越界按 `Capacity`（2000） |
| `tail` | 否 | 取**最新** N 条（升序），优先级高于 `since`；需能力 `events_history` |

返回：

```json
{
  "events": [
    { "seq": 42, "type": "join", "text": "Alice 加入了服务器", "time": "2026-01-01T00:00:00.0000000Z", "source": "game" }
  ],
  "lastSeq": 42,
  "firstSeq": 41,
  "instance": "9f2c1b7d4e6a4c1f8b3d5a7e9c0f1a2b"
}
```

- `firstSeq` 只在 `tail` 模式返回（最新一批的起始 seq）。
- `instance`（能力 `events_instance`）是事件库实例标识，旧插件不返回；后端 / 前端据此判断
  「同一地址后面还是不是同一个服」，变了就清空缓存重拉，绝不把两个服的事件拼在一起。
- `type ∈ join | leave | boss | announce | npc | chat`（未知类型前端按灰色点兜底；旧插件的 `webui` 仍兼容）。
  `announce` = 世界公告（Boss 苏醒 / 事件开始 / 陨石 / 困难模式 / 天气），`npc` = 旅商到达。
- 聊天的 `source ∈ game | webui`：真实玩家聊天 `game`、网页发言 `webui`（旧插件无 `source`，按 `game` 处理）。

#### `POST /webui/chat`（插件，后端调用）

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `text` | 是 | 发言内容（trim 后非空，≤200 字符） |
| `token` | 是 | 注入的有效 token |

返回 `{ status, name, text, line }`；错误：空内容 400 / 关闭网页发言或禁言 403 / 超限流 429。
广播带前缀（配置 `ChatPrefix`，默认 `[WebUI]`），不伪造身份，并记入事件流 `type=chat, source=webui`。

## 3. 用到的游戏内指令

| 指令 | 权限 | 说明 |
| --- | --- | --- |
| `/webui`（`/web`） | `webui.use` 或 `webui.admin` | 统一入口，不带参数显示帮助 |
| `/web init` | `webui.admin` + `tshock.rest.cfg` | **一键初始化**：打开 REST / 写限流 / 给默认组补权限（见下） |
| `/web auth <验证码>` | `webui.use` | 同意登录；仅限游戏内本人 |
| `/web deny <验证码>` | `webui.use` | 拒绝登录；仅限游戏内本人 |
| `/web limit [值\|unlimited\|default]` | `webui.admin` + `tshock.rest.cfg` | 查看 / 放宽 TShock 建令牌限流 `RESTMaximumRequestsPerInterval`；**会写入 TShock 的 `config.json`** |

> 权限节点是 TShock 动态权限字符串，需服主授予，如：`/group addperm default webui.use`、`/group addperm <管理组> webui.admin`。
> 插件启动时若没有任何组拥有 `webui.use` 会在控制台警告（否则玩家无法在线登录）。
> 全部权限节点（插件自定义 + 依赖的 TShock 内置）见 §6.1。

#### `/web init`：一键初始化

给新开服的人用：一条指令把「网页端能正常登录」的前提全补上，**幂等**（已对的不重复写，重复执行无副作用）。
在游戏内或控制台执行（需 `webui.admin` + `tshock.rest.cfg`，因为会写 TShock 的 `config.json`）：

| 写入项 | 值 | 为什么 |
| --- | --- | --- |
| `RestApiEnabled` | `true` | 不打开 REST，插件和整个网页端都不可用（**需重启 TShock** 才生效） |
| `LogRest` | `true` | 出问题能查 REST 调用记录；本插件的端点已声明 `DoLog=false`，`secret` / 聊天内容不会进日志 |
| `RESTMaximumRequestsPerInterval` | `50` | TShock 默认 5 太小：每次尝试消耗 2 点，`limit=5` 时桶为空只够 **3 次尝试**，晚高峰多人登录会被限流却报成「账号或密码错误」 |
| `RESTRequestBucketDecreaseIntervalMinutes` | `10` | 每 10 分钟恢复 1 点（≈ 每 20 分钟 1 次尝试）；小服建议调成 1–2，见下方「怎么选」 |
| 默认组权限 | `tshock.rest.useapi` `tshock.rest.command` `webui.use` `webui.request.use` | 建 token / 批量执行 / 在线授权确认 / 物资申请，缺一样玩家就用不顺 |

细节：

- 默认组取 `DefaultRegistrationGroupName`（找不到则退回 `default`）；**不会**给默认组管理类权限（`webui.admin`、`webui.request.review`、`tshock.rest.cfg`）。
- **只往上调、不往下调**：若现有建令牌上限已高于 50，保持原值（输出里会写「保持 N（不往下调）」）。
- 已全部就绪时输出「已经是推荐配置，没有改动。」；控制台 / 日志同步一条 `[WebUI] /web init 已由 <谁> 执行：改动 N 项。`
- 不碰 `Secret`：插件 `Secret` 与后端 `TSWUI_AUTH_SECRET` 需自己对齐（输出最后一行会提示）。
- **怎么选这两个数**：`limit` 管「一次能有多少次登录尝试」（每次尝试消耗 2 点 → `50` ≈ 25 次），`interval` 管「打满后恢复多快」。
  同机 / 反代部署时 TShock 只看到一个来源 IP，**所有玩家共用一个桶**（在线授权登录不消耗这个桶）。
  经验取值：`limit ≈ 4 × 最大人数`（不少于 50），`interval` 1–2 分钟；
  填 10 分钟意味着打满后**每 20 分钟才放行 1 次登录**，小服不推荐。详见 [`REST_API限制.md`](REST_API限制.md) §4。

## 3.1 在线授权防骚扰（不干扰正常游玩）

在线授权会在游戏内向玩家发确认消息，所以必须防刷。后端（Go）入口已有按客户端 IP 的登录限流，
插件侧再叠四层：

1. **复用不重发**：同一玩家已有未过期票据时，重复请求直接复用旧票据，**不再发游戏内消息**。
2. **新建冷却** `PlayerCooldownSeconds`（默认 60）：冷却期内不允许新建票据（防止反复刷新页面刷屏）。
3. **拒绝/过期冷却** `DeniedCooldownSeconds`（默认 300）：玩家拒绝或票据过期后，再次请求要等更久。
4. **全服 / 来源 IP / 单账号 三个每分钟窗口** + `MaxPendingTickets`：防止有人逐个在线玩家骚扰（前端按量）。

配套：后端调 `/webui/auth/request` 时透传网页访客的 `ip`（`s.clientIP(r)`，受 `TRUST_PROXY` 影响），
插件据此做 `MaxRequestsPerMinutePerIp`；未传 `ip` 时该限制不生效。游戏内提示也压缩为两行。

## 5. 前端模块

不是侧边栏模块，而是贯穿全站的能力：

- **在线授权登录**：登录框「在线授权」入口（探测到插件才可用）。
- **批量执行**：首页「统一执行」开关（`tswui:homeBatch`）。
- **运行时补全**：区域 / 传送点 / NPC / buff（登录后注入）。
- **服务器动态**：首页卡片 / 「聊天」页（`#/chat`，见 [`功能-服务器动态.md`](功能-服务器动态.md)）；「聊天」页底部有**网页发言输入框**（发送到游戏内聊天，带 `[WebUI]` 前缀，与真实在线玩家区分）。
- **网页会话**：设置 → 网页账号（自助查看 / 吊销）。
- **物品 / 鱼店广播**：物品详情「词缀 / 物品标签」里的「广播到游戏内」、鱼店商品详情的「广告到游戏内」
  都复用同一个 `POST /api/chat`（同样带 `[WebUI] 玩家名:` 前缀、同样受每账号限流、同样不绕过禁言）。
  文本里的 `[i:..]` 由**客户端**解析成物品图标（vanilla `ItemTagHandler`），插件只做广播。

## 6. 配置与权限

插件配置 `<TShock SavePath>/WebUI/config.json`：

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `Secret` | 空 | 与后端 `TSWUI_AUTH_SECRET` 一致；非空时 `/webui/auth/*` 要求 `secret` 匹配 |
| `TimeoutSeconds` | 60 | 单次授权有效期（10–600 秒） |
| `MaxRequestsPerMinute` | 5 | 每账号每分钟请求上限（防游戏内刷屏） |
| `PlayerCooldownSeconds` | 60 | 新建票据后的冷却（秒）：冷却期内重复请求只复用票据、不再发消息 |
| `DeniedCooldownSeconds` | 300 | 拒绝 / 过期后的额外冷却（秒） |
| `MaxRequestsPerMinuteGlobal` | 10 | 全服每分钟请求上限（防逐个骚扰）；0 = 不限 |
| `MaxRequestsPerMinutePerIp` | 3 | 同一来源 IP 每分钟上限（后端传 `ip`）；0 = 不限 |
| `MaxPendingTickets` | 64 | 未完成票据上限；0 = 不限 |
| `TokenTTLMinutes` | 0 | 铸造的 web token 有效期（0 = 不过期） |
| `AllowInGameOnlyCommands` | false | **Tier B**：允许以真实在线玩家身份执行 `allowServer=false` 指令（不提权） |
| `AllowChatConfirm` | true | 允许玩家直接回复 `y`/`n` 确认 |
| `RecordChat` | true | 把普通聊天记入「服务器动态」（不含指令） |
| `PersistEvents` | true | 把事件按天写入 `tshock/WebUI/events/*.jsonl`（重启不清空）；关掉退回纯内存 |
| `PersistChat` | false | 是否把聊天也写入磁盘（默认关，保护隐私；不影响内存里的聊天事件） |
| `HistoryDays` | 7 | 事件历史保留天数；<=0 不按天清理 |
| `HistoryMaxMB` | 50 | 事件历史目录总大小上限 MB；<=0 不按大小清理 |
| `AllowWebChat` | true | 允许网页端（`/webui/chat`）把文本发到游戏内聊天（带 `[WebUI]` 前缀） |
| `MaxWebChatPerMinute` | 20 | 同一账号每分钟最多经网页发送的聊天条数；0 = 不限 |
| `ChatPrefix` | `[WebUI]` | 网页发言前缀（游戏内与事件流），用于与真实在线玩家区分 |

物资申请的配置字段（`RequestsEnabled`、`Request*`）见 [`插件-物资申请.md`](插件-物资申请.md) §6。

后端环境变量：`TSWUI_AUTH_SECRET`、`WEBAUTH_TIMEOUT`、`TSWUI_ALLOW_INGAME_COMMANDS`（详见 `docs/ARCHITECTURE.md` §5）。

权限：**不提权**——token 就是玩家账号本人所在组（仍需 `tshock.rest.useapi`）；批量执行 / Tier B 每条指令
仍按该组判定，Tier B 不绕过 `AllowServer` 之外的任何限制。**改为默认开需用户确认**。

### 6.1 权限节点一览

**插件自定义节点**（`plugin/WebUI/Plugin.cs` 的 `WebUiPermissions`，共 4 个）：

| 节点 | 级别 | 允许什么 | 备注 |
| --- | --- | --- | --- |
| `webui.use` | 玩家 | `/web auth <验证码>`、`/web deny <验证码>` | 必须游戏内**本人**执行；玩家须已 `/login` 到 TShock 账号。没有任何组持有时控制台警告 |
| `webui.admin` | 管理 | `/web init`、`/web limit [值\|unlimited\|default]` | 两者都还需 TShock 的 `tshock.rest.cfg`（会写 `config.json`） |
| `webui.request.use` | 玩家 | 物资申请：REST `/webui/requests`、`/webui/requests/create`、`/webui/requests/cancel`；网页「物资申请」提交 / 查看 / 撤回 | 详见 [`插件-物资申请.md`](插件-物资申请.md) |
| `webui.request.review` | 管理 | 物资申请审核：REST `/webui/requests/all|review|deliver`、游戏内 `/web req list|show|ok|no|give`、网页「待审核」tab | 审核记录带审核人 |

**依赖的 TShock 内置权限**（插件不发放，须服主自行授予）：

| 权限 | 作用 | 触发点 |
| --- | --- | --- |
| `tshock.rest.useapi` | 铸造 REST token 的资格 | 在线授权 `/webui/auth/request` 前校验，缺则返回 `no_api_permission`；`superadmin` 组豁免 |
| `tshock.rest.command`（`RestPermissions.restrawcommand`） | 批量执行端点 | `/webui/batch`（`SecureRestCommand` 声明此权限）→ 网页批量执行 / Tier B `/api/command`；也是 `/api/me` 的 `canRunCommands` |
| `tshock.rest.cfg` | 改 TShock 配置 | `/web limit` |
| 每条指令**自身**的权限 | 能否跑该指令 | 批量执行 / Tier B 逐条按 token 所属组判定，与 `/v3/server/rawcmd` 同构 |

**不需要权限节点的端点**：

| 端点 | 保护方式 |
| --- | --- |
| `/webui/auth/{request,poll,cancel}`、`/webui/meta`、`/webui/restlimit` | 无 token 要求；靠 `Secret`（配置项，非权限）+ 玩家游戏内确认 |
| `/webui/{commands,me,data,serverinfo,events,chat,auth/sessions,auth/revoke}` | 只要有效 token，不额外要求权限；内容按调用者用户组过滤（区域 / 传送点缺权限返回空、指令目录按 `Command.CanRun` 过滤、`me` 只返回自己） |
| `/webui/chat` | 同上；仍尊重 TShock 禁言（在线且 mute → 403）与 `AllowWebChat` / `MaxWebChatPerMinute` |

**语义细节**：

- 统一入口 `/webui`（`/web`）按 TShock 的 **OR** 语义注册 `webui.use` / `webui.admin` / `webui.request.review` 三个节点——持有任一个即可进入子命令分发；
  具体子命令在 handler 内再细分：`init` / `limit` 要 `webui.admin` + `tshock.rest.cfg`，`req` 要 `webui.request.review`，`auth` / `deny` 额外要求游戏内本人。
- 在线授权登录**不新增任何权限**：铸造的 token 组 = 玩家账号所在组，与 `/v2/token/create` 完全一致。
- 授予示例：

```
/group addperm default webui.use
/group addperm default webui.request.use
/group addperm <管理组> webui.admin
/group addperm <管理组> webui.request.review
```

## 7. 已知限制 / 坑

- 插件不支持热重载：改 DLL 后必须**重启 TShock**。
- **启动报告什么时候出现**：插件初始化在**世界加载之前**，那时打日志会被「正在加载世界数据 / 正在侦听端口」冲掉。
  所以 `[WebUI] REST 端点已注册` / Secret 提醒 / 权限体检现在推迟到 `GamePostInitialize`（世界加载完、端口已监听，
  与 TShock 自己的 UUID / 登录提醒同一段），并在首个 `GameUpdate` 保底补打。启动时看不到这几行 = 日志被清或插件未加载。
- `/web limit` 会修改并保存 TShock 的 `config.json`（属服主明确要求的例外）：只改 `RESTMaximumRequestsPerInterval` 一个字段，需 `webui.admin` + `tshock.rest.cfg`（控制台 / superadmin 满足）；`/webui/restlimit` 只读、不消耗限流桶。
- `/web init` 同样会改动 `config.json`（`RestApiEnabled` / `LogRest` / 限流两项）并给默认组加权限，同样需 `webui.admin` + `tshock.rest.cfg`；只往上调不往下调，详见 §3 的 `/web init`。
- **`LogRest=true` 不会让本插件泄密**：所有 `/webui/*` 端点都声明了 `DoLog=false`（参数里有 `secret`、聊天内容、申请物品），TShock 的 REST 日志只记它自己的端点（`/v2/token/create` 本身也是 `DoLog=false`，且日志里的 URI 已剔除 `token`）。
- **权限隔离**：统一入口 `/web`（`/webui`），功能指令为二级子命令。`auth` / `deny` 面向持 `webui.use` 的玩家组且必须游戏内本人（真正边界是「本人 + 有 TShock 账号 + 组有 `tshock.rest.useapi`」）；`limit` 需 `webui.admin` + `tshock.rest.cfg`。详见 §6.1。`/webui/commands` 指令目录按调用者用户组过滤（与 TShock `/help` 一致），普通玩家拿不到带权限的指令。
- `/webui/auth/*` 在登录前调用，本身不需要 token；真正的安全边界是「玩家在游戏内确认」，
  公网部署务必同时设置 `Secret` 且 REST 端口只对后端可达。
- token 只在 TShock 内存与后端内存，重启即失效；后端识别 `token_invalid` 会清会话回登录。
- Tier B 默认关；开启后仍要求目标玩家在线，且权限不多一分。
- **网页发言不绕过禁言**：目标账号在线且 `TSPlayer.mute == true` 时 `/webui/chat` 返回 403；离线账号无法判定禁言（允许发言）。
- 网页发言走 `TSPlayer.All.SendMessage` 广播，**不经过** `PlayerHooks.PlayerChat`，因此不会触发依赖该钩子的插件（如聊天监听）。

## 8. 验证命令

```bash
# 构建插件
cd plugin/WebUI && dotnet build -c Debug        # → bin/Debug/net9.0/WebUI.dll
# 或：PLUGINS_DIR="$HOME/tr/s/ts/plugins" bash scripts/build-plugin.sh && docker restart tshock

# 探测（未登录，需 Secret 时带上）
curl -s --get 'http://127.0.0.1:7878/webui/auth/request' --data-urlencode "name="

# 网页发言（需有效 token）：会带 [WebUI] 前缀广播，并记入事件流 type=webui
curl -s -X POST --get 'http://127.0.0.1:7878/webui/chat' \
  --data-urlencode "text=大家好" --data-urlencode "token=<TOKEN>"
curl -s -X POST --get 'http://127.0.0.1:7878/webui/events' --data-urlencode "token=<TOKEN>"
```

手动验收（在线授权）：玩家 A 游戏内 `/login` → 网页「在线授权」输入 A 的名字 →
A 收到 6 位验证码 → `/web auth <验证码>` → 网页登录成功。
