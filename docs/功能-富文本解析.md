## 1. 定位与范围

TShock 通过 `/v3/server/rawcmd` 返回的 `response` 行里可能带 Terraria 富文本标签，
最常见的是颜色标签，例如 `/playing` 的输出：

```
在线的玩家([c/AAFFAA:1]/8)
hf
```

WebUI 的**执行结果面板**需要把这些标签渲染成彩色文本 / 物品图标，而不是显示 `[c/AAFFAA:1]` 原文。

- 范围：**只渲染**，不执行、不回传；解析在前端完成（纯函数，无网络）。
- 与「物品 ID 作为指令参数」无关：标签只影响显示（`docs/设计原则与约束.md` §6）。
- 浏览器安全：渲染一律用 React 文本节点 / 受控 `style`，**不使用 `dangerouslySetInnerHTML`**。

## 3. 标签语法

```
[ tag ( "/" options )? ":" text ]
```

- `tag`：1–10 个字母（大小写不敏感）。
- `options`：`/` 之后到 `:` 之前，不能含 `:`；可含 `/`（如 `s21/p81`）。
- `text`：`:` 之后到 `]` 之前，**至少 1 个字符**（空文本标签不匹配）。
- `\[`（前有反斜杠）不视为标签；`text` 内的 `\]` 会被还原为 `]`。

**语义（与 Terraria 完全一致）**

- 标签**只作用于自身的 `text`**，**不向后延续**；标签之后的文本回到默认色。
- 无法识别的 tag、或非法 options → **丢弃标签外壳，只保留 `text`**（不会原样显示 `[x:...]`）。

## 4. Terraria 已注册标签全集 与本项目支持情况

| tag | 含义 | 本项目 | 备注 |
| --- | --- | --- | --- |
| `c` / `color` | 彩色文本 | ✅ 渲染 | 核心需求 |
| `i` / `item` | 物品图标 | ✅ 渲染 | 需 `itemsById` + `atlas`；缺失时按原文显示 |
| `n` / `name` | 玩家名（含鼠标悬浮） | ⬜ 按文本 | 暂时只保留内部文本 |
| `a` / `achievement` | 成就 | ⬜ 按文本 | 同上 |
| `g` / `glyph`、`gx` / `gp` / `gn` | 手柄按键字形 | ⬜ 按文本 | 同上 |

> 未支持的标签不会报错，按内部文本显示；后续需要时按下文「扩展指南」新增。

## 5. 解析算法（`web/src/lib/richtext.ts`）

```ts
export type RichToken =
  | { kind: 'text'; text: string }
  | { kind: 'color'; color: string; text: string }   // color 形如 "#RRGGBB"
  | { kind: 'item'; raw: string; itemId: number; stack?: number; prefixId?: number }

export function parseRichText(text: string): RichToken[]
export function hasRichTags(text: string): boolean
```

- 正则（JS，`s` 对应 .NET 的 `Singleline`）：
  ```ts
  /(?<!\\)\[([a-zA-Z]{1,10})(?:\/([^:]+))?:(.+?)(?<!\\)\]/gs
  ```
- 逐匹配切分：匹配之间的原文 → `text`；`c/color` 且 options 为 3/6 位十六进制 → `color`（归一化为 `#RRGGBB`）；
  `i/item` 且 `text` 为数字 → `item`（从 options 提取 `sN`/`pN`）；其余 → `text`（仅保留内部文本）。
- 无任何标签时返回单个 `text` token，`ResultPanel` 直接输出字符串，避免多余 DOM。

**边界情况**

- `[c/f0a:x]`：3 位缩写展开为 `#FF00AA`。
- `[c/ZZZZZZ:x]`：非法色值 → 按 `text`（`x`）显示。
- `\[c/AAFFAA:1]`：被转义屏蔽，原样显示。
- `[c/55D284:[i:29]]`：嵌套不被支持（正则非贪婪），与 Terraria 行为一致。
- `[c/AAAAAA:]`：空 text 不匹配，按原文显示（Terraria 亦如此）。

## 6. 前端渲染（`ResultPanel.tsx`）

`RichLine` 用 `parseRichText` 一次扫描，按 token 渲染：

- `color` → `<span style={{ color: token.color }}>`。
- `item` → 有 `itemsById` + `atlas` 时渲染 `ItemIcon`；否则渲染 `token.raw`。
- `text` → 纯文本。

颜色渲染**不依赖物品数据**；`itemsById` / `atlas` 缺失时物品标签降级为原文，颜色照常生效。

### 6.1 物品图标的绘制尺寸（与游戏一致）

图标尺寸由 `web/src/lib/iconScale.ts`（纯函数 `iconContentSize`）唯一决定，`ItemIcon` 只负责绘制。
**事实来源（反编译 1.4.5.8）**：

| 事实 | 出处 |
| --- | --- |
| `DrawItemIcon(..., float sizeLimit, ...)` 调用点：背包 / 箱子 / 聊天（含 `CoinSlot.DrawItemCoin`）均传 `32f` | `Terraria.UI/ItemSlot.cs:2847`、`ItemSlot.cs:2500/2525`、`CoinSlot.cs:254` |
| 物品落到世界（物块 / 家具）用 20 / 40，鼠标手持用 9999（不限） | `Terraria.GameContent.Drawing/TileDrawing.cs:8094/8136`、`Main.cs:45892` |
| **只在长边 > sizeLimit 时缩小，从不放大**：`num = max(w,h) > sizeLimit ? sizeLimit / max(w,h) : 1`；`finalDrawScale = inventoryScale * num` | `Terraria.UI/ItemSlot.cs:2965` `DrawItem_GetColorAndScale` |
| `inventoryScale`：背包 0.85 / 聊天 `1 × 0.75` / 热键栏选中格 1.0 | `Main.cs:41768`、`Terraria.GameContent.UI.Chat/ItemTagHandler.cs:37`、`Main.cs:44431` |
| 聊天 `[i:..]` 的占位宽度固定 `32 × 0.75 = 24px`，与实际图标大小无关 | `ItemTagHandler.cs:52` `size = new Vector2(32f) * scale` |

**前端等价公式**（`mode: 'game'`，默认）：

```ts
scale = boxScale(box) * (max(w, h) > 32 ? 32 / max(w, h) : 1)
// boxScale：box/32 > 1 时取整（Math.floor），否则保持小数（即「放大取整、缩小不取整」）
```

`box` 等价于游戏的「一个 32px 图标框的缩放」，即 `inventoryScale × 32`。因此金币（12×12）永远只占
12/32，木剑（32×32）占满，天顶剑（56×56）被压到 32/32 —— 保留「金币天生小、武器天生大」的原生比例。
`mode: 'fit'`（contain 填满方框）是旧行为，仅在确需抹平大小差异时使用。

**采样（插值）方式**：**缩小用双线性、整数倍放大用最近邻**（`lib/iconScale.ts` 的 `shouldSmooth`）。

| 事实 | 出处 |
| --- | --- |
| 画到屏幕时 `Main.DefaultSamplerState = LinearClamp`（双线性）；只有渲染到 render target 才 `PointClamp` | `Terraria/Main.cs:2955` |
| 背包 / 槽位所在的 UI batch 显式用 `LinearClamp` | `Terraria/Main.cs:45824`（`Main.DrawInventory` 在其中，`Main.cs:41752`） |
| 聊天（含 `[i:..]` 图标）在同一套 UI 绘制里（`SpriteBatch.Begin` 未指定 sampler → XNA 默认 `LinearClamp`） | `Terraria/Main.cs:41748`（`chatMonitor.DrawChat`） |

游戏只会**缩小**（`inventoryScale` ≤ 1：0.85 / 0.75），所以缩小时开插值 = 原味（之前用最近邻会在非整数缩放下
产生宽窄不一的硬像素边，比游戏“扎眼”）。而 Web 端大屏需要**放大**（本项目按整数倍，如 2× → 64px）：
整数倍放大用插值会发糊，且贴图四周的透明像素会被混进来、在边缘渗出 1px 虚边 —— 所以放大必须用最近邻。
`ItemIcon` 用 `shouldSmooth(贴图边长, 内容边长) = 内容边长 < 贴图边长` 判断：缩小时开插值、放大与 1:1 时关掉。

**像素取整**：`game` 模式**放大一律取整数倍**（`floor(box/32)`），**缩小仍保留小数**（与游戏的 0.85 / 0.75 一致）。
理由：非整数放大会把整张图重采样一遍（无论插值还是最近邻都会长宽不一 / 发糊）；保持整数倍才能像素无损。
用 `floor` 而非 `round` 以保证不溢出方框。`fit` 模式不做取整。`ItemIcon` 再把内容尺寸与居中偏移四舍五入到设备像素整数。

| 方框 | 放大倍数 | 铜币 12×12 | 木剑 32×32 | 天顶剑 56×56 |
| --- | --- | --- | --- | --- |
| 24 | 0.75×（缩小） | 9 | 24 | 24 |
| 32 | 1× | 12 | 32 | 32 |
| 40（图鉴列表） | 1×（1.25 → 取整） | 12 | 32 | 32 |
| 44（图鉴详情） | 1×（1.375 → 取整） | 12 | 32 | 32 |
| 64 | 2× | 24 | 64 | 64 |

聊天气泡内的换算（`RichLine`）：`text-sm` 14px + `leading-6` 24px 行高，图标 `size={24}`（= 游戏 32×0.75 的占位框）：

| 物品 | 贴图 | 渲染最大边 | 游戏聊天（24px 框） |
| --- | --- | --- | --- |
| 铜币 / 银弹 | 12×12 | 9px | 9px |
| 火把 | 14×16 | 12px | 12px |
| 治疗药水 | 20×26 | 19.5px | 19.5px |
| 木剑 / 铁镐 | 32×32 | 24px | 24px |
| 天顶剑 | 56×56 | 24px | 24px |

> 注：本次改动只影响「小贴图不再被撑满方框」（贴图长边 ≥ 方框时，`game` 与旧 `fit` 结果相同），
> 不引入新的缩放误差；`size` > 32 的方框（图鉴 40 / 详情 44）因像素取整会变为 1×（内容最大 32px），
> 方框本身只作布局占位。

最终实测（同一块 32×32 棋盘贴图）：64px 方框（2× 放大）→ **4096 像素全为纯色、0 混色**；
24px 方框（缩小）→ 320 个混色像素（平滑过渡）。

**数量徽标（`stack > 1`）**：位置贴 `size × size` **方框**右下角（`right-0 bottom-0`），字号随**图标实际尺寸**缩放
—— `fontSize = min(max(9, round(max(content.w, content.h) × 0.5)), maxStackSize ?? 18)`，字体描边模糊量随之缩放
（`round(fontSize × 0.25)`，固定 3px 在 9px 小字号上会糊成一团黑）。

- 旧实现字号跟 `size`（方框）走，在图鉴 40/44px 方框里会算出 18px 的大数字，与旁边 12px 的金币完全不搭。
- 为什么数字不贴到图标角上：实测（Chrome headless 逐像素）会把 9px 的金币盖掉（只剩 5/144 像素可见）；
  方框角 + 小字号才是可用解（金币在方框角时仍保留 54/81 可见像素）。
- 执行结果面板传 `maxStackSize={11}`（默认公式在 24px 方框下为 12–13px，在正文行里偏大）。
- 回归测试：`web/src/components/ItemIcon.test.tsx`。

**悬停提示与指针**：提示左下角固定显示 **`ID · key`**（如 `2665 · GreenDungeonCandelabra`，纯文本，方便直接当参数用）。
底色是**纯半透明黑**（`bg-black/85`，**不加 `backdrop-blur`**），整块 `font-medium`。
**全项目只有一套尺寸**（不再区分 md / lg）：容器 `max-w-96 px-3 py-2.5 text-[15px]`、
图标 **28px**、名称 15px `font-semibold`（按稀有度着色）、属性行 `text-sm leading-5`、页脚 `text-xs`。
最大宽度从 `max-w-80`（320px）放宽到 `max-w-96`（384px）——有些物品描述较长；实测详情左列 384px 时提示宽 **382px**。

实测（Chrome headless）：`backdrop-filter: none`、`font-size: 15px`、`font-weight: 500`、
`background-color: rgba(0,0,0,0.85)`。可悬停看提示的 `ItemIcon` 自带 `cursor-pointer`（手形指针，表示“可交互”；调用方可用 `className` 覆盖）。

**数据**：`data/items-atlas.json` 的 `regions[id] = [x, y, w, h]` 是**贴图原始像素的第一帧**，即 `w`/`h` 就是上面的 `w`/`h`（6195 件中长边 >32 的有 1548 件，最小 12，最大 92）。
