## 1. 定位与范围

物品 ID 是玩家侧的**只读浏览工具**：按集合/关键词找到物品，查看图标与 ID，复制 ID / 名称 / `[i:...]` 标签，
再把标签粘贴进指令编辑器。

- **不是**物品生成/商店/管理后台；本页不发起任何指令或 `/api/*` 请求。
- 图标沿用图集方案（`data/items-atlas.json` 的 `regions[item.icon]` 裁切第一帧），见 `docs/设计原则与约束.md` C10 / C11；
  **绘制尺寸与游戏一致（只缩不放，`sizeLimit=32`）+ 像素取整（放大取整数倍）**，见 `docs/功能-富文本解析.md` §6.1。
- 标签只影响聊天显示，不等同于指令参数（`docs/设计原则与约束.md` §6）。

**数据结构**

```ts
type CollectionGroup = 'category' | 'class' | 'friend' | 'range'

interface ItemCollection {
  id: string          // `${group}:${name}`，全局唯一，用作 <select> 的 value
  name: string        // 显示名（保留原始书写，含 emoji / 省略号）
  group: CollectionGroup
  ids: number[]       // 保留原始书写顺序，仅去重
}
```

- `COLLECTION_GROUPS` 决定分组侧抽屉里的**分组顺序**：集合 → 职业 → 水友专属 → ID 范围（最常用的在前）。
- `COLLECTIONS_BY_ID` 提供 id → 集合 的 O(1) 查找。
- `resolveCollectionItems(collection, itemsById)` 按集合内顺序解析为物品，缺失 ID 自动跳过（不报错）。

## 4. 页面模板（布局）

```

├─ 工具条：**不套卡片**（直接铺在页面上，与结果区一致）
│   └─ 桌面单行、手机两行：**搜索框与结果数紧挨着占第一行，一级模式 / 分组从下一行开始**；
│       **页面设置与全屏按钮在内容区顶栏右侧**（`TopBarActions`），不再占工具行
│       - 搜索框：`max-w-sm`，`InputGroup`，防抖 180ms；打字不自动弹历史，只点「最近搜索」按钮展开
```

**状态保留**：**主筛选方式（`mode`）/ 集合 / 游戏分组页签** / 搜索词 / 滚动位置 / 选中项都放在 `lib/dexState.ts` 的 `DexState` 里，
卸载时写进**模块级内存**（`rememberDexState`），再次挂载即还原 —— 因此「切到其它模块再回来」状态不变；
**刷新页面会清空模块内存**，于是回到默认状态（默认「全部物品」、滚动到顶部）。
测试用 `resetDexState()` 隔离（语义上等价于刷新）。

页面高度由 `useLayoutEffect` 实测得出，两处坑都踩过并修掉：

1. **写死 `calc(100dvh-7rem)`** 比真实可用高度小 64px → 下方留一条空白。
2. **用「视口 − `rect.top`」算高度**：从其它长页面切过来时容器 `main.scrollTop > 0`，
   `rect.top` 会偏小（甚至为负，例如滚了 300px 时 `24 → -276`）→ 高度算成 `1065`（真实 765）→
   **`main` 变成可滚动**，于是在左右空白处滚轮会带着整个页面（连输入框）一起滚。
   现在改成先减掉容器滚动偏移：`可用高度 = 容器 clientHeight − (rect.top − 容器顶 + 容器 scrollTop) − padding`，
   并在挂载时把容器 `scrollTop` 复位为 0；网格滚动容器另加 `overscroll-contain` 阻断滚轮链式传递。
   高度测量统一走 `hooks/usePageHeight.ts`，只用 `ResizeObserver` + `window.resize`；
   **不要**再加 `MutationObserver` 盯子节点 —— 虚拟列表每挂/卸一行都会触发一次 `measure()`，
   滚动时会频繁强制回流，明显掉帧。

### 4.0.1 滚动位置还原（切模块回来）

滚动位置记在 `DexState.scrollTop`（模块内存），但**渲染不能直接用它**：

- 挂载那一帧滚动容器还没有固定高度（`pageHeight` 未生效），浏览器会把 `el.scrollTop = 上次位置`
  静默夹回 `0`；而虚拟窗口按旧位置算，格子画在几千像素之外 → **可视区一片空白**（切回来大概率复现）。
- 现在：先只渲染占位高度，等 `pageHeight` 就绪后，在同一个 `layout effect` 里量尺寸、
  设 `scrollTop`（读回浏览器夹取后的真实值）再放开格子渲染；这一切发生在首次绘制前，不闪、也不多挂一轮格子。
- 滚动事件用 `requestAnimationFrame` 合并，且**只有可视行窗口变化时才 `setState`**（行内小幅滚动不重渲染）；
  持久化用的位置放在 ref 里，滚动本身不触发整页重渲染。

### 4.1 尺寸与格子样式

| 项 | 规则 |
| --- | --- |
| 图标框 | **恒定 64×64**（= `sizeLimit` 32 的 2 倍）→ `mode='game'` 下是整数 2× 最近邻放大（不糊、无 1px 虚边） |
| 格子尺寸 | 仅图标 76×76（手机 68×68），带文字 110×110（手机 88×88）；横纵间距统一 4px。列数按容器宽度计算（不再有 10 列上限），**剩余宽度均摊给每格**，右侧不再留空白；全屏同理 |
| 格子高 | 固定 **110**（内边距 12 + 图标 64 + ID 行 14 + 名称行 20） |
| 间距 | 8 |
| 外观 | `rounded-xl`、**无默认底色**；**整块格子** hover `bg-primary/10` 并轻微上浮 2px、选中 `bg-primary/20`（取自主题令牌）；图标本身无背景框，不使用投影；整格 `cursor-pointer` + `focus-visible:ring-2` |
| 提示锚点 | 绑在 `ItemIcon`（64×64 图标区域）上；ID / 名称文字不弹提示，避免遮挡卡片 |
| 采样 | **缩小用插值**（同游戏 `LinearClamp`）、**放大用最近邻**（`lib/iconScale.ts` 的 `shouldSmooth`） |

> 之前自定义格子描边时用过 `outline` + 负 offset（保证"朝内"且不占布局）——随自定义样式一并取消，
> 现在格子外观直接由主题令牌决定，hover / 选中都不会改变尺寸。

> 实测（Chrome headless + 探针，1440×900）：格子底色 `rgba(0,0,0,0)`（**无白底**）、图标 **`64px`**、格子 `130×110`、一行 **10 个**；
> 在格子的**图标区域**派发 `mouseover` → 提示出现；
> **复现"先停在长页面滚 300px 再切到图鉴"**：修好后 `mainScrollTopAtMount=0`、`mainScrollable=0`、`overscroll-behavior-y: contain`；
> 点格子 → `role="dialog"`、宽 `576`（`max-w-xl`）、打开后 `main` 仍不可滚；弹框内中间区域滚动（标题 / 底部固定）；
> wiki 链接实测 `…/zh/wiki/%E7%81%AB%E6%8A%8A`（返回 200）。

## 5. 交互规则

| 场景 | 行为 |
| --- | --- |
| 默认（全部物品，无搜索） | 按**原始顺序**一次展示全部结果（**无翻页控件**）；结果数紧挨搜索框显示 `6195 个结果` |
| 刷新页面 | 模块内存清空 → 回到默认状态（全部物品、滚动到顶部） |
| 切到其它模块再回来 | 状态**原样保留**（主筛选 `mode` / 集合 / 游戏页签 / 搜索 / 滚动位置 / 选中项） |
| 输入关键词 | 在当前池子内搜索（`searchItems`，按匹配分数排序），并把网格**滚动复位到顶部** |
| 一级模式（`ToggleGroup`） | 全部物品 / ⭐ 收藏（`DexState.mode` + `favoritesOnly`）；一键切换；切换会清空分组筛选并**复位滚动到顶部**；「再点一次」含义见下 |
| 全部物品（默认） | 按原始顺序一次展示全部结果；**再点一次** = 清空搜索词与分组、回到顶部 |

### 5.1 首开性能

- App 在数据集加载完成后的浏览器空闲期预取 `ItemsPage` 路由 chunk，并预热 / 解码 `items-atlas.png`；桌面悬停、触摸按下、键盘聚焦物品图鉴入口时也会立即触发同一预热。
- `loadAtlasImage()` 在 `onload` 后调用 `img.decode()`，避免首次 `drawImage` 时才同步解码约 1.9 MB 的整张图集。
- `ItemsPage` 首帧不立即挂虚拟格子，等 `usePageHeight` 与滚动容器实测尺寸提交后，再按真实列数挂可视行；overscan 为 1 行。
- 浏览器 PerformanceObserver 实测（DevTools 移动视口、Mock 数据）：优化前切页出现约 **474ms** 长任务；优化后为约 **77ms**，路由 chunk 已在空闲期加载，不再出现在点击时的资源等待中。

## 6. 设置按钮位置修复（跑偏）

- **现象**：点击侧栏底部「设置」后，面板出现在错误位置（向左溢出屏幕、向下超出视口）。
- **原因**：面板使用 `absolute right-0 mt-2 w-72`，而容器在**左侧栏底部**、宽度仅 240px：
  右对齐 + 288px 宽度导致面板向左溢出，向下展开又超出视口。
- **修复**（`web/src/components/SettingsMenu.tsx`）：
  - `right-0 mt-2` → `bottom-full left-0 mb-2`：改为**向上展开、左对齐**（按钮在底部，上方空间充足）。
  - 增加 `max-w-[calc(100vw-1.5rem)]` 与 `z-50`，防止小屏溢出。
  - 补充 `role="dialog"` / `aria-label` / `aria-haspopup`，改善可访问性。

## 14. 游戏自身的物品分组（v1.4 / v1.5）：创意菜单页签

游戏创意菜单的 11 个分类页签**作为「分组」侧抽屉的第一个手风琴分区**显示（放在集合分组之前），
始终可见，不再占据工具条右侧的独立页签栏。

### 数据来源（`data/item-groups.json`）

- **页签**：`Terraria.GameContent.Creative.ItemFilters`——与游戏
  `UICreativeInfiniteItemsDisplay` / `NewCraftingUI` 构造时使用的过滤器列表**完全一致**（顺序也一致）：
  武器 / 盔甲 / 时装 / 物块 / 家具 / 配饰 / 装备 / 消耗品 / 工具 / 材料 / 其他（MiscFallback）。
- **物品分组 / 组内顺序**：`ContentSamples.CreativeHelper.GetItemGroup` 与
  `ContentSamples.ItemCreativeSortingId`（即 `ByCreativeSortingId` 排序用的 `ItemGroup` + `OrderInGroup`）。
- 生成：`tools/gamedump/Program.cs` 的 `DumpItemGroups`（先用反射调
  `Main.Initialize_TileAndNPCData1/2` 填充物块/家具所需的 `tileSolid` / `tileFrameImportant`，否则分组会全错）
  → `tools/gen-item-groups.mjs`。

### 行为

- 点页签 → 进入游戏分组模式，只显示该页签内的物品；**一个物品可同时属于多个页签**（如生命水晶同时在消耗品与材料，与游戏一致）。
- 只要处于游戏分组模式就**按游戏 `ByCreativeSortingId` 顺序**（`ItemGroup` 值 → 组内顺序）展示，**不洗牌、也不显示「换一批」**。
- 页签在 `Accordion` 分区内以**两列按钮**呈现（`aria-pressed` 标识当前页签），点选后 Popover 关闭。
- 文案在 `web/src/lib/i18n.tsx` 的 `dex.tab.<id>`，与游戏 `CreativePowers.Tab*` 官方文案对齐（无「全部」页签）。
  （故意**不**改 `loc.<culture>.json`，避免为了几个 UI 标签重生成全部本地化数据。）

### 为何不用 `ItemGroup` 当页签

`ItemGroup` 有 53 个有物品的分组（如 `RemainingUseItems` / `ConsumableThatDoesNotDamage`），是**内部排序**枚举，
不是玩家能认出的分类；游戏里真正的分类**页签**是 `ItemFilters`，且有官方文案。故页签用 `ItemFilters`，
`ItemGroup` 用于组内排序。两者都已落在 `item-groups.json`（`tabs` 与 `items[].g/gv/o/t`）。

- **为了「两列」时的左右对齐会做局部微调**：单配方方块排前面，**配方条数多的方块（手机 / 全球定位系统 / 魔镜、
  泰拉靴线里的熔岩靴 / 幽灵靴）排到最后**——否则一行只有 1 行、一行有 5 行，两列会参差不齐。
  因此**不再强求**「材料一定在产物后面」（已在 `recipeCategories.realdata.test.ts` 里去掉这条硬约束）。
- **每件物品先看「合成表」**（怎么做出它）；如果它**本身没有配方**（只能捡 / 买的，如猛爪手套、泰坦手套、
  邪恶臂环、银护腕、蛇形手环），该方块改为显示**「用于合成」**（它被用在哪些配方里），保证列出的物品都有内容。
  方块的**右上角只在「用于合成」时标「用于合成（n）」**——页面本身就是合成表，再写一遍「合成表（n）」是冗余的。
- **hover 是「整张卡片」的**（与物品格子同一套反馈）：鼠标滑过某个方块时，**整块底色加深（`hover:bg-primary/10`）
  并整体上浮 2px**（`-translate-y-0.5`，150ms 过渡）；同时**该行右端浮出「复制」按钮**
  （复制这一条的文本，是否带 `[i:ID]` 由「复制含标签」勾选框决定；`RecipeRow` / `ShimmerRow` 与详情里共用）；
  滑到物品图标上约 350ms 后弹出物品提示。行本身不再单独变色。
- **只显示「微光嬗变」内容、不显示「可丢微光分解」**：物品有微光转换时，方块里追加 `源 → 目标` 行
  （行首固定 **5362** 图标）。「可丢微光分解」只在详情抽屉里显示。
  注：当前 11 个大类的物品在 `data/shimmer.json` 里**都没有微光转换记录**（微光主要作用于矿石 / 物块 / 火把），
  所以速查页目前不会出现微光行；代码已就绪，将来加大类（如矿石 / 物块）会自动出现。
- 配方行复用详情里的 `RecipeRow`（`RecipePanel` 导出）：hover 右上角复制按钮、`iconOnly` / `copyTags` 与详情共用开关。
- 「两列」勾选框（`tswui:dex:recipeTwoColumns`，跨刷新记忆，默认关）：勾选后容器宽度 ≥900px 时左右两列（容器查询 `@[900px]`，
  与「数据ID」图格的两列表格同一个思路）；两列时每个方块 `items-start`，不被同行最高的方块拉伸。
- 大类清单（当前 11 个，**`宝石` 已移除**）：
  `手机` `天顶剑` `药水` `泰拉靴` `召唤物` `制作站`
  `手套`（烈火 / 狂战士 / 机械 / 强力 / 邪恶之爪）、
  `护盾`（十字章护盾 → 十字章护身符 → 5 个免疫饰品 → 黑曜石护盾 → 黑曜石骷髅头，
  最后是**英雄护盾 / 冰冻护盾 / 银盾 / 恢复之盾**）、
  `天界贝壳`（天界贝壳 → 天界石 + 月亮贝壳）、

  `1.4.5`（**最右**：炽天使项链 / 交错心形项链 / 秘术腰带 + 鹰身女妖护符 / 碎裂之石 / 淬毒刺 /
  邪恶臂环 / 银护腕 / 蛇形手环 / 钴护盾 的「用于合成」记录）。

  （炽天使项链 / 凤凰箭袋），所以 `RecipeCategory.useOnly` 把它强制成「用于合成」。
- **材料之间的微光转换关系另起一条独立记录**（`ShimmerRelRow`，**不塞进配方行里**，只在本页显示，
  物品详情抽屉里不显示）：
  - **互为转换**（A→B 且 B→A）→ `[5362] 甲 ⇄ 乙 微光可互转（只需其中一种）`
    例：`盔甲抛光剂 ⇄ 维生素`（十字章护身符的 5 个组件都是这种成对关系）、`攀爬爪 ⇄ 鞋钉`。
  - **单向链条**（A→B、B→C…）→ `[5362] 甲 → 乙 → 丙 微光可按箭头方向依次转换`
    例：`渔民袖珍宝典 → 六分仪 → 天气收音机`（探鱼器）、`钻石 → 红玉 → 翡翠 → 蓝玉 → 黄玉 → 紫晶`（宝石类）。
  - 判定：只用 `data/shimmer.json` 的**直接**转换（`S[a] === b`），**不做跨物品过桥推算**，
    所以没有直接关系的两件材料不会被凑成一行；同一条链/环只出一行。
    全库共 15 组（5 组互转 + 10 条链）。
- 大类配置在 **`web/src/lib/recipeCategories.ts`**（人工维护的 id + 顺序，理由见该文件头注释）：
  静态配置而不是从 `data/` 算，是因为游戏里有**反向（拆解）配方**（`木平台 → 木材`、`土墙 → 土块`），
  自动算依赖深度会被环带偏，顺序不可控。
  配置由 `web/src/lib/recipeCategories.realdata.test.ts` 用真实 `data/recipes.json` 校验：
  id 存在且**有配方或有用途**、无重复、中英名可解析、页签顺序（`宝石` 已移除 / `1.4.5` 在最右 / `手套` 在它左边）
  （`手套`、`1.4.5` 里那些无配方物品必须有用途，否则页面会空）。升级游戏版本跑一次测试即可发现问题。
- **仅图标时「可丢微光分解」也只留 5362 图标、不显示文字**（`DecraftTag` 的 `iconOnly`），
  与之同理的还有配方组「任何XX」（见 `功能-合成表与物品提示.md` §4 的 34 个配方组清单）。

## 25. 改版记录（v1.15）：合成表页签 = 一棵棵完整合成树（脑图）

> 本节取代 §22.2 里「逐个物品列配方」的展示方式（数据 / 大类配置 / 微光记录仍按 §22.2 执行）。

### 25.1 为什么改

原来的展示是**扁平配方列表**：每个物品一个方块、方块里若干条配方，每条只回答「这一层怎么合」。
一个成品要往下拆 4–6 层（贝壳电话 → 手机 → PDA → GPS → 金表 → 金锭 → 金矿），玩家得在好几个方块之间
来回对照拼接，同一材料（金锭 / 木材 / 瓶装水）在多行里重复出现，也看不出「到底要准备多少」。

第一版改成**竖向缩进列表**（`├─` 缩进）后仍然要顺着缩进一行行读，层次不够直观；最终改成**脑图**：
根在左、材料向右一列列展开，父子关系用曲线直接连出来（同层对齐 → 一眼看出「第几层」）。

### 25.2 新的结构（脑图）

```
├─ 工具条卡片：大类 Tabs（**「两列」勾选框已移除**：脑图需要整行宽度）
└─ 配方区（内部滚动，data-testid="dex-recipes"）
   └─ 每个大类 = 若干棵**完整合成树**（data-testid="recipe-block"，data-kind="make"）
      ├─ 脑图画布（data-testid="craft-tree-map"，超宽横向滚动）
      │   ├─ 根（成品）在最左，材料向右一列列展开（同层同一列）
      │   ├─ 曲线连线（SVG <path>，data-testid="craft-tree-links"）
      │   ├─ 每个节点 = 物品卡：图标 + 名称 + `×N` + 制作站 + 环境条件
      │   ├─ 多配方节点的右上角有数字角标，点一下循环切换
      │   ├─ 点节点 = 展开 / 收起它的材料（折叠节点带折角提示；桌面默认全展开，窄屏默认只开第一层）
      │   └─ 节点会按容器宽度放大（浅树铺满一行），仍放不下才整体缩放、再不行才横向滚动
      ├─ 树下方：**基础材料汇总**（叶子合并去重后的总数量 + 制作站并集，data-testid="craft-summary"）
      └─ 根物品的微光嬗变 / 材料之间的微光互转（与 §22.2 相同，另起记录）
```

尺寸（`craftTree.ts` 的 `CraftTreeMetrics`）：节点宽 164（**浅树会按容器放大到最多 200**，见
`fitCraftTreeMetrics`）、列间距 28、行高 28、行距 6。实测（1:1 尺寸）：贝壳电话 1324×510、
天顶剑 1308×650、超级治疗药水 1116×198。

- **每件成品只出现一次**：已经出现在别的物品合成树里的物品，不再单独占一个方块。
  「手机」大类因此从 9 个方块收敛成 1 棵树（贝壳电话），「天顶剑」1 棵，「十字章护盾」1 棵；
  药水 / 召唤物 / 制作站这类互不依赖的成品仍是多个方块（每个一棵自己的树）。
  例外：`useOnly` 指定的物品、以及本身**没有配方**的物品（只能捡 / 买）仍显示「用于合成」方块
  （`data-kind="use"`，`RecipeRow` 列表，未改成脑图）。
- **默认全部展开**（完整链路一眼看完，不用一节节点开）；点节点可以单独收起某一支，
  汇总行右侧有「全部收起 / 全部展开」和「复制基础材料」。
  **窄屏（容器 < 640px）默认只展开第一层**——手机上全展开只会变成一条要横拖很远的长带。
- **先用满宽度，再考虑缩放**：
  1. `fitCraftTreeMetrics`：层数少的树把节点放大（164 → 最多 200），让整张图铺满一行
     （例：药水的 4 层树节点变宽，名称不再被截断）；
  2. 仍超宽则整体等比缩小（`scale = clamp(容器宽 / 画布宽, 0.8, 1)`），所以桌面「全部展开」通常正好铺满；
  3. 缩到 0.8 还放不下（手机）才横向滚动，左右边缘出现 40px 渐隐提示。
  收起几支后画布变窄，缩放自动回到更大字号。
- **脑图始终显示名称**：不再跟随详情抽屉的「仅图标」勾选（图标墙认不出物品），
  速查页的「用于合成」方块同样强制显示名称；「仅图标」只影响物品详情抽屉里的配方行。
- **数量按整次合成取整并穿层相乘**，以 `×N` 文本跟在名称后面（图标不再叠加数字角标——20px 图标上
  「×32」会盖住贴图）：`铁锭 ×5 → 铁矿 ×15`（一次合成出 1 个锭、每个锭 3 个矿）。
  汇总里的叶子数量 = 各分支需求之和（`金表 10 + 魔镜 8 = 18 个金锭 → 72 个金矿`）。
- **多配方**：节点右上角一个很淡的数字角标（如 `2`），点击循环切换（默认选**材料最少**的那条，
  不并排铺开 17 条）。切换按物品 id 全页共享（`RecipeLookup` 的 `choices`），换大类 / 重挂载后复位。
- **配方组**（34 组）当叶子：只显示「任何木材 / 任何铁锭」+ 代表物品图标，不展开成子树（数量照常累乘）。
- **微光**：树的每条配方都参与「材料之间微光互转」判定（`ShimmerRelRow`），所以嵌套在树里的链
  （如 探鱼器 的 渔民袖珍宝典 → 六分仪 → 天气收音机）仍会在方块里出一条；根物品的「微光嬗变」照旧。
  「用于合成」方块也显示它自己的微光转换行。
- **名称与数量**：名称始终显示（过长时截断，悬停看物品提示）；`×N` 紧跟名称，
  制作站图标贴在节点右端。
- **「两列」勾选框已移除**（`StorageKeys.dexRecipeTwoColumns`、`recipe.twoColumns` 文案一并删除）：
  一列脑图 + 一列空白的两列布局没法读，速查页固定单列、整行宽度给脑图。
- 复制：节点 hover 时右上角浮出复制按钮，复制该条记录（`材料 @ 制作站(条件) → 产物`，与详情一致）；
  汇总行的复制是**基础材料清单** `金锭 x2 + 铁矿 x72 + …`（是否带 `[i:ID]` 跟随「复制含标签」）。

### 25.3 关键实现与数据坑

| 事项 | 位置 / 做法 |
| --- | --- |
| 建树 / 汇总 / 数量 | `web/src/lib/craftTree.ts`（纯函数）+ `craftTree.realdata.test.ts` |
| 脑图布局 | `layoutCraftTree()`（右手 tidy tree，纯函数）：同层 x 固定、父节点垂直居中于子树；返回节点坐标 + 连线 SVG path。尺寸常量 `DEFAULT/COMPACT_CRAFT_TREE_METRICS`；单测 `craftTree.test.ts` |
| **反向（拆解）配方** | 递归时过滤掉「材料能沿配方回到本物品或任意祖先」的配方：`铁锭 ← 铁栅栏`、`玻璃 ← 玻璃平台`、`木材 ← 木平台`、`黑曜石 ← 黑曜石墙`。全部配方被过滤掉的物品（木材 / 黑曜石 / 硬币…共 419 件）当基础材料 |
| 环检测 | 走「材料 → 产物」的完整可达集（含配方组代表物品），所以经过配方组的环也能识别 |
| 根节点特例 | 游戏里少数物品是**真实互转**（`血肉克隆台 ⇄ 骨头焊机`，两边都是正经配方）。只对**根**放开这类配方（`allowCycleRecipe`）：会绕回根的那件材料显示成基础材料、不再展开；嵌套节点永远不选它 |
| 深度兜底 | `MAX_DEPTH = 8`（真实数据最深 6 层，天顶剑 36 个节点） |
| 大类方块计划 | `planRecipeCategory()`（`web/src/lib/recipeCategories.ts`）：先算每棵树覆盖到的物品，再只保留根；`useOnly` / 无配方物品走「用于合成」 |
| 配方选择 | `craftRecipeCandidates()`：过滤不可用配方后按「材料少 → 产出多 → 原始顺序」排序 |
| 铺满宽度 | `fitCraftTreeMetrics()`：按容器宽度反解节点宽度（164→最多 200），层数少的树把一行铺满；仍超宽才 `scale` 缩（≥0.8），再不行横向滚动 |
| 窄屏 | 容器 < 640px 时默认只展开第一层（`compactViewport`） |

- 「基础材料汇总」按**当前选中的配方**计算；切换配方会同时改变树和汇总。
- 谓词「每件成品只出现一次」按**默认配方**判断覆盖；若某个成品的默认配方不含某件材料（该材料另一条配方才用），
  这件材料仍会单独成块（例如药水类里的治疗药水）。
- `useOnly` 物品即使已经出现在别的树里，也仍保留自己的「用于合成」方块（配置明确要求看它的用途）。
- 方块 hover 仍是「整块底色加深 + 上浮 2px」（与 §22.2 一致）；脑图节点 hover 时该节点单独高亮
  （`hover:bg-accent/60` + 主题色边框），方便在长树里跟住当前节点。
- 手机上画布通常仍比屏幕宽：先按 0.8 倍缩放，再横向拖（左右边缘渐隐提示）；根节点带主题色边框 +
  轻微阴影，作为方块标题。
