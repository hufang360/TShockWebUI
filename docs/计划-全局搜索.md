# 计划：全局搜索（侧栏）

> **状态：已实施（2026-11-07）。** 当前行为以 [`功能-全局搜索.md`](功能-全局搜索.md) 为准；
> 本文件保留方案、取舍与分期（实施偏差见 §10 末尾）。

## 1. 目标与定位

侧栏常驻一个搜索框：任意页面输入关键词，就能在**物品 / NPC / Buff / 图格墙 / 指令 / 页面 / 玩家**里找到目标，
并把它带到能继续操作的地方。

三条体验目标，按优先级：

- **不打断**：物品就地打开详情（不跳页）；复制类动作不跳页。
- **落地能接着用**：需要跳页的域，跳过去就带好搜索词 / 选中项，不是跳到页面顶部再让用户重搜。
- **可预期**：分组、排序、每行显示什么，全站一致；命不准就不显示，不做「猜你想要」。

它**不是**命令面板（不做「切换主题 / 退出登录 / 执行指令」这类动作），也不替代各页面自己的搜索框。

## 2. 范围

做：

- 侧栏输入框 + 分组结果面板 + 键盘操作 + 无障碍（combobox / listbox）。
- 静态数据域（无需登录）：页面导航、物品、NPC、Buff、图格 / 墙、指令、物品集合。
- 登录后追加：在线玩家（数据 `App` 已有）。
- 每条结果一个**主操作**；组标题右侧提供「全部 N 条」跳转到对应页面并带上搜索词。

不做（v1 明确排除）：

- 不做语义 / 拼音 / 模糊匹配：只做字面匹配（大小写不敏感），避免「看起来匹配其实不对」。
- 不发任何服务器指令、不代管理员身份（沿用 `设计原则与约束.md` C5 / C6）。
- 不搜本地文件（`.plr` / `.wld` / 精灵图），不搜聊天消息、服务器动态、世界地图内容。
- 不搜鱼店货架 / 物资申请条目（数据在各自页面内部拉取，`App` 层没有缓存，见 §8）。
- 不新增设置项，不改各页面现有搜索框行为。

## 4. 交互规格

### 4.1 入口

- 侧栏页头**第二行**常驻输入框（标题行下方、「首页」之上），宽度随侧栏；导航滚动时它不动。
- `Ctrl/Cmd+K` 聚焦（桌面）。`/` 不占用：各页面自己的搜索框已经在用 `/`，会抢焦点。
- 移动端：侧栏是抽屉，抽屉里同一输入框可用；**打开抽屉不自动聚焦**（否则键盘顶起来，导航看不见）。
  是否在顶栏加一个搜索图标入口见 §9 D5。

### 4.2 结果面板

- 锚定在输入框下方的浮层（portal，比 16rem 的侧栏宽，约 26rem），最大高度 `min(60vh, 28rem)`，内部滚动。
- 分组标题：小字类别名（如「物品」）；每组最多 **3 条**，总计最多 **12 条**。
  被截掉的由组末行的「更多」进二级（组内前 20 条）承接，超 20 条的才跳页 + 带词。
- 行结构：图标（24px）+ 名称（超长截断）+ 右侧弱化的次要信息（ID / 分类）。**不加二级说明文字。**
- 输入 ≥1 个字符即搜索，防抖 120ms；输入法组合期（`isComposing`）不触发。
- 空查询：显示「最近搜索」（≤5 条，规则见 `功能-搜索记录.md`；新键 `tswui:global:searchHistory`）。
- 无结果：单行「没有找到「xxx」」。
- 点击 / 回车执行主操作后面板收起；`Esc` 收起并清空；点外部收起；切页时清空（不留过期结果）。

### 4.3 键盘

`↑` / `↓` 跨组移动高亮（鼠标悬停同步），`Enter` 执行高亮项（默认第一项），`Esc` 收起，`Tab` 离开收起。
无障碍走 combobox 模式：输入框 `role="combobox"` + `aria-expanded` / `aria-activedescendant`，
结果 `role="listbox"`，分组 `role="group"` + `aria-label`，行 `role="option"`。

## 5. 匹配与排序

- 数字查询：各域的 ID 字段参与评分，组内「精确 > 前缀 > 包含」；组顺序不因得分变化。
- 组顺序固定：**页面 → 物品 → 指令 → NPC → Buff → 图格 / 墙 → 物品集合 → 玩家**。
  页面与物品最高频，放最前；登录门控的组（玩家）在不可用时整组不出现，不留空标题。
- 组内沿用各域已有的匹配函数（`searchItems` / `searchTargets`、NPC 的 `name` / `key` / `sb` / 别名、
  Buff 的 `name` / `key`、指令的 `name` / `aliases` / 中英帮助），保证「全局搜索的结果」与「那个页面里的结果」口径一致。
- 需要补两张小词表（放 `web/src/lib/`，可单测）：
  - **页面别名**：如「物品 / ID / 图鉴」→ 物品 ID 页，「数据 / NPC / 图格」→ 数据 ID 页；
  - **指令别名**：`dataset.commands` 已含 `aliases`，只需补 `zh` 帮助参与匹配（默认就参与，无需新表）。

## 6. 跨页跳转：`searchIntent`（新机制）

沿用 `lib/editorView.ts` 的模块级一次性意图模式（页面还没挂载也能收到），新增 `web/src/lib/searchIntent.ts`：

```ts
requestSearchIntent({ tab: TabId, query: string, kind?: 'npc' | 'tile' | 'wall' | 'buff', collectionId?: string })
useSearchIntent(tab, apply) // apply 必须是稳定引用
```

各页面的消费改动都很小（各 5–10 行，不改现有本地状态逻辑）：

- 数据 ID：切到对应 `kind` + 写入 `query`（精确定位到某条留 P2，当前只按词过滤）。
- 指令小抄：写入 `query`。
- 玩家管理：把名字作为查询词。
- 物品图鉴：集合走 `searchIntent.collectionId`（物品本身继续复用现有 `dexFocus` / `onOpenInDex`）。
- 鱼店（P2）：打开商品详情。

## 7. 性能与加载

- 预建小写索引（页面 / 指令 / 物品名 / NPC / 图格名），界面语言或数据集变化时重建一次；
  一次按键扫描 ~8k 条，成本可忽略，不需要 worker 和预计算 trie。
- 图标：物品图集首屏已预加载；NPC / Buff 图集按需懒加载（与「数据 ID」页共用同一个 Promise 缓存）。
  图集没就绪时先出占位，不阻塞结果列表，也不因加载失败报错。
- 组内 3 条封顶，不需要虚拟滚动。

## 10. 分阶段实施

### P1（本次）

1. `lib/searchIndex.ts`（各域匹配器 + 小写索引）+ `lib/searchIntent.ts` + 单测。
2. `components/GlobalSearch.tsx`（输入框 + 面板 + 键盘 + 无障碍），移动端宿主复用同一内容组件。
3. `AppShell` 页头第二行接入；`App` 传入 `nav` / `dataset` / `players` / 能力门控。
4. 三处页面消费 `searchIntent`：数据 ID、指令小抄、玩家管理；物品集合走 `searchIntent.collectionId`。
5. i18n（中英）、测试（组件 + 索引 + intent）、`docs/功能-全局搜索.md`、`docs/UI组件.md` 组件条目、
   `docs/功能-总览.md` 一行、`changelog.md` 未发布段与单版本文档。

### P2（另开任务）

- 鱼店商品：先在 `App` 或专用 hook 里做「按服务器 + 能力探测」的懒取缓存，再收录该组。
- 精确跳条目：数据 ID 滚动定位到某条 NPC / 图格并高亮。
- 动作类命令（切换主题 / 语言、重新登录）—— 需要另外确认范围，默认不做。

### 实施偏差（已落地）

- 图格 / 墙**拆成两组**（原来合并成「图格 / 墙」），行右侧统一显示 `#id`（组名已经说明类别，不用重复）。
- 新增**鱼店商品**分组：`lib/fishGoodsCache` 按服务器缓存货架，打开弹框时才懒加载（未登录 / 鱼店模块没开时整组不出现）。
- 行内操作（复制 ID / 复制指令 / 填入浮动终端）用 `aria-hidden` 的点击区 + 悬停/选中显示，
  因为 `role="option"` 里不能放真按钮；填入终端在终端不可用（未登录）时**不显示**，避免点了没反应。
- 快捷键在**抽屉 / Popover 开着时也生效**（只让位给模态弹框）：看商品详情时也能直接搜。
- **不再搜玩家名**（用户确认移除）：玩家名由「玩家管理」页自己查，搜索不做「查号」入口；
  玩家管理的 `useSearchIntent` 消费也随之删掉。
- 指令结果支持**就地执行**（二级页显示结果）：`allowServer !== false` 且已登录时 `Enter` 直接跑，
  其余情况仍然跳到「指令小抄」。执行走 `transport.runCommand`，与指令页同一条通路。
- 行内操作改到**悬停 / 高亮时浮在右侧信息之上**（绝对定位），不再给按钮预留 44px，右侧不再有空白。

- **「全部」改成弹框内的二级列表**（用户确认，替代直接跳页）：一级组末行是「更多」+ 命中数，进二级看前 20 条；
  二级末尾在命中 > 20 时才留「更多」+ 目标页名。二级里可继续改词在组内过滤，词清空回一级。
- **指令主操作：一律就地执行**（用户确认，替代早先「必填参数 → 填终端」）：数据里的 `required` 由
  `tools/gen-data.mjs` 从 TShock `Commands.cs` 解析，`/help`、`/userinfo` 这类可省略参数的指令会被误标成必填，
  拿它拦执行会挡住本来能跑的指令。改为：缺参数就让 TShock 回用法错误，失败时结果下给「查看用法」（+ 标了必填参数的
  再给「填入终端」）。`allowServer=false` / 未登录仍然只跳「指令小抄」。
- **层级返回 + 60s 位置记忆**：`Esc` 逐级退（执行结果 → 二级 → 一级），一级才关弹框；
  位置存在 `lib/searchDrill.ts`（模块级 + TTL，不进 localStorage）——因为弹框每次开关都重挂载，
  component state 留不住。cmdk 本身没有这套机制。
- `Esc` 的处理必须在 `DialogContent` 的 `onEscapeKeyDown` 上：Radix 的 DismissableLayer 在 document
  **捕获阶段**就吃掉了 Escape，写在 `Command` 的 `onKeyDown` 里收不到（或已被 preventDefault）。

- **D1 最终定为「一个独立弹框」**（用户确认）：桌面侧栏那行是「长得像搜索框的按钮」，点它 / `Ctrl·Cmd+K` /
  移动端顶栏图标都打开同一个居中弹框。原本的「贴着输入框的锚定浮层」已删除（连带 portal 定位、外部点击、
  展开侧栏再聚焦那套逻辑），全站只剩一套搜索界面。

- 结果面板改用 shadcn `ui/Command`（cmdk）而不是手写 listbox：分组 / 键盘 / `aria-activedescendant` 交给它，
  排序仍是我们自己的（`shouldFilter={false}`）；「全部」从一个组标题小按钮变成组内最后一条 option
  （可键盘选中，代价是每组多一行，面板更高、可能滚动）。
- 「最近搜索」仍是 cmdk 的 `option`（可 `↑` / `↓` 选中），删除走 `Delete` / `Backspace` 快捷键；
  行尾 ✕ 只是鼠标辅助（`aria-hidden` 的点击区）：`role="option"` 里不能放真按钮，键盘路径用快捷键。
  快捷键只在**空查询**时接管，有搜索词时 `Backspace` / `Delete` 仍归输入框。

- `searchIntent` 没有单独的待办清理入口：`App` 的 `navigate(tab, intent?)` 里「带意图才留待办、普通导航就作废」，避免旧词残留。
- 组标题的「全部」**不带条数**（`search.global.seeAll` = 「全部」）：每组扫描上限 40 条，带数字会说谎。
- 物品组的「全部」也会带 `query` 预填（物品 ID 页新增了 `query` 意图消费），不只是集合。
- 数字查询不跨组置顶（那会打乱「组顺序固定」）：各域 ID 参与评分，组内精确命中排最前。
- 移动端不在侧栏抽屉里放入口（抽屉 + 弹框叠层体验差），改为顶栏图标，见 `功能-全局搜索.md` §2。

## 11. 验收

单测（`npx vitest run` 相关文件）：

- 索引：各域匹配命中 / 排序 / 数字 ID 精确优先 / 空词返回空 / 大小写不敏感。
- 组件：输入→分组出现、组内 3 条上限、`↑↓` 跨组、`Enter` 执行、`Esc` 清空、无结果文案、登录门控组隐藏。
- 集成：`AppShell` 里输入框在「首页」之上；`searchIntent` 冷启动（页面未挂载）与热启动（已挂载）都生效。

手工：

- 在首页 / 指令 / 设置页各按一次 `Ctrl/Cmd+K`，输入「天顶」→ 回车 → 物品详情弹框打开且**页面没跳**。
- 输入「tp」→ 选指令 → 落到指令小抄且搜索框已填 `tp`。
- 输入「僵尸」→ 选 NPC → 落到数据 ID·NPC 且已过滤。
- 未登录：结果里没有「玩家」组；登录后出现。
- 侧栏收起后按 `Ctrl/Cmd+K`：侧栏展开且输入框获得焦点。
- 面板打开时打开物品详情抽屉 / 弹框：`Ctrl/Cmd+K` 不抢焦点（沿用 `SearchInput` 的浮层检查）。

收尾：`npx tsc -b`、`npx markdownlint-cli2 "docs/*.md"`、一次全量 `npx vitest run --maxWorkers=4`。

## 12. 风险与取舍

- **面板比侧栏宽**：会盖住内容区左上角。可接受（关闭即消失）；若不行只能压到 16rem，物品名会被大面积截断。
- **`Ctrl/Cmd+K` 冲突**：Chrome 用它在地址栏搜索。页面内 `preventDefault` 可控，但仅在焦点不在输入框时接管；
  输入框内按 `Ctrl/Cmd+K` 保持浏览器默认行为以外，其余场景一律接管。
- **分组多导致「看起来杂乱」**：靠固定组顺序 + 每行右侧弱化次要信息 + 每组 3 条上限控制；
