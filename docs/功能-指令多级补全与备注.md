# 功能：指令多级补全与取值备注

文档版本：1.0
相关代码：`web/src/lib/commandMeta.ts`（**手工维护的唯一入口**）、`web/src/lib/completion.ts`（补全逻辑）、
`web/src/lib/dataset.ts`（`withCommandMeta` 合并）、`tools/gen-data.mjs`（核心指令与单层用法串）
相关测试：`web/src/lib/commandMeta.test.ts`、`web/src/lib/completion.realdata.test.ts`

> 目标：让补全下拉框不仅给出参数值，还能说明它是什么；并把 TShock 生成器提取不到的
> **多级子命令**（如 `/worldevent invasion <入侵类型>`、`/pm export <玩家名>`）補全出来。
> 本文同时列出核心指令与 PM / WM / Fish 插件的二、三级子命令含义，方便后续维护。

---

## 1. 配置在哪、怎么加

所有需要手工维护的内容都在 **`web/src/lib/commandMeta.ts`**，只有两处：

| 配置 | 作用 | 什么时候用 |
| --- | --- | --- |
| `LABELS[指令名][取值] = { zh, en }` | 补全下拉框里显示在取值下面的**备注名** | 给某个枚举取值 / 子命令加中文名 |
| `EXTRA_PARAM_SETS[指令名] = [cmd(...)]` | 追加 / 覆盖**参数形态**（多级子命令） | 生成器没提取到、或要手工纠正时 |

要点：

- **指令名用规范名**（小写、不含 `/`）。TShock 核心指令就是它的名字；插件指令用插件注册名：
  `playermanager`（不是 `pm`）、`worldmodify`（不是 `wm`）、`fishshop`（不是 `fish`）。
- `cmd(显示用指令名, '子命令', [后续参数])` 会生成用法串与首参 `literal`；后续参数按 `CommandParam` 写：
  `kind` 决定候选来源（`player` / `item` / `npc` / `buff` / `enum` / `region` / `warp` / `number` / `text`…）。
- 第 4 个参数是可选说明 `{ zh, en }`，会拼在**参数提示行**后面，用来说明「不加参数」时的含义，
  例如 `cmd('fish', 'jar', [...], { zh: '不加参数 = 查看鱼罐', en: 'no arg = view jar' })`。
- 合并规则：运行期由 `dataset.ts` 的 `withCommandMeta()` **按 `syntax` 覆盖**同名形态（幂等）。
  所以重复写同一个 `syntax` 只保留最后一条，可用来覆盖生成器的结果。
- **字面量子命令会自动进补全**：`completion.ts` 的 `computeLiteralCompletions()` 会把当前层所有匹配形态的
  `literal` 都列出来，并附上 `LABELS` 里的备注名。
- 加完后跑 `cd web && npm run typecheck && npm run test:run`；`commandMeta.test.ts` 的
  「真实数据覆盖度」用例会检查**所有 TShock enum 取值都有备注**。

示例（给 `/worldevent invasion` 的第 3 级加补全）：

```ts
worldevent: [
  cmd('worldevent', 'invasion', [
    { name: 'invasion type', required: true, kind: 'enum',
      values: ['goblins', 'snowmen', 'pirates', 'pumpkinmoon', 'frostmoon', 'martians'] },
    { name: '入侵波数', required: false, kind: 'number' },
  ]),
],
```

## 2. TShock 核心指令（多级 / 字面量）

> 这些指令里 `/pm`、`/sb` 等多数是 `allowServer=false`，WebUI 只补全、不执行。

## 6. 注意与限制

- 上表来自**本机源码**，不是从测试服务器实时拉取；插件升级后以插件源码 / 游戏内 `/xx help` 为准。
- 插件指令的**名称 / 别名 / 帮助文本**由自研信使插件在运行期提供（`/webui/commands` →
  `transport.runtimeCommands()`），补全里的指令帮助行会显示它们；本文件的 `EXTRA_PARAM_SETS` 只补**参数形态**。
- 目前 `EXTRA_PARAM_SETS` 只按**第一层子命令**补全；更深层（如 `/pm backup help` 的子命令）在对应
  `cmd()` 的后续参数里写 `kind: 'text'` 占位，需要时再按同样方式细化。
- **参数是「指令名」时不补**（`/help <command/page>`、`/aliases <command or alias>`，即 `kind: 'command'`）：
  一级指令玩家前面已经敲过了，空格后不再弹一屏命令名（TShock 的 `/help` 也只收一个参数，
  `Commands.cs:5351`，`/help user add` 直接报语法错，后面没有下一级可补）。
  要看二级子命令就敲 `/help user`（游戏会把 `user` 的子命令逐行列出），或看指令页的「指令库」。
