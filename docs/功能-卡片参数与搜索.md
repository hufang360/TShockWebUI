# 功能：指令卡片的参数与指令搜索

文档版本：1.0
相关代码：`web/src/lib/cardParams.ts`（模板 / 拼指令 / 对回指令库 / 指令搜索）、
`web/src/components/card/`（`CardTemplateDialog` 添加与编辑、`CardParamForm` 卡片上的输入区、
`ParamValueField` 取值控件、`CustomCommandCard` 卡片外壳）、
`web/src/lib/homeCards.ts` 与 `web/src/lib/moduleCards.ts`（存储字段）、
`web/src/lib/completion.ts` 的 `paramValueCandidates()`（取值来源，与指令编辑器补全同源）
相关测试：`lib/cardParams.test.ts`、`components/card/*.test.tsx`、`components/HomeCardManager.test.tsx`、
`pages/HomePage.test.tsx`、`pages/CommandModulePage.test.tsx`、`pages/FishShopPage.test.tsx`、`lib/moduleCards.test.ts`
数据：`data/commands.json`（`paramSets`）、`lib/commandMeta.ts`（插件指令的参数表补充 + 中文备注）

> 定位：让「指令卡片」从一条**写死的指令**，变成一张**可以填参数的卡片** —— 参数名、必填、取值全部来自指令库，
> 不引入 `{item}` 这类手写模板语法。首页 / 世界管理与自定义模块 / 鱼店三处的**用户自定义卡片**共用这一套；
> 内置固定卡片（`/who` `/time` `/worldinfo` …）不变。

## 1. 两种卡片

| 形态 | 存储 | 行为 |
| --- | --- | --- |
| 普通指令卡片（老形态） | `{ id, name, command }` | 照旧执行 `command` 原文（取第一条非空行、补前导 `/`） |
| 参数卡片 | 多一个 `template` | 按 `template` 拼指令；卡片正文出现输入框 |

参数卡片仍然保留 `command`（= `/指令名`）：它是**参数对不上指令库时的兜底基线**，也让「管理卡片」等老代码不必判空。

## 2. 数据模型（`lib/cardParams.ts`）

```ts
interface CardArgState { mode: 'fill' | 'fixed' | 'omit'; value: string }
interface CardTemplate  { command: string; syntax: string; args: CardArgState[] }
```

- `command`：规范指令名（小写、不含 `/`）。
- `syntax`：选中的**用法形态**（`CommandParamSet.syntax`）。指令库更新后靠它重新对上，指令名不够（`/region` 有 12 种写法）。
- `args`：与 `paramSet.args` **一一对应**（含字面子命令），靠下标对齐而不是靠名字。
- 三种 `mode`：
  - `fill`：卡片上留一个输入框，每次执行前填（值同时是下次的默认值）；
  - `fixed`：值固定在卡片里（等价于老卡片，只是有控件帮忙选）；
  - `omit`：不传（可选参数；以及可选字面子命令，如 `/region info <区域> [-d]` 的 `-d`）。
- 默认策略（`defaultArgMode`）：必填值参数 → `fill`；可选值参数 → `omit`；字面子命令 → `fixed`（必填）/ `omit`（可选）。

存储位置（都按服务器分开，字段是可选的，老数据不迁移）：

- 首页：`tswui:homeCards` → `byServer[serverId].custom[].template`
- 模块 / 鱼店：`tswui:moduleCards` → `byServer[serverId][moduleId][].template`

`sanitizeCardTemplate()` 做结构校验（`mode` 必须是三态之一、`value` 必须是字符串），**非法就整条丢弃**，
卡片退回普通指令卡片 —— 手工改坏 localStorage 不会让首页崩。

## 3. 拼指令规则（`buildCardCommand`）

```
/give 29 张三 10
```

- 跳过 `omit`；可选参数**留空也等于不传**（不拼出空占位）。
- 必填参数没值 → 记进 `missing`，`command` 为 `null`：**不发一条半截指令**；卡片按钮置灰 + 一行「还需要填写：玩家」。
- 字面子命令按 `mode` 决定是否带上（`fixed` = 带，`omit` = 不带）；值仍取参数表里的字面量。
- 含空格的值加双引号（TShock 的 `ParseParameters` 支持引号），值里自带的双引号会被去掉（TShock 不解析转义引号）。
  可变参数（`<permissions...>`）同样按「含空格就加引号」处理。

## 4. 对回指令库（`resolveCardTemplate`）

指令还在、`syntax` 还在、`args` 个数一致，才算可用。任一条不满足 → 卡片显示
「指令库已变化，请到「管理卡片」里重新配置这张卡片。」并且**不能执行**（不拿旧参数拼一条可能是错的指令）。

## 5. 卡片上的输入区（`CardParamForm`）

- **只渲染 `fill` 参数**：固定值与不传的参数不出现在卡片上（它们已经体现在页脚的指令预览里）。
  一个卡片没有任何 `fill` 参数时，就是普通卡片的外观。
- 标签用指令库里的参数名（与「指令小抄」「编辑器」看到的用法串一致），placeholder 用类型提示
  （玩家名 / 物品名或 ID / 数字…），枚举为空时显示「选择取值」。
- 取值控件按 `kind`：`enum` 用 `Select`（选项名取 `commandMeta` 的中文备注，如「白天 · day」）；
  其余（玩家 / 物品 / NPC / Buff / 词缀 / 区域 / 传送点 / 用户组 / 权限）用输入框 + 候选下拉，
  候选与指令编辑器补全**同源**（`paramValueCandidates`），但**允许手输任意值**（离线玩家、自定义组、运行期才存在的名字都合法，TShock 自己校验）。
- 页脚右侧显示**最终会执行的那条指令**（`data-testid="card-command-preview"`，可悬停看全文）：
  填完先看一眼再点执行。
- 输入值有本地草稿：**点执行立刻用当前值**，停止输入 400ms 后才写回 localStorage（不逐键写整份存储）。

## 6. 执行语义

- **有 `fill` 参数的卡片恒为手动执行**（`needsUserInput`）：不参与自动刷新、「刷新全部」、「统一执行」——
  用上次的值跑等于悄悄替用户做了决定，`/give` 尤其不能这样。管理列表里那张卡的「自动执行」开关**置灰**并说明原因。
- 没有 `fill` 参数的参数卡片（全固定 / 全不传）与普通卡片一样，可自动执行。
- 执行仍然走 `/api/execute`，权限由 TShock / 插件判定；参数只是拼出一条指令，**不绕过 Tier A**。

## 7. 添加 / 编辑（`CardTemplateDialog`，按需加载的 chunk）

「管理卡片」→「添加卡片」打开弹框（抽屉里不再有内联表单）：

1. 搜指令（§8）→ 点一条进入参数页；没有参数表的指令（`/help`、`/hardmode`）直接建普通卡片。
2. 多形态指令（`/group`、`/region`、`/warp`、`/pm`、`/wm`、`/fish`）先选「用法」（下拉里是完整用法串）。
3. 每个参数一行：名称 + 「取值方式」下拉（每次填写 / 固定值 / 不传）+ 取值控件。必填参数不给「不传」。
4. 名称默认 `/指令名 子命令`，可改。
5. 提交：带参数的存 `template`；纯字面量的存普通卡片。

- **仍支持直接写一条完整指令**：搜索框输入 `/xxx args` → 「使用「/xxx args」」。这条路径是插件指令、未收录指令的兜底。
- **仅游戏内**的指令（`allowServer === false` 且未放行，见 `lib/ingame.ts`）在列表里标「仅游戏内」，
  选中后给一行说明并**禁用提交**：网页卡片跑不了它，建出来只会误导。
- 编辑：**参数卡片**行尾的 ✎ 打开同一个弹框（名称 / 用法 / 参数都能改）；**普通卡片**仍是行内改名称与指令。

## 8. 指令搜索（`searchCardCommands`）

匹配字段：指令名、别名、`help` / `helpZh` / `helpEn`、参数名与字面子命令、枚举取值的中文备注
（所以搜「白天」能找到 `/time`、搜「设置世界时间」也能）。前导 `/` 不参与匹配。

计分（数字小的排前面）：名称全等 0 / 名称前缀 1 / 别名全等 2 / 别名前缀 3 / 名称包含 4 / 别名包含 5 / 帮助包含 6 /
参数或备注包含 7；同分按名称长度、再按字母序。**不做模糊匹配**：指令库只有 90 多条，玩家找的多半是「名字里有没有这个词」，
可预期的排序比花哨的算法好用。

## 9. 「管理卡片」里的过滤

- 卡片数 > 6 时，抽屉顶部出现「过滤卡片」输入框；按**名称 + 指令**匹配。
- 参数卡片在这一列显示**拼好的指令**（如 `/give 29 张三 10`，不是半截 `give`），并带一个「参数」徽标；
  「复制指令」复制的也是这一条。
- **过滤期间禁用拖拽排序**（拖拽落点算的是「过滤后的第几行」，照着它移动会挪错位置），「上移 / 下移」菜单项一并禁用。

## 10. 不做（刻意留下的边界）

- **不做手写模板语法**（`/give {item} {player}`）：参数表只来自指令库，避免自造语法与引号 / 转义问题。
- **不自动猜参数**：没有 `paramSets` 的指令（多数插件指令的运行时版本）只能当普通卡片写完整指令。
- **不在卡片上改参数结构**：卡片只填值；增加 / 删除参数、改用法的入口在弹框里。
- **参数卡片不因为 Tier B 放行就默认可建**：`allowServer=false` 的指令要看能力矩阵放行名单（`IngamePolicy`），
  没放行一律禁用提交。
