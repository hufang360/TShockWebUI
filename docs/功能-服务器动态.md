# 服务器动态（Server Feed）

> 首页「服务器动态」卡片：把服务器的**进服 / 退服 / Boss 击杀**做成一条实时时间线，
> 并叠加上世界状态徽标（困难模式 / 血月 / 日食 / 下雨 / 入侵），让首页「活」起来。
>
> 本文是这个功能的**唯一专门文档**：现状、契约、限制都在这里；
> 后续关于「服务器动态」的一整套想法统一追加到 **§7 想法 / Roadmap**，不要再散落到别处。

## 1. 边界

- **只读、不落盘**：事件只在**插件内存**里（环形缓冲），TShock 重启即清空；不写数据库、不写文件。
- **不新增权限**：`/webui/events` 是 `SecureRestCommand`，只要一个**有效 token** 即可（同其它只读端点），
  不额外要求 `tshock.rest.*` 权限，也不提权。
- **属于自研信使插件的能力**：未安装 `WebUI` 时该端点 404，后端返回 `plugin_not_installed`，
  前端**直接隐藏**该卡片（`pluginMissing('events')`，见 `HomePage.tsx`）。
- 纯展示，不参与指令执行。

---

## 2. 数据流（一眼版）

```
TShock 事件钩子（插件主线程）
  ServerJoin / ServerLeave / NpcKilled / PlayerChat
        │  EventLog.Add(type, text)
        ▼
插件内存环形缓冲 EventLog（最近 200 条，seq 单调递增，重启清空）
        │  插件 REST：GET /webui/events?since=&limit=&token=   (SecureRestCommand)
        ▼
后端 GET /api/events?since=&limit=   （同源，带会话 Cookie；内部转发 + 注入 token）
        │
        ▼
首页「服务器动态」卡片：首次进入拉一次 + 之后每 15s 增量轮询（带上次 lastSeq）
```

世界状态徽标走的是**另一条**只读端点 `/api/serverinfo`（→ 插件 `/webui/serverinfo`），
首次进入时拉一次，见 §5。

## 3. 事件来源（插件）

`plugin/WebUI/Plugin.cs`：

| 钩子 | `type` | 文本模板 | 条件 |
| --- | --- | --- | --- |
| `ServerApi.Hooks.ServerJoin` | `join` | `{玩家名} 加入了服务器` | 总是 |
| `ServerApi.Hooks.ServerLeave` | `leave` | `{玩家名} 离开了服务器` | 总是 |
| `ServerApi.Hooks.NpcKilled` | `boss` | `Boss「{NPC 名}」被击败` | **仅 `e.npc.boss == true`**（普通小怪不记） |
| `PlayerHooks.PlayerChat` | `chat` | `{玩家名}: {聊天内容}` | `Config.RecordChat`（默认开）；**仅普通聊天** |

- NPC 名取自 `Lang.GetNPCNameValue(netID)`（服务端语言），取不到时回退 `NPC#{netID}`
  （`EventLog.NpcName`）。
- 文本是**插件端硬编码的中文**，不随网页端语言切换（见 §6）。
- 事件文本里包含玩家名 / Boss 名，均为 TShock 服务端已公开的信息，不含 IP、token 等敏感数据。

关于聊天（`chat`）：

- 聊天里可能带 Terraria 物品标签 `[i:..]`，前端按富文本渲染成图标（`RichText`），不会显示原始标签。
- 用 TShock 的 `PlayerHooks.PlayerChat`（**不是** OTAPI 的 `ServerChat`）：该钩子在
  **权限 / 禁言 / 长度**校验之后触发，且**只对真正的聊天**触发，以 `/` 开头的指令不会进事件流。
- 在线授权的 `y` / `n` 确认走 OTAPI `ServerChat` 并被拦截（`e.Handled`），**不会被记录为聊天**。
- 采集开关：插件配置 `RecordChat`（默认 `true`）。关掉即完全不采集聊天内容，重启 TShock 生效。
- 文本截断：`EventLog.MaxTextLength = 200`，超出加省略号。

`plugin/WebUI/EventLog.cs`：

- `Capacity = 200`，`LinkedList` 环形缓冲 + `lock` 串行化；超出逐个 `RemoveFirst()`。
- 每条字段：`seq`（`long`，从 1 递增）、`type`、`text`、`time`（UTC，ISO-8601 `"o"`）。
- `Since(since, limit)`：返回 `seq > since` 的最多 `limit` 条（`limit <= 0 || > Capacity` 时按 `Capacity`），
  并附当前最大 `lastSeq`。
- `Clear()`：测试 / 需要时清空。

## 4. 接口契约

### `GET /webui/events`（插件，后端调用）

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `token` | 是 | `SecureRestCommand` 注入，只要有效 token |
| `since` | 否 | 只返回 `seq > since` 的事件，默认 `0` |
| `limit` | 否 | 最多返回条数，默认 / 越界按 `Capacity`（200） |

返回：

```json
{
  "events": [
    { "seq": 42, "type": "join", "text": "Alice 加入了服务器", "time": "2026-01-01T00:00:00.0000000Z" }
  ],
  "lastSeq": 42
}
```

`type ∈ join | leave | boss`（未知类型前端按灰色点兜底）。

### `GET /api/events?since=&limit=`（后端，浏览器调用）

- 需登录会话；agent 转发到 `/webui/events`，token 由后端注入，**浏览器不持有 token**。
- 响应与上面同构（`{ events, lastSeq }`）；插件缺失时返回 `plugin_not_installed`。
- 实现：`server/internal/api/plugin_handlers.go` 的 `handleEvents` → `tshock.Client.Events`（`extras.go`）。

### `GET /api/serverinfo`（世界状态，卡片徽标用）

返回 `{ hardMode, bloodMoon, eclipse, raining, invasionType, invasionSize, … }`。
前端只把其中几项渲染成徽标：困难模式 / 血月 / 日食 / 下雨 / 入侵（`invasionType > 0`）。
完整字段见 `web/src/lib/transport.ts` 的 `ServerInfoExtra` 与 `docs/API_SPEC.md`。

## 5. 前端展示（`web/src/pages/HomePage.tsx`）

> 事件文本用共享的 `components/RichText.tsx`（从 `ResultPanel` 抽出）渲染：
> 聊天里若带 `[i:123]` / `[i/s5:75]` / `[c/RRGGBB:文字]` 会渲染成**物品图标 / 彩色文字**（与指令结果面板一致）。

- **卡片位置**：「服务器动态」固定排在第 **2** 位（第 1 是「服务器状态」）、
  「快捷入口」固定排在第 **3** 位。默认顺序定义在 `web/src/lib/homeCards.ts` 的 `BUILTIN_CARD_IDS` /
  `DEFAULT_HOME_CARDS`。
  - 用户仍可在「管理卡片」里自行拖拽 / 隐藏；改动只存本机 `tswui:homeCards`。
  - 变更默认布局时递增 `HOME_CARDS_LAYOUT_VERSION` 并配 `upgradeHomeCardsLayout()`：
    老布局一次性升级——**只**把 `events` / `quick` 落到第 2 / 第 3 位，其余卡片相对顺序、隐藏态、
    自定义卡片全部保留（`web/src/lib/homeCards.test.ts` 有覆盖）。
- **拉取时机（v1.4 起）**：`useServerFeed` 挂载即刷新一次（**进入首页 / 指令模块即触发**）；
  之后每 **`settings.eventsRefreshInterval`**（设置 → 服务器动态刷新间隔：1 / 3 / 5 / 15 分钟）
  拉一次 `/api/serverinfo`（含游戏内时间）+ `/api/events?since=lastSeq` 增量。
  「页面数据刷新间隔」触发时，`HomePage` 把 `refreshToken` +1，**连带刷新**服务器动态。
- **展示**：徽标 + 最近 **6** 条事件（内存最多 **20** 条，每条按 `type` 配色圆点：join 绿 / leave 灰 / boss 橙 / chat 蓝）；
  **卡片底部**一行 `刷新于 HH:MM:SS · 游戏内 HH:MM`（`formatGameTime`：白天 4:30 起算 / 夜晚 19:30 起算）。
- **服务器状态卡片**底部也显示 `刷新于 HH:MM:SS`（`loadStatus` 成功时记录 `lastStatusAt`）。
- **1 分钟选项限权**：仅 `GM` / `superadmin` / `vip` 组可选（设置页拉 `/api/me` 得到用户组后启用该选项）。

### 指令页「动态」tab（`web/src/pages/CommandPage.tsx`）

右侧卡片 tabs 追加了 **「动态」**（`editor.tab.events`，图标 `Activity`，排在「历史」之后）。
它渲染 `components/ServerFeed.tsx` 的 `ServerFeedTab`：

- 只在**该 tab 挂载时**轮询（切走即卸载、停止轮询），最多保留 **100** 条，列表可滚动；
- 复用首页同一套 `useServerFeed` hook 与 `ServerFeedList`；插件缺失时显示提示而非隐藏。
- 需要在版本 / 服务器切换时重新拉取，所以 `CommandPage` 新增 `serverId` prop（由 `App.tsx` 传入 `activeServerId`）。
- **插件缺失**：捕获 `kind === 'plugin_missing'` → `eventsPlugin = false` → 隐藏卡片并停止轮询。
- **Mock**：`web/src/lib/mockTransport.ts` 提供 3 条假事件 + 假 `serverInfoExtra`，Mock 模式在界面上有 `Mock` 标记。

## 6. 已知限制 / 待解问题

| 限制 | 现状 | 影响 |
| --- | --- | --- |
| 4 类事件 | join / leave / boss / chat | 建造、死亡、商店购买等仍没有 |
| 聊天默认采集 | `Config.RecordChat = true` | 涉及玩家隐私，部署方需知晓；可关 |
| 文本服务端硬编码中文 | `Plugin.cs` 直接拼中文字符串 | 网页切英文时事件文本仍是中文 |
| 内存缓冲、重启清空 | `EventLog.Capacity = 200` | 无历史、不可回放 |
| 世界状态与事件流分离 | 徽标来自 `/api/serverinfo`，非事件 | 状态变化不在时间线里体现 |
| 无去重 / 无合并 | 每条事件独立 | 高峰进出服会刷屏（前端截断到 6 条 / 20 条） |
| 轮询而非推送 | 按设置间隔（≥1 分钟）`setInterval` | 最多一个间隔的延迟；多标签页各自轮询 |
