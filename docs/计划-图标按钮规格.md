# 计划：图标按钮规格统一

> **状态：已实施（2026-11-01）。** 决策由用户确认，实施结果与偏差见 §9。
> 当前行为以 [`UI组件.md`](UI组件.md)「图标按钮」一节为准；本文件保留证据与取舍（尤其是 §1.1 那个坑）。

## 1. 问题

同一类「只有图标的按钮」在 `web/src` 里有 **60 处** 手写实现（另有 11 个文件已经在用 `IconAction`），
彼此在 **尺寸 / 形状 / 灰阶 / 有没有 Tooltip** 四个维度上不一致。表现为：
顶栏、页头、卡片角、表格行、输入条里的图标按钮大小肉眼可辨地不同，有的纯黑、有的灰，有的悬停才出提示、有的一辈子只有一个原生 `title`。

根因不是「有人偷懒」，而是**尺寸有三个来源**：

| 来源 | 位置 |
| --- | --- |
| `Button` 尺寸变体 | `web/src/components/ui/Button.tsx:22-23`（`icon: size-10 md:size-9`、`icon-sm: size-10 md:size-7`） |
| 调用点 `className` 覆盖 | 各页面，**只写 base**（`size-7` / `h-7 w-7` / `size-6`） |
| 绕过 `Button` 的裸元素 | `ItemTooltipContent.tsx:188`、`ResultPanel.tsx:192` 等 |

### 1.1 为什么「只写 base 的覆盖」必然翻车（实测证据）

`cn()` = `clsx` + `tailwind-merge`（`web/src/lib/utils.ts`），冲突按 twMerge 规则消除；
而变体带的 **`md:` 尺寸属于另一个修饰符组，不会被 base 覆盖消掉**。用仓库内 `tailwind-merge@3` 实测：

| 写法 | twMerge 合并结果 | 手机 <768px | 桌面 ≥768px |
| --- | --- | --- | --- |
| `size="icon-sm"` | `size-10 md:size-7` | 40px | **28px** |
| `size="icon" className="h-7 w-7"` | `size-10 md:size-9 h-7 w-7` | 28px | **36px** |
| `size="icon" className="size-7"` | `md:size-9 size-7` | 28px | **36px** |
| `size="icon" className="size-6 md:size-6"` | `size-6 md:size-6` | 24px | 24px |
| `size="icon-sm" className="size-6"` | `md:size-7 size-6` | 24px | 28px |
| `size="icon-sm" className="size-7"`（`SlicePanel` / `MergeWorkspace` / `SearchInput:302`） | `md:size-7 size-7` | 28px | 28px（**冗余，无效果**） |
| `size="icon-sm" className="size-9"`（`ResultPanel:111`） | `md:size-7 size-9` | 36px | 28px |

结论：**桌面端永远是变体说了算**。`size="icon" + size-7` 得到的是「手机上 28、桌面上 36」——
与 `DESIGN.md` §Layout「移动端触控目标放大（图标按钮 40px，≥768px 才回到 28px）」**正好相反**。
所以「`h-7 w-7` 当作标准」这条路走不通；标准必须落在**变体**上，调用点不写尺寸。

## 2. 已确认的决策

1. **手机端保留放大触控目标**：走 `icon-sm`（40 / 28），不采用恒定 28px。
2. **形状以方形 `rounded-control` 为准**：正圆只保留在「输入条内的发送键」（`CommandEditor` / `WebChatInput`）。
   `DESIGN.md` §Components/Buttons「图标按钮正圆」按此修正。
3. **新增 24px 档 `icon-xs`**，安置结果行 / 表格 / tooltip 这类行内密集按钮，不把全部按钮拉到 28px。

## 3. 规格

### 3.1 尺寸阶梯（只有三档，全部在 `Button` 变体里）

| 变体 | class | 手机 <768px | 桌面 ≥768px | 用在哪 |
| --- | --- | --- | --- | --- |
| `icon-xs`（新增） | `size-9 md:size-6` | 36px | 24px | 行内密集：结果卡角、表格单元格、tooltip 内、chips 上的删除 |
| `icon-sm`（**默认标准**） | `size-10 md:size-7` | 40px | 28px | 顶栏、页头、工具条、开关、抽屉标题栏 |
| `icon` | `size-10 md:size-9` | 40px | 36px | 主操作：输入条正圆发送键、分页箭头、Dialog × |

### 3.2 唯一推荐写法

```tsx
// 默认：一律用 IconAction（自带 Tooltip + aria-label + 灰阶 + loading/pressed）
<IconAction label={t('dex.settings')} icon={Settings2} onClick={open} />

// 需要严格的「次要灰 + 选中态」
<IconAction label={…} icon={…} active={settingsOpen} asChild>…</IconAction>

// 例外：输入条里的正圆主按钮
<Button size="icon" variant="primary" className="rounded-full"><Send /></Button>
```

**规则（写进 `Button.tsx` 文件头注释与 `UI组件.md`）**：
> 图标按钮的尺寸只由 `size` 变体决定。调用点 `className` **不得**再写 `size-*` / `h-*` / `w-*`
> （只在需要恒定尺寸时成对写 `md:`，如 `size-7 md:size-7`）。颜色走 `text-muted-foreground hover:text-foreground`。

### 3.3 `IconAction` 需要补的能力

| 新增 | 为什么 | 现有受阻点 |
| --- | --- | --- |
| `asChild` | `PopoverTrigger` / `DropdownMenuTrigger` 必须直接包住 `Button`，`IconAction` 内部自建 Button，包不进去 | `ItemsPage:742`、`DataIdPage:383`、`FishShopPage:480`、`ItemPickerPopover:54`、`RecipeFavoritesPopover:50`、`InfoPopover:23`、`TopBar:85` |
| `size?: 'icon-xs' \| 'icon-sm' \| 'icon'` | 三档阶梯 | 现在写死 `icon-sm` |
| `variant?:` | `primary` / `danger` 的正圆例外 | 现在写死 `ghost` |
| `active?: boolean` | 选中态 `bg-accent text-foreground` | `ItemsPage` / `DataIdPage` / `FishShopPage` / `SearchInput` 各写一遍（4 处重复） |
| `tooltip={false}` | 浮层内部的工具栏不需要再叠 Tooltip | 现在无条件包 Tooltip |
| `title?: string` | 少数场景（原生 title 与 Tooltip 并存会造成双提示，需要显式关闭 Tooltip） | 现在 `title` 与 Tooltip 重复 |

## 6. 护栏测试规格

新增 `web/src/components/ui/iconButtons.test.ts`（沿用 `Card.test.tsx` 的 vitest 风格），源码扫描，任一命中即失败：

1. `<Button` 且 `size="icon*"`，其 `className` 里出现 `\b(size|h|w)-\d`（无 `md:` 前缀）→ 失败（提示改用变体）；

4. 白名单：`ui/Button.tsx`、`ui/Pagination.tsx`、`IconAction.tsx`、`CommandEditor.tsx`、`WebChatInput.tsx`、`ItemTooltipContent.tsx`（各附一行「为什么是例外」）。

## 8. 验收标准

- 全站图标按钮**只剩三种尺寸**（24 / 28 / 36 桌面；36 / 40 / 40 手机），且都能用 `size` 变体解释。
- 所有图标按钮都有 `aria-label` + Tooltip（浮层内 `tooltip={false}` 的除外）。
- 灰阶一致：常态 `text-muted-foreground`，hover / active `text-foreground`。
- 形状一致：除输入条发送键外全是 `rounded-control`。
- `iconButtons.test.ts` 通过；`npm run test`、`npm run build`（或 `tsc -b`）全绿。
- 手动验收：375px 与 1280px 下逐页过 首页 / 指令 / 物品图鉴 / 数据 ID / 鱼店 / 玩家管理 / 世界管理 / 设置 / 精灵图，触控目标不小于 36px。

## 9. 实施结果与偏差（2026-11-01）

已按 §4 迁移完毕：`web/src` 里手写的图标按钮只剩合法例外——`ConfirmButton`（图标 + 就地二次确认）、
`CommandCard`（图标 / 文字两态）、`QuickPreferences`（中 / EN 文字）、shadcn 原语（`Sidebar`、`Pagination`）、
`InputGroupAddon` 内压到 28px 的输入框按钮。

与计划的差异（实现时才定下来的）：

1. **不加 `asChild`，改成「把 `<IconAction>` 套进 `asChild` 触发器里」。**
   `IconAction` 把剩余 props 透传给内部 `Button`，Radix 的 `asChild` 自然把 `onClick` / `ref` / `aria-*` 转进去；
   `Popover` 与 `DropdownMenu` 两种触发器都实测可用。
2. **发送键用现成档位。** `CommandEditor` / `WebChatInput` 原来是 `compact ? size-7 : size-8`，
   实际效果是「手机 28 / 32、桌面统一 36」。现在改成 `compact ? 'icon-sm' : 'icon'`（手机 40、桌面 28 / 36），
   `CommandPage.test.tsx` 的断言同步改成校验档位、且不许再出现 `size-6/7/8`。
3. **`InputGroup` 内的按钮保留 28px。** `InputGroupAddon` 的 `[&_button]:size-7` 不是遗留物：
   按钮必须塞进 36px 高的输入框（`SearchInput` 的历史 / 清空、物资申请的收藏入口）。已写成明示例外。
4. **新增 `iconClassName`。** 星标 `fill-current`、折叠箭头 `-rotate-90`、Wi‑Fi 探活三态着色都要给 svg 加类；
   顺带把图标标成 `aria-hidden`（按钮已有 `aria-label`）。
5. **`ResultPanel` 的复制键取 `icon-sm`**（原 `size-9 + rounded-full`）：它浮在灰底输出区右上角，24px 太挤；
   结果卡右上角的三个操作仍是 `icon-xs`。
6. **计划外发现**：`ItemsPage` 页面设置弹框外层的 `TooltipProvider` 不是冗余——弹框里每个设置项的「info」提示靠它。
   迁移时被当成冗余删掉，测试立刻报 `Tooltip must be used within TooltipProvider`，已补回并加注释。

验收：`npx tsc -b`、`npx vitest run`（112 文件 / 1180 用例）、`npx vite build`、`npx oxlint` 均通过；
新增护栏 `web/src/components/ui/iconButtons.test.tsx`（源码扫描 3 条 + 尺寸阶梯 2 条）。

**还没做**：375px / 1280px 两档的真实浏览器目视过一遍（§8 最后一条），需要人工点一遍页面。
