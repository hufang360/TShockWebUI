> 只能进游戏用 `/fish list`。

## 1. 插件是什么 / 依赖什么

- TShock 第三方插件 **FishShop**（指令 `/fish`），是一个「指令商店」：除物品外还卖
  召唤 Boss / 入侵、生成 NPC、buff、调时间天气月相等服务。
- 上游 REST 前缀：新版 `/fishshop/*`；`v1.6.2 ~ v1.6.6` 是 `/v3/fishshop/*`（后端会自动回退，见 §2）。
- 本仓库把它做成**「鱼店」模块**（默认不在侧边栏，需在「设置 → 激活模块」里打开）。
- 运行时配置在 `<TShock SavePath>/FishShop/`：`settings.json`（按 id 的预设，含图标/限购）、
  `config.json`（货架）、`record.json`/`jar.json`（记录/鱼罐）。

## 2. 上游 REST 端点

| 端点（新版） | 老版地址 | 参数 | 权限（新 / 老） | 说明 |
| --- | --- | --- | --- | --- |
| `GET /fishshop/list` | `/v3/fishshop/list` | — | 无 / `fishshop.rest.use` | 货架 |
| `GET /fishshop/ask` | `/v3/fishshop/ask` | `serial` | 无 / `fishshop.rest.use` | 单件详情 |
| `GET /fishshop/buy` | `/v3/fishshop/buy` | `serial`、`amount`、`args`(可选)（老版多一个 `player`） | 无 / `fishshop.rest.buy` | 购买；新版只能买 token 同名玩家 |
| ~~`GET /fishshop/refund`~~ | `/v3/fishshop/refund` | `seq`、`player`(可选) | — | **新版已删**（连同 `/fish refund` 指令）；仅 v1.6.2 ~ v1.6.6 有 |

- **权限（新版已取消，已核实 TShock `SecureRest.cs`）**：不传权限参数时 `Permissions.Length == 0` → 只校验 token 有效，
  与游戏内 `/fish list|ask|buy` 一致。状态码：`401` 没带 token；**`403` 只表示 token 无效 / 用户组已变动**；
  业务失败全部 `400` + `error`。老版本缺 `fishshop.rest.*` 也会 403，后端用 `/tokentest` 区分（保留为兼容分支）。
- **游客**：`list` / `ask` 不限；`buy` 在 SSC 开启时被拒（`400`「游客无法访问鱼店」），WebUI 原样展示该文案。
- **前缀兼容（已实测于插件源码 `RestApi.cs`）**：后端先试 `/fishshop/*`，**404 再回退 `/v3/fishshop/*`**，
  成功的前缀按 TShock 上游地址缓存（`fishPrefixCache`），老服不会每次多打一次 404。
- 缺 `serial` → 400（探测用：说明插件已装）；插件缺失 / 没注册端点 → 404。
- 业务失败（钱不够 / 商品不存在 / 商店打烊 / 游客 / 玩家不在线）→ 400 + `error` 文案。

> 本仓库的 WebUI **不提供代购**（新版插件也已删除 `player` 参数，只能买自己）。

## 4. 前端模块

- id：`store`；入口：`设置 → 激活模块 → 鱼店`。
- 页面 `web/src/pages/FishShopPage.tsx`：
  - **头部白底卡片只放「输入框 + 一行件数」**：`InputGroup`（输入框 + 右侧刷新图标，旧 `Input`+`Badge`），
    刷新图标 hover 显示上次刷新时间。下面一行文字由「点击商品查看价格 / 询价 / 购买」改为 **`{n} 件商品`**。
  - **商品网格铺在页面背景上**（不在卡片里、无左右内边距），图标 64px；在 xl 下自身是滚动区域
    （`xl:flex-1 xl:min-h-0 overflow-y-auto overscroll-contain`），滚轮不会传递给右列。
  - **背景点缀**：页面底层加一层淡淡的**水波光晕 + 几条淡鱼/水滴**（`pointer-events-none`、`-z-10`、低透明度），突出鱼店氛围。
  - 点击商品 → **右侧详情抽屉**（shadcn `Sheet`，宽度 `w-full sm:max-w-xl`）：标题「商品详情」，下面居中放商品大图标 + `#序号 词缀 名称` + 可退徽章；
    **属性（价格 / 解锁 / 别名 / 限购 / 备注）统一排版：文字标签在值框上面一行的左上角**（`Field`：`dt` 在上、`dd` 在下，不再用左侧固定标签列）；值框 = 富文本条（`rounded-xl bg-accent/60`）；
    **右下角半透明渔夫指南图标（3120）点缀**；**点抽屉外关闭**（或右上角 X / Esc）。
  - 默认焦点：需参数 → 参数输入框；否则 → 购买按钮。
  - 购买：`buyMax>1` 才显示数量框；`needArgs` 显示参数框（数量固定 1）；两步确认。
    「参数」「数量」也走同一套排版：标签在输入框上面一行、左上角对齐（不再在输入框左边占一列）。
  - **购买成功不关闭抽屉**：在界面显示结果（`name`/`cost` 里的 `[i:..]` 渲染成图标）+ 「请打开游戏，进行查收！」提示，
    并刷新货架。失败提示（如「玩家不在线」）显示在数量/输入框下方、购买按钮上面一行。
  - 底部操作栏（固定）：左「关闭」（内附 `Esc` 的 `Kbd`）→ 右「购买」；右上角也有 X。
  - **货架加载时机**：进入页面（含从其它页面切回来）**总是拉一次**；停留在页面时再按
    「设置 → 页面数据刷新间隔」定时重拉（0 = 只拉进入那一次）。
    货架是组件内状态、离开页面就丢，因此**不能**套用首页卡片那套 `refreshGate`
    （否则 2 分钟内回到鱼店会一片空白）；右侧指令卡片的结果存在全局 store，仍走门控。
  - **不可用时的提示（三种，按探测结果区分）**：
    - `plugin=false`（没装或无法确认）→「服务器未安装 FishShop 插件」；
    - `plugin=true, rest=false`（v1.6.2 之前的老版本）→「鱼店插件版本过旧，没有网页接口」，
      文案提示去升级、并说明进游戏可用 `/fish list` / `/fish buy <编号>`（网页右侧只保留「钓鱼信息」卡片）；
    - `plugin=true, rest=true, permission=false` → 老版本缺 `fishshop.rest.use`（新版不需要该权限，恒为 `true`）。
- 界面状态（搜索词）按 `serverId` 记忆在 `tswui:moduleState`。

## 5. 数据字段

`FishGood`（上游 → 本仓库同名）：

| 字段 | 上游类型 | 说明 |
| --- | --- | --- |
| `serial` | int | 编号（界面显示 `#serial`） |
| `name` | string | 商品名 |
| `icon` | string | 图标标签 `[i:ID]`（**服务类商品 `desc` 只有文字，靠它显示图标**）；为空回退解析 `desc` |
| `map` | `List<string>` | 别名/分类；前端用 `, ` 连成一行显示 |
| `desc` | string | 说明（物品类通常是 `[i:..]`，服务类等于名称） |
| `cost` | string | 价格（含 `[i:..]`，用 `CommandOutput` 渲染图标） |
| `unlock` | string | 解锁条件 |
| `comment` | string | 备注（也可能含 `[i:..]`） |
| `buyMax` | int | 单次最多购买数（1 = 不显示数量框） |
| `needArgs` | bool | 指令类商品含 `{args}`/`{0}`，购买时需填参数 |
| `refund` | int `0/1` | **仅老版本 v1.6.2 ~ v1.6.6 返回**（新版已删退款机制）；可退徽章只在 true 时显示 |
| `allowGroup` | `List<string>` | 限购：仅限用户组 |
| `allowPlayers` | `List<string>` | 限购：仅限玩家（白名单） |
| `denyPlayers` | `List<string>` | 限购：禁止玩家（黑名单） |

**字段类型陷阱（已实测，必须容错）**：
- `map` 是**数组**（`List<string>`），不是字符串 → Go 侧用 `stringList` 兼容数组/裸串。
- `refund` 是**数字 `0/1`**，不是 bool → Go 侧用 `boolInt` 兼容数字/布尔，对外统一输出 bool（新版无该字段 → false）。
- `icon`/`desc`/`cost`/`unlock`/`comment` 里的 `[i:..]` 都要渲染成图标。

## 6. 权限与限购

- **权限**：
  - 新版插件：**不需要任何自定义权限**。任意有效 token 都能看货架 / 询价 / 购买（与游戏内 `/fish` 一致）；
    WebUI 探测得到的 `permission` 恒为 `true`，页面上不会出现「无权限」提示。
    - 游客 `buy` 在 SSC 开启时会被插件拒（400「游客无法访问鱼店」），WebUI 在购买框中原样展示。
  - 老版本 `v1.6.2 ~ v1.6.6`：查看/询价要 `fishshop.rest.use`，购买要 `fishshop.rest.buy`（代购 `buyas`）。
    只有这种服才会看到「老版本鱼店插件需要 fishshop.rest.use 权限」的提示。
- 限购条件（`allowGroup` / `allowPlayers` / `denyPlayers`）在详情弹框「限购」字段展示：
  - 仅限用户组：`GM`
  - 仅限玩家：`hf、star`
  - 禁止玩家：`bad`
- `fishshop.ignore.allowgroup` 权限可豁免用户组/玩家白名单（黑名单不豁免）。

## 7. 已知限制 / 坑

- **防重复购买**：购买成功后弹框不关闭、在按钮上方显示结果，并给按钮加 3 秒冷却
  （显示「请稍候 N 秒」、禁用）+ 结果块闪烁提示。此前后台提示不明显，玩家容易连点重复购买（已踩坑）。
  实现：`FishShopPage.tsx` 的 `buyCooldown` 状态 + `index.css` 的 `.tswui-flash` 动画。
- **购买时可能返钱**：如「野生狗奶」第二次购买会关闭时间静止并返还一半费用到鱼罐。这属于
  插件内部的开关行为（`RefundHalfOnClose`），**REST 不返回返款金额**。
- **退款**：新版插件已删除自助退款（商品 `refund` 字段、`/fishshop/refund`、`/fish refund` 指令都没了）。
  WebUI 对 `refund` 字段的解析与「可退款」徽章保留，只对老版本（v1.6.2 ~ v1.6.6）生效；
  本仓库后端从来没有接过退款端点（只保留类型）。
- **插件版本分三代**（实测插件 `changelog.md` + `git log RestApi.cs`）：
  - v1.6.2 之前：**只有游戏内指令**，没有任何 REST 端点 → 网页只能提示「版本过旧」；
  - v1.6.2 ~ v1.6.6：`/v3/fishshop/*`；
  - 下一版：去掉 `v3` 前缀 → `/fishshop/*`；同时**取消 REST 自定义权限**、删除代购 `player` 参数与自助退款。
  后端对两个前缀自动回退 + 按上游地址缓存，所以**服务端升级 / 回退插件都不用改 WebUI**。
- 老版本没有 REST 时**网页上看不到货架**：右侧卡片列只保留「钓鱼信息」（`/fish info`），
  要看货架只能进游戏执行 `/fish list`（`/fish list` 卡片已移除）。
- 解锁文案里的 `{0}`：插件 `UnlockID.GetNameByType` 对「渔夫任务」始终用 `stack`（默认 1）填充，
  否则默认次数会显示成 `完成{0}次渔夫任务`（已修）。
- 目标玩家必须在线（购买发到玩家身上，钱从玩家身上扣）。
- **游客 / 无权限**：新版插件不查权限，只有 SSC 开启时游客 `buy` 被拒；WebUI 不做前置拦截
  （前端拿不到 SSC 开关状态，提前拦会误拦 SSC 关闭的服），直接展示插件返回的 400 文案。
- **插件 REST 注册有延迟（5 秒）**：新版插件在 `OnEnabled` 里 `Task.Run` → `await Task.Delay(5000)`
  之后才 `RegisterRestApi()`（源码 `TShockFishShop/TShockFishShop/FishShop.cs`）。
  所以**刚重启 / 刚更新插件就打开鱼店**会探到 404，页面显示「未安装 / 版本过旧」是正常的；
  等几秒点提示里的**「重新检测」**（`fish.recheck`）即可，不用切页面。

### 7.1 排障：更新插件后仍提示「未安装 FishShop 插件」

按顺序排查（2026-10-21 实际踩过）：

1. **WebUI 后端是不是老构建**（最常见）。
   看后端日志里探测打的端点：只有 `endpoint=/v3/fishshop/ask` → 老构建（只认 `v3` 前缀，
   新版插件必然 404）。当前代码是「先 `/fishshop`，404 再回退 `/v3/fishshop`」，日志里应出现 `/fishshop/ask`。
   开发环境重建：`scripts/dev-container.sh backend`；线上需要重新构建镜像 / 二进制。
2. **直连验证插件本身**（不经过 WebUI）：
   `curl 'http://<tshock>:7878/fishshop/ask?token=<token>'` →
   `400 {"error":"缺少 serial 参数"}` = 插件在且 REST 正常；`404` = 没装 / 还没注册（等 5 秒）；
   `401` = token 无效；`403` = 老版本缺 `fishshop.rest.use`。
3. 前端点「重新检测」再确认一次（页面自带的按钮，避免切页面）。

> TShock 侧要求：`RestApiEnabled=true`（插件注册 REST 不依赖它，但调用需要），
> `EnableTokenEndpointAuthentication=true` 时 token 必须是有效令牌。

## 9. 货架物品提示 + 词缀（v1.1，v1.3 调整）

- **悬停提示（仅原生物品）**：货架格子与详情页大图标共用 `GoodThumb`。
  - **原生物品**（`desc` 带 `[i:..]`，即插件按物品类返回）→ `ItemIcon` 开 `tooltip`，显示
    全项目统一的游戏同款物品提示（`ItemTooltipContent`）。
  - **服务 / 指令类**（`desc` 只有文字，`icon` 只是借来当识别的图，如一本书）→
    `goodIsNativeItem(good) === false` → `tooltip={false}`，**两处悬停都不弹提示**（避免把书当成真物品）；
    图标本身**不压透明度**，与真物品一样正常显示。
  - 物品来源：`goodIcon(good)` 从 `icon` 字段（其次 `desc`）解析 `[i/...]` 标签；
    `goodIsNativeItem` 只看 `desc` 里有没有物品标签。
- **词缀（prefix）**：`[i/p<id>:itemId]` 里的 `p<id>` 会解析成 `prefix`，前端用
  `dataset.prefixesById` 拿到词缀名（如「传奇」），**在商品名前用语义色 `text-warning` 显示**
  （亮/暗主题都清晰；不再用只在暗底可读的 `text-amber-300`；物品提示内部仍用 `text-amber-300`）：
  - 货架格子：`传奇 天顶剑`；
  - 详情标题：`#2 传奇 天顶剑`；
  - 悬停提示：`ItemTooltipContent` 自带「词缀 + 名称」行。
- 辅助函数 `goodPrefixName(good, dataset)` 统一取词缀名。
- 格子保留 `aria-label={good.name}`（去掉原生 `title`，避免与自定义提示双重弹出）；测试用
  `getByRole('button', { name })` 定位。

## 10. 右侧指令卡片列

鱼店页右侧有一列指令卡片（`web/src/components/FishCommandCards.tsx`），与首页卡片同一套外观
（共享 `components/CommandCard.tsx`）：

| 卡片 | 指令 |
| --- | --- |
| 钓鱼信息 | `/fish info` |

- **只保留「钓鱼信息」**：它的内容没有 REST 端点，只能靠 rawcmd 取回。
  货架 / 鱼罐 / 消费榜 / 鱼篓榜的卡片已移除（货架走 REST 货架；其余不再作为网页入口）。
- **不依赖鱼店 REST API**：卡片只走 rawcmd（`transport.runCommand`），所以插件没有 REST 接口
  （`plugin=true, rest=false`）或当前用户组无权限时，左侧只显示提示，右侧卡片**照常可用**。
  卡片列在 `authenticated` 时始终渲染，与 `canUse = plugin && rest && permission` 无关，**没有收起开关**。
- **批量执行（统一执行）**：与首页一致；开关已从首页搬到**「设置」**（`Switch`，存 `tswui:homeBatch`），
  未安装批量执行信使插件（WebUI）时开关禁用并提示，自动回退为逐条执行。
- **卡片密度与管理**：鱼店与首页共用压缩版 `CommandCard` / `CardManagerSheet`。卡片底部不再重复显示指令；
  管理器中点击「添加卡片」才展开名称 / 指令表单，自定义卡片按需进入编辑态，「自动执行」统一为 `Checkbox`。
- **页头收进顶栏**：页内不再有标题行；「重新检测」「页面说明」「上次刷新」「管理卡片」「刷新全部」都在内容区顶栏右侧（`TopBarActions` + `IconAction` + `InfoPopover`）。
- **两列 + 锁定视口高（v1.3 / v1.4，v1.50 去掉标题行）**：鱼店页外层是 2 列 grid，
  `xl:h-[var(--fish-fill)]`：左列 = 搜索 + 商品，右列 = 指令卡片列表，两列各自内部滚动。
  具体做法：左页头、左内容各是一个 grid 项（`xl:col-start-* xl:row-start-*`）；`FishCommandCards` 根节点
  在 xl 下用 **`xl:contents`（`display: contents`）**，让它的表头 / 列表**脱离包裹层**直接成为 row1 / row2 的右格。
  这样无论左页头是一行还是两行（描述换行、切语言），**两边第一张卡片的顶部都会对齐**。
  整页高度锁定到 `--fish-fill`，row2 取 `minmax(0,1fr)`：
  - 货架区 `xl:flex-1 xl:min-h-0 overflow-y-auto overscroll-contain`（内部滚动，所有行可达；不再用
    `max-h-[var(--fish-fill)]`——那样会比可用高度多出「页头 + 间距」，导致最后一两行被截到视口外、只能靠页面滚动看到）；
  - 右卡片列表 `xl:min-h-0 overflow-y-auto`（同样在 row2 内填满、内部滚动）。
- 卡片内边距与列间距：左卡 `CardBody pt-3` = 右卡 `CardHeader py-3`；列内 `gap-4`。
