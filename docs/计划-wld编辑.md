## 0. 结论先行

| 结论 | 说明 |
| --- | --- |
| **能做，但要分层** | 头部字段（世界名 / 种子 / 难度 / 出生点 / 时间 / Boss 进度…）**可行且风险可控**；图格绘制是另一个量级的工程 |
| **不能只打补丁** | `.plr` 是加密的定长字段，就地补丁即可；`.wld` 的**段指针表记录每段结束位置**，头部长度一变，后面所有段都要平移 + 重写指针表 |
| **有一个隐藏坑** | footer 里**重复**存了「世界名 + worldId」，游戏加载时逐字节比较，改了世界名不改 footer → 世界直接打不开 |
| **图格编辑建议后置** | 小世界 4200×1200 = 500 万格、大世界 2000 万格；RLE 解压/重压 + frame 数据 + 内存，属独立工程 |

## 1. 现状

- 只读解析：`parseWorld()` 读文件头（release / FileMetadata / 段数 / 段指针 / `frameImportant` 位图）+ **整个头部字段段**，
  并断言 `r.pos === pointers[1]`（这本身就是对齐校验）；图格段及之后只给出起点 `tilesAt`，不解析。
- 页面：`pages/WorldPage.tsx` + `components/world/WorldPanel.tsx`（缩略图 + 世界信息 + 导出原文件 / 导出 PNG + 来个 Demo）。
- 文件大小上限：`MAX_WORLD_FILE_BYTES = 64 MiB`（1.4.5.8 最大世界约 15.5 MiB）。

## 2. 文件结构（1.4.5.8 事实，出处 `Terraria.IO/WorldFile.cs`）

写入端 `SaveWorld_Version2` 依次写 11 段，并**把每段的结束位置**记进指针数组：

| # | 段 | 内容 | 我们是否需要解析 |
| --- | --- | --- | --- |
| 0 | `SaveFileFormatHeader` | `int32 release` + FileMetadata（8 字节魔法 + revision + 收藏位）+ `int16` 段数 + 段指针 × N + `frameImportant` 位图 | 已解析（不写） |
| 1 | `SaveWorldHeader` | 世界名、种子、worldGenVersion、GUID、worldId、边界、宽高、**难度 / 特殊种子**、创建 / 最后游玩时间、月相与背景、**出生点**、地面 / 岩石层、**时间 / 白天 / 月相 / 血月 / 日食**、**地牢点**、邪恶类型、**Boss 与事件进度**、渔夫名单、横幅、四柱… | 已解析（可写：见 §3） |
| 2 | `SaveWorldTiles` | RLE 压缩的图格（含墙、液体、染料、斜坡、actuator…） | 不解析 |
| 3 | `SaveChests` | 箱子 + 内容 | 不解析 |
| 4 | `SaveSigns` | 招牌文本 | 不解析 |
| 5 | `SaveNPCs` | 已入住 NPC | 不解析 |
| 6 | `SaveTileEntities` | 标牌 / 物品框 / 训练假人 / 逻辑门… | 不解析 |
| 7 | `SaveWeightedPressurePlates` | 称重板 | 不解析 |
| 8 | `SaveTownManager` | 城镇房间 | 不解析 |
| 9 | `SaveBestiary` | 怪物图鉴 | 不解析 |
| 10 | `SaveCreativePowers` | 旅途世界能力 | 不解析 |
| — | `SaveFooter` | `bool true` + **世界名** + **worldId** | 需读：名字要跟着改 |
| — | `SaveHeaderPointers` | 回到文件开头重写 release + 跳过 20 字节 + 段数 + 所有指针 | 需重写 |

加载端对应的硬校验（会直接返回 `BadSectionPointer` / `BadFooter`）：

- 每段读完的 `Position` 必须等于 `positions[i]`；文件头读完必须等于 `positions[0]`；
- footer 的 `worldName` 必须等于头部读到的世界名、`worldId` 必须一致。

## 3. 三种编辑级别

### A 级：头部定长字段（就地补丁，最安全）

可编辑且**长度不变**的字段（都是 `int32` / `bool` / `double`）：

| 字段 | 类型 | 校验 / 说明 |
| --- | --- | --- |
| 难度 `gameMode` | ≥209 是 `int32`，更早是 `bool` | 0 普通 / 1 专家 / 2 大师 / 3 旅途；改难度会改敌人与掉落规则（已生成内容不变） |
| 出生点 `spawnX/Y` | `int32 × 2` | 必须在 `[0, width)` / `[0, height)` 内，否则进游戏会被挪到地表 |
| 时间 `time` / `dayTime` | `double` + `bool` | `time` 是 0–54000 的当日时间（4:30 起算）；不校验也能进，但建议 0–54000 |
| 月相 `moonPhase` | `int32` 0–8 | 只影响夜晚贴图与部分刷怪 |
| 血月 / 日食 | `bool` | 只影响当晚事件 |
| 地牢点 `dungeonX/Y` | `int32 × 2` | 世界结构相关，**建议只读**（改了不会移动地牢，只会挪「地牢位置」标记） |
| Boss / 事件进度 | 约 30 个 `bool` | 单独勾选；注意「困难模式」`hardmode` 是独立位，勾了 Boss 不等于进入困难模式 |
| 渔夫 / 派对等杂项 | `bool` / `int32` | 可选做，价值低 |

**做法**：与 `.plr` 同一套思路 —— 解析时记录偏移（`WorldTrack`），写回时只改这些字节。
**不会移动任何段**，指针表原样不动，footer 原样不动。**零结构风险**。

### B 级：变长字段（世界名 / 种子）—— 需要重排

`SaveWorldHeader` 的第一个字段是 `WriteString(worldName)`，第二个是 `WriteString(seedText)`（≥179）。
字符串是 7-bit 长度前缀 + UTF-8，**长度一变整段就变长**。步骤（已推演，可行）：

1. 拆段：`[0, pointers[0])` 文件头、`[pointers[0], pointers[1])` 头部段、`[pointers[1], footer 起点)` 其余段、footer 尾部；
   **footer 起点 = 最后一个有效（> 0）的段指针**，不是 `pointers[N-1]`：老存档（release < 210）没有
   bestiary / 创造之力段，指针表里多出来的槽位写的是 `0`（见 `docs/技术事实.md`）。
2. 在头部段里按偏移**替换字符串**（新名字 / 新种子），其余字节原样拷贝 → 得到新头部段（长度 `L'`）；
3. 其余段与 footer 整体平移 `delta = L' - L`；
4. 重写指针表：`pointers[0]` 不变，`pointers[1..]` 全部 `+ delta`（**`0` 占位保持 `0`**）；
5. **重写 footer 里的世界名**（`bool true` + 名字串 + `worldId`）——不改就会被游戏判 `BadFooter`；
6. `Revision++`（游戏自己保存时也这么做，云存档冲突检测用）。

风险点与对策：

- 段指针写错 → 世界打不开：写完后用**自己的解析器重新解析**（它断言每段对齐）+ 逐段断言 `pointers[i]` 与重算的偏移一致；
- 世界名长度：游戏建世界时限制 20 字符，**超过 20 会有隐性后果**（文件名、UI 截断），编辑时限制 ≤ 20 个字符；
- 改种子**不会重新生成地形**：只影响「显示 / 未来用同种子重生成」，UI 必须写清；
- 名字里含非 ASCII 时按 UTF-8 长度算（.NET `WriteString` 用 7-bit 编码长度）。

### C 级：图格 / 箱子 / 招牌（大的那块，建议后置或做「安全子集」）

- 图格段是 RLE：每列按 `header1..header4` 位流描述「激活 / 有墙 / 液体 / 图格 id 宽度 / 重复次数」，
  解码必须按 `for x { for y }` 顺序（`docs/技术事实.md` 已记录解码规则）。
- 编辑需要：解码整段（小世界 500 万格 / 大世界 2000 万格）→ 修改 → 按游戏规则重新压缩 → 段长度变化 → 重写指针（同 B 级）。
- 内存：每格至少 1 字节 → 小世界 5 MB、大世界 20 MB；编码时还要按列缓冲。可行但要做**分块 + 进度条**。
- `frameImportant` 图格（箱子、门、画、平台…）的 `frameX/frameY` 是独立数据，**不能随便换 id**：
  安全子集 = **只允许在「同为 frame-important」或「同为普通方块」之间替换**，保留原 frame 数据；
  这样「石头→雪块 / 土→泥」这类替换是安全的，「空位→箱子」这类不做。
- 箱子内容 / 招牌文本是独立段，长度变长同样要重排指针，且箱子还有「名字 / 世界 ID」等一致性要求 → 另立计划。

## 4. 校验规则（与游戏同口径）

| 项 | 规则 | 依据 |
| --- | --- | --- |
| 世界名 | 1–20 字符；不能为空 | 游戏建世界限制 20；footer 会逐字节比较 |
| 种子 | 任意文本（≥179 的存档才有；179 是 `int32`） | `WorldFileData.SeedText` |
| 难度 | 0–3；只允许在「当前存档已支持的取值」内（`gameMode` 是 `int32`，都能写） | `Main.GameMode` |
| 出生点 | `0 ≤ x < width`、`0 ≤ y < height` | 否则游戏把玩家放到地表 |
| 时间 | `0 ≤ time < 54000`；`dayTime` 布尔 | `Main.time` / `Main.dayTime` |
| 月相 | 0–8 | `Main.moonPhase` |
| Boss 位 | 布尔；勾「机械三王任一」时提示「困难模式需单独勾」 | `LoadHeader` 字段独立 |
| 图格替换（若做） | id 必须存在；只允许同 `frameImportant` 类内替换 | 见 §3 C |

## 5. UI 方案

- 入口：「查看世界」工具卡新增「编辑」按钮（`view &&`），与 `.plr` 保持一致的心智：**编辑态在本页切换**。
- 编辑态布局：
  - 卡片一「世界」：世界名（`Input`，≤20）、种子（`Input`，旧存档置灰）、难度（`NativeSelect`）、
    出生点 X/Y、时间（`Input` + 白天/夜晚切换）、月相（`Select`）。
  - 卡片二「进度」：Boss / 事件复选框网格（沿用 `WorldPanel` 的中文名与顺序），旁边提示「困难模式独立」。
  - 底部操作：`保存并下载 .wld` / `放弃修改`（有改动时二次确认），与 `.plr` 相同。
- 编辑态保留缩略图（只读），让人能确认「改的是哪个世界」。
- 文案必须写清两条：**改种子不会重生成地形**；**服务器上正在用的世界要先关服再替换文件**（TShock 退出时会写回世界文件）。

## 7. 测试策略

1. **合成夹具**：`web/src/test/worldFile.ts` 已能现场拼 `.wld`（现有单测在用），扩展成「带 11 段指针 + footer」的完整小文件；
2. **写回不变量**：
   - 空编辑 → 输出与输入逐字节相同；
   - A 级改一个 `int32` → 只有那 4 字节变化（`.wld` 没有加密，可以直接逐字节 diff）；
   - B 级改世界名 → 段指针 = 重算值、footer 名一致、重新解析通过、**其余段逐字节相同**；
3. **真实文件回归**：仓库里有 `web/public/demo/world.wld`（81 KB 空白小世界），加一份用户真实世界（若可提供）做「解析 → 写回 → 再解析」；
4. **游戏内验证（必须人工）**：改难度 / 时间 / 出生点 / 世界名 → 进游戏看是否生效、世界能否打开；
5. 反例：名字超 20 字、出生点越界、把 `pointers` 弄乱 → 都要有可读错误（不是静默坏档）。

## 10. 与 `.plr` 编辑的差异（实现时别搞混）

| 项 | `.plr` | `.wld` |
| --- | --- | --- |
| 加密 | AES-128-CBC，需重新加密 | 无加密，直接字节 |
| 变长字段 | 名字在**文件头之后**、且后面紧跟定长字段，改名字需要重排整份（当前**不允许**改名字） | 世界名/种子在头部段内，**允许**，但要平移段 + 改 footer |
| 指针表 | 无 | 有（11 段结束位置），任何长度变化都要重算 |
| 尾部一致性 | 无 | footer 校验世界名 + worldId |
| 修订号 | FileMetadata revision（我们目前不动它） | `Revision++`（游戏自己保存时也这么做） |

## 7.9 W3 实现补注（安全子集，已交付）

实现见 `web/src/lib/save/worldTileReplace.ts` + `components/world/WorldTileReplace.tsx`。

比计划更保守的一条：**只允许「id 字节宽度相同」的替换**（都 <256 或都 ≥256），
于是改动只落在 run 里的 id 字节上，**文件长度、段指针表、footer 全部不变**，不需要重压 RLE、也不需要重排段。
（计划里写的「重压整段 + 重写指针」是通用做法；在这里可以整段跳过，风险更低。）

守卫（`checkTileReplace`）：同一种图格 / 换成空气 / 源是空气 / id 不存在 / 字节宽度不同 / `frameImportant` 不同 → 直接拒绝并给出原因。
保留原 `frameX/frameY`（同计划）；**已知限制**：同为 frame-important 但形状不同的图格换完可能显示错位。

验证：合成世界（RLE 逐条、1 字节与 2 字节 id）、真实世界（75 个 PC 世界逐个做一次替换：长度不变、
被换格数 == 原计数、墙/液体/空气统计不变、段指针与 footer 位置不变）。

实现：`lib/save/worldContent.ts`（草稿/校验/差异）、`lib/save/worldSections.ts`（箱子段/招牌段编码）、
`components/world/WorldContentEditor.tsx`（UI），写回走 `worldWrite.ts` 的**按段拼装**。

范围：**改内容不改结构** —— 箱子名（≤20）、箱子物品（物品/数量/词缀/清空单格）、招牌文本（≤1000）。
箱子 / 招牌的**数量与坐标不变**；「加/减箱子」要在图格段里放置/移除箱子图格并保持索引一致，属于另一个量级的改动，不做。

做法（把第 1、3、4 段统一成「按段拼装」）：
```
第 i 段 = [pointers[i-1], pointers[i])，第 0 段从 0 开始
重建需要变的段（头部 / 箱子 / 招牌），其余段原样拷贝
新指针 = 各段长度的前缀和（原来为 0 的占位保持 0）
footer：改了世界名才重建（footer 里没有箱子/招牌数据）
Revision++
```
为什么不「就地补丁」：这两段含变长字符串，长度一变后面全部要平移 —— 所以干脆整段重建，
让「长度变化」变成唯一需要小心的地方，而不是「部分改 + 部分不变」的混合状态。

校验：箱子名 ≤20 字符（`Utils.TrimUserString(name, 20)`）、招牌 ≤1000 字符（宽松上界）、
物品规则与背包一致（id 存在 / 禁入背包 / 数量 ≤ maxStack / 词缀可滚），只校验改过的格子。

验证（`localSaves.test.ts`，75 个真实世界逐个跑）：
1. **原样重建箱子段 / 招牌段 == 逐字节相同**（唯一差异是 `Revision+1`），且段指针表不变 —— 这是最强的一条；
2. 真改一次（招牌文本变长 + 箱子名）：重新解析读到新值、箱子/招牌数量不变、**图格段逐字节不变**。
