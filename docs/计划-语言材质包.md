# 计划-语言材质包（Terraria 语言 Resource Pack）

> 状态：**已实现（2026-11-04）**；当前行为见 [`功能-语言材质包.md`](功能-语言材质包.md)。
> 实施时的取舍与偏差见本文 §8。
> 目标：在「设置」里上传 / 勾选 Terraria 语言材质包，让物品名、物品提示、NPC / Buff / 词缀 / 图格名等
> **显示文本**改用材质包里的内容；可同时应用多个包，列表靠上的优先；数据只留在本机浏览器。
>
> 本文记录机制与取舍；页面上的具体文案 / 交互以功能文档为准。

## 2. 调查结论（全部为实测 / 读源码，非推测）

### 2.1 材质包文件格式

Terraria（Steam 创意工坊）语言包解压后是**带 depot 包装层**的目录：

```
<SteamId>/depots/105600/<ManifestId>/
  pack.json                       # 包元信息
  workshop.json                   # 创意工坊元信息
  Icon.png / icon.png             # 封面（本项目不用）
  Content/Localization/<culture>/ # zh-Hans / en-US …
    Items.json  Items.csv         # 1.4.4+ 用 JSON，1.4.2 时代用 CSV
    NPCs.json / Game.json / Main.json / Legacy.json / Projectiles.json / Town.json …
  Content/Itеms.json              # 实测：Potralia 包里还有一个西里尔字母 е 的仿冒文件（见 §3.3）
```

`pack.json`（两者一致）：

```jsonc
{
  "Name": "1.4.2 汉化修正",
  "Author": "hufang360",
  "Description": "…",
  "Version": { "major": 1, "minor": 1 }   // 包自身版本，不是游戏版本
}
```

`workshop.json`：`{ WorkshopPublishedVersion, ContentType: "ResourcePack", SteamEntryId, Tags: ["Language/Translations"], Publicity }`。

**语言表的两种格式**：

| 格式 | 结构 | 备注 |
| --- | --- | --- |
| JSON（1.4.4+） | `{ "ItemName": { "Ruby": "红玉" }, "ItemTooltip": { … }, "NPCName": { … }, "LegacyTooltip": { … }, … }` | 与官方 `Terraria.Localization.Content.<culture>.*.json` 同构；字符串里可带 `{$Key}`、`{InputTrigger_*}`、`\n`、`[c/hex:text]`、`[i:ID]` |
| CSV（1.4.2） | 首行 `key,translation`（**带 UTF-8 BOM**），每行一个扁平 key，如 `ItemName.Ruby,红玉`、`NPCName.CrimsonBunny,猩红兔兔` | 值可能含引号 / 逗号，需要真正的 CSV 解析 |

两者都可以还原成 `{ 分类: { key: value } }`：CSV 在**第一个点**处切分类。

### 2.2 两个示例包实测

| | `2447707451-【语言包】1.4.2汉化修正.zip` | `2588891124-Potralia的个人汉化.zip` |
| --- | --- | --- |
| 体积 / 条目 | 11,356 B / 20 条 | 470,869 B / 23 条 |
| 格式 | **CSV**（1.4.2） | **JSON**（1.4.4+） |
| pack.json | `1.4.2 汉化修正` / hufang360 / v1.1 | `Potralia的个人汉化(26.10.26)` / Potralia / v145.56 |
| SteamEntryId | 2447707451 | 3786727901 |
| 语言目录 | `zh-Hans` | `zh-Hans` |
| 实际词条 | Items 14、NPCs 8、Game 2、Main 16、Projectiles 7 | ItemName 6178、ItemTooltip 2438、Prefix 97、NPCName 703、BuffName 333、BuffDescription 300、MapObject 78、CommonItemTooltip 49、LegacyTooltip 61、GameUI 133、LegacyInterface 125、PaintingArtist 39 …… |
| 与本项目 1.4.5.8 数据的差异 | 12 个物品名、1 个词缀、2 条物品提示、8 个 NPC 名、2 个图格名 | 物品名 **1386** 条不同、NPC 名 **193** 条、Buff 名 **179** 条、`ItemTooltip` **2256** 条、`CommonItemTooltip` **43/49**、`LegacyTooltip` **24/61**、`GameUI` **71/133** 不同 |
| 富文本 | 无 | `ItemTooltip` 里 602 条含 `[c/...]`、204 条含 `[i:ID]`（微光转化提示）；`{$Key}` 引用 423 个、19 个引用键包内未定义 |

其他实测事实：

- zip 里文件基本都是 **deflate**（`defN`），只有目录是 store；所以必须能解压，不能只处理 store。
- 包内 `ItemTooltip` 的 key 就是**物品内部名**（`BookStaff` / `RodofDiscord`），与 `data/items.json` 的 `key` 完全对得上
  （Potralia 包 6178 个 `ItemName` 里 6175 个命中本项目 6195 件物品；`ItemTooltip` 2438 个里 2437 个命中）。
- 旧包（1.4.2 CSV）仍能按 key 命中 1.4.5.8 的物品 / NPC；缺的新条目应**回退到内置文本**，不报错。
- 包内文本是**不可信输入**：可能出现任意分类、任意文件（含上文的仿冒 `Content/Itеms.json`）、超大 JSON。解析要限路径、限大小、只认白名单分类。

### 2.3 项目现有的文本链路（为什么「只覆盖名字」不够）

- `data/items.json` / `npcs.json` / `prefixes.json` / `buffs.json` **只存内部名**，显示名在 `loadDataset()` 里从
  `data/loc.<culture>.json` 解析；`tiles` 的显示名（`tileNameById`）也在同一处用 `loc.MapObject` / `loc.ItemName` 预计算；
  配方组名走 `locText(dataset.loc, …)`。
  → **只要在 `loadDataset()` 里把 loc 表按材质包覆盖，名字类文本（物品 / NPC / Buff / 词缀 / 图格 / 配方组）全部自动生效**，
  搜索、指令补全、图鉴、数据 ID 页都不需要单独改。
- `data/loc.<culture>.json` 目前只收 `ItemName / Prefix / LegacyMisc / Misc / NPCName / BuffName / MapObject` 七类。
- **物品 tips 是构建期算好的死文本**：`data/item-tips.<culture>.json`（zh 340KB / 6049 件，en 376KB），
  由 `tools/gen-item-stats.mjs` 复刻 `Main.MouseText_DrawItemTooltip_GetLinesInfo()` 生成，
  运行期只被 `ItemTooltipContent` 当数组渲染。
  → 只覆盖 `ItemName` 的话，**物品提示里的自定义文案（`ItemTooltip.<key>`）和通用行（`CommonItemTooltip.*` / `LegacyTooltip.*`）
  仍然显示 1.4.5.8 官方文案**，与本需求 R2 不符。这是本功能的主要工程量。
- `ItemTooltipContent` 里还有一处耦合：`applyPrefix()` 用 **i18n 里的 8 个速度词 / 9 个击退词**（`prefix.speed.*` / `prefix.kb.*`）
  识别提示行来重算词缀。若材质包改写了 `LegacyTooltip.6–22`，这里会匹配失败 → 换词缀后速度 / 击退词不更新。
- 物品提示行现在是纯文本 `<p>`，没有富文本渲染；而材质包文本带 `[c/...]` / `[i:...]`（§2.2）。
- `tools/gen-item-stats.mjs` 里数值后缀（伤害 / 防御 / 镐力 / 速度档 / 击退档…）分别引用
  `LegacyTooltip.*`、`CommonItemTooltip.*`、`GameUI.*`、`LegacyInterface.65`、`ItemTooltip.<key>`；
  展开 `{$Key}` 最多 4 层，`{InputTrigger_*}` 用固定展示名替换（官方共 16 个触发器键，脚本目前只替换 7 个）。
  - 顺带发现一处**数据源本身的笔误**：官方 `ItemTooltip.RubblemakerLarge` 是
    `{InputTrigger_ToggleOrOpen切换放置大小`（缺 `}`），所以现在物品 5330 的提示会原样显示这个占位符。与本功能无关，可顺手在解析里容错。

### 2.4 做「完整覆盖」还缺什么

| 缺口 | 说明 |
| --- | --- |
| 运行期拿不到 tip 的构成 | `item-tips.*.json` 只有最终字符串，没有「这一行来自哪个本地化 key」 |
| 缺 tip 用到的本地化表 | `loc.*.json` 没有 `ItemTooltip`（官方 zh 约 129KB）、`CommonItemTooltip`、`LegacyTooltip`、`GameUI`、`LegacyInterface`、`PaintingArtist`、`BuffDescription`；全加约 **+148KB / 语言** |
| 缺 `InputTrigger` 展示名表 | 需要在运行期把 16 个 `{InputTrigger_*}` 换成可读文本（中文 / 英文各一份） |
| 若要在前端复刻 tip 生成逻辑 | `item-stats.json` 缺 `social` / `hasVanityEffects` / `tooltipDamageMultiplier` / `useStyle` / `tileWand` / `mountCart` / `placeTileOnAltUse` / `notAmmo` / `chlorophyteExtractinatorConsumable`，且负值 `createTile` 被丢弃，还缺「宠物 buff」集合 → 需要重跑 GameDump 再生成 |

### 2.5 存储与构建现状

- 前端**只有 localStorage**（`web/src/lib/storage.ts`，统一前缀 `tswui:`；键清单见 `docs/设计原则与约束.md` §4.6），
  项目里**没有 IndexedDB**、没有 zip 读取代码（精灵图只有 store-only 的 ZIP **写入**器 `web/src/lib/spriteSheet/zip.ts`）。
- 浏览器原生 `DecompressionStream('deflate-raw')` 可用（Chrome 103+ / Firefox 113+ / Safari 16.4+），项目暂未使用；
  Node 26（本机）也有，便于测试。
- `web/vite.config.ts` 的 `dataDirPlugin`：dev 下 `/data/*` 可读**任意子路径**；但 `closeBundle` 只复制 `data/` **顶层文件**到 `dist/data/`。
  → 若内置包放在 `data/langpacks/`，构建拷贝需要改成递归（约 10 行）。
- Go 端 `//go:embed all:internal/webdist` 已包含子目录；`/data/*.json` 有 ETag + `no-cache`。
  **本功能不需要任何新的 `/api/*`**，也不需要服务端写盘。
- 设置页结构：`SettingsPage` 双栏；左侧顶部 `PreferencesCards section="interface"`（登录 / 未登录两个分支都渲染），
  右侧 `PreferencesCards section="behavior"` + 插件诊断 + 在线授权。
  已有可复用件：`CollapsibleCard`、`Switch`、`Badge`、`IconAction`、`ConfirmButton`、`toast`（sonner）；
  `CustomModulesSection` 里已有「拖拽 + 上移 / 下移 + 抓手柄」的排序实现可照抄。

## 3. 方案

### 3.1 范围

- **只做显示文本**（localization）。材质包里的贴图 / 音效 / 图集**一律不处理**（本项目图标来自自建图集）。
- 只影响**本浏览器**的界面文本，不改服务器、不改 TShock、不影响指令实际执行与权限（§3.2）。
- 不新增 `/api/*`、不写服务器磁盘（保持 C14 / 单容器、浏览器不持有 token 的约束）。
- 不改 `items.json` 的内部名 / ID；只改「显示名」与提示文本。

### 3.2 存储：浏览器本地（IndexedDB）

「数据保持在本地」按**每台浏览器各自保存**实现：

| 数据 | 位置 | 说明 |
| --- | --- | --- |
| 已导入的包（解析后的词条） | **IndexedDB**：db `tswui` / store `languagePacks`，主键 `id` | 一个 Potralia 包解析后约 1.2MB 文本；localStorage 5MB 配额且同步读写，不合适 |
| 启用状态与优先级顺序 | **localStorage** `tswui:languagePacks` = `{ order: string[], enabled: string[] }` | 纯界面偏好，沿用 `useLocalState` |
| 内置包 | 随前端产物下发（`/data/langpacks/<SteamId>.zip`），启用时 fetch + 解析，**不写入 IDB** | 不可删除，只能勾选 |

记录结构（打包成一个对象存，避免多次读事务）：

```ts
interface StoredLanguagePack {
  id: string                 // 内置："builtin:2447707451"；上传：zip 字节 SHA-256
  name: string
  author?: string
  description?: string
  version?: string           // pack.json 的 major.minor
  steamId?: number
  format: 'json' | 'csv'     // CSV → 1.4.2 旧格式提示
  cultures: string[]         // 包内实际有的语言目录
  entries: Record<string, LocalizationBundle>  // culture → {分类: {key: value}}
  sourceName: string         // 上传时的文件名
  bytes: number
  importedAt: number
}
```

导入前用 **SHA-256** 去重（同包重复上传 = 覆盖更新，不叠加）。
IDB 不可用（隐私模式 / 被禁用）→ 明确提示「本浏览器无法保存材质包」，本次会话内仍可临时应用；不静默失败。

### 3.3 解析与校验（纯前端）

1. 读 zip 的**中央目录**（自行解析 EOCD / 中央目录，支持 store 与 deflate；deflate 用 `DecompressionStream('deflate-raw')`，
   本地测试用可注入的 `inflateRaw`，Node 下用 `node:zlib` 对照）。
2. 定位包根：取**层级最浅**的 `pack.json`，以它所在目录为根（兼容上面的 depot 包装层；也兼容直接是包根的 zip）。
3. 只读 `pack.json` 与 `Content/Localization/<culture>/{*.json,*.csv}`；
   **忽略**其他任何路径（含 `Icon.png`、`.DepotDownloader/`、`Content/Itеms.json` 仿冒文件）。
4. 每个文件：JSON → 顶层必须是 `{分类: {key: string}}`；CSV → 首行 `key,translation`（去 BOM），按第一个 `.` 切分类，
   值做标准 CSV 反转义（`""` → `"`）。
5. 汇总成 `{ 分类: {key: value} }`，只保留**白名单分类**（§3.4）。
6. 校验与限额：
   - 必须至少有 1 个受支持的分类、至少 1 条词条，否则报「不是语言材质包」；
   - zip ≤ 20MB、解压后单文件 ≤ 8MB、解压总量 ≤ 32MB、条目数 ≤ 2000（防 zip bomb）；
   - `pack.json` 解析失败 / 无 `pack.json` → 明确错误，不猜测。
7. 结果里带 `format`（csv/json）、`cultures`、各分类词条数、`steamId`，用于 UI 标签与提示。

### 3.4 合并规则

- **按 culture 分开存**；应用时只取**当前界面语言**对应的那一份（`zh-Hans` / `en-US`）。
  - 包里没有当前语言的文本 → 该包显示「当前界面语言无对应文本」，不参与合并（不报错、不混语言）。
- 合并顺序 = 列表中**从上到下**；同一个 `(分类, key)` **先到先得**，靠上的包胜出。
  实现：从空覆盖表开始，按列表顺序写入；已存在的 key 跳过（或反向遍历、后写覆盖，二者等价，注意与 UI 顺序对应）。
- 白名单分类（其余忽略）：
  `ItemName`、`Prefix`、`NPCName`、`BuffName`、`MapObject`、`Misc`、`LegacyMisc`、
  `ItemTooltip`、`CommonItemTooltip`、`LegacyTooltip`、`GameUI`、`LegacyInterface`、`PaintingArtist`、`BuffDescription`。
- 合并结果是 `LocalizationBundle` 的覆盖层，交给 `loadDataset(lang, overrides)`：
  `mergedLoc = { ...baseLoc, [分类]: { ...base[分类], ...override[分类] } }`。
  名字解析、`tileNameById`、配方组名全部基于 `mergedLoc`，**无需其他改动**。

### 3.5 物品 tips 如何跟随材质包（核心决策）

**推荐方案 A：把「tip 配方」放进数据，运行期按当前 loc 解析。**

- `tools/gen-item-stats.mjs` 不再只输出最终字符串，而是把 `composeTip()` 的每一行输出成**语言无关的描述符**，
  统一写 `data/item-tips.json`（单个文件，替换现在的 `item-tips.<culture>.json`）：

  ```jsonc
  { "meta": { "gameVersion": "1.4.5.8", "generatedBy": "tools/gen-item-stats.mjs" },
    "items": {
      "3852": [
        { "k": "LegacyTooltip.2", "p": "36" },              // 36 + 魔法伤害
        { "k": "LegacyTooltip.5", "p": "4%" },              // 4% + 暴击率
        { "k": "LegacyTooltip.8" },                          // 快速度
        { "k": "LegacyTooltip.19" },                         // 很强击退力
        { "k": "CommonItemTooltip.UsesMana", "a": ["20"] },  // 使用{0}魔力
        { "k": "ItemTooltip.BookStaff", "b": 1 }             // 物品独占文案块（按 \n 拆行）
      ]
    } }
  ```

  描述符字段：`k` = 本地化 key；`p` = 前缀字面量（数字 / `4%`）；`a` = `{0}` 参数；
  `t` = 追加的另一个 key（`tileWand`：`LegacyTooltip.52` + 目标物品名）；`b` = 独占文案块；
  `keep` = 键缺失时仍保留 `p`（伤害行是「有就拼、没有只留数字」）。
- 运行期 `web/src/lib/itemTips.ts` 解析：
  1. `k` 在 `mergedLoc` 里查值；缺失 → 该行省略（`keep` 时只留 `p`）；
  2. 展开 `{$Key}`（最多 4 层）与 `{InputTrigger_*}`（16 个键 → `loc.InputTrigger`）；
  3. 代入 `{0}` 参数；`b` 按 `\n` 拆成多行；`t` 追加 `ItemName.<key>` 的**当前**名字。
- 新增 `loc.<culture>.json` 分类（`gen-data.mjs` 的 `LOC_CATEGORIES`）+ `InputTrigger` 展示名；
  总增量约 148KB / 语言（其中 `ItemTooltip` 129KB）。
- 这样**材质包的 `ItemTooltip` / `CommonItemTooltip` / `LegacyTooltip` / `GameUI` 全部自然生效**，
  而且游戏版本升级只需重新生成数据，前端解析逻辑不变。
- 体积：`item-tips.<culture>.json`（340KB + 376KB）可以下线，换成单个描述符文件；
  独占长文案不再重复（只在 `loc.ItemTooltip` 里存一份），总体**更小**。
- **正确性护栏**：
  - 迁移期保留现有 `item-tips.<culture>.json` 作为 fixture，加一条 realdata 测试：
    用描述符 + 官方 loc 解析出的 tips，与现有文件**逐件逐行完全相等**（zh / en 各 6049 件）；
  - 相等后再决定是否删除旧文件（建议先保留一个版本，便于回滚；但运行期不再 fetch）。

**备选方案 B：把 `composeTip()` 的判定逻辑搬到前端。**
不新增数据格式，但要给 `item-stats.json` 补齐 §2.4 的字段（需重跑 GameDump），并把 ~200 行游戏规则复制到前端。
规则会在两处漂移（`ItemTooltipContent` 里已经复制过速度 / 击退档位），因此不作为首选。

**两方案的共同点**：都需要新增 §3.4 的 loc 分类与 `InputTrigger` 表；都需要一个 `{$}` / `{InputTrigger_*}` 展开器；
都需要处理 `[c/...]` / `[i:...]`（§3.6）。

### 3.6 富文本标签（材质包会带 `[c/...]` 与 `[i:ID]`）

- 官方 1.4.5.8 的提示文案本身没有颜色 / 图标标签，但材质包有（§2.2）。
- 直接纯文本渲染会把 `[c/d45757:寒冻]`、`[i:3832]` 原样显示，明显是缺陷。
- 建议：物品提示行改用现成的 `parseRichText()` 渲染（颜色 + 物品图标），复用 `RichText` 的思路，但**颜色不随主题压暗**
  （tooltip 底色恒为深色，`ts-chat-color` 的浅色主题压暗规则在这里不适用）；
  图标用 `dataset.itemsById` + `itemsAtlas`，尺寸对齐 tip 行（16–18px）。
- 若实现成本超预期，退路是：解析时**去掉标签只留内部文本**（`[i:ID]` 退化为物品名），并在 UI 里说明不支持颜色。
- `RichText` 的 tokenizer 已按 Terraria `ChatManager` 正则实现，直接复用，不新写解析器。

### 3.7 内置包

### 3.9 启动与重载

- App 启动：`loadLanguagePacks()`（IDB + 内置包按需 fetch）→ `loadDataset(lang, overrides)`。
  读 IDB 是毫秒级；仍复用现有「正在加载物品与指令数据…」占位。
- 变化时：`loadDataset` 重新跑（约几十毫秒；6195 件名字 + tips 解析），保留当前页面；失败保留旧数据集并 `toast`。
  只有 `(lang, 启用包 id + 顺序)` 变化才重算；结果按 key 记忆，避免无谓重载。
- 登录 / 登出、切换服务器都**不**影响材质包（纯显示偏好，不按服务器分开）。

## 5. 风险与取舍

| 风险 | 应对 |
| --- | --- |
| 材质包文本含 `[c/]` / `[i:]` | 用现有 `parseRichText` 渲染；退路是去标签（§3.6） |
| 词缀预览与材质包速度 / 击退词不一致 | `applyPrefix` 改用 `dataset.loc.LegacyTooltip` 的同一份词表 |
| tips 重构引入回归 | 描述符解析结果与现有 `item-tips.*.json` 全量逐件比对（6195 × 2 语言） |
| zip bomb / 畸形 zip | 中央目录校验 + 大小 / 条数上限 + 明确错误（§3.3） |
| 材质包版本旧（1.4.2 CSV）缺新条目 | 缺失 key 回退内置文本；标签提示「1.4.2 旧格式」 |
| 语言不匹配 | 只取当前界面语言；无文本时提示且不参与合并（§3.4） |
| IDB 不可用 / 配额满 | 明确提示；会话内临时生效；不静默失败 |
| 重复上传同一包 | SHA-256 去重，覆盖更新而非叠加 |
| 包内恶意字符串 | React 文本节点转义；`[c/]` 颜色值按十六进制校验（沿用 tokenizer）；不执行任何内容 |
| 启动变慢 | IDB 读取 + 合并按 `(lang, 包列表)` 记忆；只解析启用的包 |

## 6. 验收

**自动化**

- zip：store + deflate 两种条目、带 depot 包装层 / 直接包根、非法 EOCD、超限 zip 的报错。
- 解析：CSV（BOM / 引号 / 逗号）与 JSON；白名单分类；忽略 `Content/Itеms.json` 等非 Localization 文件。
- 合并：多包同 key 以靠上为准；culture 过滤；禁用包不参与。
- tips：描述符 + 官方 loc 解析结果与现有 `item-tips.zh-Hans.json` / `item-tips.en-US.json` **完全一致**；
  叠加示例包后，抽查 `BookStaff` / `RodofDiscord` / `Ruby` / `NPCName` 的文本与预期一致。
- 组件：设置卡片的上传 / 排序 / 删除 / 语言无文本提示；`SettingsPage` 不因包状态影响其他设置。
- 既有测试：`dataset.realdata.test.ts`、`ItemTooltipContent.test.tsx`、`completion.realdata.test.ts` 全部通过。

**人工（本地 + 真机）**

1. 设置里上传 `2588891124-Potralia的个人汉化.zip` → 物品图鉴 / 物品提示 / NPC 名 / 图格名立即变化；
2. 同时启用内置包 + Potralia 包，交换顺序 → 重名条目以靠上为准；
3. 刷新浏览器 / 重启前端 → 顺序与启用状态保留；
4. 删除 Potralia 包 → 文本回落官方；
5. 切到英文界面 → 中文包显示「当前语言无文本」且不生效；
6. 上传非 zip / 普通 zip（无 `pack.json`）/ 超大 zip → 明确错误提示；
7. 首屏加载时间（无包 / 1 包 / 2 包）与内存无明显回退。

**收尾**：`npx tsc -b`；相关 vitest；全量 vitest 一次；`vite build` 一次；`ps` 确认无残留进程。

## 8. 实施结果（2026-11-04）

### 8.1 与 §3.5 的差异：采用方案 B

原推荐「tip 配方 + 运行期解析（方案 A）」。实施时改选 **方案 B**：

- `tools/gamedump` 的 `DumpItems()` 本来就导出了重算所需**全部**字段；只是 `gen-item-stats.mjs`
  之前只保留了一部分（`social` / `useStyle` / `tileWand` / `tooltipDamageMultiplier` / `mountCart` /
  `placeTileOnAltUse` / `notAmmo` / `chlorophyteExtractinatorConsumable` / `wireable` / `container` /
  `wireTrigger` / 槽位 / `createTile=0` 等）。补齐后**不需要改数据契约**：
- 默认仍用构建期 `item-tips.<culture>.json`（行为零变化）；
- 有材质包时由 `web/src/lib/itemTips.ts` 按 `item-stats + 合并后的 loc` 重算；
- `itemTips.realdata.test.ts` 用全部 6195 件 × 中英两语言做逐行比对，保证两套结果一致。

没有采用方案 A 的原因：会新增一套「tip 配方」数据格式与解析器，但收益（少写 ~200 行前端规则）
被数据契约变更与迁移成本抵消；方案 B 还能保留 `item-tips` 作为构建期快照与回退。

### 8.2 实际落地的数据改动

- `tools/gen-item-stats.mjs`：`stats` 增加重算所需字段；`createTile=0` 不再被 falsy 丢掉；
  `mountType !== -1` 也记录；新增 `pet` 标记。tips 生成逻辑未改（除按键占位符扩展，见下）。
- `tools/gen-data.mjs`：`loc.<culture>.json` 增加 `ItemTooltip` / `CommonItemTooltip` / `LegacyTooltip` /
  `GameUI` / `LegacyInterface` / `PaintingArtist` / `BuffDescription`，并新增 `InputTrigger` 表
  （16 个按键触发器展示名，中英各一份）。语言文件体积约 +148KB/语言。
- 副作用（属修复）：`InputTrigger_Grapple` 以前未替换，27 件钩爪类物品的提示是「按**键**发射抓钩」，
  现在统一为「按抓钩键发射抓钩」。

### 8.3 前端新增

- `web/src/lib/languagePack/`：`zip.ts`（中央目录 + `DecompressionStream('deflate-raw')`）、
  `parse.ts`（zip / pack.json / JSON / CSV / 白名单 / 限额）、`store.ts`（IndexedDB + prefs + 内置包 + 合并）、
  `useLanguagePacks.ts`（控制器：导入 / 启用 / 排序 / 删除 / 就绪状态）。

- `web/src/components/settings/LanguagePackSection.tsx`；`dataset.ts` 增加 `overrides` 参数；
  `ItemTooltipContent.tsx` 的提示行改用富文本渲染，速度 / 击退词改为取 `dataset.loc.LegacyTooltip`。
- `vite.config.ts`：`data/` 构建拷贝改为递归（内置包在子目录）。
