# 物品图鉴（ItemsPage）

文档版本：1.3
对应页面：`web/src/pages/ItemsPage.tsx`（导航「物品图鉴」）
相关数据：`data/items.json`、`data/items-atlas.json`
相关代码：`web/src/lib/collections.ts`、`web/src/lib/pagination.ts`、`web/src/lib/items.ts`、
`web/src/components/ui/Pagination.tsx`、`web/src/components/ui/NativeSelect.tsx`

> 本文件描述物品图鉴页的**功能模板**：布局结构、交互规则、集合定义、复制行为、i18n 约定与验收方式。
> 集合来自 `FishShopConfig/js/search.js`，已逐条校验并固化进前端。

---

## 1. 定位与范围

物品图鉴是玩家侧的**只读浏览工具**：按集合/关键词找到物品，查看图标与 ID，复制 ID / 名称 / `[i:...]` 标签，
再把标签粘贴进指令编辑器。

- **不是**物品生成/商店/管理后台；本页不发起任何指令或 `/api/*` 请求。
- 图标沿用图集方案（`data/items-atlas.json` 的 `regions[item.icon]` 裁切第一帧），见 `docs/设计原则与约束.md` C10 / C11；
  **绘制尺寸与游戏一致（只缩不放，`sizeLimit=32`）+ 像素取整（放大取整数倍）**，见 `docs/功能-富文本解析.md` §6.1。
- 标签只影响聊天显示，不等同于指令参数（`docs/设计原则与约束.md` §6）。

**数据结构**

```ts
type CollectionGroup = 'category' | 'class' | 'friend' | 'range'

interface ItemCollection {
  id: string          // `${group}:${name}`，全局唯一，用作 <select> 的 value
  name: string        // 显示名（保留原始书写，含 emoji / 省略号）
  group: CollectionGroup
  ids: number[]       // 保留原始书写顺序，仅去重
}
```

- `COLLECTION_GROUPS` 决定 `<optgroup>` 顺序：分类 → 职业 → 水友 → ID 区间。
- `COLLECTIONS_BY_ID` 提供 id → 集合 的 O(1) 查找。
- `resolveCollectionItems(collection, itemsById)` 按集合内顺序解析为物品，缺失 ID 自动跳过（不报错）。

## 4. 页面模板（布局）

```
ItemsPage（高度 = 实际可用高度，页面自身不滚动）
├─ 工具条：**一张卡片**（Card > CardBody，三行）
│   ├─ 第 1 行：搜索 Input（防抖 180ms）+ 集合 Native Select（全部物品 + 3 个 optgroup）
│   ├─ 第 2 行：**「显示 ID」「显示名称」两个 Switch toggle**（**默认都关**，只显示图标）
│   ├─ 第 3 行（弱化）：「换一批」ghost 按钮（有搜索词时隐藏）+ 数据版本（font-pixel 10px、opacity-70）
│   └─ 第 4 行：件数文案（单独一行）
├─ 结果区：**不是卡片**（直接铺在页面上，data-testid="dex-list" 的滚动容器占满剩余高度、`overscroll-contain`）
│   └─ 只渲染**当前页**的物品（默认 50 个/页）
│   ├─ 虚拟滚动：外层撑总高度，内层只挂可视行（绝对定位到 startRow）
│   └─ 每个格子：`cursor-pointer`、**无底色**；**整张卡片都会触发 tips**（不只图标画框）
│       = **64×64 图标** + 可选 **ID** 行 + 可选 **名称行（truncate）**
├─ 翻页器（底部固定，与件数小字同一行）：`共 N 件` + 每页个数 Native Select（50/100/200/500）+ `第 x / y 页` + shadcn `Pagination`（上一页 / 页码窗口 + 省略号 / 下一页）
└─ 详情：**弹框**（Dialog，默认不渲染；data-testid="dex-detail"，`max-w-xl`（576px，常见弹框宽度）；
    **标题 / 底部固定**，仅中间「tips + 用于合成 + 作为合成」`flex-1 overflow-y-auto` 滚动）
    ├─ 左列（384px，内部滚动）：游戏同款 tips（与悬停提示同宽同组件；`bg-black/85` 半透明黑、无模糊）
    └─ 右列：**复制控件（下拉选内容，默认 ID + 单个「复制」按钮）** + **「前往 wiki 查看」** + **合成表（内部滚动）**
```

**状态保留**：页码 / 每页数量 / 集合 / 搜索词 / 两个开关 / 滚动位置 / 选中项都放在 `lib/dexState.ts` 的 `DexState` 里，
卸载时写进**模块级内存**（`rememberDexState`），再次挂载即还原 —— 因此「切到其它模块再回来」状态与随机顺序都不变；
**刷新页面会清空模块内存**，于是重新取 seed：从全部物品里重新随机取第 1 页（默认 50 个）。
测试用 `resetDexState()` 隔离（语义上等价于刷新）。

页面高度由 `useLayoutEffect` 实测得出，两处坑都踩过并修掉：

1. **写死 `calc(100dvh-7rem)`** 比真实可用高度小 64px → 下方留一条空白。
2. **用「视口 − `rect.top`」算高度**：从其它长页面切过来时容器 `main.scrollTop > 0`，
   `rect.top` 会偏小（甚至为负，例如滚了 300px 时 `24 → -276`）→ 高度算成 `1065`（真实 765）→
   **`main` 变成可滚动**，于是在左右空白处滚轮会带着整个页面（连输入框）一起滚。
   现在改成先减掉容器滚动偏移：`可用高度 = 容器 clientHeight − (rect.top − 容器顶 + 容器 scrollTop) − padding`，
   并在挂载时把容器 `scrollTop` 复位为 0；网格滚动容器另加 `overscroll-contain` 阻断滚轮链式传递。
   `MutationObserver` 继续盯容器子元素增删（移动端顶栏 / 侧栏收起按钮 / banner）。

### 4.1 尺寸与格子样式

| 项 | 规则 |
| --- | --- |
| 图标框 | **恒定 64×64**（= `sizeLimit` 32 的 2 倍）→ `mode='game'` 下是整数 2× 最近邻放大（不糊、无 1px 虚边） |
| 格子宽 | `clamp(round((容器宽 − 8) / 10) − 8, 88, 132)` → 一行约 10 个（大屏 10 个、小屏 3~4 个） |
| 格子高 | 由两个 toggle 决定：都开 **110**、只 ID **90**、只名称 **96**、都关 **76**（内边距 12 + 图标 64 + 各自行高） |
| 间距 | 8 |
| 外观 | `rounded-xl`、**无默认底色**（不铺白底）；hover `bg-primary/10` + `-translate-y-0.5`（整体上移 2px）、选中 `bg-primary/20`（都取自主题令牌，只是加深）；整格 `cursor-pointer` + `focus-visible:ring-2` |
| 提示锚点 | 绑在**整个格子**上（`useItemTooltip`），鼠标落在 ID / 名称文字上同样弹提示 |
| 采样 | **缩小用插值**（同游戏 `LinearClamp`）、**放大用最近邻**（`lib/iconScale.ts` 的 `shouldSmooth`）——当前格子恒为 1:1，等于不重采样 |

> 之前自定义格子描边时用过 `outline` + 负 offset（保证"朝内"且不占布局）——随自定义样式一并取消，
> 现在格子外观直接由主题令牌决定，hover / 选中都不会改变尺寸。

> 实测（Chrome headless + 探针，1440×900）：格子底色 `rgba(0,0,0,0)`（**无白底**）、图标 **`64px`**、格子 `130×110`、一行 **10 个**；
> 在格子里的**名称文字**上派发 `mouseover` → 提示照常出现（整卡触发）；关掉「显示名称」→ 格高 `110 → 90`；
> **复现"先停在长页面滚 300px 再切到图鉴"**：修好后 `mainScrollTopAtMount=0`、`mainScrollable=0`、`overscroll-behavior-y: contain`；
> 点格子 → `role="dialog"`、宽 `576`（`max-w-xl`）、打开后 `main` 仍不可滚；弹框内中间区域滚动（标题 / 底部固定）；
> wiki 链接实测 `…/zh/wiki/%E7%81%AB%E6%8A%8A`（返回 200）。

## 5. 交互规则

| 场景 | 行为 |
| --- | --- |
| 默认（无搜索） | **随机态**：对当前池子（全部物品 / 选中集合的条目）做确定性洗牌后分页，默认**每页 50**（总共 124 页） |
| 翻页 | 底部 shadcn `Pagination`：上一页 / 下一页（文字 + 图标）与页码窗口（`paginationRange`，页数多时用省略号收窄，如 `1 … 61 62 63 … 124`）；按钮 36px（`icon`/`md`，与工具栏同高），越界自动禁用；切页同时把网格滚动复位 |
| 每页个数 | 翻页器里的 Native Select：50（默认）/ 100 / 200 / 500；改动后回到第 1 页 |
| 当前页播报 | `第 x / y 页` 作为 `sr-only` + `aria-live` 状态，视觉上不重复（页码按钮已用 `aria-current="page"` 标识当前页） |
| 刷新页面 | 模块内存清空 → 重新随机（每次刷新拿到的 50 个不同） |
| 切到其它模块再回来 | 状态与随机顺序**原样保留**（页码 / 每页数量 / 集合 / 搜索 / 开关 / 滚动位置 / 选中项） |
| 点「换一批」 | 更换随机种子并从当前池子重新随机；滚回顶部 |
| 输入关键词 | 在当前池子内搜索（`searchItems`，按匹配分数排序）；此时隐藏「换一批」 |
| 选择集合 | 解析集合物品后**同样洗牌**（每次换一批都从该集合条目里随机取） |
| 搜索 + 集合 | 先集合过滤，再在集合内搜索 |
| 滚动 | 网格区内部滚动；只渲染可视行（虚拟化） |
| 显示 ID / 显示名称 | 搜索框下方的两个 Switch 控制格子里的行（**默认都关**）；格高随之变化（76 / 90 / 96 / 110） |
| 悬停格子 | 底色加深 + 整体上移 2px；**整个格子**（含 ID / 名称文字）悬停都会弹出同一个物品提示 |
| 点击图标 | 打开**详情弹框**（tips / 复制下拉 + 复制 / 前往 wiki / 合成表）；Esc、点遮罩、右上角 × 关闭 |
| 复制 | 单个「复制」按钮 + 下拉框选内容（**默认 ID**，另有名称 / `[i:ID]` 标签）；反馈 1.2s 内显示「已复制」；剪贴板不可用时静默失败 |
| 前往 wiki | 按当前语言打开 `terraria.wiki.gg`：中文 `/zh/wiki/<中文名>`、英文 `/wiki/<英文名，空格→下划线>`（`lib/items.ts` 的 `wikiUrl`） |

> 「每次随机」的实现：对当前池子做一次洗牌，因此**整页都是随机组合**，「换一批」重掷；
> 选中集合时池子 = 该集合条目。输入搜索词后改为按相关度排序（便于定位），不再洗牌。
> 不分页意味着最多 6195 件同时在滚动区里，因此用 `web/src/lib/virtualGrid.ts` 只渲染可视行
> （否则 6195 个 `ItemIcon` canvas 约 100MB+，首帧也会卡死）。

## 6. 设置按钮位置修复（跑偏）

- **现象**：点击侧栏底部「设置」后，面板出现在错误位置（向左溢出屏幕、向下超出视口）。
- **原因**：面板使用 `absolute right-0 mt-2 w-72`，而容器在**左侧栏底部**、宽度仅 240px：
  右对齐 + 288px 宽度导致面板向左溢出，向下展开又超出视口。
- **修复**（`web/src/components/SettingsMenu.tsx`）：
  - `right-0 mt-2` → `bottom-full left-0 mb-2`：改为**向上展开、左对齐**（按钮在底部，上方空间充足）。
  - 增加 `max-w-[calc(100vw-1.5rem)]` 与 `z-50`，防止小屏溢出。
  - 补充 `role="dialog"` / `aria-label` / `aria-haspopup`，改善可访问性。

## 9. 校验与测试

**集合数据校验**（升级游戏版本后执行）：

```bash

node -e "const d=require('./data/items.json');const s=new Set(d.items.map(i=>i.id));console.log(d.items.length,Math.max(...d.items.map(i=>i.id)),[...s].length)"

# 2) 集合内 ID 全部存在（示例：检查 collections.ts 里出现的数字是否都在 items.json）

```

## 11. 翻页器改版（v1.2）：改用 shadcn 组件

图鉴底部的翻页器不再是手写的 `<select>` + 两个 `Button`，而是新增/复用的 shadcn 组件：

- `web/src/components/ui/Pagination.tsx`：`Pagination` / `PaginationContent` / `PaginationItem` /
  `PaginationLink` / `PaginationPrevious` / `PaginationNext` / `PaginationEllipsis`。
  这里 `PaginationLink` 直接复用项目 `Button`（保留 radix `asChild`），因此天然支持 `disabled`（越界禁用）与主题变体；
  图标一律 `data-icon`、由 `Button` 统一尺寸，页数多时用 `PaginationEllipsis` 收窄。
- `web/src/components/ui/NativeSelect.tsx`：无 JS 的原生 `<select>`（`size="sm"` 用于紧凑区），
  物品集合、每页个数、复制内容三处下拉均改用它。
- `web/src/lib/pagination.ts` 新增纯函数 `paginationRange(page, pageCount, siblings)`：
  始终含首尾页、当前页两侧各 `siblings` 个，断开处返回 `'ellipsis'`（有单测覆盖）。
- 切页（上一页/下一页/点页码）会同时把网格滚动复位（`goToPage`），避免翻页后停在旧滚动偏移出现空白。

对齐 shadcn 设计规范顺带修正：`Button` 基础样式补上 `[&_svg:not([class*="size-"])]:size-4` 与 `icon` / `icon-sm` 尺寸，
使图标在有 `data-icon` 时无需再手写 `size-*`（详见 `.agents/skills/shadcn/rules/icons.md`）。
